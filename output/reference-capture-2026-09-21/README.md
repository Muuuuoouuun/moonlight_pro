# 자료함 사용성 시안

2026-09-21 · 대화 안에서 탐색하는 UI 시안. 운영 앱 구현·DB 저장과 구분한다.

- `reference-capture.html`: 대화에 표시하는 HTML fragment. 자료 370건과 선별 여부 26건을 기존 `docs/research/2026-09-20-reference-writing/library.json`에서 투영했다. 사용자의 개인 메모와 즐겨찾기는 빈 상태로 시작한다.
- `preview.html`: 브라우저 확인용 wrapper. visualize의 `scripts/render.py`로 생성했다.
- 기획 근거: [입력·모아보기 우선 기획](../../docs/superpowers/specs/2026-09-21-reference-capture-and-browse-usability-design.md).

시안에서 작동하는 범위는 한 칸 입력, 링크·메모 보관, 370건 검색, 선별 자료·플랫폼·즐겨찾기 필터, 상세 열기, 제목·내 메모 편집, 중복 링크의 메모 덧붙이기, 여러 링크의 분리/묶음 저장, 휴지통·복구다. 디자인 비교 컨트롤은 목록 간격·입력란 크기·데스크톱 상세 배치를 제공하며 제품 설정으로 확정된 것이 아니다.

상태는 화면 메모리와 제공되는 widgetState 기능에만 저장한다. 내용은 `privateContent`, 비교 설정만 `modelContent`에 기록한다. 호스트 상태는 15,000바이트에서 더 저장하지 않으며 화면에 한계를 알린다. 네트워크·Supabase 호출, 원문 자동 수집, AI 생성, 실제 공유·발행은 없다. 새 입력의 제목은 직접 입력한 첫 줄 또는 플랫폼 이름으로 표시하며 원문 제목을 추정하지 않는다.

## 확인한 내용

Codex in-app Browser에서 직접 조작했다.

- 기본 370건 표시, 선별 자료 26건 표시.
- 검색 조건을 유지한 새 메모 저장, 조건 밖 저장 안내와 상세 열기.
- 상세 메모 수정·즐겨찾기, 원본 URL 표시.
- 기존 Instagram 링크에 메모 덧붙이기. 기존 메모를 덮지 않는 동작 확인.
- 여러 링크의 선택 화면, 링크별 2건 저장 및 한 메모의 복수 원본 링크 표시.
- 휴지통 이동 후 실행 취소.
- 입력 중 내용의 wrapper 새로고침 복원.
- 기본 데스크톱, 390px 상세, 320px 목록 배치. 마지막 320px 검사에서 root `scrollWidth=clientWidth=286` 확인.
- 마지막 브라우저 error 로그 0개.

검사 중 sandbox 내 form submit 대신 명시적 버튼 핸들러로 저장을 연결했고, 상태 복원 이벤트가 진행 중 편집을 덮지 않도록 최초 복원과 사용자 조작 이후를 구분했다.

실제 모바일 키보드, 운영 저장 실패·권한·충돌·재시도, 전체 앱 회귀 테스트는 이 시안의 검증 범위가 아니다. 브라우저 검사에서 넣은 점검 메모는 wrapper의 로컬 상태이며 원본 fragment의 초기 데이터에는 포함되지 않는다.
