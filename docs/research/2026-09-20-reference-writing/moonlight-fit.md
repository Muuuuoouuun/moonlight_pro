# 수집 자료를 Moonlight와 내 글쓰기에 연결하는 방법

2026-09-20 · **읽기 전용 조사와 권장안** · 코드 기준 HEAD `a3b2938` 및 현재 작업 트리

> 상태: HISTORICAL — 최초 조사 시점의 코드 사실과 연결 제안을 보존한다. 현재 후속 권장안과 구현 경계는 [레퍼런스·글쓰기 흐름 기획](../../superpowers/specs/2026-09-20-reference-library-writing-workflow-design.md)이 우선한다. 아래 본문에 출처를 함께 적는 방식은 당시 코드로 사용할 수 있는 수동 연결 방법이다.

**권장: 통합 파일에서 지금 쓸 주제를 고르고, 선택한 자료와 내 관점을 하나의 소재 카드로 만들어 기존 Studio로 이어간다.** 자료 전체를 먼저 앱에 적재하거나 자동 생성기를 새로 만드는 것보다, 이미 저장한 자료를 다시 찾고 한 편을 끝내는 흐름부터 확인하는 편이 운영 기준에 맞는다.

이번 입력은 Instagram 저장 85건·DM 자료 20건·고유 YouTube 영상 265건의 **후보 기록 합계 370건**이다. 최종 플랫폼별 중복·접근 상태 집계는 함께 만드는 통합 인덱스를 따른다. YouTube 영상 264건의 내용 요약이 있다는 것과 외부 주장이 검증됐다는 것은 다르다. Instagram 자료도 캡션·일부 화면·전체 영상의 확인 수준을 그대로 구별한다.

이 문서는 앱 구현·DB 적재·상시 수집 활성화 승인이 아니다. 앱 코드, 운영 DB, 외부 계정은 변경하지 않았다. 실제 AI 공급자 호출이나 브라우저 저장 왕복도 실행하지 않았으므로 아래의 “있음”은 코드로 확인한 구현을 뜻한다.

## 1. 확정된 방향과 이번 권장

**확정된 운영 기준**은 참고 영상에서 자신의 주제와 연결된 아이디어를 얻고, 우선 저장한 다음 여유와 몰입이 생겼을 때 고르는 것이다. 가장 큰 부담은 “어떤 아이디어를 만들지 결정”하는 일이고, 복잡한 점수보다 직감과 지금 만들 수 있는지를 우선한다. 단일 소재함·참고 링크·떠오른 이유·원본의 채널별 재사용도 이미 운영 기준이다. [운영자 프로필](../../../docs/operator-workflow-profile.md#L457)

**기존 제품 계약**은 원문→기획→초안→AI 후보 비교/적용→채널 파생이며, Studio 1차 구현이 승인됐다. 9월 15일 통합 기록은 소재함·빠른 메모·수동 발행을 그 Studio에 연결했다고 명시한다. 문서의 나머지 자동화·성과·대표 자산 제안을 전부 구현됐다고 읽으면 안 된다. [콘텐츠 제작 스펙](../../../docs/superpowers/specs/2026-09-12-content-notes-drafts-ai-workflow-design.md#L10), [브랜드·콘텐츠 통합 기록](../../../docs/superpowers/specs/2026-09-11-brand-content-refocus-proposal.md#L7)

**이번 권장**은 플랫폼을 가로질러 자료를 찾는 파일 인덱스와, 실제로 쓰려는 글의 소재 카드를 분리하는 것이다. 통합 인덱스는 참고 자료 전체를 보관하고, Moonlight에는 지금 제작할 것만 보낸다. 어느 브랜드에서 무엇을 주장할지, 실제 자신의 경험은 무엇인지, 반복 수집 범위와 주기는 아직 미정이다. 저장 목록만으로 사용자의 신념·경험·브랜드 정체성을 확정하지 않는다.

## 2. 이미 있는 것과 부족한 것

| 단계 | 코드에서 확인한 현재 기능 | 이번 자료에 적용할 때의 의미 |
|---|---|---|
| 소재 담기 | 본문 또는 참고 URL로 저장. 브랜드는 나중에 선택 가능. 개인/회사 범위를 기록하고 저장 후 재조회한다. | 선별한 카드만 수동으로 넣는 데 새 화면이 필요하지 않다. [입력 UI](../../../apps/hub/components/hub/pages/content-idea-capture.jsx#L19) |
| 소재 저장 | 원문은 `content_items.source_idea`, 참고 URL은 `meta.source_url`, 빠른 메모 출처는 `meta.source_note_id`. 새 소재는 `idea` 상태와 `threads_post` 초안으로 만들어진다. | 최소 글쓰기 단위에 맞는다. 외부 자료 전체를 보관하는 전용 라이브러리 계약은 아니다. [메타 저장](../../../apps/hub/lib/repositories/content-ledger.js#L178), [소재 생성](../../../apps/hub/lib/repositories/content-ledger.js#L800) |
| 소재→Studio | 큐의 항목을 누르면 해당 `item`의 Studio로 간다. | 이미 있는 경로로 제작을 시작할 수 있다. [큐 연결](../../../apps/hub/components/hub/pages/content.jsx#L117) |
| 내 관점 정리 | 원문, 기획 제목, 결과물 제목이 분리된다. 독자·목적·핵심 메시지·관점·근거·마무리의 기획 필드가 있다. | 남의 주장과 내가 하려는 말을 구조적으로 나눌 최소 공간은 있다. [기획 필드](../../../apps/hub/lib/content-workflow-client.js#L10), [Studio 원문·기획](../../../apps/hub/components/hub/pages/content-studio.jsx#L112) |
| AI 초안과 편집 | 원문→초안, 다듬기, 줄이기, 도입 3안, 채널 변형. 후보를 보고 명시적으로 적용하며 확인할 내용을 표시한다. | 전체 자료를 한 번에 먹이는 대신 선택한 짧은 자료로 한 편씩 만들 수 있다. [작업 종류](../../../apps/engine/lib/content-transform.ts#L28), [비교·적용 UI](../../../apps/hub/components/hub/pages/content-studio-ai.jsx#L135) |
| 원문 메모 추적 | 메모 발췌→Studio 경로는 원문 ID·revision·발췌를 `source_refs`에 넣고 원문 메모로 돌아갈 수 있다. | 반복 사용되는 내 관점·경험 메모에 적합하다. 현재 외부 영상 전체의 출처 탐색 UI와 같지는 않다. [출처 생성](../../../supabase/migrations/20260913_0027_journal_notes.sql#L231), [원문 메모 링크](../../../apps/hub/components/hub/journal-links.jsx#L11) |
| 결과물만 내보내기 | 복사·파일 내보내기는 선택 variant의 결과물만 대상으로 한다. | 비공개 기획 메모를 공개 원고와 나눌 수 있다. 단, 원고 본문에 직접 붙여 놓은 비공개 내용은 사용자가 검토해야 한다. [내보내기·복사](../../../apps/hub/lib/content-workflow-client.js#L99) |

현재 생성 경로의 이름은 Hub `buildContentIdeaRecords` → Engine `create_draft`이며, Studio 편집 저장은 별도의 `content_workflow_v1` 경로다. 새 기획의 출처 packet은 이 기존 경로를 확장하는 제안이며 이미 존재하는 별도 저장 API를 뜻하지 않는다.

연결할 때 중요한 공백은 네 가지다.

1. **URL만 넣으면 AI가 원문을 읽는 구조가 아니다.** Engine은 저장된 `sourceIdea`, `brief`, `source_refs`, 브랜드, 현재 variant만 AI 입력으로 조립하고, 외부 URL을 가져오지 말라고 명시한다. `meta.source_url`도 현재 `sourceData`에 직접 포함하지 않는다. 따라서 참고 링크 칸만 채우고 영상·캡션을 이해한 초안을 기대하면 안 된다. [문맥 조립](../../../apps/engine/lib/content-transform.ts#L179), [생성 계약](../../../apps/engine/lib/content-transform.ts#L194)
2. **참고 URL 저장과 출처 UI는 다른 수준이다.** 목록 데이터에는 `sourceUrl`이 있지만 Studio의 출처 컴포넌트는 `journal` 참조를 열고, 일반 외부 자료의 ID·확인 수준·발췌 위치를 관리하는 편집기는 확인되지 않았다. Studio 저장 요청도 임의의 외부 `source_refs`를 받는 인터페이스가 아니다. [목록 투영](../../../apps/hub/lib/repositories/content-ledger.js#L364), [메모 참조 필터](../../../apps/hub/lib/journal-client.js#L45), [Studio 저장 필드](../../../apps/hub/lib/content-workflow-client.js#L47)
3. **현재 큐는 수백 건의 자료 검색을 위한 목록이 아니다.** 기록 조회가 최근 수정 item 80건·variant 160건을 가져오고, 큐는 그 결과를 브랜드·상태로 좁힌다. 이번 자료를 모두 넣으면 과거 자료가 기본 목록에서 빠질 수 있다. 원문 ID 중복 검사·플랫폼별 접근 실패·통합 전문 검색도 이 큐 경로에서 확인되지 않았다. [조회 한도](../../../apps/hub/lib/repositories/content-ledger.js#L971), [큐 필터](../../../apps/hub/components/hub/pages/content.jsx#L121)
4. **좋은 글쓰기 기준은 있으나 내 말투 학습과 사실 검증은 자동으로 완성되지 않는다.** 현재 편집 기준은 근거와 불확실성 보존, 없는 사실은 `missing`에 남기기, 원문의 재가공을 새 경험으로 포장하지 않기를 포함한다. 브랜드의 `writing_examples`를 읽을 수 있지만 수집한 외부 자료를 곧 사용자의 글쓰기 예시로 바꾸는 근거는 없다. 자신의 실제 글 예시를 별도로 골라야 한다. [편집 기준](../../../packages/content-manager/editorial-criteria.ts#L12), [브랜드 입력](../../../apps/engine/lib/content-transform.ts#L170)

## 3. 최소 소재 카드: 출처와 내 관점을 한 번만 명확히 적기

아래는 **새 스키마가 아닌 텍스트 작성 양식**이다. 지금 만들 글 하나당 카드 하나를 사용하고, 참고 자료는 필요한 소수만 연결한다. 제목은 자료의 자극적인 제목을 그대로 복제하기보다 이번에 다룰 질문으로 적는다.

```text
이번에 쓸 질문:

[외부 자료]
출처 ID:
원문 URL:
내용 확인 수준: 자막 기반 / 영상 분석 / 캡션만 / 일부 화면 / 내용 미확보
다시 볼 위치: 영상 시점·슬라이드·로컬 요약 파일 위치
외부의 주장: “누가 무엇을 말한다” 형태로 짧게 재서술
주장 검증 상태: 미검증 / 해당 주장만 원출처 대조

[내 관점]
내가 말하고 싶은 한 문장:
동의·수정·반박하는 지점:
내 실제 경험: 있는 내용만. 없으면 ‘아직 없음’
독자에게 남길 질문 또는 작은 행동:

[남은 확인]
발행 전에 확인할 숫자·인용·맥락:
다음 행동:
```

내용에 접근했는지와 주장이 사실인지 두 축을 분리한다. 영상 요약 완료는 발언 확인의 출발점이고, 연구 효과·매출·건강·심리 주장을 검증했다는 표시가 아니다. 캡션만 확인한 릴스를 영상 전체의 주장으로 바꾸지 않는다. 내용 미확보 항목은 링크 북마크로 남겨두고 논증의 근거로 사용하지 않는다.

내 경험이 없다면 “내가 해보니 효과가 있었다”는 초안을 만들지 않는다. 대신 자료를 보고 생긴 질문, 반론, 적용해 보고 싶은 가설을 글의 관점으로 삼을 수 있다. 서로 상반되는 자료도 평균을 내어 성공 공식으로 합치지 말고 “어떤 상황에서 어느 조언이 도움이 되는가”라는 비교 소재로 쓴다. 신앙·철학·동기부여 발언은 해당 관점임을 유지한다.

**기존 화면에 옮기는 방법 — 후속 실행 권장:**

1. 통합 인덱스에서 지금 쓸 질문을 고르고 원문을 다시 연다. 제목이 비슷한 자료를 더 모으기보다, 이번 주장에 실제로 필요한 부분만 고른다.
2. 위 카드의 출처 ID·URL·확인 수준·선택 요약·내 관점을 **소재 메모 본문에 함께 넣는다.** 참고 링크 칸에는 대표 URL을 넣되, AI 문맥과 재찾기를 위해 본문에도 URL을 보존한다. `meta.source_url` 단독 누락을 피하는 현재 코드에 맞는 방법이다.
3. Studio의 원문 메모에는 카드를 유지하고, `핵심 메시지`에는 내 논지, `관점`에는 경험담/질문/비교 등 형식, `근거와 사례`에는 외부 주장과 확인한 내 경험을 표시해 넣는다. 같은 요약을 여러 번 길게 붙이지 않는다.
4. AI 초안 후보를 비교하고 `확인이 필요한 내용`을 확인한다. 생성은 문장 작성 보조이며 사실 검증 완료가 아니다. 개인 경험·인용·수치가 새로 생겼는지 확인한다.
5. 실제 원고를 결과물 본문에 남긴 뒤 결과물만 복사한다. 외부 자료를 출처로 밝힐 문장은 원고에 명시적으로 넣는다. 내 비공개 메모와 참고 목록 전체를 자동으로 공개하지 않는다.
6. 같은 관점을 다시 쓰게 되면 실제 자신의 기록을 메모로 보관하고, 기존 발췌→Studio 기능으로 원문 관계를 남긴다. 통합 파일에는 어떤 글에 썼는지 링크만 덧붙여 다시 찾는다.

최초 소재 생성은 원문과 초안 본문에 같은 텍스트를 넣는다. 따라서 소재 카드를 저장한 직후 곧바로 `복사`해 발행하지 않고, Studio에서 결과물 본문을 원고로 정리해야 한다. [초기 본문 저장](../../../apps/hub/lib/repositories/content-ledger.js#L806)

## 4. 세 단계의 효용·부담·진행 조건

아래 순서와 조건은 **권장**이다. 기간·작업량·유료 API 비용은 실측 전이므로 수치로 단정하지 않는다.

| 단계 | 할 일 | 얻는 효용 | 비용·부담 | 다음 단계로 갈 조건 |
|---|---|---|---|---|
| **1. 파일 큐레이션 — 지금** | 저장·DM·YouTube를 한 인덱스로 묶는다. 출처 ID·원문 URL·확인 수준을 유지하고, 지금 쓸 질문별로 소수의 자료와 글감 카드를 둔다. | 앱을 바꾸지 않고 다시 찾기·비교·초안 준비가 가능하다. 모으는 부담을 글 고르는 행동으로 바꾼다. | 일회성 중복·분류 점검과 선택한 자료의 원문 대조. 기존 요약 재사용에 새 API 호출은 필수가 아니다. | 실제 질문으로 자료를 찾고, 연결된 원문으로 돌아가며, 한 편의 초안을 끝낼 수 있는지 본다. 후보 개수보다 “찾지 못한 이유/쓸 수 없던 이유”를 기록한다. |
| **2. 기존 소재함 연결 — 반복 사용 시** | 파일 전체 대신 지금 쓸 카드를 기존 소재함에 넣고 Studio로 제작한다. 직접 텍스트 연결부터 사용하며 API 일괄 적재는 별도 범위로 둔다. | 소재 선택→내 관점→초안→복사까지 기존 기능으로 이어진다. 다음 행동·막힌 이유와 버전을 남긴다. | 선택 카드 작성·검수 시간, 수동 AI 생성 사용량, 앱의 실제 저장/재조회와 AI 설정 확인. 전량 적재하면 목록 한도·검색·중복 문제가 추가된다. | 본문/출처를 저장·재조회한 뒤 같은 글과 원문을 다시 찾는 왕복을 확인한다. 실제 이용 중 반복되는 복사·누락 문제가 있을 때만 좁은 가져오기 기능을 검토한다. |
| **3. 자동 수집 확대 — 수요가 확인된 출처만** | 자주 쓰는 컬렉션/재생목록/공유 경로의 신규 항목부터 추가한다. 수집 위치·플랫폼 ID·중복·접근 실패를 기록하고, 깊은 분석은 고른 자료에만 한다. | 새 참고자료 정리의 반복 수고를 줄인다. 이미 쓰는 주제에 필요한 갱신을 돕는다. | 로그인/화면 변경/스크롤 누락 대응, 수집 실패 복구, 선택 미디어의 OCR·전사·영상 처리와 API 비용, 지속 유지보수. | 반복 실행에서 신규·중복·실패가 구별되고, 화면 끝만 읽어 누락하지 않으며, 새 자료가 실제 글에 쓰이는지 확인한다. 주기·대상·월 비용 한도는 활성화 전에 확정한다. |

1단계만으로도 유용한 결과가 나와야 한다. 2단계를 위해 전체 자료 적재를 선행할 이유는 없다. 3단계의 필요성은 “저장 자료가 많다”보다 “다시 쓰는 출처의 새 자료를 놓치거나 같은 수집을 반복한다”는 관찰로 판단한다.

## 5. 확인할 장면

- **지금 쓸 주제:** 통합 자료를 열었을 때 내가 답하려는 질문 하나와 쓸 이유를 고를 수 있는가.
- **다시 찾기:** 제목을 정확히 기억하지 않아도 주제·용도·출처 ID로 같은 자료를 찾을 수 있는가.
- **원문 추적:** 초안의 외부 주장 한 문장에서 원문 URL과 확인한 위치로 돌아갈 수 있는가.
- **내 글로 발전:** 외부의 요약, 내 판단, 내 실제 경험이 구별되고 내 논지가 한 문장으로 남는가.
- **완성으로 연결:** 소재를 늘리지 않고 한 편의 원고를 끝낼 수 있는가. 못 끝났다면 근거 부족인지 관점 부족인지 기록하는가.

복잡한 자료 점수, 전체 자동 발행, 새 지식 그래프는 이 확인의 전제 조건이 아니다. 최초 몇 편의 사용 사례가 생기면 실제로 반복되는 불편에 맞춰 다음 범위를 정한다.
