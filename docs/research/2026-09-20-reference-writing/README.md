# 저장 자료에서 내 글로 — 통합 레퍼런스 정리

2026-09-20 · 인스타·YouTube 기존 수집 결과 통합 및 선별 원문 대조

저장소 보관본: 최초 수집·선별 당시에는 로컬 산출물만 작성했다. 이후 운영자의 “커밋, 기획” 요청으로 이 폴더에 자료와 재생성 도구를 보관한다. [보관·재생성 안내](ARCHIVE.md) · [후속 제품 기획](../../superpowers/specs/2026-09-20-reference-library-writing-workflow-design.md). 앱 구현·운영 DB 적재는 이번 보관 범위에 포함하지 않는다.

**활용할 가치가 있다. 가장 유용한 단위는 ‘좋은 내용 요약’보다 ‘내가 답하고 싶은 질문 + 관련 출처 + 내 판단’이다.** 이미 확보한 자료를 이 형태로 꺼내 쓰는 작업을 우선 권한다. 전량 자동 수집이나 초안 대량 생성의 효용은 이번 결과만으로 확정하지 않는다.

## 왜 가치가 있어 보이는가

**첫째, 이미 원하는 제작 흐름과 맞는다.** 운영 기준에는 참고 콘텐츠를 보고 자신의 주제로 연결하고, 단일 소재함에 저장한 뒤 지금 만들 수 있는 것을 고르는 방식이 명시돼 있다. 자료 선택에 드는 부담이 가장 크다고 기록돼 있어, 이번 정리는 그 선택에 직접 쓰일 수 있다. [운영 기준](../../../docs/operator-workflow-profile.md#L457)

**둘째, 서로 다른 역할의 재료가 있다.** 이번 표본에서 YouTube는 설명·학습·실행을 길게 전개한 자료가 많고, 인스타 비즈니스 컬렉션에는 고객 대화·전달 방식·제품 사례가 있다. DM 표본에는 제작 도구와 도입 사례가 있다. 이 역할 분담은 이번 확보 자료에 대한 편집적 해석이며 계정 전체나 사용자의 성격을 설명하는 결론은 아니다.

**셋째, 원문을 대조하니 요약만 읽을 때 빠지는 조건이 실제로 발견됐다.** 이는 단순 목록 복사보다 선별 정리에 시간을 쓸 이유다.

반대로 이 자료만으로 **내 말투**, **내가 겪은 사건**, **성공·건강·심리 주장들의 사실성**까지 확보되지는 않는다. 외부 자료에서 얻은 질문에 자신의 판단을 붙여야 자기 글이 된다. 다른 사람의 경험을 일인칭으로 바꾸는 방식은 사용하지 않았다.

## 어떻게 활용하는 편이 좋은가

추천 흐름은 **전체 자료함 → 이번에 쓸 질문 → 출처가 붙은 소재 카드 → 내 관점과 실제 경험 → 초안**이다.

자료 하나에는 다음 세 층을 유지한다.

1. **출처:** 누가 무엇을 말했는지, 어디서 확인했는지, 실제로 확보한 내용은 어디까지인지.
2. **내 생각:** 왜 관심이 갔는지, 동의·수정·반박하는 지점, 적용될 조건과 예외.
3. **글감:** 독자에게 남길 주장 한 문장, 실제 장면 또는 아직 확인할 질문, 다음에 쓸 형식.

같은 자료도 발상·설명 구조·사례·검증된 사실 중 어떤 역할로 쓰는지 다르다. 이번 자료 대부분은 **발상과 관점 비교의 재료**로 쓸 수 있으며, 원문 확인만으로 검증된 사실이 되는 것은 아니다. 신앙·철학·동기부여·사업 자기보고는 각자의 맥락을 유지한다.

좋은 자료 두 개가 다른 말을 하면 하나의 성공 공식으로 섞지 않는다. 예를 들어 ‘내 목소리’와 ‘독자의 이해’는 초안과 퇴고의 다른 목표로, ‘먼저 계획’과 ‘작게 실행’은 반복 업무와 불확실한 일의 다른 접근으로 비교할 수 있다. [긴장하는 조언 세 쌍](youtube-insights.md)

## 제품에 연결하는 세 가지 선택

| 접근 | 얻는 것 | 부담·한계 | 판단 |
|---|---|---|---|
| **파일 정리와 선별 글감** | 지금 자료를 다시 찾고 한 편을 시작할 수 있다. | 새 수집은 별도이며 자기 경험·관점은 적어야 한다. | **이번에 수행. 먼저 사용 가치를 확인하기 적절하다.** |
| **기존 Moonlight 소재함·Studio에 선택 카드 연결** | 원문·기획·AI 후보·채널 초안 흐름을 재사용한다. | 참고 URL만으로 원문이 AI에 전달되지 않는다. 저장·재조회 왕복은 후속 실측이 필요하다. | **다음 권장. 전량 대신 지금 만들 카드만 넣는다.** |
| **전용 레퍼런스 관리와 반복 수집 확대** | 신규 자료 갱신·중복·수집 실패·검색을 지속 관리할 수 있다. | 플랫폼별 유지보수와 OCR·전사·분석 비용 관리가 추가된다. | 반복 사용에서 드러난 불편에 맞춰 범위를 정한다. |

현재 코드의 참고 URL은 `meta.source_url`에 저장되지만 AI 입력에 직접 포함되지 않고, AI는 외부 URL 내용을 읽지 않는다. 따라서 **선별 요약·출처 URL·확인 수준을 소재 본문에도 넣는 방식**이 당장 가능한 연결이다. 또한 현재 콘텐츠 큐는 최근 item 80건·variant 160건 조회라 전체 370개 레퍼런스 탐색 화면으로 쓰기에 제약이 있다. [코드 근거와 연결 방법](moonlight-fit.md)

확장 여부는 다음 사용에서 판단하면 된다. 원하는 자료를 찾았는지, 원문으로 돌아갔는지, 초안을 끝냈는지, 실제 자신의 생각을 더하는 데 무엇이 부족했는지를 기록한다. 1주 동안 짧은 글 3편에 써보는 것은 권장하는 작은 실험이며 확정 발행 일정은 아니다. 비용과 시간 절감률은 아직 측정하지 않았다.

## 건수와 확인 범위

| 항목 | 범위 |
|---|---:|
| 기존 원 목록 연결 | 401건: YouTube 296 + 저장 85 + DM 20 |
| 병합한 중복 | 31건: 같은 YouTube 영상의 목록 간 중복 |
| 통합 고유 자료 | **370개** |
| 플랫폼별 | YouTube 영상 265 · Instagram 게시물 103 · Facebook 1 · YouTube 커뮤니티 1 |
| YouTube 기존 내용 요약 | 264편: 자막 기반 194(품질 주의 2 포함) + 영상 분석 70 |
| 이번 선별 인사이트 | **26개: YouTube 14 + Instagram 12** |
| 이번 원문 구간 재대조 | **22개: 저장 자막 10 + 공개 캡션 12** |
| 이번 기존 AI 응답만 검토 | YouTube 4개. 직접 시청·자막 재대조와 구별 |

**370개 전체를 이번에 새로 정독·시청한 결과는 아니다.** 전체에는 이전 요약·분류를 유지하고, 선택한 26개에만 추가 검토를 붙였다. 선별 26개는 의도적으로 고른 글감이므로 자료 전체의 정확도 표본 검증으로 해석하지 않는다.

YouTube의 원 자막 확보는 196편이다. 그중 2편은 품질 문제로 영상 분석을 사용했으므로 자막 기반 요약 194편과 숫자가 다르다. 이전 보고서·JSON의 이 구별을 유지했다. 일부 자동 자막의 오류와 구간 공백은 선별 인사이트에 기록했다.

인스타 저장 JSON은 원 캡션 전문을 보존하지 않았으므로, 새로 원문을 확인하지 않은 항목은 분석자 제목·분류·링크 이상의 내용을 만들지 않았다. **저장 자료 76개와 DM의 Instagram 자료 15개는 이번에 원문을 다시 읽지 않았다.** 기존 분류의 낮은 확신 29개도 이번 작업이 모두 해결한 것으로 표시하지 않았다.

추가 미확보 범위: YouTube 숨겨진 목록행 38개(고유 영상 수 아님), 회원전용 영상 1편, 다른 인스타 저장 컬렉션 9개, 지정 DM의 확인하지 못한 이력, 원문을 열지 못했던 외부 공유 2개. 접근 불가 DM 공유 1건은 URL이 없어 통합 370개에 포함하지 않았다.

## 보존과 검증

- 원 수집 파일 17개(기존15개 + Threads 추가2개)를 `sources/`에 바이트 그대로 보존하고 [경로·SHA-256 기록](source-manifest.json)을 남겼다. 원본 영상·모든 슬라이드·캡션·자막 전문 전체의 보존은 아니다. 스냅샷 안의 당시 절대경로·문구는 해시 보존을 위해 유지하며 [예외 범위](ARCHIVE.md)를 따른다.
- 공개 원문 링크와 영상 시점을 유지했다. 선별 YouTube 대조에 사용한 임시 파일은 복사하지 않았다. [대조 파일 해시](evidence-manifest.json)의 `original_location_at_review`는 당시 위치 기록이며 현재 재생성·검증의 입력이 아니다.
- 집계·중복·필수 필드·로컬 문서 링크·내부 스냅샷 해시는 [검증 스크립트](verify-archive.py)로 다시 확인할 수 있다. [검증 기록](validation.md)은 최초 수집 검증과 이번 저장소 보관 검증을 구분한다. 외부 링크 전부의 현재 접속 성공을 뜻하지 않는다.
- 최초 수집 당시에는 커밋·푸시·발행 없이 로컬 정리본·글감·초안까지만 작성했다. 이번 저장소 보관은 그 산출물과 후속 기획을 기록하는 작업이다. Moonlight 앱 코드와 운영 DB, 플랫폼 저장 목록·메시지·발행 상태는 변경하지 않는다.
