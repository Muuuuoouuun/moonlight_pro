# Guru 멘토 경험 객관 점검 — 2026-09-25

> 범위: 격리 개발 브랜치의 서가·레일·고객 상세·기존 Guru 대화, 카드 카탈로그와 요청 경로. 운영 배포와 실제 조언의 유용성 평가는 포함하지 않는다. 기존 확정 방향은 `2026-09-24-guru-dual-experience-design.md`다.

## 판정 기준과 결과

| 기준 | 현재 판정 | 관찰 근거와 한계 |
|---|---|---|
| 필요할 때만 도움 | 코드 경로 확인 | 서가·레일 열람, 분야 전환, 넘김은 생성 요청을 보내지 않는다. 질문 입력을 열어도 `전송` 전에는 조언을 생성하지 않는다. 홈·오늘 승인 대기에는 Guru 카드를 붙이지 않는다. 실제 알림 운영 로그의 장기 관찰은 별도다. |
| 개인·ClassIn 경계 | 이번 점검에서 교정 | 고객 상세의 Guru 질문은 ClassIn 화면 범위와 회사 고객 소속이 함께 확인될 때만 열린다. 개인·전체 범위에서는 출처 카드 열람만 가능하다. 답장 초안도 `workspace`·`type`·`brand`를 함께 판정하고, 충돌하거나 알 수 없는 명시 범위면 생성 경로를 닫고 확인 상태를 표시한다. 소속 정보가 전혀 없으면 기존 수동 선택을 유지한다. 거래의 Guru 진입도 회사 유형을 기준으로 개인·상충 소속을 막는다. 레거시 회사 유형은 ClassIn으로 인정한다. 중복된 무범위 ‘맞춤 연락 초안 (Guru)’와 계정 이름으로 엉뚱한 거래를 참조할 수 있던 ‘Ask Guru’를 제거했다. 기존 대화의 영업 API에는 세일즈 카드만 전달한다. 고객 목록 필터 전체의 충돌 행 처리까지 통일된 것은 아니다. |
| 상황 적합성 | 부분 충족 | 고객 목록은 `new`·`active`·`dormant`라는 넓은 구분만 안다. 이 구분으로 제안 내부 검토·문제 진술·긍정 답변을 추론하던 MEDDIC·SPIN·Voss 자동 노출을 중단했다. 이 세 카드는 인물 서가에서 직접 찾을 수 있다. Ross는 `sales:new`가 명시적으로 일치할 때만 순환하고 기본 서가·미지 맥락에는 나오지 않는다. 나머지 네 자동 카드는 확인되지 않은 사건을 전제하지 않는다. 고객의 실제 발언·거래 단계에 맞춘 추천이라고 표현할 수는 없다. |
| 정기 순환 | 규칙성 확인, 다양성 제한 | 서울 09·14·19시 한 장씩, 당일 같은 분야에서 중복 없이 결정적으로 선택한다. 30일·90구간 시뮬레이션에서 연속 같은 카드 0회. 세일즈 신규는 고유 5장, 진행 중·기약 없음은 각 4장이라 다음 날 일부가 반복된다. 마케팅의 대상 미기록은 4장이나 인물은 2명뿐이다. 콘텐츠의 소재·제작중·검토도 각각 4장이다. |
| 출처와 내용 | 선택 카드 검수, 전체 문서는 미검수 | 카드의 문구는 인용이 아닌 편집 요약으로 출처 절·원전 링크·응용 여부를 표시한다. Harry Dry 첫 문장 카드의 2차 링크는 본인 게시물로 교체했다. `docs/research/2026-09-24-guru-source-quality.md`에 남은 미검증 인용·성과 수치가 있어 긴 문서 전체를 카드 재료로 자동 사용하지 않는다. HTTPS 링크 형식 테스트는 원전의 내용 검증을 대신하지 않는다. |
| 탐색 경험 | 개발 화면에서 개선 확인 | 390×844 사전 점검에서 전체 서가는 첫 화면보다 약 2.2 화면 아래였고 세일즈 분야별·인물별 13개 행이 거의 같았다. 상단 바로가기, 분야별 방법론 중심/인물별 이름 중심, 선택 상세에서 목록 초점 복귀, 작은 필수 메타의 대비를 개선했다. 수정 후 개발 브라우저에서 바로가기·선택·복귀를 확인했다. 스크린리더 음성 시험과 라이트 테마 재검사는 남았다. |
| 조언의 실효성 | 미검증 | 소스와 요청 경로가 연결된 것은 확인했지만, 실제 상황에서 맞는 답을 주는지에 대한 운영자 평가 표본이나 채택·무시 기록은 아직 없다. 카드 열람 수를 유용성의 증거로 쓰지 않는다. |

## 입력 → 변환 → 연결에서 확인한 것

| 단계 | 현재 계약 | 객관적 한계 |
|---|---|---|
| 자료 → 카드 | 원본 플레이북을 통째로 모델에 넣지 않는다. 원전과 대조한 주장만 편집 카드로 만들고, 카드 ID를 선택한 질문에 방법론 요약·출처·응용 범위를 첨부한다. | 카드가 인물의 전체 지식을 대변하지 않는다. 원본 문서에 남은 수치·인용은 일괄 승인되지 않았다. |
| 화면 맥락 → 시간대 팁 | 서울 09·14·19시에 분야와 넓은 상황 구분으로 한 장을 고른다. 열람과 넘김은 요청·업무·알림을 만들지 않는다. | `new`·`active`·`dormant`는 고객의 발언이나 제안 진행 상태가 아니다. 따라서 상황형 세부 기법은 확인된 사건이 생기기 전까지 자동으로 고르지 않는다. |
| 명시적 질문 → 조언 | 운영자가 전송한 뒤에만 Hub가 해당 멘토 요청을 Engine으로 보낸다. ClassIn 고객 질문은 화면 범위와 레코드 소속이 모두 확인될 때만 허용한다. | AI가 실제로 출처를 해석하고 적절히 답하는지 운영 사례로 검증해야 한다. 과거의 `persona-chat` 세일즈 프롬프트는 카드 카탈로그와 별도 경로다. |
| 단일 고객 입력 → 초안·추출 | `outreach-draft`·`extract-contact-outcome`은 선택한 원문과 명시된 단일 기록 맥락을 사용한다. Hub의 다른 최근 거래 자동 첨부와 Engine의 일반 메모 RAG 자동 검색을 이번 점검에서 끊었다. | 호출자가 원문이나 `context`에 이미 다른 고객 내용을 섞으면 그대로 전달된다. 입력 화면의 데이터 품질은 별도로 확인해야 한다. |
| 결과 → 실행 | 요청 결과는 조회·복사하거나 운영자가 후속 행동을 직접 선택한다. 카드 순환으로 승인 큐나 작업지시서가 생성되지는 않는다. | 실효성은 카드 조회 수가 아니라 실제 질문의 도움, 오판, 불필요한 조치 유도 여부로 평가해야 한다. |

## 다음 검증 순서

1. 현재의 넓은 화면 구분과 별도로, 실제로 저장된 고객 발언·제안 상태·후속 응답 등 **확인 가능한 사건**이 있을 때만 구체 카드의 자동 노출 자격을 넓힌다. 사건이 없으면 일반 질문 네 장을 유지한다.
2. 카드·AI 조언을 각각 소수의 실제 업무 사례에서 평가한다: 상황 사실과의 일치, 출처 해석, 질문의 도움 정도, 불필요한 후속 조치 유도 여부를 분리해 기록한다. 사용자의 질문 없이 카드만 읽은 경우는 조언 성과로 집계하지 않는다.
3. 콘텐츠와 마케팅의 새 인물 카드는 원전의 해당 주장과 적용하지 않을 상황까지 검토한 뒤 늘린다. 현재 마케팅 `audience-unrecorded`가 두 인물로 반복되는 현상은 새 카드 검수 전까지 UI만으로 해결할 수 없다.
4. 고객 목록 자체의 범위 필터는 충돌 태그를 양쪽에 표시할 수 있다. 이번에는 조언 생성 경계에서 차단했으므로, 목록 분류를 단일 판정으로 바꿀지 별도로 검토한다. 계정 전용 Guru 진단을 다시 열려면 계정 ID와 연결된 정확한 초점 모델을 먼저 만든다. 레일의 맥락 태그만으로 고객의 구체 사실을 만들어서는 안 된다.
