# Instagram 레퍼런스 수집·분석 점검

2026-09-20 · 로그인된 Chrome의 실제 화면으로 확인

> 상태: 관찰 기록. 분류·활용·후속 구현은 제안이며 확정 제품 사양이 아니다.

**저장 목록과 DM 공유 자료를 수집해 검색·분류·업무용 초안으로 가공하는 것은 가능하다.** 이번에는 비즈니스 저장 컬렉션 85개와 지정 DM의 참고자료 20개, 합계 105개의 출처를 정리했다. 두 목록의 Instagram 게시물 ID에 중복은 없었다. 계정 전체 수집이나 모든 영상의 내용 분석을 완료했다는 뜻은 아니다.

## 내용 접근은 어디까지 되는가

**링크·작성자·보이는 캡션:** 이번 비즈니스 목록 85개에서 모두 확인했다. 다만 21개는 캡션이 100자 미만이고, 긴 캡션도 인물 소개·홍보 문구일 수 있다. 캡션이 있다고 영상 내용을 파악한 것은 아니다.

**정지 이미지:** B001은 브라우저가 제공한 이미지 파일을 1440×1800 JPEG로 저장하고 화면 내용까지 확인했다. 업로드 원본 해상도를 보장하지는 않는다.

**캐러셀:** B002의 2·3·4번째 화면을 열어 앱 창업·UGC 크리에이터 사례를 읽었다. 이 이미지들의 대체 텍스트는 비어 있어 캡션만 추출하면 슬라이드 본문이 빠진다. 전체 슬라이드는 검토하지 않았다. 향후에는 페이지별 이미지 또는 화면 캡처와 OCR을 결합해야 한다.

**릴스:** B003의 재생과 일부 프레임·화면 자막은 확인했다. 별도 HTML 자막 트랙은 관찰되지 않았으며 전체 음성 전사도 하지 않았다. 이번 도구의 영상 다운로드는 파일 확보로 이어지지 않았고, 미디어 묶음 수집 시도 2건도 실패했다. 이는 해당 도구·표본에서의 결과이지 모든 릴스 수집이 불가능하다는 뜻은 아니다. 현재 결과만으로 ‘릴스 전체 분석 자동화가 된다’고 약속할 수는 없다.

**DM:** 공유 게시물의 원문을 열어 링크·공개 캡션을 수집할 수 있었다. 이번에는 별도의 사적 대화 문장을 수집하지 않았다. 메시지별 직접 링크는 확인하지 못해 로컬 원본에는 대화 URL과 화면의 날짜 구분자를 함께 기록했다. 저장소 사본에는 해당 정보를 제외했다. 공유 시각과 게시물 발행 시각은 구분했다.

삭제·비공개 전환 등으로 현재 계정에서 볼 수 없는 원문은 이 방식으로 복구할 수 없다. 게시물에 나온 성과·매출·가격·유명인 발언의 사실 여부도 별도 검증이 필요하다.

## 1차 분류에서 드러난 활용 방향

비즈니스 85개는 영업·협상 18, 마케팅·브랜딩 15, 성장·실행 14, 조직·리더십 12, 창업·제품 11, 경제·투자 3, 내용 확인 필요 9, 주제 재검토 3개로 임시 분류했다. **영업·마케팅·제품 관련 자료가 44개**여서 상담 준비·콘텐츠 기획·제품 실험에 먼저 연결하기 좋다.

분류 근거가 약한 항목은 총 29개다. ‘확인 필요’라는 임시 분류의 9개만 미확인이라는 뜻은 아니다. 나머지 56개도 캡션에 근거한 중간 수준 분류이며, 영상 전체 확인이나 사실 검증을 의미하지 않는다.

DM 표본은 AI 업무 자동화 4, 앱·제품 제작 4, 영상 제작·편집 3, 사업·조직 운영 3, 웹 디자인·브랜딩 2, 음악·인터랙션 2, 주제 미확인 외부 링크 2개다. 저장 컬렉션보다 제작 도구와 실행 아이디어의 비중이 높게 관찰됐다. 계정 전체 성향에 대한 결론은 아니다.

실사용 분류는 주제 태그와 별도로 `고객 대화·후속 / 콘텐츠·전달 / 제품·실험 / 협업·일하는 방식 / 배경·영감`을 제안한다. 각 자료에 `캡션만 확인 / 일부 화면 확인 / 전체 확인`을 따로 붙여야 과도한 요약을 막을 수 있다. [활용 틀](reusable-actions.md)에 실제 작성 가능한 양식과 출처를 연결했다.

## 다음 단계의 현실적인 순서

1. **수집 목록 완성:** 다른 저장 컬렉션을 같은 방식으로 순회하고, 지정 DM은 마지막 확인 위치를 기록하며 과거 구간을 추가 수집한다. 신규 공유 링크를 하나의 수집함으로 받는 방식도 병행하면 반복적인 과거 탐색을 줄일 수 있다.
2. **원문 보존 보강:** 링크·요약 외에 캡션 전문, 수집 시각, 이미지·슬라이드, 접근 실패 사유를 보존한다. URL보다 게시물 ID로 중복을 제거하고 같은 자료가 저장·DM 양쪽에 나타난 관계는 남긴다.
3. **선택한 자료의 깊은 분석:** 실제 쓸 항목부터 이미지 OCR·음성 전사·영상 확인을 진행한다. Gemini API 등을 연결하더라도 분석할 수 있는 파일이나 텍스트를 먼저 확보해야 한다. 이번에는 외부 모델 API로 업로드하지 않았다.
4. **Moonlight 연결:** 검증된 수집 결과를 레퍼런스 수집함에 넣고, 요약·용도·출처·확인 수준·사용 기록을 검색하게 만든다. 현재는 JSON/Markdown 감사 산출물까지이며 앱 기능이나 상시 수집기는 구현하지 않았다.

브라우저 수집은 작동했지만, 화면이 가상화되어 비즈니스 목록 하단의 DOM에는 28개 링크만 남았다. 스크롤마다 누적해 85개를 확보했으므로 마지막 화면만 읽는 수집 방식은 누락을 만든다. 로그인 유지·화면 변경·지연 로딩을 포함한 무인 반복 수집의 안정성은 아직 검증하지 않았다.

## 검증 기록

- 비즈니스 85개 URL·캡션 길이·순서를 브라우저의 수집 결과와 대조했다. 순서 포함 FNV-1a 체크섬: `846360419`.
- Instagram 게시물 ID 기준으로 저장 목록 내부, DM 목록 내부, 두 목록 사이의 중복을 점검했다.
- 건수·형식·분류 집계를 JSON에서 계산했고, 정지 이미지 파일 형식과 크기를 확인했다.
- 관찰한 캡션과 미디어 화면을 근거로 요약했으며, 게시물의 주장 자체에 대한 외부 사실 검증은 수행하지 않았다.
