**점수를 지금 올렸다고 말하기 어려운 이유.** 현재 테스트는 모델 출력이 주어졌을 때의 방어·저장 계약을 주로 증명한다. 한국어 회의의 화자 불명, 담당 변경, 부정, 여러 날짜, 반복 인용을 실제 모델이 얼마나 정확히 처리하는지는 검증하지 않았다. `mine/related` 판정은 안전을 위해 명시 표현에 제한돼 있어 실제 표현을 `unknown`으로 놓칠 수 있다. 인용은 맞지만 “공유한다”를 “내가 확인한다”로 바꾸는 의미 비약은 문자열 검증만으로 걸러지지 않는다. 2만 자 단일 호출·후보 30개 상한은 긴 회의의 뒤쪽 행동 누락 가능성을 남긴다. UI 개선이나 테스트 개수 증가를 실제 추출 점수로 환산하지 않는다.

## 권장 · 100점 실사용 평가표

아래는 **앞으로 측정할 기준**이다. 현재 총점은 **미측정**이며 코드 계약 통과분만 더해 임의 점수를 만들지 않는다. 한 건의 명백한 타인/부정 담당을 `내가 할 일`로 확정 후보화하거나 일정 언급을 기한으로 잘못 확정하면, 총점과 별도로 중대 실패로 기록한다.

| --- | ---: | --- |

## 권장 · 비식별 실제 회의 골드셋

1. **20~30건**의 사용 허용된 한국어 회의 메모·전사문을 비식별화한다. 명확한 담당, 화자 불명 `제가`, 타인 작업의 영향, 담당 취소·보류, 기한과 방문 예정일의 공존, 상대 날짜, 반복 문장, 실행 단계 1개/여러 개, 행동이 없는 회의를 의도적으로 섞는다. 원문 전체를 평가 결과물에 복제하지 않고, 접근 제한된 원본과 해시·사례 ID를 분리한다.
2. 두 평가자가 독립적으로 **행동 단위, 원문 근거 구간, 실제 담당/영향, 날짜 역할과 확정일, 방법·단계, 중요도**를 주석한다. 불일치는 원문으로 조정하고 불명확한 화자는 정답도 `unknown`으로 둔다. 골드셋과 채점 규칙의 버전을 고정한 뒤 모델을 비교한다. 같은 행동의 인용 범위가 재분석마다 달라질 때는 현재 목록에서 자동으로 합쳐지지 않으므로 중복도 별도 집계한다.
3. 동일한 입력과 모델·프롬프트 버전으로 실행해 후보의 정밀도·재현율과 **중요 행동 누락/허위 내 일/허위 기한**을 별도 집계한다. 사용자가 문장을 고치고 작업으로 등록하는 데 걸린 시간과 오류도 소수 실사용 세션에서 관찰한다. 공급자 토큰, 처리 시간, 출력 후보·검증 폐기 건수와 이유를 함께 남겨 품질과 비용의 관계를 본다.
4. 첫 기준선을 얻은 후 문구·검증기를 한 번에 하나씩 바꿔 같은 골드셋으로 비교한다. 안전 반례가 재발하면 총점과 무관하게 출시 보류 대상으로 기록한다. 골드셋 학습 과적합을 막기 위해 새 회의 일부는 마지막 확인용으로 보류한다.

## 우선순위

1. **P0 · 안전/가시성:** 부정된 담당·영향 관계와 여러 날짜의 반례를 유지한다. 근거 없는 날짜·단계는 해당 필드만 격리하고, 유효 행동 전체를 조용히 숨기지 않는다. 탈락한 후보의 **건수와 이유**를 원문 없이 기록해 `후보 없음`과 `검증에서 제거됨`을 구분한다.
2. **P1 · 측정:** 위 골드셋을 만들고 실제 모델 의미 정확도·사용자 수정 부담을 측정한다. 분석 run에 처리 시간·후보 수·폐기 수, 입력 상한과 30개 후보 상한의 도달 여부를 더해 재분석·분할 처리 필요성을 결정한다.
3. **P2 · 적용 확대:** 기준선과 운영 왕복이 확인된 뒤 긴 회의 분할/중복 병합, 현재 읽기 전용 주시 목록의 알림·완료 처리·페이지네이션, 음성·화자 분리, 월 비용 원장을 순서대로 다룬다. 녹음·외부 에이전트 배분을 M0 성능 개선으로 주장하지 않는다.
