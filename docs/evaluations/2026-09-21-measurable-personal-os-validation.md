## 구현 결과

- `현황 → 목표·성과`에서 목표, 결과/선행 활동/보호 지표, 실제값과 날짜 있는 근거, 관측 이력을 관리한다. 증가·감소·범위 방향을 계산하며 0과 미측정, 부분 측정을 구분한다. 정의는 보관 후 새로 만들고 관측은 누적 이력으로 남긴다.
- 프로젝트·할 일·캠페인·브랜드·콘텐츠·딜·리드·고객·메모·일일 리뷰의 목표 연결을 지원한다. 개인/회사와 workspace를 읽기·연결·AI 문맥에서 검사한다. 소속이 이동하거나 원문을 읽을 수 없는 연결은 상태를 표시하고 해제할 수 있다.
- 자동 지표는 현재 완료 작업, 실제 CRM 연락, 발행 기록, 일일 리뷰다. **개인/회사 전체의 해당 기간 집계**이며 연결된 업무만의 귀속 실적은 아니다. 연결 자체는 실적을 늘리지 않는다. 주간 보고도 같은 정의를 사용한다.
- 저장된 할 일·프로젝트·콘텐츠에서 Gemini 초안/표현 개선/품질 검토/근거 분석을 요청하거나 외부 AI 후보를 저장한다. 후보 채택·수정·반려와 시간 기록은 업무 완료·발송·발행과 분리한다.
- MCP `assistant` 프로필 13개 도구가 같은 목표·AI 서비스에 연결된다. 목표/AI 쓰기는 별도 scope를 요구한다. 모델 생성, 후보 저장, 실제 업무 적용은 다른 동작이다.

## 검증 환경과 실행 결과

실제 PostgreSQL 17 + PostgREST 16.3을 별도 임시 DB로 띄우고 새 0036/0037 마이그레이션을 적용했다. Hub3040·Engine3041을 사용했다. 업무 데이터는 이 로컬 DB에만 준비했으며 제품 코드에 예시 업무 레코드를 추가하지 않았다. Gemini 검증에는 이 합성 업무 맥락만 사용했다.

### 실제 브라우저 검사

CUA의 접근성 트리·스크린샷·읽기 전용 DOM 측정을 사용했다. 브라우저 요청을 가로채는 자동화 시험을 했다고 주장하지 않는다.

- 목표 생성 → 수동 지표 → 실제값 0과 근거 저장 → 새로고침 후 관측 이력 1개·0% 확인. 자동 지표는 로컬 완료 작업 1/목표4 = 25% 확인.
- 저장 후 지표 폼 재열기, N 생성 단축키, 첫 입력 포커스, ESC 닫기, 재열기 입력 보존, 마지막 버튼 Tab 순환 확인. 생성/상세 닫기 후 원래 버튼/목표 링크로 포커스 복귀 확인.
- 개인 목표 2개와 ClassIn의 실시간 빈 목록을 분리해서 표시. 오류·로딩·부분 상태도 확인.
- 목표에서 할 일 맥락과 편집으로 이동해 같은 목표 연결과 실제 Gemini·Codex 후보를 확인.
- 삭제된 프로젝트의 연결은 부분 상태·설명으로 표시하고 깨진 링크를 제공하지 않음. 해제 저장 후 연결 1→0, 상태 부분→실시간, 목표 보존을 확인.
- 390/768/1440px에서 목표 화면의 문서 너비가 각각 viewport와 같음. 390px 생성 폼·AI 드로어, 390/1440px 라이트·다크 화면 확인. 모든 관련 도메인 화면/크기 조합을 완주한 것은 아니다.

## 독립 검토로 발견해 고친 문제

1. UI 생성 payload의 허용되지 않은 필드로 저장이 거절되는 문제, 성공 후 비운 draft의 null로 폼 재열기가 실패하는 문제를 실제 브라우저에서 재현·수정했다.
2. CRM `account_kind`·별칭·lane·company_id 소속 판정을 기존 CRM과 맞췄다. 누락된 부모는 개인으로 추정하지 않는다.
3. 미래 일일 리뷰 집계와 미래 목표에 대한 수동 관측의 잘못된 달성을 차단했다. 관측 시각과 해당 시간대의 시작일을 검사하고 기존 잘못된 관측도 달성에 사용하지 않는다.
4. 영수증 조회 권한/가용성 오류나 결과 불명 이후의 재시도가 기존 명령 번호를 지우지 않도록 했다. 저장 후 새로고침은 저장 전 시작된 GET을 재사용하지 않는다.
5. 삭제/소속 이동한 연결의 확인·해제 경로를 추가했다. 보관된 목표에서도 CAS를 지키며 연결을 정리한다.
6. 모델 성공 후 저장 실패한 답변을 보존하고, 서명된 자료로 저장만 복구한다. 드로어를 닫는 동안 응답이 와도 브라우저 세션에 복구 자료를 남긴다.
7. JSON 이스케이프까지 포함해 MCP 응답을 제한하고 긴 후보를 나눠 읽는다. 주간 보고가 범용 요약 제한 때문에 수치·기간을 잃던 문제는 전용 투영으로 고쳤다.
8. 주간 딜 집계는 기존 단계 별칭과 `meta.stage_detail`을 우선한다. 일일 리뷰 근거 링크 경로를 수정했다. 원장·소속 참조와 목표 연결은 묶어서 읽는다.

## 가혹 평가

독립 UI/통합 검토자가 실제 실행 증거를 바탕으로 채점했다. 축마다 5개 항목, 항목당 20점이다. 점수는 이 구현 범위의 완성도 판단이며 사업 성과·벤치마크가 아니다. 계획·미실행 클라이언트·운영 배포에는 실행 점수를 주지 않았다. 재현된 데이터 손실·교차 범위 누출·거짓 달성 문제는 평균과 별개로 완료를 막는 조건으로 처리했다.

### 감점과 남은 한계

- 목표 조회는 200개, 지표·관측은 각각 1,000개 등의 상한이 있다. 초과하면 일부 상태로 표시하지만, 오래된 전체 이력을 끝까지 읽는 일반 UI 경로는 충분하지 않다. 다음 최적화의 첫 순위다.
- 자동 완료 지표는 현재 완료 상태 집합이다. 재오픈·재완료 시 과거 집계도 바뀐다. 불변 완료 사건 원장은 별도 개발이 필요하다. 매출·입금·전환율은 이번 자동 소스에 포함하지 않았다.
- 작업별 시간 차이는 자기 기록 기반이며 설정·시스템 유지 비용을 제외한다. 로컬 QA에서 입력한 18분은 사업 시간 절감 실측이 아니다.
- 세 앱에서 쓸 수 있는 stdio 계약과 설정 예시는 제공했지만 Codex·Claude Desktop·Antigravity 각각의 로그인된 UI 실행은 확인하지 않았다. 기존 구독의 MCP 사용과 Gemini API 비용은 별도다.
- 운영 DB/배포·지속 실행·모든 업무 표면의 완주·스크린리더 앱·장기 사용 효과는 미검증이다. 기존 자동화 크론의 실행 전체를 새 보조 기능의 중복 방지 보장으로 일반화하지 않는다.
