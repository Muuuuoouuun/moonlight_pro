## 오늘: 등록에서 3개 지정까지

- 분리돼 있던 등록과 집중 선택을 한 줄 입력으로 연결했다. 선택 여유가 있으면 등록한 할 일을 오늘 3개에 넣을 수 있고, 이미 3개면 일반 목록 등록을 계속한다. 기존 최대 3개 규칙을 유지한다.
- 저장 요청 중 입력·선택을 잠그고, 빠른 연속 조작은 동기 잠금과 공통 작업 큐로 처리한다. 등록 receipt를 재사용하므로 응답 유실 뒤 재시도가 같은 할 일을 중복 생성하지 않는다.
- 할 일 생성과 집중 지정의 성공을 별도로 확인한다. 생성 성공 뒤 지정만 실패하면 입력을 다시 생성하지 않고 해당 할 일 ID로 지정만 재시도한다. 미확인·실패 응답을 저장 성공으로 취급하지 않는다.
- 선택·해제·완료 응답은 DB의 실제 snake_case 행을 읽어 즉시 반영한다. 제한된 화면 행으로 전체 카운트를 다시 만들지 않아 열린 할 일 수가 왜곡되지 않는다. 완료된 슬롯의 제목과 완료 상태를 유지하며 낮에도 해제할 수 있다.
- 날짜 경계·창 복귀·갱신 때 선택 상태를 재확인한다. 느린 읽기 때문에 후속 쓰기 큐가 무한히 멈추지 않도록 처리했다. 모바일 입력과 해제 버튼은 44px 터치 기준을 맞췄다.

실제 브라우저에서 확인한 순서는 다음과 같다. 모든 API는 로컬 QA 프록시가 처리하며 외부 API로 전달하지 않았다.

1. Enter 등록 → 첫 저장은 합성 원장에 반영됐지만 503 응답 → 입력 유지 → 같은 receipt 재시도 → 같은 행 1개만 존재.
2. 등록 후 집중 PATCH 503 → 저장된 할 일의 지정 재시도 → Inbox 재등록 없이 슬롯에 1회 표시.
3. 후보 두 개 추가 → 정확히 3개 → 네 번째 선택 비활성. 완료·실행 취소 대기·저장 확인 → 완료 슬롯 제목 유지 → 해제 → 새로고침 후 2개 유지.
4. 모바일에서 새 할 일 Enter → 남은 슬롯 채움. 3개가 찬 상태의 추가 등록은 일반 목록에만 들어가며 네 번째 집중을 만들지 않음.
5. 선택 자체는 열린 할 일 총수를 줄이지 않고, 완료는 줄이며, 신규 등록은 늘림. light/dark와 390×844에서 입력·슬롯·해제·가로 넘침 확인.

요청 기록은 Inbox 4회가 사용자 의도 3건에 해당하며, 최초 두 요청의 receipt가 같다. 최종 집중 ID는 서로 다른 3개다. 완료 후 해제와 전체 선택 뒤 일반 등록도 기록으로 확인했다. KST 날짜 전환·창 복귀·같은 개수의 다른 ID 교체는 실제 effect/handler 하네스에서 검증했으며 실제 자정까지 기다린 검사는 아니다.

## 프로젝트: 모바일 진입과 생성·할 일 연결

- 수정 전 모바일 선택기에서 새 프로젝트로 진입하면 폼이 가려져 빈 화면처럼 보이는 문제를 baseline에서 재현했다. 생성·선택 화면의 표시 조건을 정리해 실제 폼으로 연결했다.
- 모바일에서 프로젝트 검색·필터·현재 프로젝트 전환이 보이고, 상태와 최근 활동으로 목록을 좁힐 수 있다. 7일 필터의 실제 2→1 결과를 확인했다.
- 프로젝트 생성·편집·연결 할 일의 실패 후 입력과 요청 ID를 보존한다. 성공 후 선택·목록·연결 할 일을 갱신한다.
- `/`로 검색을 열고, 검색 결과 Enter 선택 후 전환 버튼으로 포커스를 돌린다. 선택기 Escape는 검색어를 먼저 지우고, 다음 Escape에서 닫힌다. 기존 할 일 입력 초안은 유지한다.

모바일 실제 조작으로 생성 503→같은 ID 재시도 성공, 해당 프로젝트에서 할 일 503→같은 ID 재시도 성공, 편집 503→입력 유지→성공을 확인했다. 새로고침 후 편집한 이름과 같은 프로젝트에 연결된 할 일이 남았다. 이 성공은 QA 프록시 메모리 안의 저장이며 운영 DB 저장을 뜻하지 않는다.

## OKR·KPI: 새 목표 설정과 과거 기록 분리

- 목표 ID 없이 진입하면 기존 확정 목표를 기본값으로 제시하지 않고 빈 목표 구조와 설정 동선을 보여준다. KPI·체크인·주간 하위 구조와 기존 입력·편집 기능은 유지한다.
- `setup=1`을 유지해 설정 중 하위 보기·소속을 바꿔도 과거 기록으로 돌아가지 않는다. `records=1` 및 명시 목표/기록 ID는 과거 기록을 열며 기존 편집을 유지한다.
- 새 목표 초안 키를 기존 목표·과거 초안과 분리했다. 제목·기간·숫자를 복사하지 않으며, 새 제목·수치·기간을 임의로 만들지 않았다.

실제 OKR·KPI 내비게이션 → 새 설정 → KPI 하위 보기와 모바일 dark 화면을 확인했다. 기본 화면에서 기존 합성 목표 제목은 0개였고, 기록 보기에서는 진행 중·보관된 기록의 제목과 기간이 그대로 보였다. 새 폼의 제목·시작일·종료일은 모두 빈 값이었다. 빈 제출은 검증 메시지만 표시하고 POST하지 않았다. 합성 제목 입력 → 닫기 → 재진입은 해당 새 초안을 복구하며 날짜는 비어 있었다. 검수 제목은 이후 지웠다. 목표 생성·수정·삭제·초기화 요청은 0회다.

첫 최종 실행에서 남았던 4개 시험은 바뀐 컴포넌트/경로의 기존 하네스 불일치였다. 실제 callback의 목적지·scope·query 재소비를 검사하도록 고친 뒤 위 최종 전체 실행에서 비 DB 실패 0을 확인했다. 시험을 삭제하거나 실패를 skip으로 바꾸지 않았다. 새 원격 CI는 실행하지 않았다.
