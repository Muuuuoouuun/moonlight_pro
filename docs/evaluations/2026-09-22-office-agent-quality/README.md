## 구현 결과와 품질 판단의 구분

역할별 전문 지식·판단 절차·근거·경계·인계·말투를 하나의 role card에서 관리한다. 회의는 실제로 역할별 첫 의견을 생성하고, 설정에 따라 공개 발언을 읽는 응답 라운드와 주관 합성을 실행한다. 반론·깊이·말투·수렴 및 참여자별 비중이 요청과 결과에 보존된다. 같은 공급자 모델의 여러 호출이며 독립 사실 검증이나 인간 회의가 아니다.

출처 검수는 인용이 현재 자료나 사용자 발언에 실제 있는지 확인한다. **인용이 있다는 사실은 최종 문장이 그 근거에 부합한다는 증명이 아니다.** 실제 응답에서 미확인 성공 판정, 지원·기능 창작, 없는 합의, 종결 뒤 과도한 설명이 남았다. 생성 성공·스키마 통과·테스트 통과를 의미 품질 점수로 바꾸지 않았다.

## 실제로 확인한 개선 한계

- 기술 답변이 성공 JSON 계약을 모른다고 설명하면서도 파싱 이후 `showDone`을 호출했다. 뒤의 주의 문구로 앞의 잘못된 코드가 교정되지 않았다.
- 매출·리스크·콘텐츠 관점이 미측정 효과 수치는 지웠지만, 화면 하나로 준비 단계가 줄어든다는 미확인 기능·효과를 새로 넣었다.
- 개별 토론 발언은 구현 실험을 추천했는데 최종 합성이 수동 관찰에 합의했다고 서술한 사례가 있다.
- 원문 인용의 정확성·응답 계약·시간 제한을 통과하지 못한 경우 결과를 성공으로 공개하지 않았다. 이 차단은 안전한 경계지만 실용성 목표를 만족했다는 뜻은 아니다.
- 단순 확인·종결 요청에서도 전문 절차와 수용 기준을 반복하는 답변이 남았다. 자연스러운 말투와 요청 크기 조절이 더 필요하다.

## 화면·코드 검증

후속 `21f720e`에서는 전체 테스트 **1,976개 중 1,965개 통과·11개 skip·실패 0**, 타입 검사 4개 workspace, Hub·Engine 빌드 2개를 통과했다. 새 adapter의 프로세스 종료·취소·출력 경계 검증을 포함하며 의미 점수와는 별개다. UI 변경은 없어 아래 기존 화면 검증을 재수행한 것으로 기록하지 않는다.

통합 커밋 `7a3345e`에서 전체 테스트 **1,916개 중 1,905개 통과·11개 skip·실패 0**, 타입 검사 4개 workspace 통과, Hub·Engine 빌드 2개 통과를 확인했다. 이 커밋에는 다른 작업에서 완료한 CRM 연락 결과 추출·공급자 finishReason 전달 변경도 함께 들어 있다. 모델 평가 journal의 정확한 실행 코드는 각 provenance 파일 hash가 정본이며, 통합 커밋 전체를 동일 모델 평가로 인증하지 않는다.

브라우저 검증은 1440px·390px, 밝은/어두운 테마에서 수행했다. Office 설정 보존·실제 요청과 결과의 일치·이전 고객 응답 무시·원문 보존·주간/고객 진입 등을 15건 확인했고, 기존 자문 및 공통 진행률·모션은 18건 확인했다. 보고는 [Office](ui/office.json), [고객 전환](ui/customer.json), [자문·모션](ui/advisor-motion.json)에 있다. 브라우저 API는 테스트에서 가로챘으며 실제 업무 쓰기·모델 호출로 검증한 것이 아니다.

운영 DB의 Office 0038 적용과 배포는 이번 작업에서 수행하지 않았다. 기존 Phase 1B·1C의 운영 잔여도 완료로 바꾸지 않았다.

## 추가 실험과 남은 개선

완성된 AI 초안을 반복 교정하면서 새 사실을 덧붙이는 문제를 줄이기 위해, 첫 호출을 원문 근거·요청 범위·짧은 판단 정리로 제한하고 둘째 호출에서 본문을 처음 작성하는 방식을 별도 평가한다. 현재의 전체 역할 절차·예시를 최종 작성 단계까지 반복하는 구조도 줄인다. 회의 합성에서는 발언과 합성 초안을 중복 전달하지 않고 실제 이견·조건을 보존해야 한다. 호출 수·48초 제한·입력 보존·공개 응답 계약은 유지하는 방향이다.

위 구조를 세 개발 사례·6회 모델 호출로 [별도 실험](diagnostics/preparation/probe.report.md)했으나, JSON만 보고 완료 표시·미확인 검토 상태 창작·실제 검증 약속이 남았다. 이 결과로 제품 적용을 정당화할 수 없어 채택하지 않았다. [스크립트](diagnostics/preparation/probe.mjs)와 [원문 결과](diagnostics/preparation/probe.results.json)는 실행 당시 로컬 경로를 보존한 진단 자료이며 배포 코드가 아니다. 다음 개정은 의미 오류가 실제로 제거되는지 먼저 확인해야 한다. 현재 개발 세트로 개선을 확인한 뒤, 구현자가 아직 읽지 않은 별도 평가 자료로 검증한다. 준비한 비공개 세트의 SHA256은 `d1bd074499e855d59ab85ea73c19d4c8a786b66c425166f44cf0da2f35760673`이며 이번까지 실행하지 않았다. 그 자료를 구현 수정에 쓰게 되면 다시 새 독립 자료가 필요하다.
