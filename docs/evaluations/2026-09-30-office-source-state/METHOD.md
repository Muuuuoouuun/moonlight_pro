# Method and limitations

1. Root authorized exactly one complete development replay and one fresh private run after non-author specification and root code-quality approval of commit `c6d1ca8de5ca8e531c145a7f869b1fd85fec16f6`. Product tests reported by root are not re-certified by this evidence validator.
2. Development uses the unchanged six-case dataset and criteria from the prior v26 heldout run. Its adapter changes only the dataset/printed claim labels; both adapter hashes are in `suites/development/run-purpose.json`. The original v26 journal, suite and lock are untouched.
3. Fresh cases and criteria were prepared without inspecting the candidate implementation or outputs. The author knew earlier observed failure categories and the approved general correction category. Freeze occurred after implementation began and 27.833037 seconds after the candidate commit; `suites/holdout/chronology.json` supplements the original unchanged freeze record. No model calls were used in preparation.
4. The runner verified exact HEAD, configured model and clean tracked runtime. It inherited the previously approved exception for the existing root-owned `docs/README.md` unstaged edit; staged changes and every other tracked edit remained prohibited. This guard adjustment changed no case, criterion or runtime source. The prior adjustment record is preserved in the sibling v26 artifact.
5. Node v24.18.0 loaded existing Engine environment configuration without exposing credential values. The adapters import the candidate's actual Office generation service, Gemini provider, evaluation runner and trace wrapper. Existing source-context/message contracts were used. Frozen expectations were not injected into generation. No runtime prompt/model substitution, business ledger persistence, customer message, tool execution or application launch occurred.
6. Actual concurrency was one (the generic header's maximum is a limit, not actual concurrency). Each planned generation was attempted once. Development generated 8/8 with 36 provider calls; fresh generated 5/5 with 35 provider calls. Every provider call reported success and `gemini-3-flash-preview`. There was no recovery, retry or splicing. Journals retain every attempt/result and before/after runtime integrity coverage.
7. Journals include complete validated public responses, actual input/context/history and public council positions/reconsiderations/synthesis. They do not retain private intermediate draft/reviewer text; the existing trace retains hashes, diagnostics and usage metadata for those calls. Evaluation can judge observed public text only.
8. The non-author assessor read every generated public field and manually judged each frozen expectation. Exact source/output anchors are validated mechanically; semantic decisions are manual. Partial satisfaction is distinguished from noncompliance, and concerns outside frozen criteria are separate. Correct synthesis does not erase an unsupported public draft. A recommendation that explicitly states sufficient completion conditions is checked for missing prerequisites; the rubric does not require every field to repeat all facts.
9. The original full role rubric is not applied here. The development set contains all nine roles, but the fresh set covers six roles and two targeted multi-turn situations. These counts are not nine-role certification, independent score estimates, production acceptance or a broad benchmark. There is no repeated sampling, matched control, attribution of defects to influence weights, causal improvement claim or business-outcome measurement.
10. The configured/reported model identity is an alias, not proof of an immutable provider model build. Reproduction requires the exact candidate tree/dependencies and credentials; deterministic identical model text is not promised. The saved runner, cases, source/tooling hashes, requests and journals support auditing without additional calls. The one-shot locks remain present. Any further execution needs separate authorization and is development after disclosure.

The observed source-state hypothesis is insufficient. Later-confirmation positive controls work in this run; unknown prerequisites still disappear from some public drafts and dependent fields. No follow-up tuning or new suite was performed after these observations.
