# 데스크톱 연결 전환·세션 복구 검증 — 2026-10-22

기준: `c89ecbf2` · 범위: `apps/desktop` 및 Mac 네이티브 `prototypes/moonlight-pet-macos`. Mac 일반 실행은 SwiftUI, Windows는 Electron 펫이라는 별도 플랫폼 계약을 유지한다. 설치본 교체·운영 쓰기·유료 모델 호출은 하지 않았다.

## 재현과 수정

| 문제 | 재현·근본 원인 | 수정·검증 |
| --- | --- | --- |
| 이전 Hub로 뒤늦은 쓰기 | 로컬 pending 복원을 기다리는 동안 주소 변경. `run`은 준비 대기 후 현재 연결을 확인하지 않아 이전 Hub에 task POST를 보내고 나서야 `stale-origin`으로 보고했다. | 준비 대기 직후 연결 동일성을 검사한다. 신규 회귀에서 실제 fetch 호출 1건 → 0건. |
| Office 질문이 새 Hub로 전송됨 | 같은 준비 대기 동안 주소를 바꾸면 `chatSend`가 새로 구성된 공유 chat을 사용해 이전 질문을 새 Hub에 보냈다. | 준비 대기 뒤 연결 검증. 신규 회귀에서 새 Hub의 `/office/chat` 호출 1건 → 0건. |

| 쿠키를 읽는 동안 연결을 바꿔도 쓰기가 시작됨 | 연결 검사를 통과한 요청이 비동기 쿠키 조회를 기다리는 동안 주소가 바뀔 수 있었다. | 연결 수명 AbortSignal과 개별 취소 신호를 함께 사용한다. 주소 변경·dispose에서 이전 신호를 취소하며, 쿠키 조회 후 이미 취소됐다면 fetch를 시작하지 않는다. |

이미 서버에 도착한 쓰기는 네트워크 취소로 되돌릴 수 없다. 이 경우 기존 origin별 pending 명령의 저장·재확인 계약을 유지하며 자동 재전송하지 않는다.
