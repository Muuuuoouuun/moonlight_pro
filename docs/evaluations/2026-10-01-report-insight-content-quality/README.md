# 보고서·리서치 인사이트 내용 품질 검토

2026-10-01 02:52 KST에 보호된 읽기 API와 저장 당시 근거를 대조했다. 실제 AI 리서치 3건과 회사 주간 AI 정리 1건을 검토했다. 개인 주간 AI 정리는 이 표본에 없으므로 평가하지 않았다. 코드·운영 데이터 변경과 유료 모델 호출은 하지 않았다. 고객명·연락 원문·개인 메모는 이 문서에 포함하지 않는다.

**최초 운영 표본은 의미 오류가 있었고, v5 조합의 자동 후보는 4/5건이 채택 가능했다. 후속 정치 v6 raw도 보류하여 모델 raw 내용 판정은 4/5로 유지한다. 서버가 원문 범위로 좁힌 정치 결과는 일정형 검토 자료로 별도 채택 가능하다.** v5 조합은 Nomad·정치 v5와 교육·회사·개인 v4다. 정치 1건은 일정표에 없는 인과·의도·논의 이력을 덧붙여 보류했고, v6와 서버 보정후 결과는 §5 마지막에 구분해 기록했다. 아래 최초 기준선과 각 시도는 그 시점의 판정이며, 수동 편집본이나 서버 보정후 자료를 모델 raw 품질 합격으로 세지 않는다. 인용 문자열과 위치가 존재해도 작성한 주장 전체를 뒷받침하는지는 별개다.

## 2. 편집 루브릭

공통 anchor는 **0=오도하거나 사용할 수 없음, 1=일반론·큰 재작업, 2=핵심 수정 필요, 3=작은 수정으로 판단에 사용 가능, 4=명료하고 구체적이며 재정리 부담이 거의 없음**이다. 표본과 근거가 없으면 `미평가`로 둔다. 아래 항목은 문서 전체의 실제 효용으로 판단하며 제목 수, 글 길이, 체크리스트 수, 특정 문구 출현에는 점수를 주지 않는다.

| 기준 | 확인할 질문 |
| --- | --- |
| 판단 유용성 | 독자가 알아야 할 변화·선택·보류 조건을 좁혀 주는가? 읽은 뒤 무엇을 판단할 수 있는가? |
| 사실의 구체성 | 대상·기간·상태·단위·제공 조건을 정확히 보존하고 핵심 사실을 골랐는가? 정보가 적을 때 빈칸을 꾸며 채우지 않는가? |
| 논지의 일관성 | 관찰→해석→독자 영향→결론이 이어지는가? 단순 뉴스 목록이나 거대한 전망으로 뛰지 않는가? |
| 근거·불확실성 | 핵심 주장이 인용의 의미와 범위 안에 있는가? 발표자 주장·예정·완료·추론·미확인을 구별하고 중요한 제한을 결론에도 보존하는가? |
| 우선순위·부담 | 가장 중요한 판단이나 작은 확인을 먼저 제시하는가? 근거 없이 전수 점검·새 과제·기한을 늘리지 않는가? 추가 행동이 필요 없으면 멈추는가? |
| 자연스러운 한국어 | 다시 해석할 필요 없이 읽히는가? 추상어·과장·장식·반복·맥락에 무관한 면책 문구가 내용을 가리지 않는가? |
| 독자·브랜드 차별 | 같은 사실을 브랜드 이름만 바꿔 재사용한 수준을 넘는가? 정치=사실·제도·쟁점 이해, class.moon=원장 운영·교육 판단, 22nomad=기술 이해·시작 조건에 각각 맞는가? 주간 정리는 개인/회사 목적·범위를 지키는가? |

총점으로 상쇄할 수 없는 탈락 조건은 **중요 사실 창작, 예정→실행·일부→전체·횟수→사람 수 변환, 0↔미측정 변환, 비교 범위·비용·제공 조건 누락으로 인한 오도, 개인/회사 경계 위반, 하지 않은 조회·사용·검증·발송을 했다는 주장**이다. 명백한 오류의 위치와 대조 근거를 남긴다. 자료가 없다는 이유만으로 억지 결론이나 행동을 요구하지 않는다.

이 표본의 평가는 22nomad **조건·초보자 효용 보완 필요**, class.moon **사실 범위 수정 필요**, 정치 **상태 보존과 논지 재작성 필요**, 회사 주간 **지표 보존과 판단 범위 수정 필요**다. 단일 검토자의 기준선이며 숫자로 품질 인증을 만들지 않았다.

## 3. 자동 평가와 실제 전후 합격 방법

1. **재현 가능한 고정 묶음:** 지금의 원고와 생성 당시 공개 원문·회사 집계·기간·범위·hash를 기준선으로 보존한다. 새 후보는 기존 생성 core의 평가용 호출로 별도 만든다. 기존 source claim을 초기화하거나 이전 결과를 덮어쓰지 않는다. 모델·프롬프트 버전, 호출 설정, provider 호출 수, 토큰·추정 비용, 실패를 함께 기록한다.
2. **기계 검사는 정확히 이름 붙인다:** 스키마·상한·인용 위치·원문 문자열, 숫자/지표 키·기간·범위·coverage 보존, 근거 ID·본문 연결을 검사한다. 이는 형식·추적 검사이며 의미 품질 통과가 아니다. 사실은 맞아도 읽기 어렵거나 결정에 도움이 안 될 수 있다.
3. **자동 의미 심사는 근거를 요구한다:** 각 핵심 주장에 출력 JSON pointer·짧은 실제 인용·원문 위치·지지/부분 지지/모순/근거 없음 판정과 이유를 남긴다. 루브릭 평점에도 같은 근거를 붙인다. 생성 모델의 자기점수나 다른 모델과의 동의만으로 사실 인증을 하지 않는다. 심사 실패·근거 누락은 `미평가`로 처리하며 좋은 점수로 채우지 않는다. 개인 자료는 평가에 필요한 최소 집계만 전달한다.
4. **같은 입력의 블라인드 A/B:** 프롬프트를 고친 사람이 아닌 검토자가 버전을 가린 기존/후보 원고와 고정 근거를 함께 읽는다. ‘더 길다’가 아니라 잘못된 결정을 줄였는지, 독자가 한 번에 이해하는지, 수정 부담이 줄었는지 평가한다. 제공 입력이 바뀌었다면 동일-input 개선이라고 부르지 않는다. 원래 입력과 새로 추가한 문맥을 구분해 기록한다.
5. **합격은 실제 결함을 닫는 것:** 현재 4건에서 위의 범위·상태·지표·조건 오류를 모두 바로잡고 새로운 중대 오류가 없어야 한다. 적용 가능한 7개 기준이 각각 3 이상이어야 하며 미평가가 남으면 전체 합격을 선언하지 않는다. 일정/실행, 일부/전체, 발표자 성능 주장/직접 검증, 연락 2건/고객 1명, 0/누락, 부분 집계, 이전 기간 부재·0 기준 비교의 추가 사례도 확인한다. 숫자와 문장 개선은 별도로 남긴다.
6. **실사용 지표는 별도로 관찰:** 이후 운영자가 검토한 원고의 수정 이유·판단까지 걸린 시간·킵/디벨롭/완성 선택을 기록한다. 미응답과 킵은 품질 실패가 아니며 발행량·조회수·자동 평가 점수만으로 효용을 대신하지 않는다.

## 4. 구현 계약과 비용 표기의 확인

- [리서치 검증 코드](../../../apps/engine/lib/research-prepare.ts:37)는 quote와 지정 L범위의 문자열 존재를 검사한다. `facts.text`가 quote의 의미를 보존하는지나 draft 전체의 논지·주장 추적을 인증하지 않는다. [현재 작성 지침](../../../apps/engine/lib/research-editorial.ts:24)은 사실/해석 분리를 요구한다. 최초 표본과 후속 자동 후보의 실제 위반은 §1·§5에 별도로 남겼다.
- [주간 작성 지침](../../../apps/engine/lib/office/workflow-prompt.ts:21)과 [최종 검수 지침](../../../apps/engine/lib/office/workflow-prompt.ts:57)은 단위·상태·미확인 보존을 요구한다. 지침의 존재와 같은 모델의 검수 호출 자체는 의미 품질의 증거가 아니다.
- 이전 실행 기록의 **생성 receipt 6건은 provider 호출 7회**로 구분해야 한다. 성공한 Office 주간 정리 receipt 1건에는 [초안 호출](../../../apps/engine/lib/office/workflow-core.ts:80)과 [검수 호출](../../../apps/engine/lib/office/workflow-core.ts:86)이 들어가고, [generation usage](../../../apps/engine/lib/office/workflow-core.ts:94)는 두 호출을 합산한다. 기존 모델 비용 추정 합계 **$0.0809925는 유지**한다. 합산된 Office 비용에 두 번째 호출 비용을 다시 더하지 않는다. [기존 회귀 테스트](../../../apps/engine/lib/office/workflow.test.mjs:17)도 호출 2회와 합산 usage를 명시한다. 이번 내용 검토에서는 이 테스트나 유료 호출을 새로 실행하지 않았다.

## 5. 실제 개선 후 검토

### 시도 1·2: 전체 합격 없음

실제 후보 파일의 연구 3건·Office 2건과 각 호출 결과를 모두 읽었다. 두 시도의 공개 원문 3개와 Office context·request 2개는 각각 JSON상 동일하다. 두 시도끼리는 입력을 고정한 비교이며, 최초 운영 보고서보다 이전 주 집계 등 입력이 늘어난 효과까지 모두 프롬프트 개선 효과로 부르지는 않는다. 개인 보고서는 최초 기준선과 다른 기간의 추가 평가다. `saved`·`generated`는 평가 core의 응답 상태이며 운영 DB에 채택됐다는 의미가 아니다.

> 9월 30일 국회 일정에 ‘인공지능 시대, 대입제도의 방향은?’ 토론회가 오전 10시, 본관 228호에 예정돼 있다. 이 자료가 확인해 주는 것은 일정과 주제까지다. 대입제도 개편이 결정됐거나 어떤 방안이 제안됐다는 뜻은 아니다. 정책 변화 여부를 판단하려면 후속 발표 자료에서 구체적인 제안과 적용 조건을 확인해야 한다.

이 편집안은 일정형 검토 자료로 사용할 수 있으며, 실제 제도 쟁점·결과를 다룬 심층 인사이트로 인증하지 않는다. 해석·브랜드 관련성 필드에서도 추세·의도·‘시작점’을 제거해야 한다. 수동 편집은 모델 재생성 결과나 자동 품질 개선 증거가 아니다. 다섯 건의 간결한 편집 예시는 [내용 예시](examples.md)에 별도로 두었다.

v5 추가 비용은 **4 provider 요청·알려진 추정 $0.1066400**이다. 이번 새 품질 작업 전체는 **40 provider 요청**, usage·단가가 있는 **34회의 알려진 비용 $0.6418315**다. 남은 **6회는 HTTP 404이며 usage가 없어 비용 불명**이다(v3 5회 + 별도 진단 1회). 실패 리뷰와 thinking tokens는 알려진 합계에 포함하며, 불명 비용을 0으로 보지 않는다. 기존 운영 파일럿의 7 provider 호출·$0.0809925는 이 새 평가 합계와 별도다. 이번 검토자는 유료 호출이나 DB 쓰기를 하지 않았다.

### v6 정치 추가 검토: 본문 개선, raw 전체는 보류

추가 정치 후보 1건을 원문과 별도로 대조했다. source 객체는 v5와 동일하고, 문서 hash는 `0b21270bc752aa97a9916ab089cb68bb59e348d09154c8c79fd954a8291fd77c`다. 최종 fact의 quote는 L21에 그대로 존재한다. writer·review는 모두 `STOP`, 응답은 `saved`지만 이 상태를 내용 합격으로 보지는 않는다.

본문은 v5의 ‘AI 영향 증가 → 장기 개편 의도’라는 인과 추론을 삭제했다. 개최 일정과 실제 정책 수립을 구별하고 후속 토론 결과를 확인하게 한 점은 개선됐다. 잘못된 기사 내 AI 요약을 사용하거나 실제 개최·입법이 완료됐다고 주장하지 않는다. 그러나 최종 JSON의 다른 필드에는 아래 결함이 남았다.

| 필드·정확한 표현 | 원문 대조와 판정 |
| --- | --- |
| `whyBrand`: ‘정치권이 이 의제를 어떻게 **다루기 시작했는지**’ | L21은 해당 토론회의 일정·주제만 알려 준다. 앞선 논의가 있었는지, 정치권이 처음 다루는지에 관한 이력이 없다. v5에서 지적했던 시작 이력을 다시 덧붙인 **수정 필수 결함**이다. |
| `title`: ‘AI 시대 **대입제도 개편 논의**’ | 원문 주제는 ‘대입제도의 방향은?’이다. 구체적인 개편 제안이 있는지 최종 원고 자체도 미확인으로 둔다. 표제도 ‘AI 시대 대입제도 방향 논의 예정’처럼 확인된 주제로 좁히는 것이 맞다. |
| `draft`: ‘기존 평가 방식을 **대체할** 구체적인 개편 제안’ | 미래 확인 질문이므로 대체안이 실제 나왔다고 창작한 문장은 아니다. 다만 유지·보완·변경 가능성이 열려 있는 자료에서 ‘대체’로 확인 범위를 미리 좁힌다. ‘실제 제도 변경 제안과 적용 조건이 확인되는지’로 고치면 더 정확하다. |
| `draft`: ‘중요한 것은 **질문의 무게**다’ | 실제 독자의 판단 기준이나 새로운 근거를 제공하지 않는 수사다. 삭제해도 확인 사실과 다음 관측이 모두 남는다. |

**정치 v6 raw 전체의 판정은 보류**다. 특히 `whyBrand`의 확인되지 않은 시작 이력이 남아 있어, 본문의 인과 문장이 없어졌다는 이유만으로 통과시키지 않는다. 나머지 4건을 유지한 최종 자동 조합은 **4/5 채택 가능**이다. v5의 4/5 판정은 당시 조합의 이력으로 보존한다. 이미 저장된 수동 편집 예시와 그 QA 결과는 별개이며 이 검토에서 수정하지 않았다.

필요한 표현 수정은 작다. `whyBrand`는 ‘이 일정은 AI 시대의 대입제도 방향이라는 논의 주제를 확인하게 한다. 실제 제도 변경을 판단하려면 후속 결과가 필요하다’로, 제목은 ‘AI 시대 대입제도 방향 논의 예정’으로 좁힐 수 있다. 본문에서 ‘질문의 무게’를 삭제하고 마지막 확인은 ‘주최 측 토론 결과에서 실제 제도 변경 제안과 적용 조건이 확인되는지 살펴본다’로 남긴다. 이는 **수동 편집 제안**이며 새 모델 결과나 자동 합격 5/5로 세지 않는다.

v6 추가 비용은 provider 로그의 두 추정값 `$0.019468 + $0.040514`를 합한 **2 provider 요청·$0.059982**다. 검수 호출의 thinking tokens도 포함한다. 새 품질 작업 전체는 **42 provider 요청**, usage·단가가 있는 **36회의 알려진 비용 $0.7018135**, **HTTP 404 6회의 비용 불명**이다. 기존 운영 파일럿은 여전히 별도다. 이번에는 검토 문서만 갱신했으며 코드·예시 파일·DB를 변경하거나 유료 호출을 하지 않았다.

### v6 + 서버 원문 범위 축소: 일정형 검토 자료로 채택 가능

캡처한 v6의 실제 writer·review 응답과 usage를 현재 [생성 hook](../../../apps/engine/lib/research-prepare.ts:98)에 재생한 결과를 독립 대조했다. 원문 한 줄에서 읽은 일정만 남기는 [범위 보정](../../../apps/engine/lib/research-editorial.ts:83)이며 새 유료 응답을 생성한 결과가 아니다. 최종 `result.brief`의 모든 필드는 다음 범위 안에 있다.

| 대조 대상 | 확인한 범위 |
| --- | --- |
| 제목·change·facts·factEvidence | L21의 ‘이인선 의원실 등’과 ‘인공지능 시대, 대입제도의 방향은?’라는 주최 표현·의제를 언론 기사의 예고 일정으로 남겼다. 개편·대체안이나 논의의 시작을 주장하지 않는다. |
| conditions | 제목과 L1~3의 9월 30일자 기사 시점, L21의 10:00·국회 본관 228호를 보존한다. 실제 개최·일정 변경 확인으로 승격하지 않는다. |
| whyBrand·interpretation·counterevidence·unknown | 선택한 일정 한 줄에 없는 개최 결과·논의 내용·조건은 미확인으로 둔다. 기사 전체에 후속 결과가 없다고 넓혀 단정하거나 언론 예고를 국회 공식 확인으로 바꾸지 않는다. |
| draft | 예고만으로 정책 변화를 판단하기에는 이르다는 한 논지와 ‘주최 측 후속 발표의 유무·내용 확인’이라는 다음 확인 하나를 남겼다. 원인·의도·시작 이력·평가 방식 대체 가정·장식적 수사를 제거했다. |

원문 source 객체와 v6 raw 후보, 실제 usage가 기존 캡처와 동일함을 오프라인 비교로 확인했다. sourceId·원문 quote·`L21`·문서 hash·출처 배열은 정확히 보존됐고, fact의 `text`만 확인된 일정 문장으로 좁혔다. `verificationLevel=unreviewed`를 유지하며 보정 자체를 사실 인증으로 표시하지 않는다. 완료 payload와 반환 result도 일치했다.

**서버 보정후 정치 결과는 일정형 검토 자료로 채택 가능하다.** 원문 정보가 적어 짧게 끝나는 것이 적절하며, 심층 정책 인사이트의 통과나 모델 raw 5/5로 부르지 않는다. 원래 v6 raw의 보류와 자동 조합 4/5는 그대로 유지한다. 이 재생의 추가 provider 호출·실제 DB 쓰기는 모두 0이므로 비용·요청 합계는 위 42회에서 늘지 않는다. 이미 저장된 사용자 예시 원본은 수정하지 않았다.
