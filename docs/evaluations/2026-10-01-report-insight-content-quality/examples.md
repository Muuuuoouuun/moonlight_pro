# 보고서·리서치 인사이트 내용 예시

아래 다섯 건은 실제 후보와 생성 당시 원문·집계를 대조한 **수동 편집본**이다. Nomad·정치는 v5, 교육·회사·개인은 v4를 바탕으로 했다. 자동 결과의 내용 판정은 **4/5 채택 가능, 정치 1건 보류**이며 이 편집본을 자동 합격 5건으로 세지 않는다. 고객명·연락 원문·개인 업무명과 목표명은 싣지 않았다. 이 편집본 작성에는 추가 유료 모델 호출을 사용하지 않았다. 자동 발행하지 않는다.

## 1. 22nomad — GPT-6.1 Sol, API 가격과 이용 경로부터 확인하기

OpenAI가 발표한 GPT-6.1 Sol의 표준 API 입력·출력 토큰 단가는 GPT-6 Astra의 1/5 수준이다. 백만 토큰당 입력 $2, 출력 $10이며, 캐시된 입력은 $0.10으로 표준 입력보다 95% 낮다. 긴 문서나 코드의 같은 컨텍스트를 반복해 사용하는 API 작업이라면 비교할 만한 선택지다.

모델은 ChatGPT Work·Codex의 Plus·Pro·Business·Enterprise·Edu 사용자와 API(`gpt-6.1-sol`)에 제공되며 일반 Chat에는 아직 없다. 제시된 토큰 단가는 API 기준이다. 제조사가 발표한 특정 벤치마크 성능을 모든 작업에 일반화할 수 없으며, API 단가 비교를 전체 작업의 비용 절감률로 바꿀 수도 없다. 실제 청구액은 토큰 사용량과 캐시 적용 여부에 따라 달라진다.

**다음 확인 하나:** 반복해서 읽히는 문서 하나로 기존 모델과 같은 작업을 실행해, 결과 품질과 실제 토큰·캐시 사용량을 함께 비교한다.

근거: 생성 당시 [OpenAI 발표](https://openai.com/index/introducing-gpt-6-1-sol/) L2·L4~5·L26~27. 직접 사용해 봤다는 경험은 추가하지 않았다.

## 2. class.moon — 수시 추가 접수 집계는 대학별 상담의 출발점

교육부는 수시 원서접수 마감 연장 후 80개교의 1,781개 모집단위에서 추가 접수 3,184건이 발생했다고 밝혔다. 추가 접수가 발생한 80개교의 평균 경쟁률은 마감 예정 시각인 오후 6시 기준 10.25대 1에서 10.27대 1로 바뀌었다. 이 평균만으로 학생이 지원한 개별 전형의 합격선 영향을 판단할 수는 없다.

3,184건 중 당시 오류 기록이 남은 경우는 2,329건이다. 나머지 855건에는 로그인 자체가 불가능해 기록이 남지 못한 사례가 **포함**되어 있다. 855건 모두의 원인이 같다는 뜻은 아니다. 교육부는 특별조사 연장과 2027학년도 정시 대비 합동 TF 계획도 안내했지만, 최종 조사 결과와 대책의 실제 효과는 이 자료로 확인할 수 없다.

**다음 확인 하나:** 학생 상담 전에 해당 대학 홈페이지나 원서접수 사이트에서 지원 전형의 최종 경쟁률을 확인한다.

근거: 생성 당시 [교육부 자료](https://www.moe.go.kr/boardCnts/fileDown.do?fileSeq=fd2037e1c9d64a70a0024716b058168e&m=020402&s=moe) L5·L8~10·L14·L18~22. 접수 건수를 학생 수로 바꾸지 않았다.

## 3. 정치 — AI 대입 토론회 일정과 제도 변경은 구분하기

9월 30일자 국회 일정표는 ‘인공지능 시대, 대입제도의 방향은?’ 토론회를 오전 10시, 국회 본관 228호에 예고했다. 이 자료가 확인해 주는 것은 일정과 주제까지다. 토론회가 실제로 열렸는지, 어떤 방안이 제안됐는지, 대입제도 변경이 결정됐는지는 확인되지 않는다.

**다음 확인 하나:** 후속 발표 자료에서 구체적인 제안과 적용 조건을 확인한다. 일정 하나를 교육 영향의 증가, 장기 개편 의도, 논의가 처음 시작됐다는 증거로 쓰지 않는다.

근거: 생성 당시 [국회 일정 기사](https://www.newspim.com/news/view/20260929001162) L21. 기사 내 부정확할 수 있다고 표시된 AI 요약은 근거로 사용하지 않았다. 정치 v5의 보류 사유를 수동으로 고친 일정형 검토 예시다.

## 4. 회사 주간 — 기록 감소를 거래 정체로 단정하지 않기

9월 24~30일(KST) 회사 범위의 CRM 연락 활동은 1건으로, 전주(9월 17~23일)도 1건이었다. 이는 활동 건수이며 고객 1명을 뜻하지 않는다. 새로 생성된 딜과 기간 중 수정된 현재 진행 딜은 각각 0건으로, 전주 각각 3건보다 줄었다. 성사일이 확인된 성사 딜은 0건, 해당 딜의 원화 계약 금액 합계는 0원, 기록된 단계 이동은 0건이었다. 계약 금액은 입금액이 아니다.

이 집계만으로 전체 파이프라인이 줄었거나 고객이 정체됐다고 판단할 수 없다. 연락 내용·반응과 기록 감소의 원인도 주어진 데이터에 없다.

**다음 확인 하나:** 해당 기간의 연락 활동 1건을 읽고 후속 상태를 확인한다. 전체 CRM 현행화나 새 과제를 먼저 요구하지 않는다.

근거: v4의 고정 회사 context와 전주 비교 집계. 원문 연락 내용을 읽었다고 주장하지 않으며, 후속 작업을 자동 생성하지 않았다.

## 5. 개인 주간 — 기록량과 개인 실행 성과를 나누어 보기

9월 24~30일(KST) 개인 완료 할 일은 5건으로 전주 7건보다 2건 줄었고, 하루 리뷰는 5일로 전주 2일보다 3일 늘었다. 메모는 9건으로 전주 3건보다 6건 늘었지만, 이 수치는 회사 기록도 포함할 수 있는 **워크스페이스 전체 집계**다. 메모 전부를 개인 활동이나 수익화 성과로 해석하면 안 된다.

기간 안의 개인 범위 발행 원고·기록된 연락 활동·수정된 개인 딜은 각각 0건이었다. 기록이 없는 원인이나 실제 진행 상태는 이 집계로 판단할 수 없다. 연결된 10월 목표를 9월 24~30일의 성과 기준으로 소급하지 않는다.

**다음 확인 하나:** 새 메모에서 개인 범위에 해당하는 항목만 먼저 구분한다. 전체 메모를 새 업무로 만들거나 개인 내용이 확인되지 않은 상태에서 우선순위를 정하지 않는다.

근거: v4의 고정 개인 context, 지표 정의와 전주 비교 집계. 개인 메모 원문과 목표명은 공개 예시에 포함하지 않았다.
