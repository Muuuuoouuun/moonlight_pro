# 칸반·메모 연결·데이터 활용 평가

> 2026-09-07 · 코드 기반 평가 및 로컬 개선 기록. 운영 DB의 보유 건수·실사용 빈도·배포 상태는 검증하지 않았다.
> 기준: `operator-workflow-profile.md`, 개인 운영 OS 심화 설계, `DESIGN.md`.

## 평가

| 영역 | 확인된 동작 | 평가 |
|---|---|---|
| 프로젝트 칸반 | `tasks`의 수집·계획·진행·대기·완료를 표시. 상태 변경은 Hub BFF → Engine PMS command로 저장 | 기본 실행 흐름은 구현돼 있다. 새 칸반보다 카드의 업무 문맥 보강이 우선 |
| 업무 설명 | `tasks.description`을 저장하고 편집하지만 기존 보드 projection에서 제외 | 입력한 내용을 판단 화면에서 충분히 활용하지 못함 |
| 다음 행동 | Engine은 `tasks.next_action`을 쓰지만 기존 operating ledger의 task mapping에서 누락 | 읽기 전달을 복구해야 보드에서 활용 가능 |
| 프로젝트 메모 | `notes.project_id`로 연결하고 제목·본문을 조회. 상세 화면은 4개로 잘라 전달 | 연결은 존재하지만 과거 메모 재탐색이 제한적 |
| 빠른 메모 입력 | `capture_quick_input_v1`은 task 외 hint를 `work_order`로 저장 | 프로젝트 `notes`와 별도 흐름. 빠른 입력이 프로젝트 메모로 자동 연결된다고 설명하면 안 됨 |
| 고객 메모 | CRM 활동의 note 유형으로 관리 | 프로젝트 메모와 같은 원장이 아님. 무분별한 복제보다 원본 참조가 적합 |
| 데이터 완전성 | 전역·프로젝트별 읽기 제한 및 failed/partial source 계약 존재 | 불러온 수와 전체 수, 조회 실패와 실제 빈 상태를 구분해야 함 |

근거 파일: `apps/hub/components/hub/pages/projects.jsx`, `project-detail-panel.jsx`, `apps/hub/lib/pms-ui.js`, `apps/hub/lib/repositories/operating-ledger.js`, `apps/engine/lib/pms-command.ts`, `supabase/migrations/20260715_0014_quick_capture_receipts.sql`, `apps/hub/lib/repositories/crm-activities.js`.

## 이번 구현

- Task 읽기 모델에 저장된 다음 행동을 전달하고, 칸반에 다음 행동 또는 설명을 두 줄로 표시한다.
- 칸반 검색에 설명·다음 행동을 포함한다.
- 관계가 확인된 카드에서 프로젝트 상세와 연결 메모로 이동할 수 있다.
- 카드 안의 링크·상태 선택에서 Enter/Space가 카드 편집을 함께 실행하지 않도록 한다.
- 프로젝트에 읽힌 메모를 모두 상세에 전달한다. 처음에는 4건을 보여주고 전체 펼치기, 제목·본문 검색, 개별 본문 펼치기를 제공한다.
- 메모 조회가 잘렸거나 실패하면 표시된 기록만 검색한다는 안내를 제공한다. 검색은 서버 전체 검색이 아니다.
- 기존 Supabase 테이블과 쓰기 경로를 유지한다. 이번 변경은 메모 생성·연결 편집·받은함 전환 기능을 추가하지 않는다.

## 다음 개발 우선순위 — 제안, 확정 아님

1. **빠른 메모 → 업무/프로젝트 연결**: 받은함 항목에서 대상 프로젝트를 지정하고 할 일로 전환하되 원문 식별자를 보존한다. 재시도 시 중복 생성 방지가 필요하다.
2. **프로젝트 메모 작성·수정**: Engine command와 저장 결과 확인을 갖춘 입력을 추가한다. 고객의 개인 메모를 ClassIn에 복제하지 않는다.
3. **메모 조회 확장**: 실제 기록이 읽기 제한을 넘으면 프로젝트별 페이지 조회와 서버 검색을 추가한다.
4. **실사용 평가**: 14일 동안 메모 저장 후 다시 찾기, 메모에서 할 일 전환, 연결 없이 남은 받은함 항목을 관찰한다. 현재 로그 확인 없이 활용률이나 성공률을 수치로 단정하지 않는다.

메모 그래프·자동 의미 연결은 위 흐름에서 실제 누락이 확인된 뒤 검토한다. 현 단계에는 설명과 원문을 읽고 다음 행동으로 이어가는 기능의 효용이 더 직접적이다.

## 확인 방법

- 설명/다음 행동이 있는 업무를 칸반에서 열고, 해당 내용으로 검색한다.
- 카드의 프로젝트 링크를 눌러 같은 프로젝트 상세가 열리는지 확인한다.
- 메모 5건 이상인 프로젝트에서 전체 펼치기와 본문 검색을 사용한다.
- partial/failed 메모 읽기에서는 전체 기록을 다 읽었다고 표시하지 않는지 확인한다.

로컬 검증: 관련 테스트 88개, 전체 테스트 722개, 계약 검사, workspace typecheck, Hub production build 통과. 실제 브라우저 조작 및 운영 DB 저장 재조회는 이번 검증에 포함하지 않았다.
