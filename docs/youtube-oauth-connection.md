# YouTube OAuth connection

Moonlight stores YouTube channels under provider `youtube` in `integration_connections`, keyed by `(workspace_id, provider, account_key)`. `account_key` and `external_account_id` are the channel's verified `UC...` ID returned by YouTube. The multi-account database migration `20260924_0046_social_multiaccount_connections.sql` must be applied before deploying the multi-channel callback. Existing connection IDs, tokens, and `sync_runs.connection_id` references are preserved by the migration.

## Google Cloud setup

1. In a dedicated Google Cloud project, enable **YouTube Data API v3**.
2. Configure an OAuth consent screen and add the Google account that owns the intended YouTube channel as a test user while the app is in Testing.
3. Create a **Web application** OAuth client with the exact authorized redirect URI `http://localhost:3000/api/social/youtube/callback` for the local Hub. Use the deployed Hub origin plus the same path when deployment is configured.
4. Set `COM_MOON_YOUTUBE_CLIENT_ID` and `COM_MOON_YOUTUBE_CLIENT_SECRET` in `apps/hub/.env.local`. Set `COM_MOON_YOUTUBE_REDIRECT_URI=http://localhost:3000/api/social/youtube/callback` when `COM_MOON_HUB_URL` points to an HTTPS tunnel for Meta; the YouTube override takes precedence. Keep the existing `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` for Calendar/Gmail separate. `COM_MOON_OAUTH_STATE_SECRET` and `COM_MOON_DEFAULT_WORKSPACE_ID` must also be set.
5. Restart Hub. Check `/api/social/youtube/status?channelId=UC...` for `ready`. Open `/api/social/youtube/connect?channelId=UC...` using the target channel's exact ID. Complete Google's account/channel selection. Check status again for `connected` and the expected `channelId` and `channelTitle`. Repeat for each owner/channel; the status response has a token-free `connections` array. Optionally include `brandKey=<brand-slug>` on the connect URL after the brand-to-channel assignment is confirmed. The Hub checks that the slug exists in the same workspace and stores it with the connection.

The authorization requests `youtube.readonly` to verify the selected channel through `channels.list?mine=true` and `youtube.upload` for future publishing capability. The callback rejects a channel whose ID differs from the signed expected channel ID. This change adds OAuth connection only; it does not upload videos. The access token and offline refresh token are stored server side in `integration_connections.config` and are omitted from the status response. OAuth state is signed and expires after ten minutes. If Google returns `refresh_token_expires_in`, the status reports `refreshTokenExpiresAt`; a past date makes status `reauthorization-required`. For an external app in Google OAuth **Testing**, YouTube scope refresh tokens can expire after seven days, so a successful pilot connection is not proof of persistent unattended access.
