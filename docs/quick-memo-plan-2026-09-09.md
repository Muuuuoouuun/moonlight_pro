> 요청: 작업 중 갑자기 떠오른 생각을 우측 하단 등에서 초간단 메모로 남기는 기능 기획
> 상위 기준: [운영자 프로필](operator-workflow-profile.md), [개인 운영 OS 심화 설계](superpowers/specs/2026-07-13-moonlight-personal-operator-os-deep-design.md), [DESIGN.md](../DESIGN.md)

## 1. 목적과 결정 상태

**하던 화면에서 메모를 열고, 본문만 적어 저장한 뒤, 바로 원래 작업으로 돌아간다.**

- 확정된 요청: 작업 도중 떠오르는 짧은 생각을 빠르게 적는 기능을 기획한다. 우측 하단은 운영자가 제시한 위치 후보다.
- 기존 확정 기준: 기본 캡처는 짧은 텍스트이며, 떠오른 일·메모를 10초 안에 실제 저장하는 것이 제품 목표다.
- 이번 권장안: Hub 공통 우측 하단 `빠른 메모` 버튼 + 작은 작성 패널 + 기존 메모 목록에 저장.
- 미정: 전용 열기 단축키, 탭 종료 후 초안 복원, 자동 문맥 연결. MVP를 위해 먼저 결정해야 하는 항목은 아니다.

사용 예: 프로젝트를 정리하다 “데모 전에 사용 환경 사진 받아두기”가 떠오르면 버튼 클릭 → 한 줄 입력 → 저장 → 보던 프로젝트에서 작업을 계속한다. 저장 시 할 일·프로젝트·고객 종류를 고르지 않는다.

## 2. 진입 방식

| 방식 | 판단 | 이유 |
| --- | --- | --- |
| 우측 하단 `빠른 메모` 버튼 | 기본 권장 | 화면을 옮기거나 메뉴를 찾지 않고 한 번에 열 수 있다. |
| 기존 Cmd/Ctrl+K → `빠른 메모` 명령 | 보조 권장 | 기존 키보드 진입점을 사용한다. 명령 실행 동작은 추가 구현이 필요하다. |
| 메모 페이지로 이동해 작성 | 상세 작성용 유지 | 긴 글·파일 가져오기에 적합하지만 급한 입력에는 이동 비용이 있다. |

표시 이름은 `빠른 메모`로 통일한다. `급습 메모`는 갑자기 떠오르는 생각이라는 사용 상황을 뜻하며 별도 유형으로 나누지 않는다.

- `/dashboard/**`의 공통 셸에 한 번만 배치한다. 페이지마다 별도 버튼·초안 인스턴스를 만들지 않는다.
- 데스크톱: 우측·하단 24px 여백을 기준으로, 연필 아이콘과 텍스트가 있는 높이 44px 이상의 중립 버튼. 펼친 패널은 폭 약 360px, 기본 본문 4~6줄.
- 모바일: 가장자리 16px와 safe area를 반영한 버튼, 하단 시트로 펼친다. 가상 키보드가 본문·저장 버튼을 가리지 않게 한다.
- 데스크톱은 배경을 어둡게 덮지 않는 작은 패널. 화면 전체의 작업 흐름을 차단하지 않는다.
- 모달·업무 상세 drawer가 열려 있으면 그 화면의 포커스와 Escape 처리가 우선한다. MVP에서는 뒤쪽 메모 버튼을 비활성/숨김 처리하고 중첩 입력창을 만들지 않는다.
- 하단 고정 액션·토스트와 겹치면 공통 셸에서 위치를 조정한다. 큰 z-index로 덮어 해결하지 않는다.

## 3. 최소 작성 화면

```text
┌──────────────────────────────────┐
│ 빠른 메모                  접기  │
│                                  │
│ 생각나는 대로 적어두세요.        │
│                                  │
│                                  │
│ 개인 ▾                    저장   │
│ Ctrl/⌘ + Enter로 저장            │
└──────────────────────────────────┘
                         [빠른 메모]
```

- 필수 입력은 **본문 하나**. 제목·라벨·프로젝트·기한·우선순위 선택을 기본 화면에 넣지 않는다.
- 제목은 기존 저장 로직처럼 첫 번째 비어 있지 않은 줄에서 만든다. 본문과 줄바꿈은 보존한다.
- 기록 범위는 작게 표시한다. MVP 기본값은 기존 메모와 같은 `개인`, 사용자가 `회사 업무`로 바꿀 수 있다. 페이지를 이동했다고 작성 중 범위를 바꾸지 않는다. 새 메모는 다시 개인으로 시작한다.
- `회사 업무`는 Moonlight 안의 기록 범위이며 ClassIn 발송을 뜻하지 않는다.
- 본문이 길어지면 입력 영역 내부를 스크롤한다. 짧은 메모 전용 글자 제한을 새로 만들지 않고 기존 100,000자 계약을 따른다. 한도 초과 붙여넣기를 조용히 잘라 저장하지 않는다.
- 파일 가져오기와 고급 편집은 기존 메모 페이지에서 제공한다. 두 작성창 간 초안 이동은 MVP에 넣지 않는다.

## 4. 열기·저장·복귀 동작

1. 버튼을 누르면 본문에 즉시 포커스한다. 초안이 있으면 이어 쓴다.
2. Enter는 줄바꿈, Cmd/Ctrl+Enter 또는 `저장` 버튼은 서버 저장이다. 한글 조합 중 Enter·Escape·저장 단축키를 가로채지 않는다.
3. 저장 중에는 같은 내용을 재전송하지 못하게 하고, 제출한 본문을 고정한다. 입력을 계속 수정해 저장 응답과 초안이 엇갈리는 상황을 피한다.
4. 서버의 저장/중복 응답과 ID별 본문 재조회가 일치하면 초안을 비우고 패널을 접는다.
5. `메모를 저장했어요 · 열기`를 약 4초간 표시한다. 메모 페이지로 자동 이동하지 않는다. `열기`는 해당 메모 ID로 이동한다.
6. 성공 시 원래 화면의 포커스로 복귀한다. 저장 중 사용자가 다른 화면으로 이동했다면 완료 응답이 포커스를 빼앗지 않는다.

`접기`, Escape, 패널 바깥 클릭은 초안을 보존하고 패널만 닫는다. 접힌 버튼에 `작성 중`을 표시한다. 바깥 클릭은 사용자가 클릭한 곳의 포커스를 유지하며, Escape/접기는 열기 전 포커스로 돌아간다. 복귀 대상이 사라졌다면 빠른 메모 버튼으로 복귀한다.

데스크톱 패널은 이름이 있는 비모달 dialog로 키보드 탐색을 제공한다. 모바일 시트는 모달 dialog로 포커스를 가두고 닫힐 때 복귀한다. 기존 `esc-layers`를 사용해 Escape 한 번으로 메모와 뒤쪽 업무 창이 동시에 닫히지 않게 한다.

## 5. 초안과 오류

| 상태 | 화면과 복구 동작 |
| --- | --- |
| 빈 본문·공백만 입력 | 저장 비활성, 작성은 가능 |
| 작성·접힘 | 현재 탭에 임시 보관, 다시 열면 복원 |
| 새로고침 후 초안 복원 | 패널을 강제로 열지 않고 `작성 중` 표시. 열면 내용 복원 |
| 저장 중 접기·Hub 내부 이동 | 공통 셸에서 저장을 계속 추적. 입력/요청 상태 보존 |
| 저장 실패·오프라인 | `저장하지 못했어요. 메모는 남아 있어요.`와 재시도. 초안 유지 |
| 저장 응답 후 재조회 실패 | `저장 여부를 확인하고 있어요. 다시 확인해 주세요.` 표시, 완료로 처리하지 않음 |
| 재시도 | 본문·메타가 그대로이면 동일 ID로 확인, 중복 메모 생성 방지 |
| 실패 후 내용 수정 | 기존 immutable capture 정책에 따라 새 스냅샷 ID. 이전 내용이 서버에 저장됐을 가능성을 설명 |
| 임시 보관 실패 | `이 탭에 임시 보관할 수 없어요. 떠나기 전에 저장해 주세요.` 표시. 성공으로 가장하지 않음 |
| preview·서버 미설정 | 초안 입력 가능, 서버 저장 불가를 명시. 가짜 성공·실제 메모처럼 보이는 예시를 만들지 않음 |

저장 오류가 접힌 상태에서 발생하면 `저장 실패`를 버튼에 지속 표시하고 상태 메시지를 알린다. 초안을 자동으로 펼쳐 작업 포커스를 빼앗지 않는다.

초안은 별도의 versioned sessionStorage 키를 사용한다. 기존 `moonlight:memo-draft:v1`과 분리해 긴 메모·파일 입력 초안을 덮어쓰지 않는다. 구현 시 workspace/운영자 문맥을 포함하고 문맥 변경·로그아웃 때 상태를 분리한다. 입력 후 짧은 지연으로 기록하되 접기·페이지 종료 시 즉시 flush한다.

탭 종료·브라우저 종료·다른 기기에서의 초안 복원은 보장하지 않는다. UI에는 `이 탭에 임시 보관`과 `메모 저장 완료`를 구분한다. 서버 저장 성공 후 로컬 초안 삭제가 실패해도 동일 ID의 재조회로 중복을 방지한다.

## 6. 저장 후 다시 찾기

- 저장 목적지는 기존 `notes`다. 별도 급습 메모 테이블·별도 받은함을 만들지 않는다.
- 기존 **프로젝트 → 메모**에 나타나고, 성공 메시지의 `열기`는 `/dashboard/work/projects?view=memos&memo=note:<id>`로 이동한다.
- 메모 목록이 열려 있는 상태에서 저장하면 목록을 갱신한다. 검색·프로젝트 필터에 가려질 수 있으므로 ID로 여는 동작은 반드시 제공한다.
- 프로젝트 메모 작성 화면과 빠른 메모의 미저장 초안은 서로 독립이다. 저장한 레코드만 같은 목록에서 읽는다.
- 후속 처리는 기존 `할 일로 만들기` 또는 `기존 업무에 연결`을 사용한다. 입력 즉시 할 일·일정·콘텐츠를 자동 생성하지 않는다.
- **연결 없음은 미정리와 다르다.** 생각 기록은 업무에 연결하지 않아도 가치가 있다. 강제 정리 알림·밀린 메모 숫자 배지를 추가하지 않는다.
- 현재 검색은 소스별 최신 100건 안에서 동작한다. 전체 검색이 구현된 것처럼 안내하지 않는다.

## 7. 구현 경계와 순서 — 후속 작업용

2026-09-09 기획 당시의 구현 순서다. 2026-09-10 구현 결과와 검증 범위는 §10을 따른다.

1. `apps/hub/components/hub/hub-app.jsx`의 `key={path}` 콘텐츠 래퍼 밖에 공통 빠른 메모 컴포넌트를 둔다. 현재 `app/dashboard/layout.jsx`가 HubApp을 소유하므로 Hub 내 이동 시 초안 상태를 유지할 수 있다.
2. `apps/hub/lib/memo-capture.js`의 payload·검증 계약과 `pages/memo-capture.jsx`의 저장→재조회 흐름을 공통 hook/helper로 추출한다. 기존 긴 메모·파일 가져오기 동작을 보존한다.
3. `/api/hub/memo-capture` → Engine 저장 경로를 재사용한다. `title: ""`, `labels: []`, `scope`, `source: { type: "manual" }`을 보내고, 본문과 초안 ID를 유지한다. 새 source enum이나 DB 마이그레이션은 MVP에 필요하지 않다.
4. Hub의 쓰기 검증, 서버가 정하는 workspace, Hub→Engine 공유 비밀값 검증을 그대로 유지한다. 클라이언트가 직접 Supabase에 쓰지 않는다.
5. `hub-command-palette.jsx`에 `빠른 메모` action을 추가한다. 현재 내비게이션/검색 항목과 구분해 URL 이동 없이 공통 작성창을 연다.
6. 기존 메모 목록 갱신과 ID 딥링크, 초안 충돌 방지, 모바일 키보드와 overlay 우선순위를 검증한다.

업무 연결 기능은 로컬 구현·검증 완료이나 운영 DB 마이그레이션·배포 완료는 확인되지 않았다. 빠른 메모 저장과 열기는 업무 연결 가용성에 의존시키지 않는다. 연결 기능은 별도 운영 검증 후 사용 가능으로 표시한다.

시각 설계는 기존 SUIT/JetBrains Mono와 Moonstone `#5274a8` 토큰을 사용한다. 접힌 버튼은 중립, 열린 패널의 저장 버튼이 주 행동이다. Hub 카드 배경은 `rgba(255,255,255,0.04~0.07)`, 보더는 1px dark `rgba(255,255,255,0.07)` / light `rgba(12,16,24,0.08)` 계약을 따른다. 레퍼런스의 보라·그린과 스킬 검색의 새 팔레트·폰트 제안은 채택하지 않는다.

## 8. 완료 기준

- 홈·프로젝트·CRM·캘린더에서 화면 이동 없이 한 번의 클릭으로 본문 입력 가능.
- 10~30자 메모를 열기부터 실제 저장 확인까지 10초 이내에 완료하는지 실사용 측정. 목표값이며 현재 성능 측정 결과가 아니다.
- 저장 후 기존 화면·스크롤을 유지하고, 정확한 메모 링크와 새로고침으로 원문 지속성을 확인.
- 창 접기→재열기, Hub 이동, 새로고침 후 초안 보존. 기존 파일 메모 초안과 동시 작성해도 상호 덮어쓰기 없음.
- 더블클릭·키 반복·응답 유실 재시도에서도 동일 내용/ID의 메모 한 건. 실패·재조회 불일치에서 초안이 사라지지 않음.
- 한글 IME, 키보드만 사용, Escape 우선순위, 포커스 복귀와 상태 알림 확인.
- 390×844 및 1440×1024에서 확인. 모바일 키보드·하단 액션·토스트·업무 drawer와 겹침 없음.
- 저장 계정/workspace 경계와 preview·오프라인에서 정직한 상태 표시 확인.

## 9. MVP 이후 검토

실사용에서 입력 속도·재사용 빈도를 확인한 뒤 전용 열기 단축키, 저장하고 계속 쓰기, 초안 상세창 인계, 현재 작업 문맥의 선택적 연결을 검토한다. AI 분류·음성·탭 종료 후 복원·자동 업무 생성은 이번 MVP에 포함하지 않는다.

## 10. 구현·검증 기록 — 2026-09-10

- Hub 공통 셸의 우측 하단 버튼, 본문·범위만 있는 패널, Cmd/Ctrl+K의 `빠른 메모` action을 구현했다. 전용 열기 단축키는 추가하지 않았다.
- `memo-save.js`로 기존 긴 메모와 빠른 메모의 저장→재조회 로직을 공유한다. 서버 API·Engine·DB 스키마는 변경하지 않았다.
- 초안은 서버가 만든 workspace/운영자 문맥 해시를 포함한 별도 sessionStorage 키에 저장한다. 문맥이 바뀐 셸이 렌더되면 빠른 메모 인스턴스도 교체한다. 탭 종료 이후 보관과 별도 기기 복원은 보장하지 않는다.
- 새로고침 복원 시 패널을 강제로 열지 않는다. 접기·바깥 클릭·Escape는 초안을 보존한다. 저장 중 입력을 잠그고 중복 제출을 방지한다.
- 모바일은 modal dialog·포커스 순환·배경 inert를 적용하고 visualViewport로 키보드 위 공간을 계산한다. 명령 팔레트·drawer·모바일 메뉴가 열리면 메모를 접는다. CRM 하단 선택 작업바가 있으면 80px 위로 배치한다.
- 성공 시 같은 화면에 남고 메모 목록에 갱신 이벤트를 보낸다. 저장 메시지에서 메모 ID 딥링크로 이동할 수 있다. 저장 실패·본문 재조회 불일치 때 초안과 동일 재시도 ID를 유지한다.
- 회귀 수정: 명령 팔레트를 다시 닫을 때 과거 메모 열기 요청을 재실행하지 않도록 요청 번호를 한 번만 소비한다.

검증:

- Node 24.19.0: 전체 테스트 779개 통과. 신규 테스트는 저장/중복 receipt 검증, preview·오류, 본문 재조회 불일치, 응답 유실 재시도, 초안 분리·오염된 초안 거절을 확인한다.
- `check:contracts`, `typecheck`, Hub·Engine production build 통과. 시스템 Node 22.14의 `registerHooks` 미지원 오류는 번들 Node 24로 재실행해 해결했다.
- `http://127.0.0.1:3100`, Playwright + 로컬 Chrome(headless), 1440×1024·390×844·390×470에서 검증. Browser plugin/skill이 제공되지 않아 설치된 Playwright 런타임과 Chrome을 사용했다.
- 브라우저는 **가상 API 응답**으로 메모 저장·조회·실패를 검증했다. 운영 DB에 테스트 메모를 생성하지 않았다. 실제 UI의 본문 입력, 기존 긴 메모 초안 보존, 새로고침, 다른 페이지 이동, 한글 IME 단축키, 오류 후 재시도, 이중 제출 방지, 목록 갱신, 딥링크, 모바일 포커스·배경 잠금, 임시 보관 실패를 확인했다. 관련 page runtime 오류는 없었다.
- 모바일 키보드는 짧은 viewport 및 visualViewport 대응으로 확인했으며 실제 휴대폰의 소프트웨어 키보드 검증은 별도다. 10초 목표의 실사용 성능 측정과 운영 배포 완료를 의미하지 않는다.

### 아이콘·마우스 접근 반응 — 2026-09-11

운영자 요청에 따라 기본 진입점을 48×48px 메모 아이콘으로 변경했다. 마우스가 고정된 아이콘 영역의 64px 안으로 들어오면 약 180ms 동안 140×54px 버튼으로 확장하며 `빠른 메모`와 작성/저장 상태를 표시한다. 우측 하단 기준점을 유지하고, 주변 페이지 클릭을 가로채는 투명 영역은 만들지 않는다. 작성 중에는 작은 점, 저장 확인이 필요하면 작은 사각 표시와 접근성 이름으로 상태를 알린다.

키보드 포커스에도 이름을 펼치고, 터치 기기는 기본 48px 버튼을 바로 누를 수 있다. 모션 감소 설정에서는 전환 애니메이션을 끈다. Playwright + Chrome의 1440×1024 및 터치 설정 390×844에서 기본 크기, hover 전 접근 반응, 멀어질 때 복귀, 기준점 유지, 키보드 열기, 초안 상태, 모션 감소, 모바일 터치를 검증했다.
