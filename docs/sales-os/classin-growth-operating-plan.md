# ClassIn Growth Operating Plan

> 목적: ClassIn 회사 영업 lane에서 운영자의 일상 업무 리소스를 40% 줄이고,
> 리드 처리 속도와 매출 기회를 10배까지 키우기 위한 실행 설계.
> 기준일: 2026-06-20. Moonlight 전체가 아니라 `classin` workspace에 먼저 적용한다.

## 1. 현재 사실

- ClassIn은 운영자가 현재 다니는 회사의 실전 영업 lane이다. Moonlight 전체나 개인 사업과 구분한다.
- 1차 목표는 월간 계약 수와 월간 매출이다. 신규/업셀 모두 포함한다.
- 현재 기준값은 월 6건 계약, 약 100,000 CNY다.
- 1차 타깃은 월 60건 계약 또는 하드웨어 60대, 월 300,000 CNY다.
- 하드웨어 평균 단가는 약 20,000 CNY, 소프트웨어 첫 충전은 약 10,000 CNY다.
- 리드는 약 95%가 Meta 광고/마케팅팀 Google Sheet에서 온다. 나머지는 기존 고객 연락 또는 Threads다.
- 주요 채널은 문자, 카톡, Threads DM, 전화다. 이메일은 ClassIn 회사 영업의 기본 채널이 아니다.
- 회사 CRM은 현재 read/get 중심이다. Moonlight는 자동 기록 가능하지만 회사 CRM push/자동 입력은 금지한다.
- 고객에게 직접 전달, 직접 콘텐츠 업로드, 실제 발송은 human approval 이후만 허용한다.

## 2. 핵심 숫자 모델

```
계약 수 = 문의 수 × 유효리드율 × 클로징률
매출 = 하드웨어 대수 × 20,000 CNY + 소프트웨어 첫 충전 수 × 10,000 CNY + 업셀
```

현재 최고 성과 콘텐츠 기준:

- Threads 실사용 레퍼런스 영상 3~5초
- 30개 문의 → 6개 유효리드 → 3곳 결제
- 유효리드율 20%, 유효리드 대비 클로징률 50%, 전체 문의 대비 결제율 10%

이 수치가 유지되면:

| 목표 | 필요한 문의 수 | 비고 |
| --- | ---: | --- |
| 월 6건 계약 | 60개 문의 | 현재 최고 콘텐츠 2개 수준 |
| 월 30건 계약 | 300개 문의 | 콘텐츠/광고/설명회 루프 필요 |
| 월 60건 계약 | 600개 문의 | 개인 수작업으로 불가능, 시스템 필수 |

숫자 충돌도 있다. 하드웨어 60대면 평균 단가 기준 1,200,000 CNY다. 반면 1차 매출 타깃은 300,000 CNY다.
따라서 목표를 두 단계로 분리한다.

| 단계 | 목표 | 의미 |
| --- | --- | --- |
| Gate 1 | 월 300,000 CNY | 현재 100,000 CNY의 3배. 제품/채널 검증 목표 |
| Gate 2 | 월 60건 또는 하드웨어 60대 | 처리량 10배. 개인 영업이 아니라 운영 시스템 목표 |
| Gate 3 | 월 1,000,000 CNY+ | 진짜 매출 10배. ASP/업셀/파트너 확장이 필요 |

## 3. 단순화된 세일즈 상태

기존 CRM 단계는 `Lead → Account → Opportunity → Quotation → Order → Collection`이었다.
운영자 개인 시스템에서는 아래 5단계로 줄인다.

| 상태 | 정의 | 다음 행동 |
| --- | --- | --- |
| `lead` | 연락처/문의가 존재 | 10분 안에 첫 접촉 또는 분류 |
| `valid_lead` | 학원/학교/기관, 예산/필요/권한 중 1개 이상 확인 | 상담 질문 3개 |
| `buying_signal` | 설명회 신청, 데모 요청, 가격/도입 일정 질문 | 전화/방문/카톡 전환 |
| `proposal_ready` | 의사결정자와 문제/범위가 맞음 | 견적/제안/레퍼런스 |
| `won_or_lost` | 결제 또는 명확한 보류/실패 | outcome 기록, 재접촉 주기 |

Moonlight의 `work_orders`는 이 단계 사이에서 사람이 승인해야 할 일을 보관한다.
외부 액션은 `proposed → approved → executing → executed` 순서만 허용한다.

## 4. 하루 업무 리소스 40% 절감 설계

현재 사용자가 밝힌 반복 업무는 대략 하루 4시간이다.

| 업무 | 현재 | 목표 | 줄이는 방식 |
| --- | ---: | ---: | --- |
| 콘텐츠 기획/제작 | 2.0h | 1.2h | 고성과 포맷 템플릿화, 3~5초 레퍼런스 컷 우선 |
| 리드 발굴/상담/문의/콜 | 2.0h | 1.2h | 리드 우선순위, 답장 초안, follow-up 큐 |
| CRM/기록/상태관리 | 숨어 있는 시간 | 0.2h 이하 | Moonlight 자동 기록, 회사 CRM은 수동 체크리스트 |

운영 규칙:

- 하루 첫 20분: Daily Brief에서 `설명회 신청`, `Threads 관심`, `Meta 신규` 순으로 본다.
- 오전 1블록: buying signal만 직접 연락한다. 단순 Meta lead는 템플릿 응답/질문으로 컷한다.
- 오후 1블록: 콘텐츠 1개를 만든다. 새 주제보다 실사용 레퍼런스 변주를 먼저 만든다.
- 마감 10분: outcome만 기록한다. 기록이 없으면 다음 날 Guru/followup이 틀린 판단을 한다.

## 5. 10배 속도 설계

10배 속도는 "내가 10배 더 열심히 연락한다"가 아니다. 사람이 보는 리드 수를 줄이고,
시스템이 먼저 분류·초안·기록·우선순위를 만든다.

| 병목 | 10배 설계 |
| --- | --- |
| 리드가 여러 곳에 흩어짐 | Google Sheet/Threads/기존 고객을 Moonlight lead intake로 모은다 |
| 누가 급한지 판단이 느림 | 설명회 신청 > Threads 관심 > Meta 광고 > 기존 고객 리스크 순으로 자동 점수 |
| 답장/콜 전 준비가 오래 걸림 | Guru가 고객 상태/콘텐츠/반론 기반 다음 질문 3개 생성 |
| 기록이 귀찮음 | Moonlight에 자동 기록, 회사 CRM은 push 금지 + 수동 입력 체크리스트 |
| 콘텐츠 기복 | 고성과 포맷을 1개씩 변주하고, 성과 없는 주제는 보류 |

## 6. 10배 매출로 가는 두 경로

매출 10배는 계약 수 10배만으로 만들기 어렵다. 처리량과 객단가를 같이 올려야 한다.

### A. 처리량 경로

- 문의 600개/월을 만들 수 있어야 월 60건 계약이 보인다.
- 핵심은 Threads 실사용 레퍼런스 영상의 반복 생산과 광고 리드의 SLA 관리다.
- 콘텐츠는 감성/정보성보다 "실사용 장면 + 도입 후 변화"를 우선한다.

### B. 객단가 경로

- 300,000 CNY는 하드웨어 15대 또는 소프트웨어 첫 충전 30건에 해당한다.
- 1,000,000 CNY는 하드웨어 50대 또는 혼합 패키지가 필요하다.
- 따라서 고객을 단건 판매가 아니라 "전자칠판 + 첫 충전 + 교사 온보딩 + 추가 충전" 묶음으로 봐야 한다.

## 7. AI 적용 분야

| 영역 | AI 역할 | 사람 승인 |
| --- | --- | --- |
| 리드 정규화 | Meta/Sheet 필드 매핑, 전화번호/출처/의도 정리 | 불필요 |
| 리드 우선순위 | 설명회/Threads/Meta/기존 고객 상태 기반 score | 불필요 |
| 답장 초안 | 문자/카톡/Threads DM 초안 | 발송 전 필요 |
| Guru 코칭 | 딜 막힘 진단, 다음 질문, 반론 대응 | 실행 전 필요 |
| 콘텐츠 기획 | 고성과 포맷 변주, 훅/자막/컷 구성 | 업로드 전 필요 |
| 성과 분석 | 조회수→문의→유효→결제 전환률 분석 | 불필요 |
| CRM 체크리스트 | 회사 CRM 수동 입력 항목 생성 | 사람이 입력 |

금지:

- 회사 CRM 자동 push
- 고객에게 승인 없는 직접 발송
- 콘텐츠 승인 없는 직접 업로드
- 사실 근거 없는 고객 상태 단정

## 9. 다음 개발 우선순위

| 우선순위 | 개발 | 이유 |
| --- | --- | --- |

| P1 | Threads/문자/카톡 응답 템플릿 큐 | 발송은 사람이 하지만 초안은 자동화 |
| P1 | 콘텐츠 실험 원장 | 조회수보다 문의/유효/결제 기준으로 판단 |

## 10. 7일 실행 루프

1. Day 1: 모든 Meta Sheet 리드에 source/campaign/form/intent 필드를 맞춘다.
2. Day 2: 설명회 신청 리드와 Threads 리드를 따로 태깅한다.
3. Day 3: 고성과 실사용 레퍼런스 영상 5개를 변주한다.
4. Day 4: follow-up 큐에서 buying_signal만 직접 연락하고 outcome을 남긴다.
5. Day 5: Guru에게 pipeline-triage를 돌리고 승인 큐 후보를 정리한다.
6. Day 6: 콘텐츠별 `문의→유효→결제` 숫자를 업데이트한다.
7. Day 7: 60건 계약 목표에 필요한 문의 수/유효리드 수를 다시 계산한다.

## 11. 판단 원칙

- 네가 직접 해야 하는 일은 고객 맥락 판단, 최종 발송, 방문/상담, 관계 형성이다.
- AI가 해야 하는 일은 정리, 우선순위, 초안, 분석, 반복 패턴 찾기다.
- 시스템이 해야 하는 일은 누락 방지, 상태 기록, 승인 큐, outcome 학습이다.
- 회사 CRM은 참고/수동 입력 대상이다. Moonlight가 진실원천이다.
