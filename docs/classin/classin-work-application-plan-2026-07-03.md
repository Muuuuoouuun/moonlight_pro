## 1. 목적과 스코프

이 문서는 클래스인 세일즈/마케팅/콘텐츠 자동화를 설계하기 전, 캐논이 정의한 **정체성 → 방향성 → 업무 본질** 3축을 하나의 판단 기준으로 정리한 것이다. 목적은 두 가지다.

1. 앞으로 만들어질 모든 산출물(세일즈 상담, 콘텐츠, 캠페인, 자동화 스킬)이 통과해야 할 **게이트**를 명문화한다.
2. 지금 가동 중인 것과 설계만 된 것을 구분해, 다음 라운드가 헛다리를 짚지 않도록 **현재 위치**를 고정한다.

**이 문서가 아닌 것:**
- 스킬/에이전트의 상세 설계서가 아니다. 6절의 후보 아웃라인은 이름·목적·근거·전제조건만 담고, 입출력 스펙·프롬프트·트리거 로직은 다루지 않는다.
- 인프라 가속 체계(무엇을 얼마나 빠르게 자동화할지)를 정하지 않는다.
- 다음 기획 라운드가 스킬 상세 설계 + 가속 체계를 다룬다.

## 2. 정체성 — 업무의 자기 정의

### 2.1 정체성 코어

클래스인은 전자칠판이라는 하드웨어 한 대를 파는 회사가 아니라, **한 학원의 수업이 돌아가는 방식 자체를 하나로 묶는 "수업 시스템 OS"**를 파는 회사다. 한국 1차 카테고리명은 "수업 시스템 OS"로 확정되었고("학원 시스템 OS"는 폐기), 코퍼스에서 22회 반복되는 코어 명제 — *"좋은 수업이 에이스 강사 개인기에 의존하면 안 된다, 시스템으로 표준화해야 한다"* — 로 모든 표면의 메시지가 수렴해야 한다.

진짜 판매 대상은 화면 크기·스펙이 아니라 "수업 전 준비 → 실시간 판서 → 녹화 → 복습 → 과제·시험 → 관리자 데이터"로 이어지는 운영 흐름이며, 이 흐름의 진짜 레버는 하드웨어가 아니라 **EDB 교안(최대 50p)과 데이터 연속성("끊김 없음")**이다.

### 2.2 산출물 게이트 — invariants

모든 세일즈/마케팅/콘텐츠 산출물은 아래 항목을 통과해야 게시·발송·전달 가능하다. 하나라도 위반하면 산출물 자체를 반려한다.

**게이트 A — 회사 사실**
- 회사 수치는 EEO 공식 자기소개(시리즈 D 유니콘, 누적 $500M+, 5,000만+ 교육자·학습자, 160+개국, 6만+ 기관, 월간 3,000만+ 세션, 누적 2억+ 세션)를 미러링한다. 외부 DB의 낮은 수치로 임의 하향 금지.
- **"$30B/30조원 밸류" 절대 금지.**
- 미확정 수치("12개 언어", "8만+ 글로벌 파트너", "15,000 공교육")는 반드시 "EEO 공식 소개 기준" 출처 캡션 부착.
- 법인명 EEO = Empower Education Online. "Education Everywhere Online" 아님. CEO=Song Junbo, CTO=He Qian. 딜덱의 "Robert Huang"은 오류이므로 재사용 금지. 한국 법인 주소=서울 양천구 목동동로 233-1 806호(강남구는 오류).
- 국내(한국) 도입 기관·보드 수는 정확한 CRM 확인 전까지 단정 금지 → 상담 연결.

**게이트 B — 카테고리·정체성 언어**
- 카테고리명은 "수업 시스템 OS" 단일. "올인원 하이브리드 학습 플랫폼"은 보조 설명어로만.
- 공통 금지 표현: "모든 학원 관리 기능을 대체합니다" / "결제와 오프라인 출석까지 모두 해결" / "AI가 학생 상태를 자동으로 완벽하게 파악" / "가장 싸다"·"무조건 절감" 등 보장형 문구 / 미확인 기관 수·보드 수·모델 스펙·가격.

**게이트 C — 가격·한계**
- 가격은 정확한 금액을 절대 단정하지 않는다. 견적은 전자칠판 단품이 아니라 "전자칠판+OPS+카메라+스탠드/벽걸이+소프트웨어+설치+온보딩"이 포함된 수업 시스템 OS 구성으로 설명하고 상담으로 연결한다.
- 정직하게 분리할 한계(과장 금지, "별도 시스템/API 연동/상담 확인"으로만 언급): 결제와 정산, 오프라인 출입·출석, 고급 경영 리포트, 자체 CRM·ERP 세부 연동, 모델별 정확한 가격·재고·설치 가능 여부, 미확인 하드웨어 스펙, "AI가 사람의 정서·뇌파·학습이전 상태를 자동 측정"하는 식의 표현. 정직한 한계 인정이 곧 신뢰 무기다.

**게이트 D — 보이스 분기**
- 표면별 톤 분기는 의도된 설계다. 홈/랜딩/블로그는 긴장·손실 프레이밍 허용(구매 전 인식 환기). 제품/문서센터/이메일/챗봇 등 지원·운영 중 사용자 표면은 반드시 안심시키고 다음 행동을 안내한다. 홈용 공포소구 카피의 지원 표면 복붙 금지.
- 공개 표면에 `TBD` / `placeholder` / `준비 중` / `확인 필요` 류의 내부 메모 금지 — 미확정 내용은 (1)공개 안 함 (2)더 일반적으로 씀 (3)내부 분리 중 하나를 택한다.

**게이트 E — 디자인·언어**
- 유일한 포화 컬러는 Classin Green `#084734`(파랑/보라 절대 금지). 보더는 whisper `1px solid rgba(0,0,0,0.08)`, 두껍게 하지 않는다. UI는 DESIGN.md 팔레트만 사용.
- 중국어 한자(`[一-鿿]`) 절대 금지. `lib/docs.ts`는 한국어 전용, 하드웨어 문서 작성·수정 후 한자 잔재 스캔 필수(빈발 예: 클로즈업/판서/미러링의 중국어 원어 잔재). 조사 깨짐도 함께 점검.
- 회사 수치엔 "전 세계 누적·EEO 공식 소개 기준" 캡션을 부착(표시광고법 안전장치).

### 2.3 4대 가치 기둥 — 산출물 연결 체크

콘텐츠 한 편, 세일즈 메시지 하나는 아래 4개 중 최소 하나에 명시적으로 연결되어야 한다. 연결되지 않으면 정체성에서 벗어난 산출물이다.

| 기둥 | 내용 |
|------|------|
| ① 강사 리소스 절감 | 수업 준비·자료 재호출·녹화 업로드·복습 배포·보강 안내·상담 준비 시간 절감 |
| ② 수업 품질 표준화 | 우수 강사의 교안·판서·수업 흐름을 EDB와 녹화로 남겨 반·강사·지점 편차 축소 |
| ③ 학생 경험 확장 | 오프라인/온라인 구분 없이 복습·보강·상호작용·과제/시험 제공 |
| ④ 관리자 운영 가시성 | "감이 아니라 기준으로 운영을 보는 장치" |

경쟁 비교는 항상 운영 흐름 기준(Zoom="이 흐름을 못 남긴다", 일반 전자칠판="칠판이 아니라 칠판 뒤 운영을 바꾸는 결정"), 구체 경쟁사 브랜드명은 비노출.

### 2.4 미확정 영역 (열린 질문)

- "수업 시스템 OS" 카테고리 프레임의 국내 학원 시장 인지·수용도 데이터가 캐논에 없다. 원장이 여전히 "전자칠판 파는 회사"로 인식하는 저항의 크기는 불명확.
- 코어 명제가 피고용 강사에게 "내 개인기를 시스템에 넘기라는 것"으로 읽힐 위험에 대한 대응 언어가 캐논에 없다.
- 정직한 한계 인정이 실제 딜 클로징 단계에서 이탈 사유가 되는 빈도의 검증 루프가 문서화되어 있지 않다.
- 카테고리명 단독 노출(제목·슬로건·광고 카피)에서 "학원 관리 프로그램/ERP"로 오독될 리스크의 방지책은 정의 문장 반복 외에 없다.

## 3. 방향성 — 지금의 전선과 서열

### 3.1 가동 중 vs 설계만 된 것

**가동 중(자동):**
- 매칭 자동확정(customer/partner_account만, confidence≥0.92 AND 2위와 갭≥0.15)
- 우선순위 큐 룰스코어링 + 실 mutation(`lib/crm/priority.ts`)
- 싱크 체이닝(sync → 후보 생성 → 알림)
- NEO sync cron(01:00 UTC)
- 리드 48h+ 미응답 알림 크론
- 동의 기반 트래킹(P0 배너 + Consent Mode v2 + `cln_aid`)
- `computeCustomerHealth` 기반 위험 고객 우선순위 큐

**설계만 되고 미가동:**
- 매출 자체DB 적재(자체DB 매출 소유율 **0%**, 외부 `branch_rev_deals` 의존) — NEO→`crm_orders` 적재 설계만 존재
- 리드스코어링 2축(Fit+Engagement) 엔진 — 현행 `calcScore()`는 출처+연락처만 봄
- 공개 소셜로그인(Google/Naver), 자료 게이팅 3단
- `crm_tasks` 정식 승격
- STT/AI 요약/통화분석(LLM 보류)
- 이메일 발송(코드 완성, 서비스 선택 대기로 홀딩 — `EMAIL_WEBHOOK_URL` 또는 `RESEND_API_KEY` 채우면 즉시 동작)

### 3.2 명시된 우선순위 서열

- **콘텐츠 로드맵:** 최우선 = D1(문서 Supabase 단일화) → E1 → B1 (캐논 §7). 단 D1은 어드민 수기편집본 덮어쓰기 리스크로 보류 중이라, 실질 병목은 D1의 보류 해제 조건이다.
- **세일즈 플로우 6단계:** 리스크 3개 선정 → 즉답 → 확인 필요 분리 → 쇼룸 검증 → 견적 범위 확정 → 90일 파일럿. **목동 쇼룸이 가장 강한 CTA.**
- **마케팅 채널 우선순위:** 이메일(Resend, 비용 0원·최광커버) → 카카오알림톡(심사 1~2주) → SMS(건당 8~10원) → 인스타DM(보류).
- **Phase 0 소급교정:** 홈 대시보드·매출추이 차트에서 CNY를 ₩로 찍던 활성 버그(`formatCNY`/`formatKRWAbbrev`/`CRM_CURRENCY_BADGE`).
- **/share 뷰어 구현 선행:** 공유링크 발급은 나가지만 뷰어가 placeholder라, 견적 버전 재발급 등 다운스트림이 실효 없음.

**통화 규범(최대 함정):** 오더=USD(`$`, 매출과 동급 취급·2급 격하 금지) / 매출·수금·잔액·미수·REV 목표=CNY(`¥` 만단위 2자리) / 딜 예상=KRW(`₩`). 서로 다른 통화 grand total 절대 금지.

### 3.3 CEO 거버넌스 3결정 대기

아래가 정해지지 않으면 ERP 블루프린트의 "매출 한 번만 집계"가 어느 시스템을 정본으로 삼을지 확정할 수 없다.

1. 매출 book-of-record: 구글시트 유지 vs Portal(V2) 이전
2. 매출 귀속: 단일오너 방식 vs 자문형
3. 목표(REV) 데이터 소스: 시트 유지 vs DB 이관

### 3.4 실존 리스크 2건 + 키스톤 리스크

| 리스크 | 내용 |
|--------|------|
| ① HW 매출 편중 | 상위 10사에 약 70~77% 집중 |
| ② SW 활성화 저조 | 97대 도입 중 12대 사용(약 12%) — HW 판매가 SW 정착으로 이어지지 않음 |
| 키스톤 리스크 | ERP 블루프린트 전체가 `crm_source_links` 매칭 커버리지에 의존. 커버리지가 낮으면 매출 절반이 무음 누락될 수 있음 → **커버리지 자체를 먼저 측정** |

### 3.5 90일 관점 방향

대표 최상위 가치는 **본질 우선** — 화려한 차트보다 주차별 수치·목표 대비 "숫자" 가시성이 먼저이며, mock과 live 데이터를 섞지 않는다. ERP 블루프린트("8명이 25명처럼")는 새 탭이 아니라 흩어진 3개 장부(구글시트 목표·실적 / Portal V2 딜 / 샤오셔우이·NEO 리뉴얼)를 하나의 학원(Account) 360 스파인으로 합쳐 매출을 한 번만 집계하고 "오늘 할 일"을 띄우는 방향이다. 원칙은 자동 산출 우선·수기 최소, 오너 없는 테이블은 만들지 않는다.

이 방향 전체가 키스톤 리스크 위에 서 있으므로, 90일 관점에서 가장 먼저 답할 질문은 새 자동화를 어디에 붙일지가 아니라 **"지금 매칭이 매출의 몇 퍼센트를 잡아내고 있는가"**다.

### 3.6 보류 항목 (우선순위 미부여)

세금계산서/영수증 구분(미확정), HW 제품 페이지 이미지 생성, 리드마그넷 admin 편집칸(신규 4필드 저장 시 유실 위험), HW 라인업 불일치(챗봇 S98 Pro vs 제품페이지 65/75/86/110 — 보류로만 기록), deal 매칭 자동확정(정책상 항상 수동).

| ② 어드민 코어 | 3중 인증 → `verifyAdmin()` → admin 클라이언트 → repository 파이프라인 정합성을 새 라우트마다 지키는 게이트키핑 |

### 4.1 판단형 vs 기계형 경계

**기계형(체크리스트화 가능 — 곧 스킬화 후보):**
- 신규 admin API 라우트: `verifyAdmin()` 가드 + `createSupabaseAdminClient()` + repository 패턴 준수 — 정석 예시는 `app/api/admin/settings/route.ts` + `lib/repositories/settings.ts` (playbook/02)
- 공개 페이지 신설 시 metadata(canonical/OG) + JSON-LD + sitemap 등록 + robots/noindex 체크 (playbook/01)
- 신규 CTA마다 추적 계측 부착, 신규 추적 이벤트마다 `EventNames` + `ALLOWED_EVENTS` 양쪽 동시 등록(누락 시 무음 드랍)
- 스키마 컬럼 추가 시 타입 → repository → migration SQL(`ADD COLUMN IF NOT EXISTS`) → 적용의 순서 준수
- 신규/수정 DocArticle 저장 시 한자 스캔 + 조사 깨짐 점검 + golden-set 케이스 추가
- 매칭 자동확정 임계 적용(customer/partner_account만; deal은 항상 수동)

**판단형(사람이 매번 재판별 — 스킬은 "제안"까지만):**
- 원장 22문항 매트릭스의 즉답/조건부/확인 필요/쇼룸 검증 4레벨 판별, 특히 "확인 필요" 항목(스토리지 용량·서버 위치·펜 팁 가격 등)의 단정 회피
- 콘텐츠 발행 전 요금/할인/환불/SLA/HW 스펙/권한명/개인정보 문구의 최신·확정 여부 검증 → 미확정이면 공개 안 함/일반화/내부 분리 중 택1
- deal 매칭 수동 확정, 임계 미달 후보의 `/admin/crm/matching` 수동 검토
- 매출 집계 시 정본 소스 판단, `crm_source_links` confirmed 기준 이중계상 회피
- 챗봇 민감 분기(가격/계약/환불/계정/장애)의 "가능/지원" 단정 여부 검토
- AI 생성 초안(FAQ 추천질문 등)의 어드민 검토 후 게시(자동게시 금지)
- 같은 내용의 표면별 톤 재작성 — 홈/랜딩(긴장 허용) vs 지원/제품/챗봇(안심 필수)은 자동 치환 불가, 문맥 판단 필요

### 4.2 공통 철칙·게이트의 업무 절차 내장

캐논 §8의 공통 철칙 7개와 검증 게이트는 6파트 모두에 관통 적용된다.

1. **검증 게이트 2명령** — `npx eslint app components lib --max-warnings=0` + `npm run build`(prebuild=`check:vercel-crons`, postbuild=`check:public-content` 포함). 스키마 변경 시 마이그레이션까지.
2. **어드민 API** — `verifyAdmin()` 가드 + `createSupabaseAdminClient()`(service-role). server 클라이언트를 어드민 경로에 쓰면 `auth.uid()=null` → RLS false → 빈 배열 무음 반환.
3. **마이그레이션 규율** — 컬럼 추가 시 `supabase/migrations/YYYYMMDD_*.sql` 동반+적용. 누락 시 INSERT 무음 실패.
4. **동의·PII** — 마케팅 픽셀은 `consent.marketing` 없이 발화 금지, 내부 이벤트는 allowlist+PII redaction, raw IP는 sha256만.
5. **노션 캘린더 = 라이브 읽기전용** — Supabase 복제·양방향 쓰기·토큰 노출 금지.
6. **포지셔닝 SSOT** — `lib/classin-positioning.ts` 기준, 가격·기관수 단정 금지 → 상담.
7. **UI = DESIGN.md 팔레트만.**

신뢰 순서: **실제 코드+검증 결과 > 캐논 > 제품/아키텍처 문서 > `docs/archive/` 역사기록.** 문서 간 충돌은 이 순서로 해소한다.

## 5. 업무 적용 원칙

3축을 일상 업무에 강제하는 절차다. 실존 인프라만 근거로 서술한다.

### 5.1 착수 전 체크

1. **파트 판별** — 작업이 6파트 중 어디에 속하는지 소유권 매트릭스로 판별.
2. **파트 가이드 정독** — `docs/active/playbook/0N-*.md` 해당 파트 문서를 읽는다(01~06 + README 7개 파일 실존 — 레포 실측 2026-07-03).
3. **크로스컷 의존성 확인** — 콘텐츠↔챗봇 KB, 그로스↔플랫폼 스키마, 프론트↔그로스 계측·동의, 어드민의 타 파트 화면 호스팅.

### 5.2 산출물 게이트 (정체성 invariants)

작업물 완성 직후, 게시/발송 전에 2.2절 게이트 A~E를 순서대로 확인한다. 특히:

- 회사 수치·가격·기관수 단정 문장 → 즉시 "상담 확인"으로 치환.
- 지원·운영 중 사용자 표면(문서센터/이메일/챗봇)에 홈/랜딩용 긴장·손실 카피 복붙 여부.
- 하드웨어 문서 수정 시 한자 스캔(`[一-鿿]`) 통과 여부.
- 공개 표면에 TBD/placeholder/준비 중/확인 필요 잔존 여부.

### 5.3 완료 게이트 (품질 2명령)

코드 변경을 수반하는 모든 작업은 아래 두 명령을 통과해야 완료다.

```
npx eslint app components lib --max-warnings=0
npm run build
```

스키마를 바꿨다면 `supabase/migrations/`에 마이그레이션 동반+적용까지가 게이트다.

### 5.4 실존 인프라 지도 — 캐논 서술 vs 실물

**실물이 없는 것(캐논·플레이북이 개념으로만 서술 — 레포 실측 2026-07-03 기준):**

- `.claude/agents/`의 6개 전담 에이전트(home-front/admin-core/content-pub/growth-crm/chatbot/platform-data)는 **정의 파일이 존재하지 않는다**. `.claude/skills/`도 없다. 파트 판별·가이드 정독은 현재 사람이 플레이북을 직접 읽는 수동 절차다.
- 캐논 §9 콘텐츠 자동화 표의 "금지 표현 lint", "회사 수치 차단+캡션 자동 삽입", "금지 명칭 자동 치환", "DocArticle 저장 훅 한자 스캔"은 **실행 코드가 없다**. 규칙 문서(`brand-canon/voice-charter.md`, `classin-software-feature-inventory.md` 등)로만 존재하며, 지금은 5.2절 수동 게이트가 대체 절차다.
- `chatbot_recommended_questions` 초안 자동생성 파이프라인 미착수(캐논 §7에 미착수로 명시).

**실물이 있는 것(레포 실측 2026-07-03 — 다음 라운드 스킬의 오케스트레이션 대상):**

- 파트 가이드 7개 파일: `docs/active/playbook/01~06-*.md` + `README.md`
- 품질 게이트 npm 스크립트: `lint`, `build`(pre/post 훅 포함), `test`(vitest, 130+ 테스트 파일), `typecheck`, `check:vercel-crons`, `check:public-content`, `check:alpha-db`, `sync:channel-docs` 등
- Vercel cron 8개(`vercel.json`): automation / lead-response-alerts / lead-weekly-digest / lead-monthly-digest / sync-branch / sync-branch-insights / sync-external-crm / channel-talk-sync
