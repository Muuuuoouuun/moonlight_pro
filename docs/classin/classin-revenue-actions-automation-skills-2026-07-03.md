# 클래스인 매출 기획 — 실체적 액션 → 자동화 → 스킬 구성 (2차 라운드)

> **생성일: 2026-07-03**
> 입력: 운영 캐논(2026-07-02) + 1차 기획(`classin-work-application-plan-2026-07-03.md`)
> 검증: 규범(통화/옵트인/판단형 경계/AI 역할) + 실행가능성(Classin_Home 레포 실측) 이중 검증을 통과시킨 버전. "실측" 표기는 2026-07-03 코드베이스 직접 확인 결과다.
> 1차 기획의 산출물 게이트 A~E와 "판단형 업무는 제안까지만" 원칙이 이 문서 전체에 상위 규범으로 적용된다.

---

## 1. 목적과 스코프

이 문서는 "매출을 만드는 실체적 액션"에서 출발해, 그 액션을 받치는 자동화의 현재 상태를 확정하고, 액션-자동화 갭을 메우는 스킬 12종의 구성과 착수 순서를 정한다.

- **실체 액션이 먼저다.** 스킬은 매출 액션에 연결되지 않으면 제외했다(§7). 1차 기획 그룹 A의 품질 체커류는 독립 스킬로 재나열하지 않고 매출 스킬의 가드레일로 흡수했다.
- **스킬 상세 구현(프롬프트·코드)은 이 문서 범위가 아니다.** 각 스킬은 트리거·입출력·가드레일·그룹까지 확정하고, 구현은 착수 시퀀스(§6)를 따라 진행한다.

---

## 2. 매출 인과 한 장

4개 매출 경로를 관통하는 단일 인과: **"새 자동화가 아니라, 이미 만들어진 신호·코드·규칙을 소비하는 실행 루프의 부재"가 병목이다.**

- 신규 퍼널: 48h+ 미응답 알림·우선순위 큐는 **가동 중**인데, 그 신호를 받아 "누가 무엇을 언제 보내는가"는 전부 문서화되지 않은 수동 판단이다.
- 갱신·확장: 리뉴얼 캘린더 훅은 캐논상 가동인데 D-day에 CSM이 무엇을 하는지 표준 절차가 없다. SW 활성화 ~12%가 갱신 가능 매출의 모수 자체를 줄이고 있다.
- 매출 가시성: `crm_source_links` 커버리지가 미측정이라 지금 보이는 매출 숫자 자체가 검증되지 않은 상태다. 이 경로는 매출을 만들지 않지만 나머지 경로가 "어떤 숫자를 믿고 움직이는가"를 결정한다.
- 리드 공급: 웰컴/드립/쇼룸 초대 시퀀스 전체가 **이메일 서비스 활성화라는 단일 결정**에 종속돼 있다. 코드는 완성, 키만 비어 있다.

**두 개의 인프라 병목**: ① `/share` 견적 뷰어 placeholder(견적→계약 전환 신호 자체가 발생 불가) ② 이메일 발송 홀딩(후속 접촉 채널 마비).
**한 개의 최고 ROI 결정**: 이메일 서비스(Resend) 선택 — 결정 즉시 캐논 §9 마케팅 자동화 표 대부분이 코드 변경 없이 살아난다.

## 3. 매출 경로 4개와 실체적 액션

### 3.1 경로 1 — 신규 퍼널 (리드 → 상담 → 쇼룸 → 파일럿 → 견적 → 계약)

매출을 만드는 지점은 리드 생성이 아니라 **이미 잡힌 신호를 다음 단계로 넘기는 전환**이다.

| 실체 액션 | 상태 | 받치는 자동화 / 갭 | 사람 판단 |
|-----------|------|--------------------|-----------|
| 48h+ 미응답 리드 골든타임 대응 | 감지·알림 가동 | 크론(lead-response-alerts)이 알림+큐 배치까지 자동. 이후 "무엇을 보낼지" 단계는 자동화 없음 | 접촉 채널·타이밍, 해당 리드의 22문항 리스크 판별 |
| 우선순위 큐 아침 소비 루틴 | 큐 가동, 소비 절차 없음 | priority.ts 룰스코어링+mutation 가동. today 버킷 아침 요약은 없음 | 어느 딜을 먼저, 어떤 액션으로 |
| 22문항 리스크 3개 선정→즉답→쇼룸 개시 | 매트릭스 문서만 실존 | 리드별 리스크 매핑 도구 없음(1차 §6 그룹A가 지목한 갭) | "확인 필요" 12항목은 절대 단정 금지 — 판단형 1순위 |
| 목동 쇼룸 초대(가장 강한 CTA) | 수동 | intentScore 임계 자동 트리거는 리드마그넷 경로 한정·이메일 홀딩에 종속. 콜드콜/직접문의 경로는 트리거 없음 | 쇼룸까지 데려올 가치(규모·의사결정권), 지참 자료 안내 |
| 90일 파일럿 제안 | 콘텐츠만 존재 | 파일럿 추적 상태/필드가 Deal Lite 단계에 미정의 — 추적 공백 | 즉시 견적 vs 파일럿 분기, 범위 협상(비용은 상담 확인) |
| 견적 발송 → 계약 전환 | 발급 가동 / 뷰어 placeholder | 견적 작성·버전·공유링크는 실존. **/share 뷰어가 없어 public_quote_accepted 신호 자체가 발생 불가** — quote-lifecycle P2 전체가 이 병목에 종속 | SKU 구성, 서명 요청 타이밍, 최종 버전 판별 |

**Quick wins**: 이메일 홀딩 해제(코드 완성, 키만 필요 — 최저비용 최고효과), 22문항 매핑 도구(새 인프라 불필요), 큐 아침 소비 루틴 고정(코드 변경 없음).

참고: "명함 intake(Gemini vision→staging→promote)"는 캐논·플레이북에 근거가 없다 — moonlight_pro Hub(`lead_intake_raw`)의 별도 시스템 개념이며, Classin 측 실존 여부는 확인 필요로 분리(§4).

### 3.2 경로 2 — 갱신·확장 (리뉴얼 + SW 활성화 + 기존 고객 확장)

**갱신은 새 영업이 아니라 기존 계약의 방어다**(캐논 §5: 갱신·추가구매=새 lead 아닌 Deal/Success Motion). SW 활성화가 갱신 가능 매출의 전제다 — 활성화 없이는 방어할 매출 자체가 없다.

| 실체 액션 | 상태 | 받치는 자동화 / 갭 | 사람 판단 |
|-----------|------|--------------------|-----------|
| D-90/60/30 리뉴얼 캘린더 CSM 액션 표준화 | 훅은 캐논상 가동 / **화면 실물 미확인(실측)** | expireAt 감지+액션카드는 캐논 §9 명시. 단 레포 검색에서 `/admin/crm/customers/renewals` 경로 미발견 — 실물 확인 선행. 구간별 필수 행동 SOP 부재 | 갱신 조건(재협상 여부), 성사 최종 판정 |
| SW 활성화 'Early Success at risk' 개입 | 설계만 | 설치 후 30일 SW 무활동 감지 로직은 §9에 정의만. 렌더 화면/알림 경로 실물 미확인. 노출은 동결된 탭 IA 안에서(새 탭 금지) | 무활동이 이탈 위험인지 비수기 패턴인지 학원별 판별 |
| 기존 고객사 내 확장(completed·다른 관) | 규칙만 존재 | 추가 납품 3규칙은 명문화. "새 파트너 생성 금지"를 강제하는 코드 가드는 없음 | 동일건물/다른 관, contracted/completed 판정 — deal 매칭은 항상 수동 |
| 갱신·확장 통화 분리 검증 | 부분 | formatCNY/formatKRWAbbrev/CRM_CURRENCY_BADGE 실존(실측). Phase 0 소급교정 완료 여부는 미확인 | 어느 화면이 갱신(CNY) 요약이고 어느 화면이 신규 딜(KRW)인지 구분 |

**최대 함정**: 갱신 매출(¥ CNY)을 신규 딜 파이프라인(₩ KRW)과 합산해 "성장"으로 보고하는 것 — 존재하지 않는 성장을 만들어내는 착시. grand total 절대 금지.

**Quick wins**: D-day 구간별 체크리스트를 플레이북에 문서화(코드 변경 없음), Early Success 리스트 실물 유무 확인(조사 작업), 통화 배지 스캔을 리뉴얼/딜/오더 3화면 좁은 스코프로 시작.

### 3.3 경로 3 — 매출 가시성 (숫자를 믿게 만드는 기반)

이 경로는 매출을 직접 만들지 않는다. 대신 **다른 경로가 어떤 숫자를 보고 의사결정하는지**를 결정한다. 자체DB 매출 소유율 0% + 이중계상 제거가 `crm_source_links` confirmed에만 의존하는 구조에서, 커버리지 미측정 상태의 모든 매출 숫자는 잠정치다. **순서를 어기고 브리핑부터 화려하게 만들면 신뢰할 수 없는 숫자를 더 그럴듯하게 포장하는 결과만 낳는다.**

| 실체 액션 | 상태 | 받치는 자동화 / 갭 | 사람 판단 |
|-----------|------|--------------------|-----------|
| 커버리지 실측 (CEO 3결정과 **독립 실행 가능**) | 미실행 | 매칭 엔진·인박스·테이블 전부 실존. "confirmed 매칭 수 / 전체 매출 레코드 수" 집계 쿼리 1개만 부재. 측정 자체는 3결정을 기다릴 필요 없음(구조상 추론 — 확인 필요 표기) | 낮은 수치의 원인 해석(로직 결함/소스 누락/정상 미매칭), 신뢰 임계값은 대표 판단 |
| NEO→crm_orders 정본 적재 착수 | 설계만 | 정제 4규칙(한국팀 owner 해소 / status 정규화 renewal·new_sign / CNY 태깅 / 미래날짜 이상치 제외) 설계 완료, 구현 대기. NEO sync cron(01:00 UTC)은 가동 | 정규화 매핑 완전성 검증, 최초 가동 시 시트 수치와의 격차 규명 |
| 주차별 숫자 브리핑 | 부분 가능 | 지사 시트(branch_rev_deals, CNY)+확도 필드는 읽기 가능. 브리핑 템플릿/쿼리 부재. 측정 전 수준(잠정치 라벨 필수)과 측정 후 수준을 분리해 지금 시작 | 고확도/확정 경계 판정(정량 기준 없음), 통화 분리 표기 매번 확인 |
| 매칭 인박스 정리 루틴 | UI 가동, 루틴 없음 | 인박스·일괄확정·sync-chain 가동. 담당자·주기 미지정 | **판단형 그 자체** — deal 매칭은 항상 수동, 시스템은 후보 제안까지 |
| 통화 표기 교정 완료 여부 확인 | 미확인 | 교정 도구 3종은 실존(실측). 전 지점 적용 여부는 1회성 점검 필요 | 캐논 서술이 완료형인지 지시형인지 문장만으로 불명 — 코드로 확정 |

**Quick wins**: 커버리지 측정 쿼리 1건(2주 내), 통화 교정 스팟체크, 인박스 담당자·주기 지정(신규 개발 없음).

### 3.4 경로 4 — 리드 공급 (마케팅 → 옵트인 리드 → 후속 시퀀스)

병목은 새 자동화가 아니라 **이미 완성된 코드가 대기 중인 단 하나의 결정** — 이메일 서비스 활성화다.

| 실체 액션 | 상태 | 받치는 자동화 / 갭 | 사람 판단 |
|-----------|------|--------------------|-----------|
| 이메일 서비스(Resend) 활성화 결정 | 코드 완성·키 대기 | 발송 실행부·개인화 태그·수신거부(법적 증빙용 status 변경) 전부 완성. 남은 건 자동화가 아니라 **결정**(서비스 선택·도메인 인증·법적 고지 확정) | 채택·비용 승인은 의사결정권자. 활성화 후에도 시퀀스 문구는 매번 톤 규칙 재검토 |
| intentScore 37(22질문 다운로드) 리드 포착→쇼룸 초대 | 자동화 없음 + **수동 경로도 제약(실측)** | 구독자(Subscriber) 타입에 sourceDetail 필드 없음, intentScore는 카탈로그 정적 속성이지 리드별 누적 점수가 아님, 리드 단위 임계 판정 로직 부재 — 리드스코어링 2축 미가동과 동일 계열 갭 | 초대 타이밍·문구·배정. 리드가 4레벨 중 어디까지 아는지 판별 |
| 리드마그넷 다운로드별 후속 시퀀스 | 소재 완료·발송 종속 | 13종 리뉴얼 완료, 자료-시퀀스 매핑은 이메일 활성화 후 설계 | 자료별 후속 콘텐츠 구성. 본문 가격 금액 노출 금지 승계 |
| 행사 리드 attribution 확인·후속 | 가동 | 토큰 삽입·UTM 매칭 동작. 0건 fallback 발동 빈도는 미확인. D-1 리마인더 cron(E4) 미착수 | fallback이 attribution 누락인지 실제 0건인지 개별 확인 |
| 리드마그넷 admin 편집칸 갭 관리 | 미완(제약) | 신규 4필드가 화이트리스트에 없어 admin 저장 시 영구 유실 위험 — 해소 전까지 **콘텐츠 갱신은 코드 직접 수정만 안전** | 이 제약을 콘텐츠 담당자에게 주지시키는 것 자체가 운영 판단 |

**Quick wins**: 이메일 서비스 결정을 의사결정권자에게 공식 상정(단일 최고 ROI), attribution fallback 최근 행사 1건 확인(데이터 확인만).

## 4. 병목·결정·확인 필요 지도

**인프라 병목 (스킬이 아닌 개발 작업 — §7 제외 목록과 연동):**
1. `/share` 견적 뷰어 구현 — 견적 발송·계약 전환 두 액션의 공통 선행. 이것 없이는 quote-lifecycle P2 자동화 전체가 사실상 죽은 설계.
2. NEO→crm_orders 적재 — 정본 매출 데이터의 유일한 공급로. 일회성 ETL 구현 작업.

**결정 대기:**
1. 이메일 발송 서비스 선택 — 경로 1·4의 후속 시퀀스 전체 종속. **가장 싸고 가장 넓게 매출 파이프라인을 여는 결정.**
2. CEO 거버넌스 3결정(book-of-record / 귀속 방식 / 목표 소스) — 커버리지 "측정"은 독립 실행 가능하나, 측정 결과를 어느 시스템의 정본으로 채택할지는 이 결정 이후.

**확인 필요 (다음 착수 전 실측 대상):**
1. `/admin/crm/customers/renewals` 리뉴얼 캘린더 화면 실물 — 캐논 §9는 가동으로 서술하나 레포 검색에서 경로 미발견(실측 2026-07-03).

1. **제안까지만**: deal 매칭 확정·AI 초안 게시·가격 안내·갱신 조건 판정은 스킬이 초안/플래그만 내고 사람이 확정한다.

## 7. 제외한 것과 이유

- **/share 뷰어 구현, NEO→crm_orders 적재** — 반복 호출되는 스킬이 아니라 개발 프로젝트/일회성 ETL. §4 병목으로 관리.
- **22문항 4레벨 판별 전체 자동화** — 판단형 1순위. mapper는 후보 제안까지만.
- **AI 초안 자동게시(FAQ 추천질문 등)** — 절대 규범 위배로 원천 배제.
- **명함 intake 후속 스킬** — Classin 캐논에 근거 없음(moonlight Hub 개념과 혼동 위험). 실존 검증부터.
- **90일 파일럿 추적 스킬** — 딜 파이프라인상 파일럿 상태/필드 미정의. 인프라 정의 없이 설계하면 상태값을 지어내게 됨.
- **행사 attribution 후속, 리드마그넷 admin 편집칸** — 1회성 확인/코드 인프라 작업이지 반복 스킬 아님.
- **1차 그룹A 품질 체커류**(게이트 사전검수·한자 스캐너·admin 라우트·공개 페이지·이벤트 이중등록·스키마 4단계) — 매출 액션에 직접 연결되지 않아 독립 재나열하지 않고 매출 스킬 가드레일로 흡수. 단 **1차 기획 §6의 지위는 유지** — 콘텐츠/코드 산출물 작업 시 여전히 적용.
