Only the solo final answer / Council synthesis generation format changes. Production defaults and HTTP selectors stay unchanged. No experimental model settings are adopted.

Private final output, before normal public parsing:

```ts
requestContract: {
  deliverable: string; // 1..350 characters: the artifact requested now
  doneWhen: string; // 1..350: when this answer has fulfilled the request
  currentRequestQuote: string; // 1..600 exact substring of current user message
  targetEvidence: null | 'unverified' | 'source-reported';
}
followUp: null | {
  kind: 'requested_action';
  text: string; // 1..1000; the complete public next action
  currentRequestQuote: string; // 1..600 exact current-message substring
} | {
  kind: 'answer_blocking_question';
  text: string; // 1..1000; the question needed to write the answer
  missingInput: string; // 1..350; identify the missing input
  currentRequestQuote: string; // 1..600 exact current-message substring
}
```

`requestContract` is a bounded deliverable specification, not internal reasoning or a quality verdict. Target evidence describes only what the supplied material says; `source-reported` is not an independent execution check. A completed explanation, scope confirmation, plan or test design can leave the real implementation unverified. Requested test steps belong inside the artifact; they do not by themselves require the user to execute and report back. Follow-up is an action the current request calls for, or a question actually needed to produce the requested answer. A blocking question must name the missing input; do not use a generic necessary-action category that conflates answer production with implementation work.
