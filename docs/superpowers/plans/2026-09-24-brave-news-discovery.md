# Brave News Search를 콘텐츠 탐색에 연결

> 2026-09-24 · 실행 계획. 리서치함·자동 초안 설계의 발견 단계만 구현한다. Brave 결과 저장 권한이 확인되기 전까지 검색 응답은 영속화하지 않는다.

## 목표와 경계

- 콘텐츠 탭에서 세 브랜드와 주제 묶음을 고르고 실제 Brave News Search 결과를 읽는다. 각 검색은 정확히 API 한 번만 호출한다.
- News 결과는 원문 검증 전 발견 신호로 표시한다. 링크를 열어 확인하도록 하며, `research_briefs`나 `content_items`에 자동 저장하지 않는다.
- 키는 Hub 서버에서만 사용한다. Hub 쓰기 가드로 POST를 보호하고 인증·설정·요금 제한 실패를 빈 결과와 구분한다.
- 주제·언어·국가·기간을 좁히고 결과 수를 상한으로 묶는다. URL 추적 파라미터 제거, 동일 URL 중복 제거, 짧은 스니펫, 무재시도로 비용과 응답 시간을 제어한다.

## 실행 순서

1. `research-news.test.mjs`에 브랜드·주제 입력 검증, API URL/헤더, 429·네트워크 실패, URL 중복·정렬·스니펫 상한, 키 비노출을 먼저 작성해 실패시킨다.
2. `research-news.js`에 검색 계획과 Brave 전용 어댑터를 구현하고 단위 테스트를 통과시킨다.
3. Hub POST 라우트 테스트에 인증, JSON 오류, 미설정, 정상 결과를 먼저 작성해 실패시킨다. `assertHubWriteAllowed`·`readHubWriteJson`을 이용해 라우트를 구현한다.
4. 콘텐츠 탑바의 `뉴스 탐색` 진입점과 전용 화면을 추가한다. 로딩·빈 결과·설정 필요·호출 실패를 분리하고 원문 링크를 제공한다. 모바일·키보드·디자인 토큰을 지킨다.
5. 저장소 문서에 현재 구현 범위와 환경 변수·사용법을 기록한다. 실제 키로 안전한 1회 호출을 확인하고 적합한 테스트·빌드·차이 검사를 실행한다.

## 후속 경계

이 구현은 발견 계층이다. 원문 근거 확인, AI 선별/원고, 리서치함의 영속 저장, 콘텐츠 후보·Studio 승격, 정기 실행, YouTube는 상위 스펙의 후속 작업이며 이 계획의 완료를 그 기능의 완료로 표시하지 않는다.

## 실제 연결·사용

- Hub 서버의 `BRAVE_SEARCH_API_KEY`를 사용한다. 브라우저 번들·응답·로그에 키를 싣지 않는다. 현재 개발용 Hub 환경 파일에 설정된 키로 News Search 응답을 확인했다. 배포 환경은 별도 설정이 필요하다.
- 콘텐츠 → 뉴스 탐색(`/dashboard/content/news`)에서 브랜드/주제/기간을 고르고 `뉴스 검색`을 누른다. 세 스코프의 콘텐츠 탑바와 ⌘K에서도 찾을 수 있다.
- 각 요청은 News Search `/res/v1/news/search` 한 번, `count=10`, `freshness=pd|pw`, 해당 국가·언어로 실행한다. 서버·브라우저 캐시는 사용하지 않고 429와 장애를 0건과 구분한다. 스니펫은 240자로 자르고 추적 파라미터가 다른 같은 URL은 한 건으로 보여 준다.
- API 결과는 현재 페이지 메모리에만 존재한다. 원문 열람·사실 확인 뒤 기존 소재함에서 직접 기록할 수 있다. 이 화면의 제목·검색 발췌만으로 검증 완료나 콘텐츠 후보 등록으로 처리하지 않는다.
- [Brave 공식 FAQ](https://brave.com/search/api/)는 검색 결과 일부·전체의 저장에 별도 권한이 필요하다고 설명한다. 저장 권한이 확인되더라도 제3자 원문의 저작권·접근 조건은 별도로 따른다.
