# 측정 가능한 개인 OS — 최적화와 다음 UI/UX 개발안

> 2026-09-21 · **개발 제안 / 미확정**. 구현된 기반은 [실행 계획](2026-09-21-measurable-personal-os.md), 검증 범위는 [평가 기록](../../evaluations/2026-09-21-measurable-personal-os-validation.md)을 따른다. 이 문서는 DESIGN.md나 운영자 프로필을 대체하지 않는다. 시각적 실험은 별도 시안에서 비교한 뒤 채택한다.

## 방향

AI 호출 수보다 한 업무를 끝내는 데 필요한 사람의 시간·탐색·재입력을 줄인다. 기존 업무 기록 → 목표의 근거 → 초안·분석 → 검토 결과를 연결한다. 결과가 없으면 빈칸을 보여주고, 무엇을 기록해야 측정할 수 있는지 알려준다. 자동화되지 않은 업무도 같은 화면에서 끝낼 수 있어야 한다.

## 이번 구현에서 실행한 최적화

- 자동 지표의 소속 판정에 필요한 프로젝트·브랜드·CRM 참조를 100개 단위로 미리 읽고 요청 안에서 공유한다. 50개 작업/50개 프로젝트/1개 브랜드 테스트에서 원장 조회를 6회 이내로 제한했다. 사용자가 다른 요청에서 수정한 상태를 오래 캐시하지 않는다.
- 목표 화면과 AI 패널은 필요할 때 불러온다. 기본 업무 화면에서 모델 응답을 기다리지 않는다. 같은 시점의 중복 목표 조회는 합치되, 저장 후 조회는 이전 응답과 분리한다.
- Agent 목표 응답은 32KiB, AI 문맥 응답은 96KiB 이내로 제한하고 빠진 범위를 표시한다. 긴 AI 후보는 해시와 오프셋을 사용하는 나눠 읽기로 원문을 복구한다.
- Gemini 생성은 먼저 실행 기록을 확보한다. 중복 명령은 같은 결과를 반환하고, 모델 응답 후 저장 실패는 서명된 복구 자료로 저장만 재시도한다. 매번 생성부터 다시 하지 않는다.

이는 구현·회귀 테스트 결과다. 운영 네트워크의 p95나 사업 시간 절감 효과를 측정한 결과는 아니다.

첫 적용은 개인 목표 1~2개와 반복 업무 한 종류를 권장한다. 숫자는 운영자 확정 목표가 아니다. 2주간 기록으로 입력 부담·검토시간·실사용률을 확인하고, 거래처럼 긴 주기를 가진 결과는 별도의 충분한 기간을 둔다.

## 화면별 제안

### 목표·성과: 숫자에서 근거까지 한 번에

목표 목록은 한 줄의 원하는 변화, 기간, 주요 결과, 측정 상태까지만 보여준다. 현재 모든 지표를 펼치는 구조는 목표가 많아질수록 읽는 비용이 커진다. 상세에는 `결과 / 선행 활동 / 보호 지표`를 의미 단위로 구분하고, 실측값 → 근거 → 연결 업무 순서로 탐색한다. 서로 다른 지표를 평균해 하나의 성과 점수를 만들지 않는다.

자동 지표에는 `개인 전체 · 이번 기간` 같은 집계 범위를 숫자 가까이에 둔다. 연결 업무에는 `기여 관계`를 표시한다. 특정 업무만 계산하는 기능이 생기기 전까지 연결과 집계의 의미를 합치지 않는다.

### AI: 길게 읽기 전에 무엇을 판단할지

처음에는 `초안 / 품질 검토 / 근거 분석` 중 목적을 고른다. 결과 상단은 `사용한 근거`, `확인할 부분`, `추천 다음 행동`의 짧은 요약으로 구성하고 전체 원문은 아래에 보관한다. 직접 수정한 후보와 원본의 비교 보기를 추가한다. `채택`은 후보 평가이고 `업무에 적용`과 `발송·발행`은 별도 사건으로 유지한다.

사용 시간은 매번 의무 입력하지 않는다. 필요할 때 기준 수동 시간, 지시·수정·실행 시간, 검토 시간을 기록한다. 현재 기록은 작업별 차이이며 시스템 전체 순절감은 아니다. 유지·설정·실패 복구를 포함하는 주간 합계는 다음 비용 장부와 함께 개발한다.

### 오늘: 승인함보다 선택을 돕는 첫 화면

위에는 오늘 선택한 집중 작업, 가운데에는 실제 변화가 확인된 목표와 근거가 부족한 지표, 아래에는 처리할 실패·약속을 둔다. 새 승인 큐를 무한히 쌓기보다 기존 오늘·업무 상세에서 처리한다. 작업 이동·보류·기한 조정의 키보드 동작을 통일하고, 모바일은 입력창을 키보드 위에 유지한다.

### 업무 연결: 기억하지 않아도 이어지는 탐색

목표 → 할 일 링크는 현재 메모 맥락을 거쳐 편집을 여는 흐름이다. 다음 변경에서는 `할 일 상세`와 `관련 메모`의 딥링크 의미를 분리해 목표·AI 패널까지 한 번에 도달하게 한다. 프로젝트·고객·콘텐츠 어디서 시작해도 현재 대상과 연결 목표, 최근 근거의 위치를 일정하게 유지한다.

## DESIGN 밖에서 시험할 수 있는 시각 제안

구현 전 비교 시안에 한정한다. 기존 제품 토큰을 즉시 바꾸는 제안은 아니다.

1. **업무 기록을 따라가는 세로 타임라인.** 목표→실행→결과→학습의 흐름을 선 하나로 표현한다. 근거가 없는 구간은 비워 두고, 선 색만으로 상태를 전달하지 않는다. 그래프형 관계도보다 좁은 화면에서도 읽기 쉬운지 비교한다.
2. **집중 모드.** 사이드바를 줄이고 오늘 선택한 한 작업과 관련 근거·AI 후보만 보이는 화면. 사용자의 작업 범위와 저장 상태는 계속 표시한다. 화면 복귀·닫기·초안 보존을 우선 검증한다.
3. **종이 메모에 가까운 리뷰 화면.** 다크 기기형 화면과 대비되는 밝은 독서용 표면, 여유 있는 행간, 좁은 본문 폭을 시험한다. 글쓰기 몰입에 도움이 되는지는 수정 시간과 선호도로 평가한다.
4. **미세한 변화 기록.** 점수·배지 보상 대신 `지난 확인 이후 바뀐 값`과 그 근거만 표시한다. 확인하지 않은 값은 강조하지만 실패/성공 색을 카테고리에 사용하지 않는다.
