# macOS 펫 자동 로그인과 메모 저장 안내

상태: 운영자 구현 요청(2026-10-05): “고치고 자동 로그인 되게 해놓자”.
관계: `2026-09-25-pet-hub-connection-design.md`의 §연결 중 비밀번호 미보관·재시작 후 수동 로그인을 대체한다. 기존 API 인증 경계와 메모의 명시적 저장·본문 재조회는 유지한다. Mac 네이티브 펫에만 적용한다.

## 동작

- 최초 로그인에서 서버가 실제 수락한 아이디·비밀번호만 macOS 로그인 키체인의 generic password에 저장한다. 항목은 정규화된 HTTPS 또는 정확한 loopback origin별로 분리하고 iCloud 동기화를 사용하지 않는다.
- 앱 재시작·서버 세션 만료 후 인증 거절을 받으면 같은 주소의 키체인 정보로 기존 `/api/operator/session`에 로그인한다. 동시 조회는 로그인 한 번을 공유한다.
- 조회와 기존 메모/할 일 저장만 명시적인 HTTP 401/403 인증 거절 이후 원래 payload를 그대로 한 번 재시도한다. 서버 처리 여부를 모르는 네트워크 오류와 HTTP 5xx, 충돌, 모델 생성 요청은 자동 재전송하지 않는다.
- 비밀번호 거절은 해당 실행의 자동 로그인 시도를 중지한다. 주소 변경·로그아웃 이후 늦은 인증 응답은 세션을 복구하지 않는다. 로그아웃은 키체인 정보도 지우며 초안·저장 영수증의 원본은 보존한다.
- 메모는 로그인 필요 상태의 원인과 연결 화면으로 가는 동작을 기존 하단 상태 공간에 표시한다. 저장 성공 여부와 Mac 초안 보관을 구별한다.

## 검증

- 기존 17개 transport 검사와 메모/API 계약 검사로 기준선을 확인했다. 만료 시 메모 요청 실패 및 로그인 안내 누락을 먼저 재현한 뒤 수정한다.
- 앱 재실행을 대표하는 새 transport에서 같은 origin의 로그인 복원, 다른 origin으로 자격 전송 금지, 거절 정보 미저장·반복 시도 중지, 동시 조회 합치기, 정확한 메모 payload 유지, 오프라인 로그아웃, 불확실한 쓰기·모델 요청 미재전송을 검사한다.
- 별도 일회성 키체인 항목으로 실제 macOS 키체인의 쓰기·프로세스 재시작 후 읽기·주소 분리·삭제를 검사하고 종료 시 정리한다. 운영자 로그인 정보나 업무 기록을 테스트용으로 만들지 않는다.
- 네이티브 검사·번들 빌드·서명 검증 후 설치본을 갱신한다. 현재 메모의 자동 Mac 보관을 확인하고 최초 로그인 창을 제공한다. 실제 자동 로그인 초기화에는 운영자가 새 설치본에 한 번 로그인해야 한다.

새 공개 엔드포인트·DB 마이그레이션·서버 세션 수명 변경은 없다. 키체인 접근이 거절되거나 잠겨 있으면 연결 오류로 표시하고 입력을 유지한다.
