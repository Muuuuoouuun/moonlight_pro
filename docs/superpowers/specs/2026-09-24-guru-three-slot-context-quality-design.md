# Guru 하루 세 번 관점·상황 적합성·출처 품질

> 상태: **운영자 방향 승인(2026-09-24) · 개발 서버 검증**. 하루 약 세 번 규칙적으로 바뀌는 Guru 팁과 상황 적합성·출처 교정을 요청했다. 09:00·14:00·19:00은 시범 기본 시각이며 운영자의 별도 선호가 확인되면 조정한다.
> 관계: `2026-09-24-guru-guidance-cards-design.md`의 **일간 한 장 선택**을 아래 세 구간으로 대체한다. `2026-09-24-guru-dual-experience-design.md`의 서가·레일 위치, 요청형 질문, 무알림·무업무 생성, Legend 주간 카드 원칙은 유지한다. 카드를 보는 중 자동으로 바꾸지 않는 원칙은 새 시간대 표시와 수동 갱신으로 유지한다.

## 1. 시간과 노출

- Guru의 서울 시간 구간은 **09:00–14:00 오전, 14:00–19:00 오후, 19:00–다음 날 09:00 저녁**이다. 자정에 네 번째 교체를 만들지 않는다. 같은 시각·분야·맥락은 어느 기기에서도 같은 카드를 고른다.
- 열려 있는 카드나 질문 드로어의 문구는 읽는 도중 바꾸지 않는다. 구간이 넘어가면 작은 `새 시간대 관점 보기` 동작을 제공하고, 페이지로 돌아오거나 레일을 다시 열면 최신 구간을 적용한다. 푸시·배너 알림·자동 드로어 열기는 없다.
- 수동 `다른 카드 보기`는 현재 구간의 선별 목록 안에서만 움직인다. Legend는 그대로 서울 기준 주간 관점이다.

## 2. 카드 선별과 사실 경계

- Guru는 영업·마케팅·콘텐츠 **각 5장**의 편집 카드에서 시작한다. 하루 세 구간에 같은 분야 카드가 당일 중복되지 않도록 한다. 단정적 효과 수치·가공 증언·원전과 다른 귀속을 카드에 넣지 않는다.
- 각 카드는 안정 ID, 분야, 인물·방법론, 짧은 관점, 사용 조건, 질문, 내부 참고 절, 확인 가능한 출처 URL을 가진다. 원전을 다른 업무 상황에 옮겨 쓴 경우 `Moonlight 응용`이라고 명시한다. 출처 링크는 방법론의 근거이지 현재 고객의 사실 증거가 아니다.
- 긴 인물 조사 문서는 자동 추출 대상이 아니다. `docs/research/2026-09-24-guru-source-quality.md`에 확인된 오류와 남은 미검증 구역을 기록한다. 새 카드는 원전과 내부 절을 함께 검토한 뒤 추가한다.

## 3. 상황 적합성과 질문 연결

- 카드 선택의 근거는 **현재 화면에서 확인 가능한 범주**에 한정한다: ClassIn 고객 목록의 진행 중·신규·기약 없음 단계, 개인 브랜드에 기록된 대상·약속의 유무, 개인 콘텐츠 큐의 소재·제작중·검토 단계. 범주마다 맞는 카드가 네 장 이상 있어 세 구간 순환이 가능하다. 범주를 모르면 그 분야 전체 카드로 돌아간다.
- 카드는 특정 고객의 반응·의도·예산을 추정하지 않는다. 화면 상태가 부분 읽기·미연결이면 빈 필드를 실제 부재로 단정하지 않는다. 개인 자료를 ClassIn 질문 맥락에 섞지 않는다.
- 카드 질문 버튼은 **빈 운영자 입력창**과 선택한 카드의 근거를 연다. 전송 후에만 Engine이 실행된다. 카드가 없는 자유 질문에는 임의 인물의 방법론을 자동으로 귀속하지 않는다. 이전 생성 답변은 고객 원장 사실이 아닌 생성 이력으로 표기한다.
- 범위 없는 질문의 생성 이력은 같은 Guru·같은 질문 모드·`ref` 없는 기록만 데이터베이스에서 먼저 고른 뒤 5건으로 제한한다. 다른 고객·브랜드에 관한 최근 질문이 관련 이력을 밀어내지 않게 한다.
- 요청형 질문은 원장 전체를 보더라도 질문·선택 카드와 직접 관련된 사실만 답변에 사용한다. 형식적인 반론이나 다른 프로젝트의 우선순위를 붙이지 않는다.
- 개인 브랜드 질문은 정확히 선택한 브랜드의 확인된 자료만 사용한다. 영업 질문은 ClassIn으로 확인된 고객·거래·연락 기록만 사용한다. 연결 실패는 `preview`·`error`로 드러낸다. 질문·열람·시간 교체는 승인 큐나 업무를 자동 생성하지 않는다.

## 4. 검증 기준

- 시간 경계 09·14·19시, 자정 유지, 동일 구간 결정성, 분야별 당일 세 카드의 비중복, 맥락 키별 적합성과 미지 키 폴백을 순수 함수 테스트로 확인한다.
- 출처 URL·응용 표시·잘못된 귀속 제거, 자유 질문과 카드 질문의 프롬프트 차이, ClassIn/개인 범위 및 기억 분리, 실패 봉투를 테스트한다.
- 개발 서버에서 서가·레일·기존 코칭 카드의 시각 일치, 390px 터치·가로 넘침, 샌드박스 질문 왕복을 확인한 후 운영 배포를 판단한다.
