## 0. 한 줄

오피스 탭에 들어오면 **"누구를 고를지"가 아니라 "무슨 일감인지"**를 먼저 고른다. 세 면(업무 분담 · 관점 대화 · 저장 회의)을 회의실 하나로 합치고, 결과마다 `그대로 · 고쳐 · 버림` 한 번을 앱이 기록해, 11월 판정 근거를 손 메모 없이 쌓는다.

## 2. 왜 안 쓰나 → 무엇을 고치나

회의실 스펙 D3가 적은 세 원인 중 레이아웃으로 고칠 수 있는 것은 두 개다.

| 원인 | 이번에 하는 것 | 하지 않는 것 |
| --- | --- | --- |
| 쓰는 법이 안 보임 | **일감 먼저**(§3 P2): 첫 화면의 첫 행동이 "일감 6개 중 하나 누르기". 세 면 → 한 화면(P1) | 설명 문단 · 온보딩 투어 |
| 넣기 불편 | 칩이 범위·담당·방식·템플릿을 대신 채운다. 브랜드 기록 부착(P4)으로 손 복사 제거 | 음성·파일 입력 |
| 답을 못 믿음 | 결과 카드의 `근거 확인 안 됨`·`업무 변경 없음` 영수증 유지. `버림(틀림)` 기록이 쌓이면 캐릭터별 교정 후보가 된다(front-door §10/14) | **역할 카드·말투 튜닝(동결)**, 모델 교체 |

## 3. 제안 다섯 개

### P1 · 한 화면 — 회의실이 착지다 (권장)

- 세그먼트 3면을 없앤다. `dashboard/agents/office-council`은 **저장 회의실 한 장**이다. 범위 `전체`로 들어오면 안건 보내기 전에 개인/회사를 고르는 현행 규칙 그대로(0069).
- `관점 대화·회의`(비저장)는 따로 두지 않는다. 저장 회의가 같은 기능이고, "새로고침하면 사라지는 대화"를 고를 이유가 없다. 0069의 `닫은 회의도 목록에 남음`이 대신한다.
- `이브이 업무 분담`(Shadow 커맨더)은 운영 화면에서 뺀다. 모델 호출이 없는 수동 기록 폼이라 B의 "이브이 창구"와 다른 물건이다. 처분은 Q-OF2.

### P2 · 일감 먼저 — 고정표가 담당을 고른다 (권장, B의 "일감 고정표 먼저")

안건 입력 **위**에 일감 칩 한 줄. 칩은 front-door "10월에 실제로 쓰는 법" 표를 그대로 옮긴 것이고, LLM 호출 없이 폼 값을 채운다.

| 칩 | 범위 | 주관 · 관점 | 응답 방식 | 입력칸에 미리 들어가는 것 | 어디서 |
| --- | --- | --- | --- | --- | --- |
| 정리 | 고른 범위 | 이브이 · — | 대화 | 자리표시 "뭘 해야 할지 모르면 메모를 그대로 붙여 넣으세요" | 회의실 |
| 막힌일 | 고른 범위 | 이브이 · — | 대화 | 왼쪽 레일 `오래 멈춘 할 일` 포커스 + 템플릿 B 뼈대 | 회의실 |
| 판매판단 | 개인 | 에브이 · 리피아 | 회의 | 템플릿 A 뼈대(상대 · 상품 · 현재 가격 · 관련 브랜드 · 질문) | 회의실 |
| 개인 답장 | 개인 | 부스터 · — | 초안 | "상대 · 상품 · 제시 가격 · 지난 대화" 뼈대 | 회의실 |
| 회사 답장 | 회사 | 부스터 | — | **회의실에서 하지 않는다.** 고객 상세 답장 패널로 보내는 링크 칩(점선) | 고객 › 답장 패널 |
| 원고 | 브랜드 | 님피아 | — | **회의실에서 하지 않는다.** Studio 소재 › AI 변환으로 보내는 링크 칩(점선) | 콘텐츠 › 원고 작성 |

- 칩은 선택이지 강제가 아니다. 안 누르고 바로 적으면 지금처럼 이브이 기본 + `담당 추천` 버튼(LLM 추천은 모호할 때만 — B 원칙).
- 칩을 누른 뒤 참석자를 바꾸면 칩이 꺼진다(참석자 레일이 정본). 칩 ↔ 참석자가 충돌하지 않는다.
- 회사 답장·원고가 링크인 이유: 회사=부스터는 답장 패널의 CRM 사실(숫자·날짜)을 붙여야 안전하고, 원고는 브랜드 기록·톤이 Studio에만 있다(front-door 표, 레인 규칙). 회의실로 끌어오면 같은 일을 두 곳에서 하게 된다.
- 더보기의 추천 조합 4개(고객 제안 · 기능 · 돈·시간 · 이번 주)는 칩 뒤 `더 보기 ▸`로 접는다. 첫 줄은 운영자가 실제로 하는 일감 6개뿐이다.

### P3 · 결과마다 한 번 — `그대로 · 고쳐 · 버림` (권장, B의 "앱이 기록")

- 결과 카드 아래 줄: `이 답, 어떻게 썼나요? [그대로] [고쳐] [버림 ▾ 맥락부족 · 틀림 · 쓸모없음]`. 한 판에 한 번, 누르면 글자로 바뀌고(`그대로 · 19:27`) 다시 누르면 바꿀 수 있다. 저장 봉투 `{ ok, status }`를 받기 전엔 `기록 중`, 실패하면 `기록 못 함` + 다시(빨강은 여기 한 곳).
- 저장: `agent_runs.recommendation.verdict = { value, reason, at }` — 그 판의 run 행에 덧붙인다. 이미 `elapsedMs`·`failure`·`usage`가 같은 jsonb에 있어 **마이그레이션 없음**. 구현(2026-10-29)에서 확인: `agent_runs`를 쓰는 쪽은 Engine이 아니라 Hub(`apps/hub/lib/sales-os/agent-runs.js`)라 Engine 라우트 없이 Hub BFF `POST /api/hub/office/verdict`(hub-write-guard)가 `apps/hub/lib/office/verdict.js`로 읽기-병합-PATCH 한다(동시 쓰기 없음 전제, `ponytail:` 주석).
- 하단 사용 줄에 두 칸 더: `그대로+고쳐 n/m · 버림 사유 상위 1`. 설정 › AI 사용량에도 같은 숫자. `[office]` 메모 수기는 폐지한다 — 이 줄이 판정 원천이다(§8).
- 판에 run이 여러 개(회의 모드) → 종합 카드의 run 하나에만 붙인다(같은 날 같은 일감 1건 규칙과 같다).

### P4 · 브랜드 기록 부착 (권장, B의 "회의실에도 브랜드 기록")

- 안건 줄에 `브랜드 ▾`(선택). 고르면 안건과 같이 **읽기 전용 context**로 들어간다: 브랜드 설명 · 운영 상태 · 집중점 · 최근 컨텐츠 로그 5줄(`dashboard/brands/log`와 같은 원천). Studio가 읽는 칸(설명·철학·보이스·규칙·금지어·예문)과 같은 자리에서 읽는다.
- 결과 카드에 `참고 · 브랜드 X 기록 n줄`(TruthBadge live/partial). 못 읽었으면 `브랜드 기록 못 읽음`이고 안건은 그대로 보낸다 — 조용히 빼지 않는다.
- Office 무도구는 그대로다. 모델은 읽기만 하고 브랜드 기록을 바꾸는 명령은 없다. 범위 `회사`면 회사 브랜드, `개인`이면 개인 브랜드만 고를 수 있다(레인).
- 10월엔 템플릿 A의 `관련 브랜드` 칸에 손으로 적기로 했으므로, 이것이 그 칸을 대체한다.

## 4. 화면 — 회의실 한 장

```
AI·자동화 / 오피스                                       [개인 | 회사]   (범위 전체일 때만)
이브이 오피스
안건 하나를 올리고, 필요한 관점을 불러 함께 검토하세요.

┌ 왼쪽 레일 232 ─────┬ 가운데 ───────────────────────────────┬ 오른쪽 레일 220 ─┐
│ 지금 회의          │ 일감  [정리] [막힌일] [판매판단] [개인 답장]  │ 참석자           │
│  · 판 1 · 판 2     │       [회사 답장 ↗] [원고 ↗]   더 보기 ▸    │  ◉ 이브이 · 주관 │
│ 저장된 회의        │                                          │  + 관점 더하기   │
│ 오래 멈춘 할 일    │ ┌ 안건 ─────────────────────────────┐  │ 브랜드  [없음 ▾] │
│  · … 6개           │ │ (칩이 채운 뼈대 / 자리표시)         │  │ 진행 방식        │
│ 할 일 검색         │ │                                     │  │  응답 · 발언 단계│
│                    │ └───────────────────────[보내기 ⌘↵]─┘  │  회의·기록       │
│                    │ ── 결과 카드 ───────────────────────── │                  │
│                    │  결론 · 근거 · 다음 행동 · 역할별 발언  │                  │
│                    │  [할 일로 연결] [다른 관점으로] [더보기] │                  │
│                    │  이 답, 어떻게 썼나요? 그대로 · 고쳐 · 버림▾│                  │
└────────────────────┴──────────────────────────────────────┴──────────────────┘
최근 7일 · 요청 n · 할 일 연결 n · 그대로+고쳐 n/m · 평균 ns · 실패 n · 이달 추정 ₩—
```

- 바뀌는 것은 가운데 위 **일감 줄**, 오른쪽 **브랜드 ▾**, 결과 카드 아래 **한 줄**, 하단 **두 칸**. 레일·좌석·진행 방식·드로어(참석자 바꾸기 · 회의·기록 · 안건 가져오기 · 담당 추천 · 멘토 · 로컬 스킬 요청)는 V4 그대로다.
- 색: 칩은 눌린 홈 위 고른 칸만 잉크(depth C 세그먼트 문법). 링크 칩은 점선 + `↗`. 빨강은 `기록 못 함` 한 곳. 권장은 `CertaintyBadge recommended`.
- 제목은 §11 20px/500 그대로(Futura 확장 아님).

## 10. 위험

- **칩이 또 하나의 설정이 될 위험**: 칩 뒤에 참석자 레일이 그대로 있어 두 곳에서 같은 걸 고를 수 있다. 칩은 "레일을 대신 채우는 버튼"이고 정본은 레일이라는 규칙(P2)으로 막는다.
- **판정 기록 누락**: 결과를 읽고 바로 떠나면 `그대로/고쳐/버림`이 안 남는다. 미기록은 미기록으로 센다(기본값 없음). 강제 팝업은 두지 않는다.
- **브랜드 context가 길어져 답이 느려짐**: 최근 로그 5줄 · 총 2,000자 상한. 넘으면 잘랐다고 결과 카드에 표시(`partial`).
- **품질은 그대로**: 이 기획은 "쓰는 법"과 "넣기"만 고친다. 0/9 통과 상태는 바뀌지 않으며, `버림(틀림)` 비율이 그것을 숫자로 보여 주는 것이 이번의 목적이다.
