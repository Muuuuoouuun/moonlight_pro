# 펫 Office 기능 기획 B — 바로 묻고 이어가는 창

상태: **검토용 제안 · 미선택 · 미구현**

기준일: 2026-10-03 · 대상: Mac 네이티브 펫

## 해결할 문제

작업 도중 짧게 판단을 받거나 초안을 검토하고 싶은데 Office 진입이 브라우저 호출로 끝난다. 이 안은 펫을 열어 담당자를 선택하고 질문을 보내는 행동을 우선한다.

기존 native Council 모드에는 Office 담당자 채팅이 이미 있다. Office라는 이름 아래 그 기능을 배치하고, 브랜드 Council로 가는 진입은 별도 보조 목적지로 보존한다. 두 계층을 합치지 않는다.

## 핵심 화면과 동작

Office 진입 → 담당자/범위 확인 → 질문 작성 → 보내기 → 답변 읽기 → 후속 질문.

| 표면 | 내용 | 예산 |
| --- | --- | --- |
| 상단 | Office, 개인/회사 범위, 닫기 | 한 줄 |
| 모드 | 대화 / 작업 | 두 항목 |
| 담당자 | 선택된 역할과 이름, 변경 메뉴 | 한 줄 |
| 선택 맥락 | 명시적으로 가져온 항목의 복사본 | 하나 |
| 본문 | 한 담당자·한 범위의 대화 | 주 영역 |
| 주 행동 | 작성란의 보내기 | 하나 |
| 보조 행동 | Hub에서 이어서 | 텍스트 링크 하나 |

아홉 담당자 얼굴 띠, 프롬프트 추천 카드, 작업 목록과 대화의 좌우 분할, 별도 빠른 입력 창을 추가하지 않는다. 담당자 변경은 한 메뉴에서 한다. 질문 작성을 위한 탭/메뉴 외 행동은 더보기로 보낸다.

작업 탭은 첫 버전에서 **사용자가 현재 대화에 가져온 항목의 출처 확인과 Hub 이동**을 제공한다. 저장된 모든 Office 요청을 보여주려면 A안의 요약 조회가 추가로 필요하다. 처음부터 전체 목록이 있는 것처럼 구현하지 않는다.

## 대표 사용 흐름

1. Office를 연다. 선택한 담당자와 범위, 이전에 작성하던 초안을 복원한다.
2. 필요하면 기존 할 일을 선택해 제목·내용의 복사본을 가져온다. 보내기 전 미리 확인하고 제거할 수 있다.
3. ‘보내기’를 누른 요청만 서버에 전송한다. 담당자·범위·출처를 해당 요청에 고정한다.
4. 응답을 읽고 후속 질문을 작성한다. 답변에서 할 일을 자동 생성하거나 외부에 보내지 않는다.
5. 반영이 필요한 결과는 Hub에서 검토해 명시적으로 진행한다. 로컬 스킬은 운영자의 Claude Code/Codex 요청서와 receipt 흐름으로 이어진다.

할 일의 복사본은 원본 동기화가 아니다. 원본이 바뀌어도 작성 중인 질문을 조용히 바꾸지 않는다. 개인/회사 범위에 맞는 항목만 선택하고, 다른 범위로 이동하면 해당 맥락을 다시 확인한다.

## 대화 상태와 초안 보호

| 상황 | 동작 |
| --- | --- |
| 작성 중 | 담당자/범위별 초안 보존 |
| 응답 대기 | 한 요청만 진행, 중복 전송 방지, 담당자/범위 변경 잠금 |
| 다른 펫 모드로 이동 | 요청과 초안 유지, 응답은 원래 대화에 도착 |
| 답변 도착 | 올바른 담당자/범위 대화에 추가 |
| 전송 실패 | 초안 보존, 오류 설명, 명시적 재시도 |
| 인증 만료 | 같은 창의 Hub 로그인으로 안내, 재인증 뒤 초안 복원 |
| 대기 취소 | 로컬 응답 대기를 중단했다는 사실만 표시 |
| 재전송 | 새 요청임을 구분, 자동 재시도 없음 |

‘대기 취소’를 서버의 생성 작업 취소 완료라고 표시하지 않는다. 이전 요청의 늦은 답변은 새로운 대화나 선택한 범위에 섞지 않는다.

이 앱의 대화 보존은 현재 실행 중 메모리 계약을 따른다. 재실행 뒤 전체 대화 기록이 복구된다고 약속하지 않는다. 영속 대화가 필요하면 보관·삭제·actor/scope 계약을 먼저 설계한다.

## 데이터와 개발 범위

재사용:

- OfficeChatStore의 한 번에 한 요청, 초안 보존, 오래된 응답 폐기, 기존 입력/히스토리 상한.
- 기존 Office chat API와 배포 Hub의 운영자 인증.
- AppModel의 공용 연결 서비스와 Office 담당자·범위 선택.
- 기존 대화 UI와 clear glass companion 창.

변경/추가:

1. Office 모드에 기존 Office 채팅을 배치하고 실제 브랜드 Council 진입의 이름과 위치를 정리한다.
2. Office를 보는 동안의 답변 알림/읽음 판정을 실제 모드와 담당자·범위에 맞춘다. 현재 Council 가시성만 검사하는 조건을 그대로 두지 않는다.
3. 기존 할 일의 선택적 맥락 가져오기와 보내기 전 미리보기. 입력 상한은 기존 채팅 계약을 유지한다.
4. 작업 탭에서 가져온 원본의 제목·범위·출처와 Hub 이동을 제공한다. 서버의 최신 업무 상태를 재조회하지 않았다면 현재 상태처럼 표시하지 않는다.
5. 주간 정리·고객 답장의 영속 생성 요청을 시작하는 기능은 첫 버전에서 별도 검토한다. 일반 chat 답변과 durable receipt를 같은 기록처럼 합치지 않는다.

처음에는 새 전역 요청 조회나 DB 테이블 없이 대화 중심 UI를 만들 수 있다. 모든 Office 작업의 최근 목록은 A안의 추가 개발 범위다. ‘Office에서도 작업을 띄운다’는 첫 범위를 **선택한 기존 할 일을 맥락으로 보면서 대화하기**로 명확히 제한한다.

## 창·연결·역할 계약

- 하나의 companion 창을 재사용한다. Office 요청·대화·로그인은 같은 창의 내용 변경으로 연다.
- 제안 크기는 본문 460×580pt + perch 54pt로 현재 Council과 같은 폭/높이 계열이다. 작은 화면에서는 본문만 스크롤하고 작성란은 보이게 유지한다.
- clear glass, 시스템 글꼴, 흰색 계열 글자, 1px 중립 경계를 유지한다. 펫 캐릭터 선택과 Office 담당자 선택은 별개로 보존한다.
- 생산 Hub 주소와 native 운영자 세션을 쓴다. 다른 앱의 세션 쿠키를 복사하지 않는다.
- 모델 응답은 판단·초안·검토다. 답변이 왔다고 업무 완료나 외부 전송 완료가 되지 않는다.
- 어느 담당자도 자동으로 업무를 만들거나 보내거나 도구를 실행하지 않는다.
- 창을 열거나 범위를 바꾸는 것만으로 모델 요청이 발생하지 않는다.

## 검증 기준

- Office로 직접 진입해 채팅할 수 있고 별도 창이 생기지 않는다.
- 담당자/범위 전환, 로그인, 모드 전환, 오류 뒤 초안이 보존된다.
- 요청 대기 중 두 번 보내기, 지연 응답, 취소/재전송이 다른 대화에 섞이지 않는다.
- 답변 알림은 실제 읽고 있는 담당자·범위에 대해서만 읽음으로 처리한다.
- 가져온 할 일을 제거하거나 다른 범위로 바꿔도 이전 본문이 묵시적으로 전송되지 않는다.
- 읽기 실패는 빈 작업처럼 보이지 않고, 인증 실패는 로그인으로 이어진다.
- 답변을 읽는 것만으로 업무 생성·외부 전송·스킬 실행이 발생하지 않는다.

## 장점·비용·우선순위

장점은 기존 채팅 자산을 재사용해 펫에서 바로 Office를 쓰기 쉽다는 점이다. 비용은 모든 저장된 요청을 한눈에 보는 목록을 별도로 개발해야 한다는 점이다.

출시 순서는 Office 진입/읽음 정리 → 초안과 인증 상태 → 선택 맥락 가져오기다. 기존 Hub API 계약을 유지하면 Mac 배포를 먼저 검증할 수 있다. 이후 A안의 요청 목록을 붙일 때도 같은 창의 작업 탭을 재사용한다. Windows는 별도 Acrylic 설계와 실기 검증 뒤 진행한다.
