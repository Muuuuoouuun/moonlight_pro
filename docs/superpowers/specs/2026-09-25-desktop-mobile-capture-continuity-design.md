# 데스크톱·모바일 빠른 입력 연속성 설계

> 상태: **DRAFT** — 운영자는 2026-09-25에 “공통 기록 흐름부터 설계” 방향을 승인했다. 아래의 인증·화면·전송 세부는 검토안이며 구현 승인은 아니다.
> 범위: Mac 펫·갤럭시 PWA/자동화 앱에서 시작한 입력의 로컬 보존, 전송 확인, Hub 착지. 두 기기의 전체 Hub 화면 이식은 범위 밖이다.

> 관계: [`2026-09-24-pet-approved-glass-design.md`](2026-09-24-pet-approved-glass-design.md)의 펫 외관·동작은 유지한다. 이 문서가 승인·구현되면 **연결 모드의 저장 경계만** 로컬 전용에서 확장한다. [`2026-09-24-mobile-capture-and-phone-integration-spec.md`](2026-09-24-mobile-capture-and-phone-integration-spec.md)의 클라우드·로컬 큐 서술은 현재 구현 상태가 아니라 목표 아키텍처로 읽는다. 기존 갤럭시 설정 가이드는 현재의 Mac Engine 직접 전송 경로를 설명한다.

## 1. 목적과 성공 조건

Moonlight는 운영자 한 사람의 업무 정본이다. 두 기기가 동일한 대시보드를 복제하는 대신, Mac 펫은 책상 앞 빠른 입력·집중, 갤럭시는 이동 중 공유·연락 포착을 담당한다. Hub는 결과를 확인하고 상세 작업을 이어가는 곳이다.

- 입력 직후 **기기에 남았는지**, **서버에 저장됐는지**, **검토가 필요한지**를 구별한다. 서버의 영수증 전에는 `저장 완료`를 표시하지 않는다.
- 같은 입력의 재시도는 하나의 정본 레코드로 귀결된다. 전송 실패나 앱 재시작 뒤에도 사용자가 입력한 내용과 요청 식별자를 복원한다.
- 전화·문자·카톡 사건은 `기록 후보`다. 운영자 확인 전에는 `crm_activities`가 아니다. 외부 발송·ClassIn 공식 기록도 자동 실행하지 않는다.
- Mac이 잠든 동안의 갤럭시 입력은 **상시 접근 가능한 Engine 배포와 기기 로컬 큐가 모두 검증된 뒤에만** 누락 방지 경로라고 부른다. 현재 Mac 직결 경로에는 이 보장을 붙이지 않는다.

## 2. 현재 상태와 설계 경계

| 표면 | 실제 코드·가이드 상태 | 이 설계가 더할 것 |
| --- | --- | --- |
| Mac 펫 | SwiftPM 목업의 할 일·메모는 `UserDefaults`에 로컬 저장. Hub 상세는 브라우저에서 열고 일정은 연결 상태만 표시 | 연결 여부와 전송 영수증, 안전한 기존 로컬 항목 가져오기 |
| Hub 빠른 입력 | `/api/hub/inbox` → Engine `capture_quick_input_v1`; UUID 멱등키와 `saved`/`duplicate` 결과가 있음 | Mac·모바일 어댑터가 같은 저장 판정을 사용 |
| Hub 메모 | `/api/hub/journal`의 `requestId`·`expectedRevision` 계약이 있음 | Mac의 단일 메모 초안을 한 Hub 메모에 연결하되 충돌을 표시 |
| 갤럭시 공유 | 설치형 PWA의 GET `share_target`이 `/dashboard`를 열어 빠른 입력을 채움. 영속 오프라인 보관은 없음 | 로컬 보관·재시도·영수증 표시, 공유 본문의 URL 노출 축소 |
| 갤럭시 연락 | MacroDroid → Mac Engine `phone-events` → `webhook_events` 후보 → Hub `오늘 연락`. Mac이 잠들면 기본 매크로는 재시도하지 않음 | Mac과 무관한 Engine 주소와 갤럭시 측 영속 재시도 큐 |

기존 모바일 스펙 상단의 “2단계 구현”과 `docs/README.md`의 텔레그램 버퍼 설명은 현재 코드·가이드와 맞지 않는다. 이 문서가 검토된 뒤 해당 상태 문장을 정정한다. 텔레그램 버퍼는 되살리지 않는다.

## 3. 화면과 사용 흐름

### Mac 펫

1. 미연결 상태의 오늘·메모는 지금처럼 로컬에서 동작한다. 상태 문구는 `이 Mac에만 저장`이다. 새 Hub 연결을 위해 기존 Hub 로그인 화면을 브라우저에서 열고, 설정의 `이 Mac 연결` 절차를 완료한다.
2. 연결 후 새 할 일 입력은 먼저 로컬 전송함에 기록한다. 화면은 `이 Mac에 보관됨` → `전송 중` → 서버 영수증을 확인한 `Hub에 저장됨`으로 바뀐다. 상세 편집은 해당 Hub 레코드로 연결한다. 연결된 오늘 목록은 기존 Hub의 오늘 판정 결과와 아직 전송하지 못한 로컬 항목을 상태 문구로 구분한다. 완료 토글은 Hub 확인 후 반영하고, 실패하면 이전 상태를 복원한다. 옛 로컬 항목은 가져오기 전까지 `더보기 > 기존 로컬 항목`에서 따로 보인다.
3. 빠른 메모는 기존 자동 로컬 저장을 유지한다. 연결 후 작성하는 메모에는 Hub 메모 ID를 부여하고 `requestId`와 `expectedRevision`으로 서버 저장을 확인한다. 연결 전의 기존 메모는 아래 가져오기 절차 전까지 별도로 보존한다. 서버와 이 Mac의 본문이 모두 바뀌면 한쪽을 자동 덮어쓰지 않고 두 버전을 보여 준다. `Council에서 이어서`는 기존처럼 명시적 복사·브라우저 열기만 한다.
4. 기존 로컬 할 일·메모는 연결 직후 자동 업로드하지 않는다. `기존 항목 가져오기`에서 중복될 수 있는 내용을 보고 선택적으로 옮긴다. 가져오기 영수증 뒤에만 Hub 항목으로 표시한다.
5. 기존 글래스·펫 포즈·클릭/더블클릭·집중 모드·창 앵커는 유지한다. 전송 상태는 현재 패널의 보조 문구 한 줄과 공통 더보기의 `전송 대기` 목록에 둔다. 새 상시 패널이나 기능 레일은 만들지 않는다.

### 갤럭시 공유

1. 시스템 공유 → Moonlight에서 제목·본문·링크를 한 번 확인한다. `할 일` 또는 `정리 전` 목적지를 선택한다.
2. 전송 가능 여부와 관계없이 **로컬 저장이 성공한 뒤** `기기에 보관됨`을 표시한다. 로컬 저장도 실패하면 편집 내용을 그대로 두고 실패를 알린다.
3. 서버가 `saved` 또는 같은 요청의 `duplicate`와 목적지 식별자를 돌려준 뒤에만 `Hub에 저장됨`으로 바꾸고, `내 작업에서 보기`를 제공한다. 앱이 닫힌 동안 백그라운드 재시도는 보조 수단이다. 앱을 다시 열거나 네트워크가 돌아왔을 때 전경에서도 재시도한다.
4. 390px 첫 화면에는 공유 내용과 한 개의 주요 저장 동작이 보인다. 전송 대기 건수는 기존 빠른 입력의 보조 위치에 두고 목록은 그 위치에서 연다. Hub의 `Drawer`·`TruthBadge`·토스트와 44px 터치·16px 입력 규칙을 따른다. 저장·실패 상태 변경은 한 개의 문맥 있는 `aria-live` 메시지로 알리고 입력 초점을 빼앗지 않는다.

현재 GET 공유는 본문이 URL 쿼리에 실린다. 로컬 보관 직후 쿼리를 제거하는 전환을 먼저 적용하고, 오프라인 공유 단계에서는 설치형 PWA의 `POST` Share Target과 서비스 워커 수신·IndexedDB 전송함으로 옮긴다. `POST`는 수신 페이지가 본문을 직접 읽을 수 없어 서비스 워커가 필요하다. 설치·활성화·오프라인 재실행을 실제 갤럭시에서 검증하기 전에는 전환하지 않는다. [Chrome의 Web Share Target 안내](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target).

### 갤럭시 연락

통화·문자·카톡은 현재 `phone-events`와 고객 대조·중복 키를 재사용한다. 등록 고객은 `오늘 연락 > 기록할까요`, 명시적으로 허용한 미등록 번호는 `새 고객으로` 후보에 착지한다. 원문은 확인 전 후보에만 있고, 다음 intake 때 실행되는 기존 7일 정리 규칙을 유지한다. 클라우드 Engine에 정상 저장된 후에도 공식 활동은 운영자가 기록 시트에서 확인한다. 기본값의 고객 외 사건 폐기 정책을 이 설계가 바꾸지 않는다.

MacroDroid 매크로는 사건을 **HTTP 전에 영속 큐에 기록**하고 응답 코드와 본문을 확인한다. `saved`(201)·`duplicate`(200)·정책상 폐기가 확인된 `ignored`(200)는 각각 결과를 기록하고 원문을 큐에서 제거한다. 401·400은 `설정 확인 필요`, 네트워크·502·503은 전송 대기로 남긴다. 재부팅·네트워크 전환·연속 사건에서 이 순서를 실제 기기로 검증한다. 이 큐를 MacroDroid만으로 안전하게 구성할 수 없다면 전용 Android 캡처 어댑터를 별도 결정한다. [MacroDroid HTTP 응답 코드·본문 저장 기능](https://macrodroidforum.com/wiki/index.php/Action%3A_HTTP_Request).

## 4. 정본, 영수증, 재시도

```text
Mac 펫 로컬 전송함 ─┐
                    ├─ 인증된 Hub/Engine 명령 ── 업무 정본(task/work_order/journal)
갤럭시 PWA 전송함 ──┘                              └─ 영수증 → 원래 기기

갤럭시 자동화 큐 ── 폰 전용 인증의 Engine ── webhook_events 후보
                                              └─ Hub 오늘 연락 → 운영자 확인 → crm_activities
```

- **공유하는 것은 상태 어휘와 영수증 UX**다. 할 일/정리 전 입력은 기존 `capture_quick_input_v1`, 메모는 `journal_workflow_v1`, 폰 연락은 기존 `phoneEventDedupeKey` 및 `(workspace_id, source, provider_event_id)` 유니크 계약을 유지한다. 세 객체를 한 테이블에 합치지 않는다.
- Mac/PWA 빠른 입력은 최초 로컬 저장 때 UUID 요청 ID를 만든다. 재시도는 **같은 불변 페이로드와 같은 ID**를 보낸다. 서버 도달 여부가 불확실한 항목은 먼저 같은 ID로 영수증을 확인한다. 원 요청이 확정되기 전에는 수정본을 새 명령으로 자동 전송하지 않는다. 확정 후의 수정은 해당 정본의 편집 흐름으로, 서버에 도달하지 않은 것으로 확인된 초안의 수정은 새 ID의 새 명령으로 처리한다. 전화 사건은 현재 서버의 결정론적 키를 그대로 쓴다.
- `saved`/`duplicate`도 목적지 ID·영속화 여부가 맞을 때만 완료로 인정한다. `preview`, 읽기 `status: error`, HTTP 실패, 시간 초과, 알 수 없는 응답은 완료가 아니다. 요청이 서버에 도착했는지 모르면 새 ID를 만들지 않고 같은 ID로 확인·재시도한다.
- 전송함 상태는 `기기에 보관됨`·`전송 중`·`Hub에 저장됨`·`확인 필요` 네 가지다. `확인 필요`는 인증 만료, 검증 오류, 요청 충돌처럼 자동 재시도로 해결되지 않는 경우다. 미전송 항목은 자동 삭제하지 않는다. 영수증을 받은 항목의 원문 로컬 복사본은 7일 뒤 지우되 정본의 삭제로 해석하지 않는다.
- Mac 전송함은 `UserDefaults`의 현재 UI 상태와 분리된 영속 저장소를 쓴다. 갤럭시 공유 전송함은 IndexedDB를 쓴다. 브라우저 Background Sync는 지원 범위와 실행 횟수가 제한되므로 전경 재시도가 필수다. [MDN Background Sync](https://developer.mozilla.org/en-US/docs/Web/API/Background_Synchronization_API), [MDN 오프라인 동작](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation).

## 5. 인증과 배포 경계

- PWA는 현재 운영자 로그인 쿠키와 same-origin Hub write guard를 사용한다. Mac 앱과 MacroDroid에는 `COM_MOON_HUB_WRITE_SECRET`·Supabase service-role 키를 넣지 않는다.
- Mac 앱에는 **범위가 제한된 기기 연결**을 새로 설계한다. 로그인된 Hub 설정에서 일회용 연결 코드를 발급하고, Mac이 이를 교환해 받은 기기 자격을 Keychain에 저장한다. 서버에는 자격의 해시·허용 범위·만료·폐기 상태를 보관하고 설정에서 폐기할 수 있게 한다. 허용 범위는 빠른 입력, 기존 Hub 오늘 읽기 모델, 할 일 완료 상태 변경, 연결된 메모 저장/읽기뿐이다. 일반 Hub read 라우트를 열거나 서버 간 비밀키를 기기에 복사하지 않는다. 코드 교환 경로는 자체 인증·횟수 제한을 갖춘 명시적 예외여야 한다. 코드·자격의 만료 및 갱신 세부는 Mac 연결 하위 스펙에서 확정한다.
- MacroDroid는 현행 `COM_MOON_PHONE_INTAKE_SECRET`만 사용한다. 클라우드 Engine에 현재의 `phone-events` 경로를 배포하고 해당 시크릿·서울 Supabase 서비스 자격을 서버에만 둔다. 폰의 목적지를 Mac Tailscale 주소에서 배포 주소로 옮기기 전, 401/중복/고객 대조/저장 왕복을 확인한다.
- `docs/README.md`에는 2026-09-20 확인 당시 Vercel 환경 변수 0개로 기록돼 있다. 배포 직전 상태를 다시 확인한다. 연결에 필요한 Hub 로그인 3값, Hub↔Engine 비밀키, Engine·Supabase 설정을 모두 준비하기 전에는 앱을 `연결됨`으로 표시하지 않는다.

## 6. 단계별 작업과 검증

이 문서는 공통 계약의 설계다. 구현 계획은 서로 독립적으로 검토할 수 있는 세 묶음으로 나눈다.

1. **클라우드 착지와 폰 재시도**: Engine 배포·설정, MacroDroid 영속 큐의 실기기 가능성 검증, Mac 잠자기·폰 재부팅·중복 전송 시 후보 한 건과 영수증 확인. 기존 Mac 직결 경로는 전환 전까지 현재 상태로 표시한다.
2. **갤럭시 공유 전송함**: 설치형 PWA 수신, 오프라인 로컬 보관, 전경 재시도, URL 본문 제거, 390px 저장/오류 상태 확인. 서비스 워커 준비 전에는 현행 GET 공유 경로를 유지한다.
3. **Mac 펫 연결**: 제한된 기기 인증, 빠른 입력·메모 영수증, 기존 Hub 오늘 읽기 모델과 완료 토글, 재시작 복원, 기존 로컬 기록 선택 가져오기, Hub 결과 딥링크. 일정의 양방향 편집은 별도 설계로 둔다.

통과 기준은 각 묶음에서 동일하다. **중복 정본 0건, 미확인 저장을 완료로 표시한 경우 0건, 재시작 후 미전송 원문 유실 0건, 전화 후보의 무승인 공식 기록 0건.** 로컬·클라우드 미설정은 실제 데이터와 섞지 않고 `preview`/연결 필요 상태로 표현한다. 실기기·실제 배포 검증 전에는 수치 목표 달성을 선언하지 않는다.
