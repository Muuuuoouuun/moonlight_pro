## 1. 목적과 확정된 뜻

오른쪽 아래 빠른 메모 위젯에서 생각을 적는 일과 AI에게 일을 요청하는 일을 명확히 나눈다. 요청은 대상·가능한 동작·접수 상태를 보여 주고, 결과를 원래 업무 기록에 연결한다.

운영자가 말한 “프로젝트 만들어줘”는 **Moonlight 안의 프로젝트 기록 생성**이다. 코드 저장소나 폴더 생성은 Mac 작업의 별도 요청이다. “프로젝트 진행 상황”도 기본적으로 Moonlight 프로젝트·할 일 기록을 조회한다. 저장소의 개발 진행 상황을 보고 싶다면 사용자가 Mac 작업 대상을 선택한다.

현재 확인한 기반: `QuickMemo`는 공통 셸에 한 번 배치되고, 메모 저장·콘텐츠 소재 보내기·AI 액션 추출 뒤 할 일 등록을 제공한다. 프로젝트는 `POST /api/hub/projects`와 `ProjectCreateDrawer`를 사용하며, 프로젝트명과 업무 분야가 필수다. Agent API는 프로젝트 조회와 제한된 task 명령을 제공하지만 `create_project` Agent 명령은 없다. Codex worker는 등록된 Git 저장소에서만 작업하고, 로컬 스킬 요청서는 Mac의 Claude Code·Codex가 별도로 처리한다. 이들이 항상 연결돼 있거나 자동으로 실행된다고 표시하지 않는다.

## 2. 접근 비교

| 접근 | 이점 | 비용·위험 | 판단 |
| --- | --- | --- | --- |
| **기존 위젯 안 `메모 | 요청`, 요청 안 `앱 안에서 | Mac 에이전트`** | 새 전역 버튼 없이 장소 하나. 저장과 실행의 의미, 즉시 처리와 비동기 작업의 차이가 보인다 | 위젯의 작은 면적을 지켜야 한다 | **권장** |
| 입력창 하나에서 AI가 메모·조회·쓰기·Mac 실행을 자동 판별 | 입력이 한 번이다 | 오분류 시 예상 밖 저장·실행, 상태 설명이 어렵다 | 사용하지 않음 |
| 별도 전역 에이전트 버튼·화면 | 넓은 작업 공간 | 이미 많은 AI 진입점과 중복되고 빠른 요청 동선이 길어진다 | 상세 이력 화면만 재사용 |

## 3. 화면과 핵심 흐름

접힌 48px 위젯 버튼은 한 개를 유지한다. 펼치면 첫 줄에 `메모 | 요청`을 `SegmentedControl`로 표시한다. 기본 탭은 `메모`이며, 기존 메모 본문·범위·저장 흐름은 유지한다. 현재 `콘텐츠 소재로 보내기`와 `AI 액션 추출`은 메모 작성 본문에 계속 늘어놓지 않고 `요청`에서 원문을 가져오는 선택 동작으로 수렴시키는 방향을 권장한다. 기존 기능·초안·저장 경로는 제거하지 않는다.

`요청` 탭의 두 경로는 `앱 안에서 | Mac 에이전트`로 명시한다. 모드를 바꾸면 입력 원문을 보존하고, 다른 모드의 요청을 자동 제출하지 않는다. 두 모드의 예시 문구는 서버의 현재 capability에 맞게 제한한다. 에이전트 이름을 먼저 고르는 화면은 두지 않는다.

### 앱 안에서

- **조회:** “A 프로젝트 진행 상황 알려줘” → 같은 범위의 프로젝트 후보를 확인 → 프로젝트·연결 할 일의 실제 최신 기록을 읽음 → 진행 상태, 막힌 항목, 다음 행동, 자료 기준 시각과 프로젝트 링크를 짧게 보여 줌. 동명이면 대상 선택을 먼저 한다. read API의 HTTP 200 `{status:"error"}`는 빈 결과가 아니라 읽기 실패로 표시한다. `preview`·`partial`도 구별한다.
- **변환:** “이 메모를 할 일로” 또는 “콘텐츠 소재로” → 사용자가 현재 메모 원문이나 저장된 메모를 명시적으로 선택 → 제목·본문·출처의 초안을 보여 줌 → 기존 저장 경로로 한 번에 저장하고 재조회. 단순 AI 후보는 `저장됨`으로 표시하지 않는다.
- **프로젝트 생성:** “새 프로젝트 만들어줘: …” → 문장에서 프로젝트명과 설명 후보만 추출 → 기존 `ProjectCreateDrawer`를 미리 채워 연다. 업무 분야와 개인/회사 범위를 확인한다. 분야를 추측해 확정하지 않고, 없거나 불명확하면 사용자가 고른다. `프로젝트 만들기`를 눌러 기존 Hub write guard·PMS 저장 경로가 `saved` 또는 `duplicate`를 반환하고 해당 ID를 재조회했을 때만 생성 완료로 표시한다. 중복·충돌·저장 실패에는 원문과 초안을 남긴다.

### Mac 에이전트

- 등록된 코드 저장소 대상이면 기존 Codex job의 `read`·`draft`·`apply` 중 실제 허용된 모드를 선택해 접수한다. 실행 전 대상 저장소와 원하는 산출물을 확인하고, job ID·상태·결과 링크를 보여 준다. `apply`는 기존 분리 worktree 조건을 따른다.
- 폴더·영수증 같은 로컬 스킬 일은 기존 스킬 요청서로 기록하고 ID와 수행 범위·완료 증거를 보여 준다. 요청서 저장은 Mac 실행이나 task 완료를 뜻하지 않는다. Claude Code·Codex의 로컬 스킬이 처리한 receipt를 받은 뒤에만 결과 상태를 바꾼다.
- 현재 연결된 실행기가 없거나 해당 작업을 지원하지 않으면 `실행할 수 없음`과 이유를 표시한다. 사용자가 명시적으로 대기 저장을 선택한 경우에만 `실행 전`으로 접수한다. 새 원격 Mac 제어 경로, 임의 cwd·shell 명령 입력, Office 도구 실행, 외부 발송은 이 위젯 설계에 포함하지 않는다.

## 4. 책임·데이터 경계

위젯은 입력과 결과 확인을 맡는다. 앱 안 조회는 Hub read BFF와 repositories, 앱 안 쓰기는 기존 Hub write guard와 프로젝트·메모·task 저장 경로를 재사용한다. AI가 문장을 구조화하더라도 권한·workspace·scope·필수값은 서버와 기존 생성 화면이 판정한다. 저장된 개인 메모 전체를 회사 프로젝트나 Mac job 문맥으로 자동 전달하지 않는다. 선택한 발췌 또는 저장 ID만 명시적으로 전달한다.

Mac 경로는 현재 지원하는 job 또는 스킬 요청서 어댑터로만 보낸다. 요청 원문, 대상 ID, actor, idempotency key, 접수 ID와 결과 receipt를 연결한다. 서버가 저장을 확인하지 못한 상태와 실행 결과를 확인하지 못한 상태를 분리한다. job·스킬 요청의 상세 이력은 기존 작업·실행 화면으로 연결하며 위젯 안에는 현재 요청 하나의 핵심 상태만 둔다. 새 범용 대화 이력이나 제2의 작업 원장을 만들지 않는다.

Office는 판단·초안·검토만 담당한다. 위젯에서 AI 도움을 사용하더라도 Office의 문장이나 추천을 실행 receipt로 취급하지 않는다. 업무 변경·외부 발송은 운영자 행동과 기존 인증·저장 계약을 거친다.

## 5. 상태·오류와 모바일

`입력 중`, `초안 준비`, `저장 확인 중`, `저장됨`, `실행 전`, `진행 중`, `완료`, `확인 필요`, `읽기 실패`를 서로 다른 문장으로 표시한다. 결과 카드에는 출처와 확인 시각 또는 job/요청서 ID를 둔다. 앱 안 조회 실패는 재시도 가능하게 하고, 쓴 뒤 응답이 유실되면 같은 요청 ID로 receipt·원장 재조회를 먼저 한다. 이중 클릭이나 탭 전환으로 쓰기를 중복 제출하지 않는다. Mac 실행 중 위젯을 접거나 페이지를 옮겨도 접수 ID로 상태를 다시 찾을 수 있어야 한다.

데스크톱은 현재 360px 패널 안에서 입력·첫 행동·상태 한 줄을 우선한다. 상세 필드와 긴 결과는 기존 Drawer/해당 화면으로 보낸다. 모바일은 기존 하단 시트·키보드 회피·Escape/포커스 계약을 유지하고, 390px 첫 화면에서 모드와 입력·보내기가 보이게 한다. 터치 대상 44px, 입력 16px, 가로 세그먼트 유지. `TruthBadge`·`LifecycleBadge`와 토큰을 사용하고 상태를 색만으로 표현하지 않는다. 새 전역 진입점이나 알림 배지는 추가하지 않는다.

## 6. 구현 순서와 검증 기준 — 권장

1. 위젯의 탭과 모드·초안 분리. 기존 메모 저장, 액션 추출, 소재 보내기의 경로와 단축키를 보존한다.
2. 앱 안 요청의 대상 선택·조회·프로젝트 생성 초안 연결. 프로젝트는 기존 생성 폼에서만 확정한다.
3. 메모 변환의 명시적 원문 선택·출처 연결·저장 재조회.
4. 지원 가능한 Codex job과 로컬 스킬 요청서 접수·상태 링크. 연결·권한·Mac 오프라인 상태를 기능별로 노출한다.

검증은 ① 저장 전 프로젝트가 생성되지 않음 ② 이름/분야/범위 확인 뒤 한 건만 생성되고 ID 재조회 성공 ③ 200 오류 봉투를 빈 진행 상태로 보이지 않음 ④ 개인 메모가 다른 범위의 job 문맥에 무단 포함되지 않음 ⑤ Mac 오프라인·요청서 저장만 된 상태를 완료로 표시하지 않음 ⑥ 접기·새로고침·재시도에서 입력과 접수 ID가 보존됨 ⑦ 데스크톱·390px 모바일, 키보드·포커스·중첩 Drawer가 정상임을 실제 화면에서 확인하는 것으로 한다.

## 7. 검토할 경계

운영자가 동의한 것은 위젯 안의 역할 분리와 Moonlight 프로젝트 생성 방식이다. `앱 안에서 | Mac 에이전트`의 최종 문구, 현재 메모 액션 두 개의 이동 방식, Mac 작업의 첫 지원 대상 범위는 이 설계의 권장안이다. 구현 전 실제 worker 등록 상태와 사용 가능한 프로젝트·스킬 종류를 확인하고, 지원되지 않는 예시 문구는 화면에 내지 않는다.
