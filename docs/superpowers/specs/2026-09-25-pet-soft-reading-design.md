# 펫 읽기 배경의 경계와 묶음 정리

## 관계

운영자의 2026-09-25 22:12 스크린샷 피드백(텍스트 박스 배경을 더 자연스럽게)을 반영한다. 기존 prism/readability 설계의 읽기 바탕 표현만 조정한다. 투명한 기본 유리, 흰 글자, 누름·드래그에만 나오는 캐릭터색, 외곽 프리즘과 기능 동작은 유지한다.

## 적용

- 제목과 오늘 탭은 하나의 읽기 배경을 공유한다. 선택 탭의 얇은 윤곽과 밝기 차이는 유지한다.
- 할 일 건수와 행은 같은 배경을 사용한다. 바탕은 스크롤 뷰포트에 고정하고, 짧은 목록에서는 실제 내용 높이까지만 채운다.
- 네이티브 읽기 재질과 캐릭터 색상층에 동일한 9-slice 알파 마스크를 적용해 8~12pt 가장자리에서만 투명도가 이어진다. 마스크 이미지는 캐시한다. 텍스트·포커스 링·클릭 영역에는 마스크나 흐림을 적용하지 않는다.
- 검정 보조층은 일반 상태에서 28%에서 20%로 낮춘다. 버튼·입력에는 선명한 컨트롤 경계를 유지한다. 투명도 감소·대비 증가에서는 경계 페이드를 끄고 기존 보호 바탕을 유지한다.
- 재질 구현 근거: Apple의 [NSVisualEffectView.maskImage](https://developer.apple.com/documentation/appkit/nsvisualeffectview/maskimage) 공개 API는 알파 채널로 재질 표시 영역을 조절한다. 화면 캡처와 비공개 필터는 사용하지 않는다.

## 검증

- `swift build -j 2` 및 `.app` 번들 `build_and_run.sh --verify` 성공.
- `swift run -j 2 MoonlightPetPreview --self-check`: 광학 렌더링·투명 중심·누름/드래그 복귀·레이아웃·기존 로컬 기록 검사 통과.
- CUA 실제 앱에서 할 일 18개, 스크롤 전후의 고정 읽기 배경, 일정 전환, 빈 일정의 투명 여백 확인. 업무 데이터는 편집하지 않았다.
- 첫 화면 검사에서 목록 높이 preference가 다른 하위 뷰의 기본값 0으로 덮여 바탕이 한 행 높이로 줄어드는 현상을 발견했다. reducer를 `max`로 고쳐 다행 목록·스크롤 재검사에서 전체 읽기 영역을 확인했다.
- CUA의 개별 창 캡처는 투명 영역을 흰 바탕으로 보여 주므로 실제 바탕화면 위 최종 색감은 운영자의 실사용 화면에서 추가 조정할 수 있다.
