# 갤럭시 핵심 동반 앱 — 기획·실행 준비안

> 상태: **DRAFT / 검토용** (2026-09-26). 운영자가 첫 출시 범위를 `핵심 동반 앱부터`로 선택했다. 이 문서의 배포 방식·세부 동작·일정은 권장안이며 구현 확정이 아니다.
> 상위 정본: [`operator-workflow-profile.md`](../../operator-workflow-profile.md), [`2026-07-13-moonlight-personal-operator-os-deep-design.md`](2026-07-13-moonlight-personal-operator-os-deep-design.md), [`2026-09-24-revenue-four-tabs-design.md`](2026-09-24-revenue-four-tabs-design.md), [`DESIGN.md`](../../../DESIGN.md).
> 이어받는 설계: [`2026-09-25-desktop-mobile-capture-continuity-design.md`](2026-09-25-desktop-mobile-capture-continuity-design.md). 그 문서의 인증·전송 세부는 아직 DRAFT다. 이 문서는 갤럭시 제품 범위와 실행 순서를 정리하며 기존 승인 상태를 승격하지 않는다.

## 1. 목적과 범위

운영자 한 사람이 외부에 있을 때 **놓칠 내용을 즉시 보관하고, 오늘 할 행동과 연락 후보를 확인·처리**하는 갤럭시 앱이다. 한 손으로 짧게 끝나는 입력이 먼저이며, 자세한 편집과 전체 운영 판단은 기존 Hub로 이어진다. 성공은 설치 수가 아니라 다음 네 가지 실측으로 판단한다.

1. 공유 또는 한 줄 입력을 390px 첫 화면에서 바로 시작할 수 있다.
2. 앱 종료·오프라인·재부팅·Mac 잠자기 뒤에도 **기기에 보관됐다고 확인한 원문**이 사라지지 않는다.
3. 서버 영수증 없이 `Hub에 저장됨`을 표시하지 않고, 같은 요청의 재시도로 정본이 중복되지 않는다.
4. 전화·문자·카톡 사건은 운영자 승인 전 `crm_activities`가 되지 않는다. 누락·수신 불능 조건은 화면과 설정 가이드에 드러난다.

### 첫 출시의 실제 사용 장면

| 순간 | 첫 출시에서 해야 할 일 | 완료 판정 |
| --- | --- | --- |
| 웹·카톡·인스타에서 링크/문구 발견 | 시스템 공유 → Moonlight → `할 일` 또는 `정리 전` | 로컬 보관 후 서버 영수증 또는 전송 대기 표시 |
| 이동 중 생각남 | 앱을 열자마자 한 줄 입력 | 위와 같은 영수증·재시도 규칙 |
| 오늘 할 일 확인 | 오늘 첫 행동과 기한 있는 할 일 확인, 완료 | 서버 확인 후 완료 반영; 읽기 실패를 빈 목록으로 표시하지 않음 |
| 고객 통화·문자·카톡 알림 발생 | 자동화 앱이 감지한 사건을 연락 후보로 전송 | 정상 저장/정책상 무시/설정 오류/재시도 대기를 구별 |
| 연락 후보 정리 | `오늘 연락 > 기록할까요`에서 기록 또는 버림 | 기록 시 기존 원자 RPC와 공용 기록창 사용 |

첫 화면은 **빠른 입력과 첫 행동**을 우선한다. 연락 후보·전송 대기·설정은 짧은 진입점으로 둔다. 전체 Hub 내비게이션, 거래 보드, Studio, Office 회의실 등은 이 출시의 새 모바일 화면으로 복제하지 않는다. 기존 반응형 Hub 링크는 필요한 상세 작업에 그대로 사용할 수 있다. 휴대폰 푸시는 운영자 프로필의 후순위 결정을 유지한다.

## 2. 확인된 사실과 문서 정정 대상

| 상태 | 근거 | 이번 계획의 해석 |
| --- | --- | --- |
| 구현 | `apps/hub/public/manifest.json`의 GET `share_target`; `hub-app.jsx`의 쿼리 → 빠른 입력; `quick-capture.jsx`의 `/api/hub/inbox` | 온라인 공유 입력의 시작점. 앱 설치·갤럭시 실기기 성공은 미검증 |
| 구현 | `apps/engine/app/api/intake/phone-events/route.ts`, `phone-capture-http.ts`, Hub `record-candidates.jsx` | 연락 후보 서버·검토 UI의 시작점. 실제 폰 연결은 대기 |
| 미구현 | 공유 입력의 서비스 워커·IndexedDB 영속 전송함, 전경 재시도, 서버 영수증 복원 | 현재 Quick Capture 세션은 메모리에만 남아 앱 종료를 견디지 못함 |
| 미검증 | 상시 접근 가능한 Engine 배포, MacroDroid의 영속 사건 큐, 잠든 Mac·재부팅·오프라인 왕복 | 현재 가이드는 Mac Engine의 Tailscale 주소로 직접 보내며 기본 매크로는 실패 시 버림 |
| 문서 충돌 | 9/24 모바일 스펙의 `2단계 구현` 문구, `docs/README.md`의 텔레그램 3중 버퍼, 9/25 연속성 DRAFT §2 | 구현으로 간주하지 않는다. 텔레그램 버퍼를 재도입하지 않고 문서 상태를 별도 정정 |

기본 폰 intake는 **등록 고객과 정확히 맞는 사건만** 후보화한다. `captureUnmatched` 옵션의 미등록 번호 후보 기능은 코드에 있지만 기본 동작이 아니며, 활성화 시 번호 보관 정책이 달라지므로 별도 승인 항목으로 둔다. 카톡은 수신 알림 미리보기만 범위에 있고 발신 메시지·무음방·열린 대화의 누락을 막는다고 주장하지 않는다.

## 3. 배포 형태 선택

| 안 | 장점 | 비용·한계 | 권장 시점 |
| --- | --- | --- | --- |
| **A. 설치형 PWA + 현행 MacroDroid** | Next.js Hub·로그인·후보 UI를 재사용하고 공유 시트와 한 줄 입력을 가장 빨리 실측 | Android 위젯·빠른 설정 타일·안정적 전화 센서 처리는 별도 앱/자동화가 필요 | **첫 출시 권장** |
| B. 얇은 Kotlin Android 캡처 어댑터 + Hub 모바일 화면 | Android Share Intent, WorkManager 영속 재시도, 위젯/타일을 한 앱에서 제어 가능 | 앱 프로젝트·서명·기기 인증·권한·업데이트 운영이 늘어남 | MacroDroid 큐가 실패하거나 네이티브 진입점의 실사용 가치가 확인될 때 |
| C. Hub 전체를 네이티브로 재작성 | 장기적으로 Android UI를 자유롭게 설계 가능 | 기존 단일 운영자 제품의 전체 기능을 중복 구현·검증 | 이번 계획 범위 밖 |

TWA는 기존 PWA를 Android 앱 패키지로 여는 배포 방법이며, 자체적으로 전화·문자 접근이나 오프라인 영수증을 해결하지 않는다. Capacitor/React Native 도입도 같은 필수 계약을 먼저 구현한 후 다시 판단한다. Next.js App Router의 인증 미들웨어·서버 API를 정적 웹 자산으로 그대로 내보내는 포장은 전제하지 않는다.

**전환 기준:** 실기기에서 MacroDroid가 `HTTP 전 영속 보관 → 응답별 처리 → 재부팅 후 재시도`를 안정적으로 못 하거나, 통화 직후 입력·위젯·타일이 첫 출시의 핵심 행동을 유의미하게 단축할 때 B를 설계한다. 단순히 APK 아이콘이 필요하다는 이유로 데이터 계약을 갈아엎지 않는다.

Android의 백그라운드 화면 실행 제한 때문에 9/24 스펙의 `통화 종료 즉시 플로팅 팝업`을 보장 동작으로 잡지 않는다. 사용자가 여는 알림/앱 진입을 먼저 검증한다. Quick Settings 타일과 홈 위젯은 네이티브 구성요소가 필요하며, 타일에서 클립보드를 자동 읽는 것도 Android의 백그라운드 클립보드 제한을 받는다. 개인용 캡처 APK가 전화·SMS 기록 권한을 Play 공개 배포에서 쓸 수 있다고 가정하지 않는다.

## 4. 첫 출시 화면·상태 계약

| 화면/진입점 | 꼭 보여 줄 것 | 피해야 할 오인 |
| --- | --- | --- |
| 홈 | 빠른 입력, 오늘 첫 행동, 전송 대기 건수, 연락 후보 진입 | 빈 응답을 `할 일 없음`으로 해석 |
| 공유 수신 | 제목·본문·링크 확인, 목적지 `할 일 / 정리 전`, 저장 한 동작 | 공유 원문을 오래 URL 쿼리에 남김 |
| 전송 대기 | 원문·목적지·로컬 저장 시각·상태·재시도·폐기 | HTTP 타임아웃을 성공으로 표시하거나 원문 자동 삭제 |
| 오늘 | 기한 있는 다음 행동과 완료, 상세로 이동 | 네트워크 실패 시 완료를 낙관적으로 확정 |
| 기록할까요 | 고객·채널·시각·미리보기, 기록/버림, 잘못 매칭된 경우 | 후보를 공식 활동으로 취급 |
| 연결/설정 | 현재 로그인·Engine 도달 상태, 마지막 성공, 권한과 배터리 설정 점검 | 맥이 잠든 현재 경로를 상시 연결로 표시 |

빠른 입력의 전송 상태는 `기기에 보관됨` → `전송 중` → `Hub에 저장됨`이며, 인증 만료·검증 오류·충돌은 `확인 필요`다. `saved` 또는 같은 요청의 `duplicate`와 **목적지 ID**를 확인한 경우에만 완료다. 폰 사건은 별도 계약으로 `saved`(201)·`duplicate`(200)·정책상 `ignored`(200)만 정상 처리하며, `ignored`를 CRM 저장으로 표현하지 않는다. `preview`, Hub read의 HTTP 200 + `{status:"error"}`, 타임아웃·알 수 없는 응답은 성공이 아니다. 미전송 원문은 자동 폐기하지 않는다. 빠른 입력은 앱 종료 뒤에도 같은 요청 ID와 **불변 페이로드**로 확인·재시도하고, 폰 사건은 같은 원본 필드로 서버의 결정론적 중복 키를 재현한다.

모바일 UI는 `DESIGN.md`의 토큰과 Hub 프리미티브를 따른다. 390×844 첫 화면에서 입력과 첫 행동이 보이고, 터치 타깃 44px·입력 글자 16px을 지킨다. 공유/캡처 바텀 시트는 `Drawer presentation="compact"`, 상태 표시는 기존 배지·한 개의 `aria-live` 문맥을 사용한다. 키보드가 올라온 상태에서도 저장 버튼과 실패 원문이 가려지지 않아야 한다.

## 5. 데이터·인증·개인정보 경계

```text
갤럭시 공유·한 줄 입력 → PWA 로컬 전송함 → 인증된 Hub 빠른 입력 → 할 일/정리 전 정본
                                 ↑ 서버 영수증(saved/duplicate) ────────┘

갤럭시 연락 사건 → 자동화 영속 큐 → 상시 Engine phone-events → 기록 후보
                    ↑ 응답별 영수증 ───────────────────────┘
기록 후보 → 운영자 확인 → 기존 연락 기록 RPC → crm_activities
```

- **빠른 입력:** 기존 `/api/hub/inbox` → `capture_quick_input_v1`의 `idempotencyKey`, `saved`/`duplicate` 영수증을 재사용한다. `할 일`과 `정리 전`을 다른 임의 테이블로 합치지 않는다. 서버 도달이 불명확하면 같은 ID로 재확인한다.
- **공유 수신:** 우선 현행 GET 쿼리를 로컬에 보관한 직후 제거해 URL·방문 기록 노출을 줄인다. 설치형 PWA의 POST Share Target + 서비스 워커 + IndexedDB 전환은 실제 갤럭시에서 설치·활성화·오프라인 재실행을 통과한 후 켠다. Android 공유의 `url` 필드는 비어 있을 수 있으므로 `text`·`title`의 링크도 해석하고 원본 필드를 보존한다. 서비스 워커는 앱 셸을 오프라인에 준비하되 인증된 업무 API 응답을 무심코 캐시하지 않는다. 브라우저 저장 공간 부족·사이트 데이터 삭제 시 로컬 원문이 사라질 수 있으므로 저장 실패를 성공처럼 표시하지 않고 보관 상태를 점검한다.
- **폰 사건:** 기존 `phoneEventDedupeKey`, `webhook_events`의 `(workspace_id, source, provider_event_id)` 중복 계약과 `saved`/`duplicate`/`ignored` 결과를 유지한다. 후보를 `crm_activities`로 옮길 때만 운영자 확인과 `record_contact_outcome_v1`을 쓴다.
- **인증:** PWA는 운영자 로그인 쿠키와 same-origin Hub write guard를 사용한다. 휴대폰에 `COM_MOON_HUB_WRITE_SECRET` 또는 Supabase service-role 키를 넣지 않는다. MacroDroid는 기존 범위가 제한된 `COM_MOON_PHONE_INTAKE_SECRET`만 쓰고, 분실 시 회전한다. 네이티브 어댑터를 만들 때는 장기 고정 비밀값 복사를 기본으로 하지 말고 기기 등록·폐기·범위 제한을 하위 설계에서 확정한다.
- **개인정보:** 기본은 등록 고객 일치 사건만 후보화하고, 고객이 아닌 사건은 내용 없이 폐기한다. 기존 2일 노출·7일 원문 정리 규칙을 실측한다. 미등록 번호 후보·원문 전체 보존·녹음·AI 분석은 각각 보관/동의/비용 결정을 거쳐야 한다. PWA IndexedDB 원문은 잠금 해제된 기기/같은 출처에 남는 데이터로 취급하며 기기 분실·로그아웃 절차에 포함한다.
- **배포:** 서울 Supabase 운영 원장과 상시 접근 가능한 Hub/Engine, HTTPS, 운영자 로그인 3값, Hub↔Engine 비밀키, Engine 폰 intake 시크릿의 실제 배포 상태를 먼저 확인한다. 2026-09-20 당시 Vercel 환경 변수는 0개였으므로 현재 상태 재확인이 필요하다. 연결 전에는 명시적으로 `연결 필요`/`preview`를 보여 준다.

## 6. 실행 묶음과 통과 기준

| 순서 | 묶음 | 산출물 | 통과 기준 |
| --- | --- | --- | --- |
| M0 | 운영 주소·인증·실기기 기준선 | HTTPS Hub/Engine, 운영자 로그인, 폰 시크릿, Galaxy 버전/브라우저/배터리 설정 표, 현행 GET 공유·후보 왕복 기록 | Mac을 잠재워도 서버 접속; 401·중복·저장/읽기 실패를 구별 |
| M1 | 폰 사건 신뢰성 | MacroDroid 영속 큐 시제품 또는 B 전환 결론, 응답별 분기, 마지막 성공/실패 상태 | 오프라인·Mac 잠자기·폰 재부팅·연속 사건 뒤 후보 한 건 또는 정책상 `ignored`; 유실 0, 중복 정본 0 |
| M2 | 공유/직접 입력 신뢰성 | PWA 로컬 전송함, URL 정리, 전경 재시도, 서버 영수증, 보관함 UI | 앱 강제 종료·로그인 만료·타임아웃·중복 공유 뒤 원문 보존, 잘못된 성공 0 |
| M3 | 모바일 처리 루프 | 오늘 첫 행동·완료·연락 후보 검토의 390px 경로와 상세 딥링크 | 입력→오늘 확인→완료, 폰 사건→후보→공식 기록을 운영자 실데이터로 왕복 |
| M4 | 필요 시 Android 어댑터 | Kotlin Share Intent/WorkManager, 인증·폐기, 위젯/타일은 별도 사용성 판단 | M1/M2의 영수증·보존 계약을 그대로 통과하고 기존 후보 중복 없음 |

M1과 M2는 M0가 준비되면 병행 가능하다. M3는 두 입력이 실제로 도착하는 경로 위에서 검증한다. M4는 기본 일정에 포함하지 않는다. 각 묶음은 `설계 승인 → 작은 구현 계획 → 코드/테스트 → 실기기 검증 → 운영 전환`으로 닫는다. 실기기·실제 배포 검증 전에는 누락 0건을 달성했다고 표기하지 않는다.

관측은 원문을 추가로 복제하지 않고 `로컬 보관 성공/실패`, `전송 대기 건수와 가장 오래된 시각`, `saved/duplicate/ignored/401/5xx`, `후보 검토 완료`의 상태·건수로 한다. 앱에는 마지막 영수증과 마지막 오류를 볼 수 있게 하고, 원문을 로그·분석 도구·잠금 화면 알림에 싣지 않는다. 출시 직전에는 도메인·HTTPS·매니페스트 설치 가능성·로그인 쿠키·Engine 헬스·시크릿 회전·분실 폰 대응·업데이트/롤백 절차를 한 번의 체크리스트로 확인한다.

### 필수 실기기 시나리오

- Chrome·카카오톡·인스타그램에서 텍스트/링크/제목 공유; 긴 글·이모지·줄바꿈·따옴표·중복 탭·로그인 만료.
- 비행기 모드에서 공유 후 앱 강제 종료/재시작, 네트워크 복귀, 서버는 저장했으나 응답만 잃은 경우, 저장 도중 목적지 변경 시도.
- 통화 수신/발신/부재중, 문자 수신, 카톡 알림, 동명이인·미등록 번호·개인 연락처, 연속 사건, 알림 접근 해제·절전·재부팅.
- Mac 잠자기·Engine 502/503·시크릿 오입력·계정 로그아웃·Supabase 읽기 실패, 후보 승인/버림 후 재조회.
- 390px과 실제 기기 화면에서 한 손 조작, 소프트 키보드, 스크린리더/큰 글자, 44px 타깃, 배터리 소모와 전송 대기 표시.
