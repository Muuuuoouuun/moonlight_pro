# 보고서·인사이트 내용 품질 개발

사용자 지시(2026-10-01): 시각적 장식보다 내용·구성·텍스트를 개발한다. 10-01 연결 완성 스펙의 권한·원문·receipt·미검토 경계를 유지한다. 역할 카드 말투 동결은 유지하며 업무별 산출물의 편집 기준을 개선한다.

## 실제 문제와 목표

실제 회사 보고서는 연락 활동 1건을 고객 1명으로 바꾸고 신규 딜을 신규 리드로 표현했으며, 측정된 0과 미측정을 혼동했다. 비교·프로젝트 우선순위·대기 딜 데이터 없이 정체 원인을 추측했다. 리서치는 인용문 존재와 위치를 확인했지만 일정→완료, 포함 사례→전체 원인, 특정 API 단가→전체 작업 비용으로 주장 범위를 확대했다. 정확한 근거에서 독자의 판단까지 이어지는 글이 목표다.

## 실행 설계

1. **주간 입력**: 같은 scope/timezone의 직전 동일 7일도 읽고 현재/이전 값을 분리한다. 비교 읽기 실패는 현재 사실을 지우지 않는다. 미측정·정의 불일치·0 분모는 비교 불가로 남긴다. 사람 수와 활동 수, 계약과 입금, 단계 이동과 딜 수, 전체 workspace 행동과 개인 범위를 명시한 지표별 근거표를 전달한다. 기간 밖 목표는 현재 연결 목표이며 이번 주 성과가 아니다.
2. **주간 글**: 핵심 판단 → 확인한 기록/비교 → 해석과 다른 설명 → 지금 고를 행동 → 확인 한계. 숫자만 나열하거나 근거 없는 정체·원인을 만들지 않는다. 회사는 거래 진행의 의미, 개인은 목표·집중과 완결의 의미를 다룬다. 기록이 적으면 판단 보류와 최소 관측을 제안하고 업무를 억지로 늘리지 않는다. 기존 초안+원문 대조 검수 두 단계에 이 기준을 적용한다.
3. **리서치 글**: 승인된 브랜드 편집 정체성만 선별한다. 사실은 하나의 주장과 그 주장을 뒷받침하는 짧은 원문 인용을 짝짓는다. 수치 분모·발표자·시점·예정/실행·제품 제공 조건을 보존한다. 해석은 사실 → 작동 경로 → 독자 효용/부담 → 적용/비적용 조건으로 쓴다. 반대 설명과 다음 확인을 남긴다. 원고는 하나의 논지와 실제 독자의 판단에 집중한다.
4. **리서치 검수**: 자동 재시도 없이 원문·초안 대조 편집 1회를 추가한다. 같은 모델의 편집 검수이며 독립 사실 인증이 아니다. 검수본도 기존 인용/locator 검증을 통과해야 저장한다. 두 호출 사용량·추론 토큰을 합산하고 모든 단계의 실패 비용을 보존한다. 결과 불확실이면 기존 paid claim을 유지한다. 기존 초안/승인 기록을 덮어쓰거나 같은 원문 버전을 재과금하지 않는다.
5. **읽기 내용**: Office 원본의 artifact kind·불확실성·이견·다음 행동·근거 상태를 보고서 투영에서 보존한다. 기존 안전 Markdown renderer로 제목·문단·목록·표를 읽고 원문 복사는 유지한다. text/code와 기존 QA 원문은 그대로 보존한다. 새 시각적 레이아웃이나 장식은 추가하지 않는다.
6. **검증**: 같은 실제 공개 원문과 실제 완료 주간을 고정해 전/후를 대조한다. 잘못된 수치 의미, 예정→완료, 포함→전체, API 단가→총비용, 무근거 원인을 금지 사례로 삼는다. 형식·최소 글자 수·키워드 출현을 의미 품질 점수로 대체하지 않는다. 독립 내용 감사는 구체적 근거와 문장 단위 수정 이유를 기록한다. 테스트와 실모델 검증 후 운영 배포·main 통합을 완료한다.

## 파일·소유 경계

- root: Hub `office-workflow-context.js`와 비교/지표 근거 helper·tests, 설계/실행 기록, 검증·운영 적용.
- 연구 담당: Engine `research-prepare.ts`와 분리된 편집 policy/review helper·tests, 필요하면 Hub 연구 engine 호출 시간 예산. DB mutation·quota/paid claim의 변경은 root와 합의한다.
- 보고서 담당: Engine Office weekly writing policy·`workflow-prompt.ts`/core의 검수 통합, Hub reports 투영·기존 Markdown 표시·tests. 역할 카드/계약 전체 재설계는 하지 않는다.
- 독립 감사: 기준과 실제 전후 대조, 주장·원문 대조. 파일 편집/유료 호출은 root가 따로 지시한다.

추가 모델 비용은 현재 사용자 결정대로 월 상한 없이 실행별로 기록한다. 사용자에게 저장된 이전 결과는 수정하지 않고 새 결과를 생성·구분한다.

## 실제 대조 이후 확정한 운영 설정

- 보고서/리서치 전용 모델은 `COM_MOON_CONTENT_QUALITY_MODEL`로 분리하며 기본값은 `gemini-3.1-pro-preview`, thinking `low`, 출력 상한 16,384다. 다른 AI 기능의 기본 모델은 바꾸지 않는다. 각 산출물은 초안과 검토 2회이며 자동 재시도하지 않는다. 실제 5건을 완성한 조합의 토큰 기반 비용은 $0.307608이었다.
- Office 비 Council 주간만 Engine 95초/Hub 105초, 신규 DB claim 120초로 맞춘다. 다른 업무/Council의 48초/55초/60초는 유지한다. Research는 원문 수집 뒤 claim·Engine·저장을 위한 시간을 남긴다. 0061은 조회 투영에서 판단 한계를 보존하고 0062는 새 주간 claim의 판정 기한만 바꾼다.
- 실모델 최종 조합은 독립 원문 대조에서 4/5가 채택 가능했다. 정치 일정 원고에 남은 원인·의도·논의 시작 이력 추론은 별도 구체 금지 예시로 보강했으며, 그 변경은 유료 재생성으로 다시 평가하지 않았다. 검토용 예시는 사람이 원문과 대조해 편집한 것임을 명시한다. 프롬프트·인용 validator·동일 모델 검수는 의미의 정확성이나 운영자 승인을 보증하지 않는다.
