# Guru 멘토 서가·조용한 레일 제품 적용

> 상태: **운영자 확정(2026-09-24)** — A 멘토 서가와 B 조용한 멘토 레일 목업을 함께 적용한다.
> 관계: `2026-09-24-guru-guidance-cards-design.md`의 카드·출처·요청형 원칙을 유지하고, 그 문서의 코칭 화면 진입과 카드 배치 절을 이 문서가 구체화한다. `2026-09-23-studio-simplification.md`의 Studio 표면 예산은 유지한다.
> 검토 기준: `guru-mockup-a.html`(서가), `guru-mockup-b.html`(레일)의 시각·상호작용. 목업 안의 예시 업무 기록은 제품 코드로 옮기지 않는다.

## 경험과 위치

- **A · 멘토 서가:** `AI·자동화 → 코칭·대화`의 기본 상태다. 일간 Guru 한 장과 주간 Legend 한 장을 나란히 읽는다. 세일즈·마케팅·콘텐츠 분야 선택, 수동 넘김, 이 세션에서 숨기기·복원을 제공한다. 같은 탭의 기존 대화는 명시적인 `대화 시작`과 기존 `?agent=...` 딥링크로 유지한다. 새 최상위 내비게이션 항목은 만들지 않는다.
- **B · 조용한 멘토 레일:** 고객 목록, 브랜드, 콘텐츠 소재·제작의 세 맥락에만 같은 공유 컴포넌트를 둔다. 평소에는 접힌 작은 진입점이며 클릭하면 Guru/Legend와 출처를 볼 수 있다. 데스크톱은 오른쪽 드로어, 390px은 하단 시트다. 업무 화면의 폭을 상시 줄이지 않는다.
- 홈·오늘의 승인 대기, Studio 원고 본문, Office, 작업·실행에는 새 카드를 넣지 않는다. Studio의 기존 `더보기 → 멘토` 진입은 그대로다. 고객 상세에서 이미 열린 Guru 드로어와 레일이 겹치지 않게 한다.

## 콘텐츠와 동작

- 두 화면은 `@com-moon/guru-guidance`의 동일 카드와 서울 기준 일간/주간 선택을 사용한다. 화면을 보고 있는 동안 카드가 자동으로 전환되지 않는다. 수동 넘김은 저장·읽기 API를 호출하지 않는다.
- 인물·방법론·재서술 문구·`써볼 때`·질문·문서 경로와 절을 표시한다. 명언이나 성과 수치를 새로 만들지 않는다. Legend는 주간 읽기 관점이며 AI 대화의 별도 페르소나로 호출하지 않는다.
- 카드의 `질문하기`는 초안 입력만 연다. 실제 조언 생성은 사용자가 `전송`을 누를 때만 시작한다. 읽기·열기·닫기·넘김·숨김으로 알림, `work_order`, 업무를 생성하지 않는다.
- 세일즈 질문은 기존 ClassIn 영업 Guru 경로를 쓰고 **세일즈 카드 ID만** 허용한다. 마케팅·콘텐츠 질문은 개인 브랜드 멘토의 새 `open-question` 모드로 보내고, 해당 분야 카드 ID·자료 출처를 넘긴다. 이 모드는 `관찰 → 프레임 → 질문/선택`으로 답하며 다음 행동·승인 큐 후보를 강제하지 않는다. UI에 호출 대상을 `브랜드 멘토`로 밝힌다. ClassIn 브랜드/콘텐츠 범위에서는 개인 브랜드 멘토 호출을 제공하지 않는다.
- 데이터 연결이 없으면 `preview`, 읽기·생성 실패는 `error`를 명시한다. 예시 고객·브랜드·콘텐츠 행을 코드에 넣지 않는다. 요청형 생성 결과는 기존 실행 기록을 사용하며 자동 업무 생성은 없다.

## 화면 품질과 검증

- 기존 Hub 토큰과 프리미티브를 사용한다. 서가의 큰 제목은 이번 운영자 목업 승인에 따른 예외로 디자인 결정 로그에 기록한다. 레일 트리거는 맥락 화면마다 같은 상대 위치와 접근 가능한 이름을 유지한다.
- 데스크톱 다크·라이트, 390×844, 44px 터치 대상, 모바일 입력 16px, 키보드/ESC/초점 복귀, 페이지 이동 시 드로어 닫힘을 확인한다.
- 테스트는 분야별 API 격리, 카드 열람 무호출, 질문 전송 전 무호출, 날짜·수동 넘김 결정성, 도메인별 노출 위치, Studio·홈·오늘 제외를 고정한다.
