# 결정 데스크 — 정할 것 큐 + 정하기 패널

> 상태: **화면 방향 운영자 선택(2026-10-15)** · 세부 권장 · 구현(결정 일지 게이트 뒤).
> 관계: [확인할 것 — 끝내기 버튼과 막힘 풀기](2026-09-30-check-items-finish-and-unblock-design.md) §6 결정 일지의
> 화면 배치를 넓힌다. 결정 일지의 저장 계약(결정 → 그래서 할 일, 출처, 막힘 이력)은 그대로 쓰고, 일지 타임라인은
> `일지 전체` 보기로 남는다. 운영 노출은 `apps/hub/lib/feature-gates.js`의 `decisionJournal` 하나를 따른다(운영자 결정 D3).

## 1. 왜

결정 일지는 이미 정한 것을 남기는 곳이었다. 정하지 못한 것(막힌 프로젝트, 미정으로 남긴 결정)은 홈의 확인할 것
카드나 일지의 미정 줄에 흩어져 있었고, 정하려면 드로어를 열어 제목·근거를 처음부터 적어야 했다.
결정 데스크는 결정 일지의 기본 보기를 **정할 것을 정하는 자리**로 바꾼다.

운영자는 2026-10-15 디자인 캔버스의 일곱 안 중 `B×C 2 · 결정 데스크 — 정할 것 큐 + 정하기 패널`을 골랐다.

## 2. 화면

결정 일지(`dashboard/work/decisions`) 머리에 `정하기 / 일지 전체` 보기 전환을 둔다. `정하기`가 기본이고,
`?view=journal`이면 지금까지의 일지 타임라인이다.

| 자리 | 내용 |
| --- | --- |
| 머리 | eyebrow `<앵커> · 결정 일지`, 제목 `정할 것 N건`, 한 줄 `이번 주 정한 것 · 그래서 할 일 남음 · 가장 오래 미정 n일` |
| 왼쪽(최대 460px) | 거르기 `전체 · 막힘 · 미정`, 정할 것 카드(미룰 것 고르기 체크 + 메타 줄 + 제목 + 선택지 수), `+ 정할 것 추가`, `최근 결정` 3줄과 `일지 전체 →` |
| 오른쪽 정하기 패널 | 메타 줄, 질문, 맥락 칸(막힌 이유 · 목표일 · 남은 작업과 확보 시간), 선택지(라디오 + 얻는 것 · 잃는 것), `왜 A안인가`, 그래서 할 일 + 기한, 막힌 점 비우고 진행으로, `남기면` 줄, 버튼 셋 |
| 아래 | 단축키 줄 `J / K 정할 것 이동 · 1–5 선택지 고르기 · ⌘↵ 정하기 · X 고른 뒤 한 번에 미루기` |

- 고른 카드만 Moonstone 1px 테두리(현재 위치, DESIGN.md §5.2). 막힘의 메타 줄만 `--danger` 글자(다음 행동을 막는 상태, §5.3 lifecycle `blocked`). 미정은 중립.
- primary는 `A안으로 정하기` 하나뿐이고, 선택지를 고르기 전에는 비활성으로 `선택지를 고르면 정할 수 있습니다`라고 말한다. `아직 미정으로 저장`·`조언 구하기`(Council)는 ghost.
- 900px 이하는 한 열(큐 → 패널), 600px 이하는 선택지 빼기 버튼이 아래로 내려가고 단축키 줄은 숨긴다.
- 로딩은 `Skeleton`, 읽기 실패는 `EmptyState` + 다시 읽기, 막힌 프로젝트만 못 읽었으면 `TruthBadge partial`과 `미정 결정만 보입니다`.

## 3. 정할 것의 두 갈래

| 갈래 | 조건 | 메타 줄 |
| --- | --- | --- |
| 막힘 | `projects.status = blocked`이고 병목 분류가 `의사결정`이거나 분류 안 함. 그 프로젝트를 출처로 단 미정 초안이 있으면 한 줄로 합친다 | `막힘 · 의사결정 · 9일`(막힌 날부터) |
| 미정 | 결정일이 비어 있는 결정. 미룬 날(`meta.deferUntil`)이 오늘보다 뒤면 뺀다 | `미정 · 12일째`(처음 적은 날부터) |

순서는 막힘 먼저, 같은 갈래 안에서 오래된 순. 회의 결정 제안(모의안의 `회의 제안`)은 이번 판에 넣지 않는다(§7).
규칙 정본은 `apps/hub/lib/decision-desk.js`(`buildDecisionQueue`·`deskStats`).

## 4. 저장 모양 — 마이그레이션 없음

질문·선택지는 `decisions.meta`에 둔다. 스키마는 바꾸지 않는다.

| 키 | 값 | 비고 |
| --- | --- | --- |
| `question` | 300자 | 무엇을 정하는가. 결정의 제목은 고른 선택지 |
| `options` | `{ id, title, gain, loss }` 5개까지 | id는 `a`~`e`. 고르지 않은 선택지도 지우지 않는다 |
| `chosenOptionId` | 선택지 id 또는 null | 저장된 선택지 안에 있어야 한다(Engine이 거절). 선택지를 바꿔 사라지면 비운다 |
| `deferUntil` | `YYYY-MM-DD` 또는 null | 그날까지 큐에서 뺀다. 정하면 비운다 |

Engine `create_decision`·`update_decision`(`apps/engine/lib/pms-command.ts` `decisionDeskMeta`)이 검증하고,
같은 id 재시도의 duplicate 비교(`canonicalCreatePayload`)에 네 키가 들어간다. 허브의 저장 성공은 보낸 필드를
돌려받을 때만이다(`lib/check-write-ack.js` `decisionAcknowledges`·`decisionPatchAcknowledges`).

## 5. 저장 순서

`components/hub/decision-desk-actions.js`. 확인할 것·막힘 풀기와 같은 길(`decision-actions.js`·`unblock-actions.js`)을 쓴다.

1. **정하기** — 결정(초안이 있으면 그 초안을 PATCH로 확정, 없으면 새로 만든다) → 그래서 할 일 → 막힌 점 비우고 진행으로(막힘이고 켜져 있을 때) → 결정에 표시용 링크. 중간에 멈추면 무엇이 남았는지 말하고, 다시 누르면 같은 id로 남은 단계부터 이어 간다. 막힘의 새 결정은 출처 `project-unblock`, 할 일의 신호 키는 `work-blocked:<프로젝트>`라 홈 확인할 것 카드도 같이 숨는다.
2. **아직 미정으로 저장** — 결정일 없이 질문·선택지·근거(기울어진 선택지가 있으면 그것도)를 남긴다. 빈 선택지는 뺀다.
3. **한 번에 미루기** — `X`로 고른 것을 7일 뒤로 미룬다. 초안은 미룰 날만 고치고, 초안 없는 막힌 프로젝트는 미룰 날을 단 초안을 새로 만든다. 프로젝트의 막힘은 그대로다.

## 6. 하지 않는 것

- 정할 것을 자동으로 만들지 않는다. 큐는 이미 있는 기록(막힌 프로젝트·미정 결정)을 읽을 뿐이다.
- 결정 기록은 지우지 않는다(append-only 저널). 미루기는 숨김이지 삭제가 아니다.
- 게이트를 열지 않는다. `decisionJournal`이 닫혀 있으면 데스크도 보이지 않는다.

## 7. 미정

- **Q-DD1** 회의 메모의 결정 제안을 큐의 세 번째 갈래로 넣을지(모의안의 `회의 제안`). 지금은 회의 리뷰 흐름에 남는다.
- **Q-DD2** 미루기 기간을 7일 고정으로 둘지, 날짜를 고르게 할지.
- **Q-DD3** 모의안의 `30분 잡아 둠 14:00`(시간 잡기 표시)을 큐 카드에 다시 넣을지 — 지금은 결정 쪽에 시간 잡기 기록이 없다.
