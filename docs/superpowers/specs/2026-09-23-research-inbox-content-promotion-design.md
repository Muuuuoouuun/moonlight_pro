# 브랜드 리서치함 → 콘텐츠 후보·Studio 초안

> 작성: 2026-09-23 · 상태: **검토 위치와 두 목적지 운영자 확인 / 실행 계약 권장안 / 구현 미착수**
>
> 운영자 확인: 정기 수집 결과는 Studio에 들어가기 전에 브랜드 또는 콘텐츠 화면에서 읽고 버릴지 고른다. 선택한 항목의 목적지는 **Studio 초안** 또는 **콘텐츠 후보**다. 권장 매핑은 콘텐츠 후보를 기존 단일 소재함의 `idea`, Studio 초안을 편집 가능한 `draft`로 연결하는 것이다. 체크 자체가 저장을 실행하는지와 같은 세부 인터랙션도 아래 권장안으로 구분한다.
>
> 관계: [브랜드 리서치·편집 시스템](2026-09-21-brand-research-editorial-system-design.md)의 브랜드·출처 범위 §1~4, 비용·유튜브·검증 원칙 §9~11·14를 유지한다. 이 문서는 그 문서의 **첫 흐름과 상태 설명 §1·5, Studio 직행 도식 §6, review/promotion 모델 §7~8, 첫 사용자 흐름 §12~13, 첫 가동의 저장·검토·검증 §15.2~15.4** 중 이 문서와 충돌하는 부분을 대체한다. [Studio 1차 계약](2026-09-12-content-notes-drafts-ai-workflow-design.md)과 [브랜드 탭](2026-08-29-brand-tab-design.md)을 바꾸지 않은 현재 코드 상태에서 출발한다. 정기 실행 등록·DB 적용·운영 배포를 완료했다는 문서가 아니다.

## 1. 결정해야 하는 일과 용어

첫 사용자 흐름은 다음 하나다.

```text
공식 출처·Brave·지정 YouTube 채널에서 발견
  → 변경점·근거 확인, 중복 제거, 브랜드별 AI 선별
  → 리서치함의 검토용 원고
  → 운영자: 버리기 / 콘텐츠 후보로 담기 / Studio 초안으로 보내기
  → 콘텐츠 후보는 기존 소재함에서 Studio로 발전
  → Studio 초안은 디벨롭·최종 확인·발행 준비
```

| 이름 | 소유 원장 | 뜻 |
| --- | --- | --- |
| 리서치 후보 | `research_briefs` | AI가 자료를 읽고 선정 이유·근거·검토용 원고를 준비했지만 운영자가 아직 고르지 않은 항목. `content_items`가 아니다 |
| 콘텐츠 후보 | 기존 `content_items.status = 'idea'` | 운영자가 쓸 만한 소재로 채택한 항목. 콘텐츠 큐의 단일 **소재함**에 나타난다. 채널 원고는 아직 확정하지 않았다 |
| Studio 초안 | 기존 `content_items.status = 'draft'`와 `content_variants` 원고 | 운영자가 원고로 이어 쓰기로 선택한 항목. Studio에서 편집·버전 관리한다 |
| 버리기 | 리서치 결정 기록 | 현재 근거·변경점으로는 쓰지 않겠다는 판단. 콘텐츠 원장에 넣지 않는다 |

**기존 주기의 산출물은 이제 Studio 레코드가 아니라 리서치함의 검토용 원고다.** politic_officer의 2시간 간격, class.moon의 하루 3개, 22th nomad의 하루 1개·행사 때 최대 7개는 이 준비 리듬이다. 검증 가능한 새 소재가 부족하면 `0건/부족한 이유`를 기록하고 할당량을 채우려고 다른 제목의 중복 원고를 만들지 않는다. 선택한 수와 실제 발행 수는 별도다.

## 2. 화면: 한 리서치함, 두 입구

- **콘텐츠 → 리서치함**을 검토 정본으로 둔다. 브랜드·새 후보/보류/버림/전환됨 필터와 준비 시각을 제공한다. 기존 콘텐츠 큐의 `전체/소재함/제작중` 탭에 미선택 리서치 후보를 섞지 않는다.
- **브랜드 상세**에는 해당 브랜드의 `새 리서치 후보 N건`과 최근 항목의 같은 검토 카드를 보여 준다. 여기서도 읽기·버리기·선택·목적지 전환이 가능하며 `모두 보기`는 리서치함에 브랜드 필터를 적용해 이동한다. 현재 브랜드 화면에는 독립 콘텐츠 탭이 구현되지 않았으므로 브랜드별 저장함을 만들지 않고 같은 read model·review command·카드 컴포넌트를 쓴다.
- 한 카드의 기본 줄은 `제목 / 이번에 실제로 바뀐 점 / 왜 이 브랜드인가 / 출처·사건 시각 / 근거 확인 수준 / 준비 시각`이다. 펼치면 핵심 사실과 원문 위치, 해석·반대 근거, 미확인 조건, **검토용 원고**, 연결된 자료·원고 버전을 본다. 제목·검색 스니펫만 확인한 자료를 본문 검증으로 표시하지 않는다.
- 체크박스는 여러 항목을 고르는 **화면 선택**이다. 하단 `선택 N건 → 콘텐츠 후보로 담기` 또는 `선택 N건 → Studio 초안으로 보내기`를 누를 때 저장한다. 목적지가 둘이므로 체크만으로 콘텐츠 원장을 쓰지 않는 것이 권장안이다. 카드의 `버리기`는 바로 결정하며 되돌릴 수 있다. `나중에`는 미선택 상태를 유지하는 빠른 보류 동작이다.
- 저장 성공 시 항목별 `소재함에서 보기` 또는 `Studio에서 열기` 링크를 표시한다. 배치 중 일부만 성공하면 각 항목의 확인된 결과와 실패·저장 확인 중을 나눠 보여 주고, 미확인 항목을 성공처럼 목록에서 지우지 않는다.
- 수집 실패, 근거 부족, 새 사실 없음은 서로 다른 상태다. Hub read의 HTTP 200 + `status: error` 봉투를 읽어 조회 장애를 빈 리서치함으로 위장하지 않는다.

기존 Studio AI 편집의 `candidate`는 **저장된 원고의 변형 제안**이므로 이 문서의 리서치 후보와 동일 객체가 아니다. 이름이 같아도 원장·버전·행동을 합치지 않는다.

## 3. 두 목적지의 저장 계약

### 3.1 콘텐츠 후보로 담기

선택한 리서치 항목 하나당 기존 콘텐츠 원본 하나를 만든다. 브랜드·제목·원문 링크·선정 이유·핵심 메시지·확인 범위는 `source_idea`와 `brief` 및 고정된 리서치 연결로 넘긴다. `content_items.status`는 `idea`이고 첫 `base_text` variant의 본문은 비워 둔다. 현재 Studio workflow는 본문이 생기면 `idea → draft`로 옮기므로 이 계약과 맞는다. 중립 형식의 신규 계약은 §3.2를 따른다.

리서치함에 준비한 검토용 원고를 버리지 않는다. 고정된 리서치 revision에서 다시 볼 수 있고, 콘텐츠 후보를 나중에 Studio로 열어 **같은 content item**의 원고로 가져와 저장한다. 두 번째 `content_items`를 만들거나 채널별 초안을 다시 생성하는 것을 기본으로 하지 않는다. 원고를 가져오기 전에는 소재함에 있으며, Studio에 원고가 저장된 뒤 제작중으로 이동한다.

### 3.2 Studio 초안으로 보내기

선택한 revision의 검토용 원고를 같은 근거 snapshot과 함께 Studio 원본·첫 variant로 만든다. 저장 확인 뒤에만 `draft`로 표시한다. 사용자가 플랫폼과 채널을 아직 정하지 않았으므로 첫 원고는 **채널 미지정 기준 텍스트**로 다루는 것이 권장안이다. 현재 `content_workflow_v1`은 채널/variant type을 필수로 기대하므로 구현 시 중립 `base_text` 형식의 DB·Engine·Studio 계약을 추가해야 한다. 이를 몰래 `blog`나 `threads`로 지정하지 않는다. 이후 사용자가 채널을 고르면 현재의 variant 분기 기능으로 파생한다.

두 경로 모두 선택 당시의 `research_brief_id + revision + 자료 버전 + 브랜드 기준 버전`을 연결한다. 원문 정정·출처 상태 변경을 발견하면 기존 Studio 문장을 조용히 바꾸지 않고 `근거 업데이트 확인`을 띄운다. 정치 초안은 일반 공개 독자를 위한 사실·제도·쟁점 설명으로 준비하고 특정 연령 집단의 정치적 설득을 최적화하지 않는다.

## 4. 데이터와 실패 경계 — 구현 제안

[상위 설계](2026-09-21-brand-research-editorial-system-design.md) §7의 `research_sources/documents/briefs/runs`를 유지하되, review와 promotion을 구분한다.

| 단위 | 책임 | 불변식 |
| --- | --- | --- |
| `research_briefs` | 사건+브랜드+관점 root, revision별 근거·검토용 원고·선별 이유 | 같은 URL의 재게시만으로 새 후보를 만들지 않음 |
| `research_reviews` | 버리기·되돌리기·보류·목적지 선택의 append-only 결정 | actor·시각·대상 revision·선택 이유를 남김. 미응답은 거절이 아님 |
| `research_promotions` | `brief root → content item/variant` 연결과 요청 영수증 | workspace+brief root의 단일 활성 content 원본. 같은 요청·재시도는 같은 ID 반환 |

`research_promote_v1` 같은 서비스 전용 원자 RPC가 brief revision과 workspace·brand scope를 잠그고 검사한 뒤 기존 콘텐츠 원본/variant, promotion, review를 **한 트랜잭션**으로 만든다. 현재 일반 `create_draft` 명령은 item과 variant를 순차 저장하므로 이 연결에 그대로 쓰지 않는다. 기존 Studio의 `content_workflow_v1`이 제공하는 요청 해시·원자 저장·버전 검사 패턴을 재사용하되, 연구 provenance를 확실히 고정하는 새 명령 계약이 필요하다.

한 brief root가 콘텐츠 후보로 승격된 뒤 Studio 원고가 되면 **같은 content item을 업데이트**한다. 이미 Studio 초안이 된 항목의 중복 전환은 같은 링크를 돌려주며 `idea`로 되돌리지 않는다. 두 번 선택하거나 브라우저가 응답을 잃어도 영수증을 먼저 조회한다. 새로운 근거 revision이 생겨도 기존 콘텐츠를 복제하지 않고 차이를 보여 준다. 버린 사건은 사소한 재게시로 다시 올리지 않되, 결론을 바꿀 실질 변경이 있으면 `새로 바뀐 점`을 표시해 재검토 가능하다. 한 사건의 서로 독립적인 콘텐츠 관점은 별도 root로 분리한다.

## 5. 수집·비용·정확성의 실행 순서

1. 공식 피드/API와 지정 채널 업로드 목록에서 새 ID·수정 신호를 싸게 찾는다. Brave는 고정 출처 밖 발견과 빠진 원문 추적에 쓴다. 운영자가 주는 채널 목록을 차차 연결하며, 개인 구독 목록 OAuth는 별도 연결 단계다.
2. 문서 hash·사건 key로 중복을 묶고 원문 접근 수준을 기록한다. 동일 원문은 브랜드 간 한 번 읽고 브랜드별 이유·원고만 분기한다.
3. 근거가 충분하고 실제 변경이 있는 상위 항목만 모델에 보낸다. 리서치함 원고를 Studio로 옮길 때 모델을 다시 호출하지 않는다. 영상은 메타데이터 발견과 실제 본문/자막 확인을 분리한다.
4. 회차에는 시도·성공·0건·접근 실패·예산 대기·검토용 원고 수를 남긴다. 월 유료 상한과 운영 위치가 확인되기 전 반복 유료 실행을 켜지 않는다. 이는 운영자가 정한 주기를 취소한다는 뜻이 아니라 실행 설정 게이트다.

## 6. 첫 구현·검증 게이트

1. [수동 시범 3건](../../research/2026-09-23-brand-research-manual-pilot.md)을 실제 근거 버전과 함께 리서치함에 넣고 세 브랜드에서 **Studio에 들어가지 않고** 읽기·버리기·되돌리기·두 목적지 중 하나 선택을 검증한다. 이 기록은 현재 파일 예시일 뿐 DB 저장·자동화 완료 증거가 아니다.
2. 콘텐츠 후보가 기존 소재함에 한 건으로 나타나고, 나중에 Studio로 열어 **같은 content ID**의 초안으로 옮겨지는지 확인한다. 바로 Studio 초안으로 보내면 기준 원고·근거·버전이 보이는지 확인한다.
3. 중복 클릭, 동시 선택, 저장 응답 유실, 배치 일부 실패, stale revision, workspace/brand 불일치에서 중복 콘텐츠·잘못된 성공 표시가 없는지 확인한다. 모바일·키보드에서도 선택·복귀가 가능해야 한다.
4. 그다음 실제 출처 수동 회차와 비용·지연·근거 누락을 측정한다. 이를 통과한 뒤 브랜드별 반복 실행과 채널별 업로드 감지를 연결한다. 발행·예약·회사 공식 게시의 자동 실행은 이 흐름에 포함하지 않는다.

완료 지표는 리서치 항목 수가 아니라 **검토 시간, 버림/콘텐츠 후보/Studio 전환 비율, 전환 1건당 실제 호출·비용, 근거 수정 발견, 되찾아 쓴 후보 수**다. 첫 표본 전 목표 비율을 임의로 확정하지 않는다.
