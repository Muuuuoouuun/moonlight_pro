# Studio 단순화 — "Threads 글 한 편 끝내기"

> 상태: **운영자 확정 · 구현(2026-09-23)**
> 관계: `2026-09-12-content-notes-drafts-ai-workflow-design.md`의 **화면 배치**(좌 편집 / 우 도구 패널, 상시 노출 컨트롤)를 대체한다. 그 스펙의 데이터 모델·저장/복구/충돌 계약·AI 후보 비교/적용·버전 복원은 그대로 유효하다.
> 운영자 지시: "핵심적이고 간단한 것만 하면 되는데 계속 번거롭게 일이 늘어나거나 쾌적하지가 못해" → "Threads 기본으로 바로 구현" · "계속 붙는 것들 정리하자"

## 1. 문제

09-12 이후 Studio 한 화면에 원문·기획 6칸, 채널 선택·추가, 버전 저장·기록, 내보내기, 다음 행동·막힌 이유, 일지·목표 연결, 방향 검토·검수 게이트, AI 작업 5종×말투 4종, 적용 기준, 글쓰기 집중 토글, 저장 상태 7종 문구, 축하 연출이 **상시** 노출됐다(입력·버튼 20개 이상). 기능이 추가될 때마다 패널이 붙었고 빠진 적은 없다.

운영자 실제 흐름(`operator-workflow-profile.md` §12)은 `아이디어 → 선택 → 제작 → 다듬기 → 발행`이며 주력은 Threads다.

## 2. 기본 화면 (확정)

| 영역 | 내용 |
|---|---|
| 헤더 | `원고 작성` · 채널 한 줄 · 조용한 저장 표시 · `새 글 N` · `더보기` |
| 본문 카드 | 제목(선택) → 원문 메모(본문이 비면 펼침) → 본문 편집기(편집/미리보기) → `AI 초안` `AI 다듬기` → `복사` `발행했음` |
| AI 접힘 | `다른 작업 · 말투`: 줄이기·도입부 3안·다른 채널로 변형, 말투, 적용 기준 |

- 채널 기본값은 Threads(`emptyStudioDraft`). 결과물이 2개 이상일 때만 결과물 전환 선택이 본문에 나타난다.
- 저장은 자동(기존 1.2초 디바운스)이며 평소엔 `입력 중`/`저장 중…`/`저장됨` 한 단어. `서버 미연결`·`서버 저장 미확인`·`최신 내용 확인 필요`·불러오기 실패만 `TruthBadge`와 재시도로 올린다.
- 발행 기록은 URL·일시가 서버 계약상 필수라 유지하고, 일시는 지금 시각으로 미리 채운다.

## 3. 표면 예산 (재발 방지)

- 헤더 버튼: 저장 재시도(실패 시에만) · 새 글 · 더보기 — 3개.
- 본문 카드 컨트롤: 제목 · 원문 메모 · (결과물 전환) · 복사 · 발행했음 — 최대 5개 (+ 편집기와 AI 버튼 2개).
- 사이드 패널(`<aside>`) 없음.
- **새 기능은 `더보기` 드로어나 다른 탭으로 간다.** 본문에 더하려면 먼저 하나를 빼거나 이 절을 고친다.
- `apps/hub/components/hub/pages/content-studio-surface.test.mjs`가 이 예산을 고정한다.

## 4. `더보기` 드로어로 옮긴 것 (기능 삭제 없음)

분류(브랜드·결과물 제목) · 채널(첫 채널 선택·빈 결과물 추가·원본 결과물 열기) · 기록(버전 기록·지금 버전 남기기·파일로 내보내기) · 기획 구체화 6칸 · 이어서 할 일(다음 행동·막힌 이유) · 연결된 일지·목표 · 검토(방향 검토·검수 게이트 → 멘토 위젯).

## 5. 제거한 것

- `글쓰기 집중` 토글 — 기본 화면이 이미 한 단 집중 레이아웃이다.
- 상시 `버전 저장` 주 버튼 — AI 적용 시 자동으로 버전이 남고, 수동 저장은 더보기에 있다.
- Studio의 축하 연출(복사 스파클·발행 컨페티) — 전역 `celebration-fx` 모듈은 다른 표면에서 그대로 쓴다.

## 6. 범위 밖

서버·DB·저장 큐·AI 변환 API는 변경하지 않았다. 브라우저 실사용 확인(모바일 390px 포함)은 운영자 검토가 남아 있다.
