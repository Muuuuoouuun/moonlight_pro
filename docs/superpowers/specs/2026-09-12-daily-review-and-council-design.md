## 1. 만들 경험

**오늘의 상태와 실행을 짧게 기록하고, Council의 제안 하나를 다음 날 직접 확인한다.**

하루 기록 → 필요할 때 Council 리뷰 → 선택한 행동을 할 일로 연결 → 다음 리뷰에서 실행·도움 여부 확인 → 개인 주간 리포트.

가장 작은 입력은 에너지, 오늘 중요한 일의 진척, 기억할 한 줄이다. 화면에는 세 항목을 제시하지만 세 항목 전부를 채워야 저장되는 구조로 만들지 않는다. AI 없이 저장·재조회할 수 있고, 분석은 별도 버튼으로 실행한다.

새로운 가치는 조언의 다음 날을 기억하는 데 있다. 제안이 실행되지 않았다면 이유를 선택적으로 남기고, 실행했지만 도움이 되지 않았다면 다음 제안의 참고로 삼는다. 사용자에 대한 성격 평가나 의지 점수로 확장하지 않는다.

## 4. 기본 입력과 항목별 기준

### 4.1 매일 보이는 세 항목

| 항목 | 입력 | 기준 |
|---|---|---|
| 에너지 | 직접 1~5 선택 | 1 매우 지침 / 2 지침 / 3 보통 / 4 여유 있음 / 5 충분히 활력 있음. 수행 성적이 아닌 당일 체감 |
| 오늘 중요한 일 | 대상 1개 + 미착수/진행/목표 완료 | 0 오늘 목표에 착수하지 않음 / 1 착수했으나 오늘 목표에는 미달 / 2 정한 오늘 목표에 도달 |
| 기억할 한 줄 | 선택적 자유 서술 | 잘된 일·걸린 점·기억할 일 중 무엇이든 한 줄. 세 질문에 각각 답하게 하지 않음 |

- 중요한 일은 사용자가 선택한다. 선택한 task가 있으면 연결하고, 없으면 짧은 직접 입력도 허용한다. AI가 임의로 중요 대상을 확정하지 않는다.
- 하루 목표는 전체 프로젝트 완료와 다르다. 예를 들어 목표가 ‘초안 개요 작성’이면 개요를 쓴 날 2다. task 전체 완료와 일일 목표 달성도 구별한다.
- 중요한 일을 정하지 않은 날은 ‘대상 없음’으로 둔다. 휴식일에 업무 미착수를 자동 부여하지 않는다.
- 저장은 실제 답변 하나 또는 한 줄 메모가 있으면 가능하다. 전부 비어 있으면 빈 레코드를 만들지 않고 ‘기록 건너뛰기’로 닫는다.
- 0, 미입력, 대상 없음, 자료를 읽지 못함을 구분한다. 기본 선택값을 미리 점수로 저장하지 않는다.
- 에너지·진척·습관을 합친 총점은 기본 제공하지 않는다. ‘오늘 만족도 1~5’를 추가하면 그 값은 사용자의 별도 자기평가다.

### 4.2 선택해서 추가할 항목

| 항목 | 적합한 방식 | 예시 기준·입력 | 시작 범위 |
|---|---|---|---|
| 집중 | 기준 선택 또는 시간 | 미실행 / 일부 진행 / 내가 정한 집중 블록 완료. 시간은 직접 입력한 분 단위 | 기본 세 항목 실사용 뒤 선택 |
| 회복 | 직접 선택 | 충분 / 조금 / 부족. 휴식 시간을 할 일 개수로 대신 추정하지 않음 | 선택 |
| 루틴 | 실제 체크 참조 | 오늘 적용되는 루틴 중 체크된 항목. 미체크는 ‘기록 없음’이며 안 했다고 단정하지 않음 | 기존 자료 보조 표시 |
| 고객 후속 | 실제 기록 참조 | 선택한 고객 행동의 결과·다음 행동 기록 유무 | 업무 평가를 확장할 때 |
| 콘텐츠 진척 | 기준 선택 | 아이디어 정리 / 초안 / 다듬기 / 발행 기록. 단계는 우열 점수로 합치지 않음 | 선택 |
| 오늘 만족도 | 직접 1~5 | 1 매우 불만족 ~ 5 매우 만족 | 선택 |

### 4.3 내 기준 설정

항목 이름, 입력 방식, 값의 의미, 적용 요일, 시작 날짜, 표시 여부를 설정한다. 숫자 항목에는 단위와 방향도 둔다. 예를 들어 집중 시간은 ‘분’, 에너지는 체감 척도, 방해 횟수는 ‘회’다. ‘클수록 좋음’이 모든 수치의 기본이 되어서는 안 된다.

첫 버전은 기본 세 항목과 준비된 프리셋만 제공한다. 항목별 자유 수식·가중치·복잡한 조건 편집기는 후속이다. 기준 변경 시 새 버전을 만들고 기존 날짜는 당시 기준을 유지한다. 다른 기준의 값은 같은 추세로 조용히 합치지 않는다.

## 5. 자동 입력의 책임

| 출처 | 허용하는 동작 | 확정하지 않는 것 |
|---|---|---|
| 직접 선택 | 사용자가 입력한 값을 기록 | 원장 수치로 자기평가를 덮어쓰기 |
| 규칙 계산 | 확인된 기록과 저장된 기준으로 결과·근거를 함께 표시 | 원장 누락·조회 실패를 미달로 처리 |
| 메모에서 AI 추출 | 원문과 함께 입력 후보 제시. 채택 시 사용자 확정 이력 보존 | “피곤하다”를 임의의 에너지 2점으로 환산 |

- 사용자가 “에너지 2, 개요는 완성”이라고 쓰면 그 명시 값은 후보로 추출할 수 있다. 점수와 대상이 불명확하면 비워둔다.
- 캘린더의 예정 이벤트는 ‘예정된 일정’이다. 실제 참석이나 집중 시간의 근거로 사용하지 않는다.
- 오늘 완료 개수는 실제 완료 시각이 확인된 기록만 계산한다. 완료 상태만 있고 완료 시각이 없는 건은 ‘완료일 미확인’으로 별도 표시한다. 기존 화면의 fallback 집계는 이 평가 계약의 근거가 아니다.
- 원장의 조회 상한·부분 실패가 있으면 관측 범위를 표시한다. 전체를 읽지 못했을 때 ‘후속 누락 0건’이나 전체 달성률을 선언하지 않는다.
- 자동으로 모은 근거와 사용자의 수정은 별도로 남긴다. 예를 들어 사용자가 ‘실제로 했다’를 기록해도 루틴 원장을 몰래 수정하지 않는다.

## 6. Council: 매일은 짧게, 필요할 때 깊게

### 6.1 역할과 실행

Analyst는 기준·기록 차이를, Coach는 사용자가 적은 상태·맥락을, Strategist는 다음 행동을 본다. 첫 버전은 **하나의 모델 요청에서 세 관점을 참고해 카드 하나를 만드는 방식**을 권장한다. 실제 독립 에이전트들이 토론·합의했다고 표현하지 않는다.

‘저장’으로 하루 기록을 끝낼 수 있다. 사용자가 ‘카운실 리뷰’를 누를 때만 분석한다. 본문을 작성하거나 점수를 고칠 때 자동 생성하지 않는다.

### 6.2 입력 범위와 결과

입력은 선택한 날짜의 리뷰, 그날의 적용 기준, 사용자가 포함한 실제 기록의 요약·ID·기준 시각, §7에서 고른 후속 확인 행동과 그 피드백이다. 고객 상세 원문이나 다른 브랜드 자료 전체를 자동 포함하지 않는다. 선택 문맥과 자료를 못 읽은 부분을 분석 전에 보여준다.

| 결과 | 한도 | 조건 |
|---|---|---|
| 오늘 확인한 것 | 1~2개 | 각 항목에 근거 원문 또는 기록 링크 |
| 해석 | 0~1개 | 사용자 진술과 AI 추정을 구분. 원인 단정 대신 근거와 가능성 표시 |
| 내일 해볼 행동 | 0~1개 | 구체적인 동작과 완료 기준. 근거가 없으면 억지 제안 생략 |
| 더 필요한 정보 | 0~1개 | 중요한 정보가 없을 때만 질문. 답하지 않아도 저장 유지 |

자료 부족 시 숫자 평가를 만들어 채우지 않는다. 낮은 점수를 벌점처럼 해석하거나 활동량이 적다는 이유로 사용자의 의지를 평가하지 않는다. 당일 긍정 문구를 기계적으로 붙이는 대신 확인 가능한 진척을 짚는다.

### 6.3 사용 예시 — 가상 데이터

| 구분 | 내용 |
|---|---|
| 사용자 기록 | 에너지 2. 오늘 목표 ‘콘텐츠 개요 완성’은 진행. “연락 대응이 길어져 개요를 끝내지 못했다.” |
| 확인한 것 | 사용자가 연락 대응 때문에 작업 시간이 줄었다고 기록했고, 개요는 아직 진행 중이다. |
| 해석 | 집중 시간을 먼저 확보하면 도움이 될 가능성이 있다. 하루 기록만으로 반복 원인을 확정하지 않는다. |
| 행동 후보 | 내일 첫 작업으로 개요의 소제목 3개를 작성한다. 완료 기준: 소제목 3개 저장. |

‘내일 할 일로’는 기한과 기존 할 일 연결을 확인하는 작은 편집 단계로 이어진다. 버튼을 눌러 선택한 실행 요청을 다시 승인 큐에서 승인하게 하지 않는다. 같은 후보를 다시 눌러도 할 일은 하나다. 시간 지정이 없으면 날짜 기한만 설정하고 캘린더에 시간 블록을 자동 생성하지 않는다.

리뷰 결과 자체는 work_orders로 보내지 않는다. 자동으로 발견한 별도 작업 제안을 나중에 활성화한다면 proposed 경로를 사용하되, 첫 버전의 하루 리뷰는 사용자가 고른 후보만 task로 연결한다.

## 7. 다음 날과 주간 리뷰

채택 행동이 있으면 다음 리뷰에 ‘지난번 해보기’ 한 줄을 보여준다. task 완료는 조회해 표시하고 다시 입력시키지 않는다. 실행 여부를 확인할 기록이 없을 때만 ‘해봄 / 못 해봄 / 보류’를 선택적으로 받는다. 사용자 응답은 리뷰 피드백이며 task 상태를 조용히 변경하지 않는다.

‘해봄’에는 ‘도움 됨 / 변화 없음 / 아직 모르겠음’을 선택적으로 붙인다. 피드백을 건너뛰어도 오늘 기록을 저장할 수 있다. 미실행·미응답을 무능력이나 실패 점수로 환산하지 않는다.

후속 확인은 한 리뷰에 하나만 제시한다. 채택한 날의 다음 날부터 확인할 수 있고, 연결 task의 기한이 더 늦으면 그날까지 기다린다. 기한이 없으면 채택 다음 날을 사용한다. 이 확인 시점이 지났고 아직 응답하지 않은 행동 중 채택일이 가장 오래된 것을 고른다.

- ‘해봄’ 또는 ‘못 해봄’을 답하면 해당 시도의 후속 확인을 끝낸다. 도움 여부는 나중에도 기록에서 수정할 수 있다. 연결 task의 완료 상태는 실행 정보로만 표시하고, 도움 여부를 추정하거나 피드백 기회를 자동 종료하지 않는다.
- ‘보류’는 기본 다음 날로 확인을 미루며 다른 날짜도 선택할 수 있다. 그 전에는 다음 대상에게 순서를 넘긴다.
- 질문을 건너뛰면 미확인 상태로 이월한다. ‘더 묻지 않기’를 선택하면 피드백 없이 확인을 종료하고 기록은 유지한다.
- 새 행동을 채택하거나 Council을 다시 실행해도 이전 행동·피드백을 덮지 않는다. 확인을 종료해도 연결 task를 완료·취소시키지 않는다.

주간은 기존 운영자 결정인 **월요일 개인 리포트**에 맞춘다. 이전 월요일~일요일의 기록을 읽어 기록일 수, 기준별 관측값, 반복해서 언급된 방해 요소, 채택 행동·피드백, 다음 주 실험 최대 1개를 제시한다. 입력하지 않은 날은 평균의 0점으로 넣지 않으며, 분모는 항목별 실제 응답 수다.

첫 주부터 날짜와 근거를 요약할 수 있지만, 며칠의 동시 발생을 통계적 상관이나 인과로 선언하지 않는다. 기준 버전이 바뀐 기간은 나눠 표시한다. 목요일 회사 리포트에는 개인 에너지·만족도·상세 회고를 자동 포함하지 않는다. 이 기획은 새 예약 실행이나 외부 발송을 생성하지 않는다.

## 8. 저장 구조와 일지와의 관계

### 8.1 권장 모델

일지 타임라인에 하루 리뷰를 하나의 기록 종류로 추가한다. 이미 완성된 DB가 있다는 가정은 하지 않는다. 09-05의 journal_entries 초안을 구현할 때 다음 확장을 함께 검토한다.

| 정보 | 용도 |
|---|---|
| entry_kind | 일반 기록과 daily_review 구별 |
| review_date + review_timezone | 입력 시각과 별개인 대상 날짜·시간대 |
| focus_target | 선택한 task ID 또는 직접 쓴 대상, 그날의 목표 문장. 목표가 없으면 대상 없음 |
| review_data | 항목 ID·기준 버전·값·미입력/대상 없음·입력 출처·근거 |
| body | 사용자가 쓴 선택적 메모. AI 설명을 사용자 원문으로 넣지 않음 |
| review_revision / updated_at | 전자는 사용자 입력·목표·기준 수정에 증가해 AI 기준 판정에 사용. 후자는 저장 충돌 확인에 사용 |
| council_results | run ID별 생성 시점, 참조 revision, 모델, 사용량, 근거, 결과. 재생성은 새 결과를 추가하며 기존 결과 유지 |
| adopted_actions | 후보·run ID, 연결 task ID, 채택일, 확인 상태·보류 날짜·실행/도움 피드백. 재생성과 독립적으로 보존 |

- 개인 리뷰는 기존 workspace resolver가 정한 저장 workspace에 날짜당 하나로 저장한다. 개인 기록이라는 이유로 별도 workspace를 생성하지 않으며 브랜드 필터를 바꿀 때 별도 리뷰가 생기지 않는다. workspace·대상 날짜의 부분 unique 조건을 DB에서 보장한다.
- 작성일이 지나도 대상 날짜를 직접 고를 수 있다. 초기에는 저장 후 날짜 이동 대신 해당 날짜 기록을 열어 수정한다. 시간대는 리듬의 기존 resolver를 사용하고 저장된 과거 날짜를 나중 설정으로 다시 계산하지 않는다.
- 동일 문장을 쓴 다른 날짜를 중복으로 제거하지 않는다. 09-05 초안의 body 필수·content_hash unique 규칙은 일반 메모용으로 한정하고, daily_review에는 날짜 키와 실답변 유효성 검사를 적용하는 변경이 필요하다.
- 기준 정의는 프리셋 ID·버전으로 식별하고 그날의 의미를 스냅샷으로 보존한다. 기존 리뷰를 재작성해도 기준 변경을 자동 소급하지 않는다.
- Council 결과 추가·행동 연결·피드백 저장은 사용자 입력의 review_revision을 올리지 않는다. 새로운 결과는 참조 revision을 유지하며 채택 행동은 원래 run·후보에 계속 연결한다. 정확한 컬럼/하위 레코드 배치는 구현 계획에서 정하되 이 보존 계약은 유지한다.
- 루틴·tasks·고객 활동은 기존 원장에 남긴다. 리뷰는 필요한 근거만 참조·요약한다. 목록 API는 본문·모든 근거를 전부 반환하지 않고 상세 열기에서 읽는다.
- 주간 AI 결과는 개인 일지에 별도의 리포트 기록으로 남기며 생성 출처·기간·참조 기록의 revision을 보존한다. 일반 사용자 메모로 위장하지 않는다. 해당 기록 종류의 구체 저장 필드는 주간 단계에서 정한다.

### 8.2 저장·생성·연결의 실패 처리

- 리뷰 저장은 날짜별 생성 중복과 revision 충돌을 처리하고, 실패 시 입력을 유지한다.
- Council 요청은 리뷰 ID·revision·문맥 fingerprint·요청 키로 중복 호출을 방지한다. 동일 요청 재시도는 기존 요청 상태·결과를 재사용한다.
- 생성 중 원문이 바뀌면 결과를 ‘이전 기록 기준’으로 표시한다. 현재 값이나 최신 결과로 자동 덮어쓰지 않는다. 오래된 결과의 task 연결은 최신 입력을 확인한 뒤 새 요청에서 한다.
- 모델 응답 여부를 모르는 timeout에는 자동 재호출하지 않는다. 사용자가 새 요청을 실행할 때 추가 사용 가능성을 알린다.
- 생성 성공 뒤 저장만 실패하면 받은 결과를 유지하고 저장만 재시도한다. 저장 확인 전 ‘보관됨’으로 표시하지 않는다.
- task 연결은 후보 ID와 영속 요청 키를 사용해 재시도 중복을 막는다. 기존 할 일을 연결할 수 있으며, 새 task 생성과 연결 기록은 원자 처리하거나 receipt로 확실히 복구한다.
- AI 미설정·실패에도 리뷰 저장·기존 기록 열기는 가능하다. 사용량을 기록하고 금액은 가격표와 실제 사용량이 있을 때만 계산한다. 세션 기반 분석을 비용 0이라고 단정하지 않는다.
- Hub read 봉투, write guard, Engine 인증, workspace 검증은 기존 계약을 따른다. 출처 본문에 적힌 지시를 실행 명령으로 취급하지 않는다.

## 9. 적용 순서

아래는 이 기능 안에서의 순서이며 제품 전체 Phase 번호나 기존 확정 우선순위를 대체하지 않는다.

| 단계 | 범위 | 끝까지 확인할 장면 |
|---|---|---|
| **R0 · 직접 하루 리뷰** | 최소 일지 저장 기반 + 세 항목 + 대상 날짜 + 수정·재조회 | 에너지 하나만 기록해도 저장되고 다음 날 다시 읽음 |
| **R1 · 기준과 기존 기록** | 기준 프리셋·버전, 루틴·정확한 완료 기록 보조 표시 | 이미 기록한 실행을 재입력하지 않고 누락과 실제 0을 구별 |
| **R2 · Council과 다음 행동** | 수동 분석, 근거 카드, 후보→task 연결, 다음 리뷰 피드백 | 제안 하나를 실제 할 일로 만들고 다음 리뷰에서 결과 확인 |
| **R3 · 개인 주간 리포트** | 지난 주 요약·반복 관찰·다음 실험 | 기록일 수와 근거를 보며 다음 주 실험 하나를 고름 |

R0는 전체 일지 임포트·태그·AI 요약을 모두 끝낼 필요가 없다. 다만 별도 임시 일지 저장소를 만들지 않고 09-05와 공유할 최소 journal 계약을 먼저 정한다. R2는 브랜드 멘토 BFF를 그대로 호출하지 않고 리뷰 전용 문맥·부수효과가 없는 결과 경로를 둔다. 전용 경로 이름과 마이그레이션 번호는 구현 계획에서 확정한다.

## 10. 검수 시나리오와 사용성 확인

아래는 후속 구현의 검수 조건이며 이번에 실행한 테스트가 아니다.

1. 세 항목 중 하나만 입력해도 저장되고 새로고침 후 값·출처·대상 날짜가 유지된다.
2. 미입력·대상 없음·0점·원장 오류가 구분된다. 휴식일이 자동 업무 실패로 집계되지 않는다.
3. 동일한 메모를 이틀 써도 각각 남고 같은 날짜의 중복 저장은 하나로 합쳐진다.
4. 완료일을 모르는 task, 참석 확인 없는 일정, 조회가 잘린 루틴에서 확정 달성도를 만들어내지 않는다.
5. 기준 변경 뒤 과거 값의 의미가 유지된다. 브랜드·시간대 변경이 과거 리뷰를 복제·재분류하지 않는다.
6. AI가 자기평가를 덮지 않고 명시되지 않은 점수를 만들지 않는다. 모델 품질은 별도 사례 검토로 확인한다.
7. 리뷰 저장·분석만으로 승인 큐나 task가 생기지 않는다. 선택한 행동 연결은 재시도해도 하나다.
8. 생성 중 편집, 모델 timeout, 생성 후 저장 실패, task 연결 실패에서 입력·생성 결과·연결 상태를 올바르게 보존한다.
9. 다음 리뷰의 실행·도움 피드백을 생략할 수 있으며 사용자 응답이 task 원장을 몰래 바꾸지 않는다. 보류·미응답·새 행동 채택·Council 재생성 뒤에도 이전 미확인 행동과 피드백이 남고 §7의 순서대로 하나만 표시된다.
10. 개인 주간 요약은 누락일을 0으로 넣지 않고, 회사 리포트로 개인 평가를 복제하지 않는다.

처음 3일은 기본 세 항목만 써보는 것을 권장한다. 기록이 1분 안에 끝나는지, 다음 날 다시 읽었는지, 고른 제안이 실제 도움이 됐는지를 관찰한다. 1분은 검증 전 목표다. 3일은 입력 부담을 확인하는 기간이며 패턴 효과를 입증하는 표본으로 해석하지 않는다.

첫 적용 후보는 R0다. 그 결과로 불필요한 항목을 덜어낸 뒤 R1·R2를 연결한다. 자유 항목 편집기, 자동 야간 Council, 여러 모델 토론, 종합 점수·랭킹, 외부 알림은 초기 검수 요건이 아니다.

## 11. 검토 상태와 참고

- 사용자 요청으로 확인한 것은 간단한 리뷰·평가와 Council의 연결을 탐색하고 기획을 이어간다는 방향이다. 기본 세 항목, 1~5/0~2 척도, 단계별 저장 설계는 이 문서의 권장안이다.
- 개인 기록의 부담을 줄이고 다음 행동을 기억한다는 기존 제품 목적을 따랐다. 업무·생활의 정확한 비중과 추가 항목은 실제 사용 후 조정한다.
- 현재 기능의 구현 상태와 새 제안을 구분했다. 앱·DB·유료 AI·외부 서비스의 동작을 이번 문서 작업으로 바꾸지 않는다.
- [Daylio](https://daylio.net/)의 기분·활동 선택 입력, [Exist 수동 기록](https://exist.io/page/help-manual-tracking/)의 사용자 정의 수치·시간·척도를 입력 형태의 참고로 사용했다(2026-09-12 확인). 이 문서의 기준·Council 루프·누락 처리 규칙은 Moonlight를 위한 별도 제안이다.
