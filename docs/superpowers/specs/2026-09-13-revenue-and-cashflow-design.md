# 매출·현금 흐름 탭 기획

> 상태: 초기 기능 범위 확정 · 상세 설계 권장안 · 구현 전
> 날짜: 2026-09-13
> 상위 정본: `docs/operator-workflow-profile.md`, `2026-07-13-moonlight-personal-operator-os-deep-design.md`
> 관계: `2026-08-31-personal-revenue-roadmap.md`의 거래 기반 30일 전망은 영업 전망으로 유지한다. 실제 현금 흐름과 분리하는 후속 설계이며, 기존 구현·내비게이션을 즉시 대체하지 않는다.

## 1. 이번 대화에서 확정한 범위

- 현금 흐름은 개인 사업의 수입·비용과 급여·생활비 등 개인 재정 전체를 관리한다.
- 탭 안에서 통합·분할 보기를 지원한다. 전체·사업·개인으로 범위를 선택한다.
- 은행·카드 자동 연동은 첫 버전의 필수 조건이 아니다. 직접 입력과 엑셀·CSV 가져오기로 시작한다.
- 계좌·카드별 관리, 계좌 잔액, 카드 결제 예정액을 첫 버전에 포함한다.
- 할부, 대출 상환, 구독·월세 등 반복 지출도 첫 버전에 포함한다.
- 아래 화면 구성·데이터·계산·출시 순서는 구체화를 위한 권장안이다. 상세 승인이나 구현 완료를 뜻하지 않는다.

## 2. 목적과 두 탭의 관계

매출은 “어떤 거래에서 얼마를 벌 수 있으며 다음에 무엇을 해야 하는가”를 답한다. 현금 흐름은 “현재 얼마가 있고, 언제 돈이 들어오고 나가며, 앞으로 얼마가 남는가”를 답한다.

| 표면 | 주요 내용 | 다음 행동 |
|---|---|---|
| 매출 | 영업 전망, 계약 금액, 수금 진행, 다음 행동 | 거래 갱신, 후속 연락, 입금 일정 등록 |
| 현금 흐름 | 계좌 잔액, 실제 입출금, 지급·수금 예정, 카드 청구 | 거래 기록, 일정 수정, 입금·결제 확인 |

현행 개인 매출 모델은 거래 종료 예정일과 단계로 전망을 계산한다. `closing`을 확정, `final`을 입금 대기로 분류하지만 실제 입금 증빙은 아니다. 이 분류를 현금 기록에 자동 복제하지 않는다. 매출 화면에서 계약일·입금 예정일·실제 입금일을 구분하고, 계약금·잔금처럼 하나의 거래에 여러 수금 일정을 연결한다.

ClassIn 회사 영업 실적은 회사 스코프에 남는다. 개인 현금 흐름에는 본인이 수령하는 급여·인센티브 등을 기록한다. 회사 계약금 전체를 개인 수입으로 합산하지 않는다.

## 3. 접근안 비교와 권장

| 접근 | 장점 | 비용·한계 |
|---|---|---|
| 하나의 기록 + 사업·개인 분류 + 두 보기 — 권장 | 이체·카드·혼합 사용을 한 번 기록하고 같은 합계를 여러 방식으로 조회 | 거래 분류와 정산 연결을 정확히 설계해야 함 |
| 사업·개인 기록을 완전 분리 | 각 범위를 독립 관리하기 쉬움 | 통합 조회와 범위 간 이체 대사가 복잡해짐 |
| 기존 영업 거래 모델에 금융 필드 추가 | 초기 변경량이 작음 | 급여·생활비·카드·대출이 영업 거래와 맞지 않아 확장에 부적합 |

권장안은 기존 영업 기록을 유지하고 별도 금융 기록을 연결한다. 금융 기록의 사업·개인은 사용 목적 분류이며 Hub의 회사·개인 workspace 권한과 별개다.

## 4. 현금 흐름 화면

상단에서 기간, 범위 `전체 / 사업 / 개인`, 보기 `통합 / 분할`을 선택한다. 기본값은 전체·통합·향후 30일을 권장한다. 기간은 이번 달·향후 30일·향후 90일·직접 선택을 제공한다.

- 요약: 현재 계좌 잔액, 예정 유입, 예정 유출, 기간 말 예상 잔액. 카드 미결제액은 별도 부채로 표시한다.
- 흐름: 실제와 예정이 구분된 날짜별 목록과 잔액 추이. 날짜 미정·기한 경과는 별도 목록에 남긴다.
- 계좌·카드: 계좌별 잔액, 카드별 미결제액·결제 예정일·출금 계좌.
- 반복·상환: 구독, 월세, 할부 회차, 대출 원금·이자 일정과 다음 지급일.
- 확인 필요: 미분류, 미연결 카드 결제, 중복 후보, 시작 잔액 미등록, 기한 경과 일정.

통합은 전체를 한 목록으로, 분할은 사업·개인 열을 같은 기간으로 비교한다. 모바일에서는 분할 열을 위아래로 배치한다. 단일 범위 선택 중에는 해당 열만 표시하고 보기 선호를 보존한다. 보기 변경은 데이터 복제나 이동을 일으키지 않는다.

계좌에 사업·개인 기본 용도를 지정하되 거래별로 변경하거나 금액을 나눌 수 있다. 혼합 계좌의 잔액은 사업·개인 거래 분류만으로 임의 배분하지 않는다. 분할 화면에 공통 계좌 영역을 두고, 사업·개인 전용 계좌 잔액과 구분한다. 전체 잔액은 모든 계좌를 한 번씩만 합산한다.

사업·개인 외에 미분류 금액을 보존한다. 통합 합계와 분할 합계를 맞출 때 미분류·공통·내부 이체 조정 내역을 확인할 수 있어야 한다.

## 5. 기록과 계산 계약

### 실제·예정·전망

- 실제: 운영자가 완료를 확인한 입출금. 수동 확인이라는 출처를 표시한다.
- 예정: 금액·지급 또는 수금일을 등록한 일정. 날짜가 지나도 자동으로 실제가 되지 않는다.
- 영업 전망: 아직 약정되지 않은 거래 기회. 기본 예상 잔액에서 제외하고 매출 탭에서 확인한다.
- 현재 잔액 = 계좌별 기준일 시작 잔액 + 기준일 이후 실제 유입 − 실제 유출.
- 향후 예상 잔액 = 현재 잔액 + 미래 미정산 예정 유입 − 미래 미정산 예정 유출.
- 부분 정산은 남은 금액만 예상에 포함한다. 초과 정산은 명시적으로 확인하고 음수 잔액 일정을 만들지 않는다.
- 과거 기한을 넘긴 미정산 일정은 기한 경과 합계로 분리하고, 새 날짜를 정하기 전 미래 일자에 임의 배치하지 않는다.
- 미래 시작 기간은 오늘부터 기간 시작 전일까지의 예정도 기초 예상 잔액에 반영한다. 과거 조회는 해당 날짜까지의 실제 기록으로 계산한다.
- 잔액 기준일 전 내역은 조회용으로 가져올 수 있으나 기준 잔액에 다시 가산하지 않는다. 기준일 포함 경계와 시작 잔액의 시각을 저장한다.

### 이체·카드·할부

- 내부 이체는 한 연결 ID 아래 출금·입금 두 항목을 원자적으로 기록한다. 통합 순현금 변화는 0이며 수입·비용으로 집계하지 않는다. 수수료는 별도 지출이다.
- 카드 사용은 비용과 카드 미결제액을 증가시키고 계좌 현금을 줄이지 않는다. 카드 대금 납부는 계좌 현금과 미결제액을 줄이며 비용으로 재집계하지 않는다.
- 체크카드 사용은 연결 계좌의 즉시 출금으로 처리한다.
- 신용카드 사용액은 청구 회차에 연결한다. 예상 청구액과 확정 청구액을 구분하고 운영자가 결제일·금액을 보정할 수 있다.
- 할부 구매는 소비 내역에 구매 총액을 한 번 표시하고, 현금 흐름에는 회차별 청구액을 반영한다. 총액과 회차 금액을 동시에 현금 유출로 더하지 않는다.
- 첫 등록 시 기존 카드 미결제액과 남은 할부를 입력할 수 있다. 이미 지난 비용을 신규 비용으로 만들지 않는다.
- 취소·환불은 원거래를 연결해 비용·미결제액 또는 현금 환입을 반영한다. 카드 청구액 감소와 실제 계좌 환급을 구분한다.

### 대출·반복 일정

- 대출 실행은 현금 유입과 부채 증가다. 매출·급여 수입에 포함하지 않는다.
- 원금 상환은 현금 유출과 부채 감소, 이자·수수료는 비용으로 별도 집계한다.
- 첫 버전은 잔여 원금과 운영자가 입력한 상환표를 사용한다. 금융기관의 이율·휴일 규칙을 추정해 확정 상환액으로 표시하지 않는다.
- 반복 규칙은 금액, 사업·개인 분류, 결제 수단, 시작일, 주기, 종료 조건을 가진다. 월말처럼 없는 날짜는 해당 월 말일로 처리한다.
- 회차는 규칙 ID와 회차 기준일로 유일하게 생성한다. 재조회·재실행해도 중복되지 않는다.
- 수정은 이번 회차만 또는 이후 미정산 회차에 적용한다. 이미 완료한 기록은 바꾸지 않는다. 해지는 미래 미정산 회차만 취소한다.
- 반복 구독의 카드 사용 예정과 그 카드의 대금 결제 예정을 연결한다. 계좌 예상 유출에는 대금 결제만 포함한다.

사업·개인의 거래 합계는 사용 목적을, 계좌 잔액은 돈의 보관 위치를 뜻한다. 이 두 축을 같은 숫자인 것처럼 표시하지 않는다. 제품상 비용·현금 분류 규칙이며 세무 신고용 회계 처리를 제공하는 범위는 아니다.

## 6. 입력과 가져오기

첫 설정은 계좌·기준 잔액 → 카드·출금 계좌·기존 미결제액 → 반복 지출·잔여 상환 → 향후 수입 순으로 진행하며 중간 저장을 지원한다. 모르는 값은 미등록으로 남기고 정확한 잔액처럼 0을 제시하지 않는다.

직접 기록은 날짜, 금액, 수입·지출·이체 유형, 계좌 또는 카드가 기본이다. 분류는 미분류로 저장할 수 있고 메모·거래처·영업 거래 연결은 선택이다. 실제 확인과 예정 등록은 서로 다른 동작이다.

엑셀·CSV는 파일 선택 → 열 매핑 → 날짜·금액·계좌 검증 → 중복 후보 확인 → 반영 결과 순으로 처리한다. 최초 공통 템플릿을 제공하고 임의 은행 양식을 자동 지원한다고 약속하지 않는다. 날짜 해석, 입출금 부호, 통화를 미리보기에서 확인한다.

가져오기 배치와 행별 식별자를 저장해 같은 배치 재시도를 중복 반영하지 않는다. 서로 다른 파일의 날짜·금액·설명이 같다는 이유만으로 자동 삭제하지 않고 중복 후보로 제시한다. 잘못된 행은 제외 이유를 남기고 정상 행 반영 수를 알린다. 되돌리기는 해당 배치의 미변경 행에만 적용하며 수정·정산된 행은 영향 확인 대상으로 남긴다.

초기 통화는 KRW를 권장한다. 다른 통화 입력은 변환 합산하지 않고 지원 범위 밖임을 표시한다. 외화·환율 자동 계산은 후속이다.

## 7. 데이터·기존 시스템 경계

논리 단위는 계좌, 카드, 실제 거래와 분류 배분, 예정 일정, 정산 연결, 반복 규칙, 할부·대출 계획, 가져오기 배치다. 확정 DB 테이블명은 구현 계획에서 정한다.

모든 기록은 사용자·workspace, 통화, 출처, 생성·수정 시각을 가진다. 금액은 원 단위 정수로 보관한다. 거래 분할 금액 합은 원거래와 일치해야 한다. 이체와 정산 연결은 원자적 쓰기로 보존한다. 중복 제출 키와 수정 시각 기반 충돌 처리를 적용한다.

영업 거래에는 참조 ID로 수금 일정을 연결한다. 영업 단계 변경만으로 입금 완료를 만들지 않는다. 은행 수동 내역과 수금 일정이 연결되면 실제 입금은 한 건만 유지한다. 계약 취소 시 실제 수령액을 삭제하지 않고 미정산 일정 취소와 필요한 환불을 별도로 기록한다.

Hub read는 repository를 사용하고 HTTP 200의 `status: error` 봉투를 확인한다. 쓰기는 기존 guard·server-write 경계를 따른다. 금융 기록을 ClassIn에 전송하지 않는다. 계좌 별칭·카드 별칭으로 운영하고 전체 카드번호·은행 비밀번호를 요구하지 않는다.

잔액 미등록, 조회 실패, 실제 빈 기록, 연결 전 preview를 구분한다. 일부 계좌를 읽지 못한 합계는 부분 집계로 표시한다. 저장 실패 시 입력을 유지하고 성공처럼 잔액을 바꾸지 않는다.

## 8. 구현 순서와 완료 기준

아래 순서는 개발 단위다. 1~4 전체가 이번에 합의한 첫 버전 범위이며 중간 단계를 전체 완료라고 부르지 않는다.

1. 금융 기록·계좌·직접 입출금·이체·전체/사업/개인 통합·분할 조회.
2. 신용·체크카드·청구·할부·반복 지출·대출·예상 잔액.
3. 엑셀·CSV 검증·중복 확인·반영 결과·되돌리기.
4. 매출 거래 수금 연결·부분 수금·미수금·환불 및 전체 흐름 검수.

- 사업 계좌에서 개인 계좌로 50만 원 이체: 두 잔액은 각각 변하고 전체 잔액·수입·비용은 불변.
- 카드로 12만 원 사용 후 대금 납부: 소비 12만 원, 현금 유출 12만 원, 납부 후 미결제액 0원.
- 30만 원 3개월 무이자 할부: 소비 총액 30만 원, 월 청구 10만 원씩, 총 현금 유출 30만 원.
- 원금 20만 원·이자 1만 원 상환: 현금 유출 21만 원, 부채 감소 20만 원, 비용 1만 원.
- 수금 예정 100만 원 중 40만 원 입금: 실제 40만 원, 잔여 예정 60만 원. 일정·입금의 중복 집계 없음.
- 구독 해지: 완료 이력은 남고 미래 회차만 취소. 같은 규칙 재실행·파일 재업로드·중복 제출로 거래 증가 없음.
- 혼합 계좌·미분류 거래 포함: 통합과 분할의 차이를 공통 잔액·미분류·이체 조정으로 설명 가능.
- 새로고침 후 입력·분류·정산 연결 유지. stale 수정 충돌, 실패 봉투, 가져오기 오류를 실제 빈 상태와 구분.

구현 시 도메인 계산·API 지속성·권한·중복/충돌 테스트, 루트 필수 검사, 데스크톱·모바일 사용 흐름 검수를 수행한다. 화면 작업 전 DESIGN.md 전체와 최신 내비 스펙을 확인한다.

## 9. 후속 범위

은행·카드 자동 연동, 외화 환산, 투자 자산 평가, 세무 신고·복식부기, 자동 이체·대출 실행은 이번 첫 버전 범위에 포함하지 않는다. 향후 별도 요구에 따라 설계한다.

## 10. 문서 검토 기록

- 확정 범위와 권장 상세를 분리했다.
- 예정 입금과 영업 전망, 소비와 현금 유출, 분류와 계좌 보유 잔액을 분리했다.
- 이체·카드 청구·할부·대출·부분 수금의 중복 계산을 예시로 확인했다.
- 기한 경과·기존 카드 잔액·혼합 계좌·가져오기 중복의 예외 경로를 정의했다.
