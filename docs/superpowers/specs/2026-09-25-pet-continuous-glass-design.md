# 펫 패널의 연속된 유리 표면

## 관계와 승인

운영자의 23:27 스크린샷과 제어 센터 비교, 이후 제안에 대한 `진행 ㄱㄱ` 승인을 반영한다.
`2026-09-25-pet-soft-reading-design.md`의 항목별 바탕·8~12pt 페더·목록 높이별 바탕을 대체한다.
기본 무채색 투명 유리, 흰 글자, 누름·드래그 동안만 캐릭터색을 표시하는 계약은 유지한다.

## 적용

- 빠른 기능과 지속 위젯은 창 크기에 고정된 네이티브 읽기 재질 하나를 공유한다. 제목·날짜·목록·빈 상태·하단의 개별 어두운 바탕을 제거한다.
- 외곽 `NSGlassEffectView(.clear)`와 광학 윤곽을 유지한다. 텍스트 패널의 공통 `NSVisualEffectView(.hudWindow)`는 외곽 안쪽 1pt에 날카로운 마스크로 배치한다. 별도 검정 채움은 추가하지 않는다. 빈 공간에도 공통 재질이 이어지는 것이 이전 설계와의 의도한 차이다.
- 배치 순서는 네이티브 유리 → 공통 읽기 재질 → 캐릭터색 한 층 → 광학 윤곽 → 텍스트다. 글자에 필터·그림자·불투명도 효과를 적용하지 않는다.
- 입력·선택 탭·버튼만 낮은 불투명도 채움과 1pt 윤곽으로 조작 가능성을 표현한다. 메모 입력 면은 글자 수와 무관하게 균일하다.
- 누름·드래그 색상은 님피아 42%, 나머지 52%로 낮춘다. 해제 후 0%, 접근성 재질에서는 기존 불투명 보호를 유지한다.
- 기존 창 크기·레이아웃 전환·펫 이미지·키보드·Hub 데이터 동작을 유지한다.

## 검증 계획

`swift run -j 2 MoonlightPetPreview --self-check`와 `.app` 빌드·기동 후 실제 앱에서 할 일 스크롤, 일정 빈 상태, 메모 전체 입력면, 키보드 전환·누름/드래그 복귀를 확인한다. 업무 데이터를 추가·변경하는 UI 테스트는 하지 않는다. 창 단독 캡처에서 데스크톱 합성 색을 확정할 수 없다는 제한을 기록한다.

## 검증 결과

- 변경 전·후 `swift run -j 2 MoonlightPetPreview --self-check` 통과: Metal 윤곽·투명 중심·누름/드래그 상태 복귀·공유 색상 상태·레이아웃·기존 로컬 저장.
- `./script/build_and_run.sh --verify`로 수정 바이너리의 번들·실행 프로세스 일치 확인.
- CUA 실제 앱: 할 일 목록과 헤더의 연속된 배경, 일정 빈 상태와 하단의 독립 검은 띠 제거, 메모 전체 면의 균일한 채움·포커스·캐릭터 걸침, ⌘2/⌘3 레이아웃 전환 확인. 업무 레코드를 추가하거나 완료 처리하지 않았다.
- 사용자 조작이 감지되어 스크롤/물리 드래그 검사는 중단했다. 드래그 상태 복귀는 기존 자체 검사로 확인했고 이번 변경은 이벤트 처리 코드를 바꾸지 않는다.
- 창 단독 캡처는 뒤의 데스크톱을 흰색으로 합성하므로 실제 바탕별 색감·대비 수치나 시스템 제어 센터와 동일한 굴절 품질을 검증했다고 주장하지 않는다. 시스템 재질의 공통 명암과 흰 글자를 유지하며 투명도 감소·대비 증가의 기존 보호 경로도 유지한다.
