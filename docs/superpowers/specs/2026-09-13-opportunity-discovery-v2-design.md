# 기회 탐색 2차 — 발견에서 판단까지

> 상태: 방향 승인(운영자 “ㄱㄱ”). 2A 구현·로컬 검증 완료, 2B·2C는 후속 단계. 관계: 09-13 1차 설계의 목록·상세 표현을 보강하며 저장·권한·충돌 계약은 유지한다. 배포/문의 크론 변경은 범위 밖이다.

## 승인된 발전 방향
- 구조: 발견하기 / 키워보기 / 다시 보기. 6단계 상태는 상세와 보조 필터로 유지.
- 디자인: 큰 현황 숫자와 중복 필터를 제거. 목록에 가능성·근거·다음 행동·검토 이유. 상세는 읽기 요약 후 편집. 처음 저장은 한 줄.
- 기능: 전체 기록 검색, 이후 출처 포착·작은 검증·결과 누적·실행 후 복귀.
- 넛지: 설명 가능한 계기, 기회별 한 개, 닫기·미루기와 반복 억제. AI/홈 알림은 별도 후속.

## 2A 구현 계약
- 서버 검색: q(최대300자), scope(all/personal/classin), view(discover/grow/revisit/all/due), status(all 또는 기존6상태), offset. 모든 검색 조건은 Supabase에서 페이지 제한 전에 적용. 문자열 특수 문자는 문자 그대로 검색. 상세 id 조회는 필터와 독립.
- 발견하기: captured. 키워보기: exploring/validating/connected. 다시 보기: paused/closed 또는 검토일이 도래한 미종료 기록. 전체와 6상태 보조 필터 제공.
- 날짜 기준 Asia/Seoul을 서버에서 계산. due는 날짜 도래·미종료만. 날짜를 브라우저 요청으로 받지 않는다.
- 최신순 updated_at desc,id desc, 페이지 40개 + 다음 존재 검사용1개. 기존 offset 호출 호환을 유지. 목록이 바뀌는 동안 snapshot 일관성을 주장하지 않음.
- 검색은 명시적 제출. 조건 변경 시 이전 요청 취소, 다음 페이지 초기화, 결과가 없는 상태와 조회 오류 구분. 저장 후 목록만 갱신하며 상세 입력은 보존.
- 관심 질문은 발견하기에서 research 방식의 한 줄 생성으로 시작. 새 필드나 AI 조사 없이 기존 본문에 확인할 질문을 기록.
- 상세: 기존 EditDrawer 계약 유지, 기존 기록은 기본 읽기 모드. 가능성·근거·가설·검증·결과·결정·링크·이력을 보이고 편집 버튼으로 동일 드로어의 입력 폼 진입.
- 검토일이 도래한 기회 최대3개를 별도 서버 조회해 상단에 제시. 전역 추천이나 중요도 순위로 표현하지 않고 “다시 보기로 한 기회”라고 표시. 2C 반복 억제/알림은 아직 없음.
- 실패/preview는 수치나 빈 목록으로 위장하지 않음. 링크는 저장된 실제 대상만. 현재 저장·재시도·revision 충돌 비교 유지.

## 2B·2C 다음 단계
2B: 출처 선택 연결, 검증별 결과 기록, 기존 task 연결·생성 복귀. 2C: 넛지 노출/미루기 저장과 요청형 AI 후보. 별도 데이터·실행 계약으로 진행하며 2A 완료에 포함하지 않는다.

## 검수
과거 페이지의 한국어/특수문자 검색, 회사/개인·상태 조합, 날짜 경계, 요청 경합, 저장 후 상세 보존, 이력, 모바일 가로 토글/오버플로, 기존 권한·실패 계약 회귀를 확인한다.

검색은 PostgREST ilike의 별표 별칭을 피하기 위해 정규식 특수문자를 모두 escape한 imatch를 사용한다. [공식 연산자 계약](https://docs.postgrest.org/en/v14/references/api/tables_views.html#operators)을 확인했고 운영 DB read-only 문법 검증을 통과했다.
