# Guru 도움 카드와 요청형 조언 — 개발 서버 시범 설계

> 상태: **운영자 방향 승인(2026-09-24), 구현 세부는 시범안**. 운영 배포와 자동 알림은 이 문서의 범위가 아니다.
> 관계: `2026-09-23-work-order-queue-reassessment-design.md`의 A 단계(승인 큐 정리)를 유지한다. B 단계의 제자리 승인·실행 연결은 이 시범안이 대신하지 않는다. `2026-09-21-council-mentor-guru-legend-operating-framework.md`의 Guru=실무 방법론, Legend=가치관 관점을 따른다.

## 목적과 위치

Guru는 매 판단을 대신하거나 일을 생성하지 않는다. 운영자가 요청할 때에는 기록과 질문에 맞는 실무 관점을 제공하고, 평소에는 읽고 지나갈 수 있는 짧은 팁을 준다. Legend는 별도 주간 카드로 판단의 관점을 환기한다.

첫 시범에서는 홈·오늘의 트리아지와 승인 대기 영역에 카드를 추가하지 않는다. 코칭·대화의 Guru 선택 화면에서는 현재의 긴 시작 안내를 `오늘의 관점` 카드로 대체한다. 영업·매출의 기존 `Guru 코칭` 패널은 대기 상태 설명을 세일즈 카드로 대체한다. 고객 상세의 기존 `Guru 전략 코칭` 진입점은 같은 위치의 상황 팁과 직접 요청 버튼으로 대체한다. 각 위치의 본문 면적은 기존 요소 안에서 해결한다.

## 카드와 출처 계약

- **하나의 선별된 카드 라이브러리**가 화면 문구와 요청형 조언의 참고 프레임을 공급한다. 카드에는 안정 ID, 분야, 인물, 방법론, 한 문장 요약, 쓸 때, 질문, 문서 경로·절을 둔다.
- 출처는 `docs/sales-guru-knowledge-base.md`, `docs/marketing-branding-gurus.md`, `docs/content-storytelling-people-v2.md`, `apps/engine/lib/legend-cards.ts`와 09-21 통합 프레임워크다. 문구는 **자료를 재서술한 요약**으로 밝히고, 명언이나 검증되지 않은 효과 수치를 인용하지 않는다. MEDDIC는 Dick Dunkel의 틀로 표기하며 Aaron Ross의 창안으로 적지 않는다.
- 일간 Guru는 서울 달력 날짜와 분야로, 주간 Legend는 서울 주차로 안정적으로 선택한다. 화면을 보고 있는 동안 자동 전환하거나 알림을 보내지 않는다. `다른 카드 보기`는 사용자가 직접 누를 때만 움직인다.
- `이 세션에서 숨기기`는 브라우저 세션에서만 기억한다. 카드 종류와 분야를 바꿨을 때도 숨김을 유지하며 `다시 보기`로 해제한다. 읽기·넘김·숨김은 API와 원장에 기록하지 않는다.
- 카드가 특정 고객의 사실을 읽지 못한 경우 “이 고객이 그렇다”는 추정을 하지 않는다. 상황 팁은 해당 화면에서 쓸 수 있는 **질문**으로만 표현한다. 고객별 진단은 사용자가 Guru를 직접 호출한 뒤에만 한다.

## 요청형 조언

카드의 `이 관점으로 묻기`는 질문 입력을 채우거나 Guru 화면으로 이동할 뿐 생성 호출을 시작하지 않는다. 실제 생성은 운영자의 전송·코칭 버튼에서 시작한다. Engine에는 선택된 카드의 짧은 방법론·출처와 실제 ledger 맥락을 분리해 전달한다. ledger에 없는 고객 반응·수치·결정자는 “확인되지 않음”으로 다룬다.

답변 기본형은 `관찰 → 적용할 프레임 → 물어볼 질문/고려할 선택`이다. 후속 행동은 운영자가 명시적으로 원할 때만 제시하고, 승인 큐 후보나 work_order 제목을 기본 생성하지 않는다. 외부 발송과 회사 CRM 자동 입력은 계속 금지한다. 생성 결과의 기록은 기존 `agent_runs`와 연동 상태 영수증을 사용하며, 카드 자체는 업무가 아니다.

## 실패와 검증

- 자료 카드 라이브러리는 빌드에 포함되므로 Supabase가 없어도 볼 수 있다. 고객 데이터나 AI 호출 실패는 기존 `preview`/`error`로 명시한다. 빈 고객 데이터에 가상의 기록을 채우지 않는다.
- 순수 함수는 서울 날짜 경계, 주차, 분야 필터, 수동 넘김의 결정성을 검증한다. UI는 페이지 전환과 숨기기 복원, 요청 전 무호출, 390px 가로 넘침, 다크·라이트 읽기성을 확인한다.
- Engine 계약 테스트는 기본 조언이 work_order를 강제하지 않고 선택된 근거를 명시하며, 후속 초안 전용 모드는 기존 JSON 계약을 유지하는지 확인한다.

## 시범 종료 기준

개발 서버에서 운영자가 카드의 밀도·문구·자리와 요청형 조언을 실제로 사용해 본다. 관찰 결과에 따라 카드 수와 노출 위치를 조정한 뒤 운영 적용을 별도로 진행한다. 성공 지표는 알림 수가 아니라 카드 열람 후 자발적 질문, 근거가 명확한 조언, 불필요한 큐 생성 0건이다.
