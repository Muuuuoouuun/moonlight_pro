### 2.1 D1 재결정 배경

운영자가 2026-06-20 프로덕션 배포(커밋 1635fa9 시점, 워크스페이스 트리 + 하단 접힘 그룹)를 다시 보고 "실용적"이라 평가했다. 그 버전의 실체는 세 가지 성질이다:

1. 매일 쓰는 목적지가 펼침 조작 없이 항상 1클릭.
2. 롱테일도 접혀 있을 뿐 사이드바 안에 존재.
3. 활성 라우트의 그룹은 자동으로 열림.

"활성 앵커만 자동 확장" 모델은 1번을 잃는다 — 오늘(Daily Brief)에서 Leads로 건너뛰려면 앵커 클릭(Overview 착지) 후 하위 클릭, 2단계가 된다. 반면 6/20 버전이 버려진 이유(워크스페이스×기능 이중 축, 기능 중복)는 7-14의 스코프 컨트롤이 이미 해결했다. 따라서 **6/20의 인터랙션 모델을 7-14의 IA에 이식**한다: 스코프 유지 + 단일 기능 축 + 수동 아코디언. ClassIn 스코프에서 매출·고객을 펼치면 옛 클래스인 워크스페이스 트리가 중복 없이 재현된다.

## 2.2 상단 3표면 경계 계약 (D5, 2026-07-16)

오늘·현황·내 작업은 모두 "여러 레인을 가로지르는 상단 표면"이라 역할이 겹쳐 보인다. 운영자가 "비효율 파악됨"이라 지적한 지점이다. 통합 대신 **각자의 단일 책임을 확정**해 경계를 명시한다. 새 상단 표면을 추가할 때는 이 셋 중 하나의 책임에 속해야 하며, 어디에도 안 맞으면 표면이 아니라 하위 뷰다.

| 표면 | 라우트 | 단일 책임 | 시간축 | 하지 않는 것 |
|---|---|---|---|---|
| **오늘** | `dashboard/daily-brief` | **판단 + 즉시 캡처** — 지금 주의할 신호·다음 결정, 그리고 놓치기 전에 한 줄 붙잡는 초고속 태스크 캡처 | 지금(오늘 하루) | 전체 집계(→현황), 다건 태스크 관리·실행 큐(→내 작업) |
| **현황** | `dashboard/overview` | **집계·시각화** — 매출·콘텐츠·프로젝트·자동화를 가로지르는 추세와 수치 | 기간(주·월 추세) | 개별 행동 실행, 판단 신호 |
| **내 작업** | `dashboard/work/my` | **실행** — tasks·deals·calendar를 한 줄씩 훑고 홈 드로어로 딥링크 | 실행 큐(처리 대상) | 추세 차트, 심층 편집(원본 표면이 담당) |

- **중복 회피 규칙:** 같은 데이터가 세 표면에 나오더라도 *목적*이 달라야 한다. 예: 열린 딜은 현황에선 "이번 달 파이프라인 금액 추세", 내 작업에선 "오늘 처리할 딜 한 줄", 오늘에선 "지금 마감 임박 딜 1건". 같은 표기·같은 상호작용이 두 표면에 중복되면 하나는 잘못된 위치다.
- **오늘의 태스크 캡처 (2026-07-16 QA 결정 A):** 오늘은 "판단"이 핵심이지만, 운영자가 신호를 보다가 **놓치기 전에 한 줄 붙잡는 초고속 캡처**(`QuickTaskCapture`)와 오늘 마감/긴급 태스크 요약(`TaskToday`)은 판단 흐름의 일부로 허용한다. 경계는 *양(量)*으로 긋는다 — 오늘은 "지금 붙잡고 오늘 마감 판단"까지, 필터·정렬·렌즈로 **다건을 관리·처리하는 실행 큐는 내 작업**이 정본이다. 두 표면의 캡처 입력은 같은 `/api/hub/tasks`로 수렴하므로 데이터는 갈라지지 않는다.
- **집계는 현황이 정본 (2026-07-16 QA 결정 B):** 오늘의 `MoreDetail`에 있던 파이프라인·퍼널·콘텐츠 집계 3카드는 현황과 중복이라 "현황에서" 링크 한 줄로 대체했다. 오늘의 `지표` 4개는 추세가 아닌 "지금 값"으로 판단 프레이밍이라 유지한다.
- **네이티브 표면 우선:** 내 작업의 각 항목은 심층 작업을 위해 원본(Deals 칸반·Projects 보드·Calendar)으로 딥링크한다. 내 작업 자체는 편집 허브가 아니다.
- 이 계약은 표면 *경계*만 규정한다. 각 페이지 내부 구성은 별도.

## 3. 사이드바 2레벨 IA

### 3.1 원칙

- 상위 앵커 세트는 **고정 계약이 아니다** (2026-07-15 운영자 정정). 같은 날 Overview 앵커(`dashboard/overview`, 오늘 바로 다음)가 운영자 지시로 추가돼 현재 7+2 구성이며, 비효율이 파악되면 추가·변경될 수 있다. 이 스펙이 규정하는 것은 앵커 개수가 아니라 **2레벨 아코디언의 동작 계약**이다.
- 3단 스코프(전체/ClassIn/개인)는 그대로.
- 매출·고객 하위의 `dashboard/revenue/overview` 라벨은 전역 Overview 앵커와의 혼동을 피해 `개요`로 표기한다.
- **하위가 있는 앵커는 셰브런 토글이 있는 수동 아코디언이다.** 펼침 상태는 `localStorage`(`mlp.nav.expanded`)에 영속되어 운영자가 자기 루프에 맞게 한 번 조정하면 유지된다.
- **활성 라우트를 소유한 앵커는 항상 자동으로 열린다** (`ownerAnchorKey(activePath)`). 자동 열림은 저장된 접힘 값을 덮어쓰지 않는다 — 해당 앵커를 벗어나면 저장된 상태로 복귀한다.
- 기본값(저장 상태 없음): **영업·매출 · 콘텐츠 펼침**, 나머지 접힘. 기본 노출 약 17행으로 데스크톱 뷰포트 안에 들어간다.
- 여러 앵커가 동시에 펼쳐질 수 있다 (수동 아코디언이므로).
- 하위 목적지가 하나뿐인 앵커(오늘 · 현황 · 내 작업 · 고객 연락)는 셰브런도 하위 목록도 렌더하지 않는다. (초기 스펙의 `할 일` 앵커는 병렬 작업에서 `내 작업`으로 대체됨 — 순수 투두는 Projects의 To-dos 뷰가 담당하고, 내 작업은 §2.2의 실행 표면이다.)
- 하위 항목도 앵커와 동일하게 스코프 인지형이다.
- `NAV_TREE`는 여전히 ⌘K 전체 카탈로그 정본이고, 사이드바는 `hub-nav.js` 계약만 소비한다 (07-14 스펙 §7 유지).

### 3.2 하위 매핑

| 앵커 | 전체 | ClassIn | 개인 |
|---|---|---|---|
| 영업·매출 | 개요 / Leads / Deals / Accounts / Cases | Deals / Leads / 세그먼트 / Accounts (동일 컴포넌트 → 동일 이름, D4) | 개요 / Leads / Deals / Accounts / Cases (`?scope=personal`) |
| 프로젝트 | Projects / Calendar / Roadmap / Decisions / Rhythm | Projects(classin) / Calendar / Roadmap / Decisions / Rhythm | Projects(brand) / Calendar / Roadmap / Decisions / Rhythm |
| 콘텐츠 | Queue / Studio / Campaigns | 콘텐츠(classin) | Queue(brand) / Studio(brand) |
| AI·자동화 | Agents: Chat / Orders / Council · Automations: Runs / Flows / Email / Webhooks / Sheets | 동일 (Sheets → classin 시트 동기화) | 동일 |
| 설정 | Settings / Evolution | 동일 | 동일 |

- 스코프별로 하위 항목의 **구성 자체가 다를 수 있다** (예: ClassIn 매출·고객에만 세그먼트).
- AI·자동화는 하위가 8개이므로 두 그룹 라벨(Agents / Automations)로 나눠 렌더한다. 그룹 라벨은 11px uppercase eyebrow, 클릭 불가.
- Calendar·Roadmap·Decisions·Rhythm은 현재 글로벌 라우트(`dashboard/work/*`)라 스코프와 무관하게 동일 경로다. 스코프별 필터링은 이 스펙의 범위가 아니다.

### 3.3 렌더링과 상태

- 하위 항목 행: 들여쓰기(좌측 인디케이터 라인 또는 22px 인덴트), 높이는 상위보다 작게(28px), 텍스트 12px 이상.
- 활성 하위 항목: 정확 라우트 매칭으로 단 하나만 강조. 상위 앵커는 `aria-current="page"` 유지, 하위 활성은 배경 `--surface-3` + 텍스트 `--fg`.
- 셰브런은 앵커 행 우측, 12~13px, 접힘 시 -90° 회전. 앵커 라벨 클릭 = 대표 경로 이동, 셰브런 클릭 = 토글만 (이동 없음) — 클릭 영역을 분리한다.
- 토글 버튼에 `aria-expanded` 실제 상태 반영 (DESIGN.md §11 펼침/접힘 계약).
- 펼침 애니메이션 160~200ms, `prefers-reduced-motion` 존중.
- 카운트 배지(연락·후속 등)는 1레벨 유지. 하위 레벨 카운트는 Phase 2로 미룬다. **접힌 앵커의 하위에 배지 대상이 생기면(Phase 2) 앵커 행에 합산 표기**해 접힘이 신호를 숨기지 않게 한다.

### 3.4 접힌 레일과 모바일

- 56px 접힌 레일: 하위 목록 없음. 앵커 아이콘 8개 유지, 클릭 시 대표 경로 이동. 하위 접근은 펼침 또는 ⌘K.
- 모바일 드로어: 데스크톱과 동일한 활성 앵커 자동 확장. 하위 항목도 44px 터치 타겟, 선택 시 드로어 닫힘. 기존 inert/ESC/포커스 복원 동작 유지.

## 4. PMS 분류 체계

### 4.1 데이터 계약

- `brands.meta.category` 한 필드만 사용한다: `'sns-channel' | 'ka-deal' | 'general'`. **스키마 변경·마이그레이션 없음** — 기존 meta jsonb 재사용.
- category가 없거나 값이 셋 밖이면 `general`로 읽는다 (읽기 fallback, 추측 기입 아님).
- 기존 채널 9개는 운영자 확인 후 `sns-channel`로 기입한다. 코드가 채널 여부를 추측해서 자동 배정하지 않는다.
- category는 orgScope(클래스인/개인)와 직교한다. 클래스인 그룹 아래에도 SNS 채널 폴더가 있을 수 있다.

### 4.2 사이드바(브랜드 트리) UI

- 상위 그룹 `업무 · 클래스인` / `개인`은 유지.
- 각 그룹 아래에 카테고리 폴더를 렌더한다: `SNS 채널` / `KA·딜` / `일반`. 항목이 0개인 폴더는 렌더하지 않는다.
- 폴더는 접기/펼치기 가능(`aria-expanded`), 기본 펼침. 접힘 상태는 `localStorage`(`mlp.pms.folders`)에만 저장.
- 사이드바 헤더 라벨 `Brands` → `분류`, 부제 카피도 "브랜드 포맷"에서 중립 표현으로 조정.
- 생성/편집 드로어(EditDrawer)에 카테고리 선택 필드를 추가해 새 컨테이너(KA·딜 프로젝트 등)가 브랜드와 동급으로 만들어질 수 있게 한다.

### 4.3 비목표

- 프로젝트 단위 다중 태그 (폴더 = 컨테이너 단위 단일 분류로 시작)
- 카테고리별 집계 API, 서버 저장 폴더 상태
- 딜(CRM) 레코드와 PMS 프로젝트의 자동 연동 — KA·딜 폴더는 우선 수동 생성 컨테이너

## 5. 글리프 처리 (단색·축소)

- 목록 행: 글리프 유지하되 **12px · `var(--fg-faint)` 단색**, 고정폭 18px 박스로 열 정렬 유지. 활성 행은 `var(--fg-muted)`.
- 선택된 브랜드 헤더·디테일 패널: 14~16px, `var(--fg-muted)` 단색.
- 톤 컬러는 글리프에 적용하지 않는다 — 톤은 기존대로 Badge/Dot에만.
- 크기 플로어 준수: 12px는 데이터 값 플로어와 동일, 10px 미만 금지 규칙 위반 없음.

## 6. 검증

### 계약/단위

- 모든 하위 항목이 3개 스코프에서 경로를 해석한다.
- 활성 라우트당 강조되는 하위 항목은 최대 1개.
- 활성 라우트를 소유한 앵커는 저장 상태와 무관하게 펼쳐진다. 저장 상태가 없으면 기본값(매출·고객·콘텐츠 펼침)이 적용된다.
- 저장된 펼침 값이 손상/이상값이면 기본값으로 fallback.
- 하위 1개짜리 앵커는 셰브런과 하위 목록을 렌더하지 않는다.
- `NAV_TREE` 카탈로그(⌘K)는 그대로 전 목적지를 노출한다.
- category 미기입/이상값 → `general` fallback.
- 빈 카테고리 폴더 미렌더.

### 브라우저

- 1440px 펼침/접힘, 390×844 드로어에서 2레벨 동작.
- 셰브런 토글 → 새로고침 후 상태 유지. 접힌 앵커의 하위 라우트 진입 → 자동 열림, 이탈 → 저장 상태 복귀.
- 기본값 상태(매출·고객·콘텐츠 펼침)에서 세로 스크롤 없이 8앵커 전부 도달 가능 (1440×900 기준).
- 키보드 순회·focus-visible·reduced-motion.
- 글리프 단색·축소 후 다크/라이트 테마 대비 확인.
- 가로 오버플로 없음 (390/768/901/1440).
