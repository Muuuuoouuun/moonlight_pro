# Guru 입력 → 판단 → 업무 연결 점검

> 상태: **AUDIT / 후속 설계 미승인** · 2026-09-23 KST. 코드를 읽고 서울 운영 DB와 로컬 `/api/hub/daily-brief`를 조회한 결과다. 이 문서는 기존 [작업 지시 큐 승인 설계](2026-09-23-work-order-queue-reassessment-design.md)의 결정을 바꾸지 않는다.

## 현상과 원인

- 홈·오늘은 같은 Daily Brief 신호를 읽는다. 이전의 “승인 대기 12건 — guru 4 · council 8”은 최근 Guru 실행이 보내는 새 알림이 아니었다. `daily-brief/route.js`가 저장된 `work_orders(proposed)`를 읽을 때마다 `queue-approvals` 신호로 재구성했다.
- 2026-09-23 점검 당시 서울 DB의 최근 Guru 실행은 7월 12일, 최근 작업 지시 생성은 8월 4일이었다. 기존 대기 13건을 운영자 요청에 따라 `dismissed`로 정리한 뒤 로컬 API의 `queue.pending`은 0이다. 이 처리는 제안 이력을 삭제하지 않았다.
- 현재 코드의 Guru 크론은 Vercel 설정에 있으나 운영 Vercel 환경 변수는 0개다. 운영 중 무작위로 매일 실행됐다는 근거는 없다. 연결 시에는 정체 딜 상위 3개로 초안을 만들며, `proposed` 항목만 중복 검사해서 보류한 제안을 재생성할 수 있다.

## 본질 우선의 후속 순서

1. **입력의 근거를 좁힌다 (권장).** Q117 확정 순서에 맞춰 추적 대상과 도래한 다음 연락일을 먼저 쓰고, N일 무접촉만으로 자동 초안을 만들지 않는 방향을 검토한다. 제안마다 고객·약속일·최근 활동의 원본 링크와 생성 이유를 남긴다.
2. **제안과 실제 행동을 연결한다 (권장).** Guru 제안에서 연락 기록 폼 또는 “업무에 연결”로 이동하고, 실제 `crm_activities` 또는 task 저장 영수증이 확인될 때만 제안을 완료 처리한다. `approved`는 실행 완료라고 부르지 않는다.
3. **재발을 막는다 (권장).** 보류·완료·최근 생성 기록을 포함한 재생성 방지 키와 유효 기간을 둔다. 같은 딜의 같은 근거가 새 정보 없이 다음 날 다시 승인 대기가 되는 것을 막는다.
4. **측정한다.** 하루 생성 수, 같은 대상의 재생성 수, 원본 근거가 있는 비율, 연락 기록·할 일로 연결된 비율을 남긴다. 알림 수 자체를 성공 지표로 삼지 않는다.

## 이번 변경의 범위

기존 승인 설계 A1과 A2의 첫 화면 신호 제거까지 구현했다. A0·A2의 보조 카드 읽기 전용화·A3~A5(필터, 정확한 건수, 삭제, 되돌리기), B 단계의 Guru 생성 기준·결과 연결은 아직 남아 있다. 기존 계획에서 운영자 확정인 A→B 순서를 유지한다.
