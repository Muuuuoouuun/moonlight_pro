# Guru 분야·인물 이중 탐색과 세일즈 12인 연결

> 상태: **운영자 방향 승인(2026-09-24) · 격리 개발 서버 구현·검증 완료, 운영 반영 별도**. 운영자는 세일즈 자료의 12명과 카드 5장의 차이를 지적하고 분야별·인물별 탐색을 함께 요청했다.
> 관계: `2026-09-24-guru-three-slot-context-quality-design.md`의 분야별 **각 5장 시작 수량**을 편집 초기값으로만 해석한다. 이 문서가 세일즈 인물 확대와 서가의 탐색 구조를 대체한다. 하루 세 번 한 장, Legend 주간 한 장, 무알림·무자동 업무의 원칙은 유지한다.

## 1. 서로 다른 세 가지 수

- `docs/sales-guru-knowledge-base.md`의 독립 본문은 12명이다: Zig Ziglar, Dale Carnegie, Napoleon Hill, Joe Girard, Brian Tracy, Grant Cardone, Jordan Belfort, Neil Rackham, Chris Voss, Aaron Ross, Jason Lemkin, Keenan.
- Dick Dunkel은 문서의 독립 12인에는 없지만 MEDDIC의 창안자를 정확히 표시한 기존 카드 인물이다. 세일즈 인물 서가에서는 12명과 별도 1명, 총 13명을 찾아볼 수 있다.
- `카드 수`는 편집·출처 확인이 끝난 관점의 수다. `현재 팁`은 매 시간대에 실제로 노출되는 한 장이다. 인물 수, 카드 수, 한 화면에 보이는 수를 같은 카운트로 표시하지 않는다.
- 2026-09-25 상황 적합성 재점검 후 세일즈 13명·13장 가운데 자동 순환 가능 5장, 직접 열람 전용 8장이다. 2026-09-24의 8장·5장은 당시 상태다. 마케팅과 콘텐츠는 각각 검수 카드 5장이다. 이 수는 편집 현황이며 시간대에 동시에 표시되는 장수가 아니다.
- 마케팅 원본 3명은 현재 검수 카드로 모두 연결된다. 콘텐츠 원본의 10개 인물·복합 항목은 아직 일부만 카드화됐고, 콘텐츠 카드 중 Donald Miller는 마케팅 문서 출처다. 인물별 탐색의 숫자는 **검수 카드가 있는 인물**을 뜻하며 원본 문서 전원 검증 완료를 뜻하지 않는다.

## 2. 카드와 로테이션의 경계

- 각 세일즈 인물은 적어도 한 장의 출처 확인 카드로 인물별 서가에 들어간다. 새 카드의 표현은 인용이 아닌 편집 요약이고 원전 URL, 문서 절, 적합 상황, 적용 제외 범위를 기록한다. 정확한 효과 수치·검증되지 않은 고객 반응·강압적 클로징은 옮기지 않는다.
- 자동 팁은 서울 기준 09·14·19시에 분야·현재 화면의 확인된 상황에 맞는 **한 장**을 고른다. 인물별 서가는 이 시간대 선택과 독립적인 수동 탐색이다. 인물에게 카드가 한 장이면 그 인물의 카드가 하루 세 번 바뀐다고 설명하지 않는다.
- Hill의 목적 설정, Cardone의 자기 활동 점검, Belfort의 비적합 고객 선별은 수동 열람 카드로 시작한다. Girard의 계약 후 관계는 현재 `active`·`dormant` 고객 구분만으로 계약 상태를 확인할 수 없어 수동 열람에 둔다. Lemkin의 고객 성공 관점도 현재 고객 단계만으로 SaaS·반복 서비스 여부를 확인할 수 없어 수동 열람에 둔다. 고객에게 무엇을 하라는 자동 팁으로 노출하지 않는다. 제품의 주간 `Legend`는 세일즈 문서의 ‘올타임 레전드’ 분류와 별개다.
- 2026-09-25에 MEDDIC·SPIN·Voss도 직접 열람 전용으로 옮겼다. `new`·`active`·`dormant`는 고객 구분일 뿐 제안의 내부 검토, 문제 진술, 긍정 답변을 증명하지 않는다. Ross는 새로 들어온 고객의 첫 접촉을 조건으로 문구를 좁혀 `new`에서만 순환한다. 다른 네 자동 카드는 고객 단계만으로 확인할 수 없는 사건을 전제하지 않는 질문으로 바꿨다.
- 카드는 `personId`, `personName`, `methodLabel`을 별도 필드로 가진다. `listGuidancePeople({domain})`는 인물 목록을, `listGuidanceCardsForPerson(personId)`는 해당 인물의 검수 카드를 반환한다. 자동 선택은 수동 전용 카드를 제외하지만 인물별 서가와 명시적 질문은 사용할 수 있다.

## 3. 화면과 질문

- `코칭·대화`의 현재 Guru 1장과 Legend 1장은 유지한다. 서가 하단의 기존 `다른 분야 둘러보기` 공간을 `멘토 찾아보기`로 교체하고 `분야별 / 인물별` 세그먼트를 둔다. 분야별은 세일즈·마케팅·콘텐츠 중 하나를 고른 다음 그 분야의 검수 카드 전체를 **방법론 이름 중심**으로 직접 탐색한다. 인물별은 선택 분야 인물을 **이름 중심**으로 고른 다음 해당 인물의 검수 카드·출처를 펼친다. 두 방식 모두 자동 시간대 카드와 독립적이다.
- 레일에는 인물 목록을 넣지 않는다. 상황형 한 장과 서가 이동 링크를 유지한다. 인물 카드의 질문은 선택한 카드 ID로 기존 요청형 Guru 경로를 연다. 열람·전환·카드 넘김만으로 생성, 알림, 승인 큐 기록은 발생하지 않는다.
- 이름·분야 선택 버튼은 키보드로 접근 가능하고 44px 터치 높이를 지킨다. 데스크톱에서는 인물 목록과 선택한 카드를 나란히 두어 카드가 목록 아래로 밀리지 않게 한다. 모바일에서는 인물 선택 후 카드 본문으로 초점을 이동시켜 바로 읽을 수 있게 한다. 390px에서 가로 넘침이 없어야 한다. 인물별 탐색은 기존 서가 안에만 두어 별도 내비게이션을 만들지 않는다.

## 4. 확인

- 원본 12명+Dick Dunkel 1명의 인물 인덱스, 각 인물의 카드·출처 링크, 수동 전용 카드의 자동 선택 제외, 하루 세 시간대의 한 장 선택과 상황 적합성을 테스트한다.
- 분야별 전체 카드와 인물별 카드 전환, 출처 표시, 선택 카드 ID를 이용한 질문 경로, 탐색 중 무네트워크·무업무 생성, 모바일 터치·가로 넘침을 확인한다. 개발 서버에서 실제 카드 열람·질문 왕복을 확인하되 운영 적용은 별도다.

### 개발 서버 확인 기록 · 2026-09-24

- 데스크톱과 390px에서 분야별 전체 카드·인물별 목록·원전·질문 드로어를 확인했다. 서가의 분야 전환은 상단 시간대 카드를 바꾸지 않았고, 390px에서 가로 넘침이 없었다.
- 수동 열람 Girard 카드를 `open-question`으로 한 번 요청해 조언 생성과 실행 기록을 확인했다. 개발 서버의 샌드박스 DB에 빠져 있던 `0044`·`0046` 마이그레이션을 대상 ref 검증과 함께 적용한 뒤 같은 경로에서 연결 기록·동기화 기록의 저장도 확인했다. `db:check`에 `0046`의 열·유니크 인덱스·이전 인덱스 제거 검증을 추가했다. 서울 운영 DB는 이 스키마가 이미 적용된 상태였고 이번 작업에서 변경하지 않았다.
- 샌드박스의 전체 `db:check`에서는 `0046` 항목이 통과하지만 다른 14개 기능은 준비되지 않아 명령 전체는 실패한다. 이번 Guru 질문 경로의 성공과 샌드박스 전체 기능의 준비 상태를 같은 것으로 보지 않는다.
- 전체 테스트 2,860개 중 통과 2,849·건너뜀 11·실패 0, Hub 빌드 및 타입 검사를 통과했다.
