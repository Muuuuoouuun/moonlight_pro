# 기회 탐색 — 대화에서 포착하는 기회 신호

> 상태: **신호 목록은 운영자 입력 / 동작 설계는 제안 / 자동 판정 기준 미확정 / 구현 전**.
> 근거: 2026-09-13 운영자 “대면 미팅, 반복된 연락2회 나 장시간 통화, 선제적 결제 일정 발언”.
> 관계: discovery-nudge-design의 현재 문맥별 제안을 보강할 후속 설계. 기존 검토 날짜·연결 할 일 완료·기록 보강의 규칙, 미루기·숨김·해제 계약을 변경하거나 배포한 문서가 아니다. operator-workflow-profile §8의 기존 순위·§11의 프로젝트 후보 기준도 대체하지 않는다.

## 1. 확인된 입력

| 관찰 신호 | 사용자에게 받은 기준 | 자동 판정에 필요한 추가 정의 |
| --- | --- | --- |
| 대면 미팅 | 대면 미팅 | 예정/완료 중 어느 시점을 셀지, 대면 여부 기록 |
| 반복 연락 또는 깊은 통화 | 연락 2회 또는 장시간 통화 | 연락 집계 기간, 횟수를 셀 대화 단위, 무응답 발신 포함 여부, 장시간의 분 기준 |
| 선제적인 결제 일정 발언 | 선제적으로 결제 일정에 관해 말함 | 발언 주체·원문·확인 여부, 구체 날짜 존재 여부 |

신호 목록 순서는 중요도 순위나 가중치의 확정으로 취급하지 않는다. ‘장시간’을 임의의 분 수로 바꾸거나 ‘연락 2회’에 임의 기간을 붙이지 않는다.

## 2. 제안하는 화면과 행동

현재 한 기회당 하나의 주요 행동을 보여주는 넛지 구조를 이어간다. 사실 배지는 색으로 단계를 올리기보다 근거를 짧게 표시한다.

| 관찰 사실 표시 예 | 제안할 다음 행동 |
| --- | --- |
| 대면 미팅 기록 | 미팅에서 확인한 문제와 다음 검증 정리 |
| 연락 2회 · 원문 2건 | 반복되는 요구를 기회로 검토 |
| 장시간 통화 · 기록 확인 | 핵심 요구와 후속 행동 정리 |
| 고객이 결제 시점 먼저 언급 · 원문 | 결제 일정과 남은 확인사항 정리 |

위 문구와 동작은 설계 제안이다. 실제 상대의 발언을 예시로 만들지 않는다. 신호에서 원문·발생일·연결 고객/기회로 돌아갈 수 있게 한다. 기존 후보가 있으면 같은 기회에 근거를 연결하는 방향을 우선 검토한다.

미확정 기준 상태에서 가능한 방식은 두 가지다.

- **직접 확인 방식(우선 제안):** 활동 기록을 보며 운영자가 신호를 직접 표시. 기간·분 기준을 발명하지 않고 대화의 맥락을 보존할 수 있다.
- **구조화 자동 감지:** 연락 단위·기간·통화 시간·대면 여부를 저장하고 정의된 조건으로 감지. 기준과 입력 경로가 갖춰진 뒤 활성화한다.

하나의 고객에 여러 신호가 생겨도 제안을 신호 개수만큼 늘리지 않고 근거를 묶는다. 현행 미루기·숨김·해제 동작과 중복 억제를 상속한다. 강한 신호가 표시돼도 영업 단계·결제 상태를 자동으로 확정하지 않는다.

## 3. 현재 코드에서 확인한 범위

- `apps/hub/lib/repositories/crm-activities.js`: 종류(kind), 본문(body), 발생일, 연결 lead/deal/account를 기록한다. 현재 write 입력에는 대면 여부·통화 시간·선제 발언 표식이 없다.
- `supabase/migrations/20260716_0016_crm_activities.sql`: 반응(reaction)과 meta 저장 공간은 있으나 이 신호의 필드 계약은 없다.
- `supabase/migrations/20260716_0018_record_contact_outcome.sql`: 연락 결과 요약·반응·다음 행동/날짜를 저장한다. 장시간이나 선제 발언을 별도 인자로 받지 않는다.
- `apps/hub/lib/discovery.js`: 기회에는 근거·가설·검증·결과와 실제 업무 링크가 있으며 활동 신호용 저장 필드는 없다.

따라서 기존 meeting 전체를 대면으로 간주하거나 note 본문에 ‘결제’가 있다는 이유만으로 고객의 선제 발언을 확정하면 안 된다. 누락값은 미확인으로 남기고 운영자가 근거를 확인할 수 있게 한다.

## 4. 구현 전 확인과 검증 기준

운영자에게 반복 연락 집계 기간·장시간 통화 기준을 질문한 상태다. 답변이 없으면 수치형 자동 감지를 활성화하지 않는다. 대면 완료 여부·대화 집계 단위·발언 주체 해석은 구현 설계에서 확정 입력과 분리해 제시한다.

구현 시에는 동일 활동 중복 집계, 무응답·예정 일정 오인, 통화 시간 누락, 잘못된 고객/기회 연결, 인용·가정·타인의 결제 발언 오인, 숨긴 제안 재노출을 검증한다. AI 원문 분석·외부 메시지 발송·영업 점수 변경·운영 DB/배포는 현재 문서 정리에 포함하지 않는다.
