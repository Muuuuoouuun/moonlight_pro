# 레퍼런스 모아보기와 편한 입력 — 첫 구현 범위

> 작성: 2026-09-21 · 상태: **우선순위는 운영자 확정 / 상세 동작은 권장안 / 구현 전**
>
> 운영자 지시: “무엇보다 사용성, 편의성에 중점. 레퍼런스 모아보기, 내가 편하게 입력하는 것부터 구현하려고 해.”
>
> 관계: [09-20 레퍼런스·글쓰기 기획](2026-09-20-reference-library-writing-workflow-design.md)의 §3·§6·§9에서 Studio 연결을 먼저 두었던 **첫 구현 순서를 대체**한다. 그 문서의 출처·확인 수준·내 경험 구분은 유지한다. `reference_packet`, AI 입력, 원고 생성은 후속 설계이며 이번 첫 구현의 필수 조건이 아니다. 아래 화면·필드·세부 동작은 구현 전에 검토할 권장안이다.

## 1. 첫 사용의 목표

사용자는 링크나 생각을 그대로 넣고 저장할 수 있어야 한다. 다음 방문에는 기억나는 단어로 다시 찾고, 원본과 당시 메모를 읽을 수 있어야 한다. 저장 시 글의 질문·브랜드·발행 채널·분류·출처 확인 수준을 작성하도록 요구하지 않는다.

**붙여넣기 → 저장 → 다시 찾기**를 첫 완성 단위로 삼는다. 입력이 끝난 뒤 제목이나 분류를 보완할 수 있으며 정리하지 않은 자료도 정상적인 저장 자료다. 저장 수나 분류 완성률을 성과 지표처럼 앞세우지 않는다.

## 2. 진입과 첫 화면

콘텐츠 영역에 **자료함**을 두는 안을 권장한다. 이름과 사이드바 위치는 기존 정보 구조에 맞춰 확정하되, 새 최상위 업무 영역을 만들 필요는 없다. 자료함 안에서 외부 레퍼런스와 직접 적은 생각을 함께 찾고, 필요할 때 종류로 좁힌다. 외부 자료와 내 글은 데이터상 구별하되 저장 전에 사용자가 종류를 선택하게 하지 않는다.

첫 화면의 순서는 다음과 같다.

1. **빠른 입력:** “링크나 생각을 붙여넣으세요” 입력란과 저장 버튼.
2. **검색:** “제목, 메모, 내용으로 검색”과 접힌 추가 필터.
3. **목록:** 최근 저장순. 전체·즐겨찾기를 간단히 전환하고, 플랫폼·주제는 필요할 때 필터를 펼친다.

첫 기본 목록은 사용자의 최근 저장 자료다. 기존에 선별한 26개는 “먼저 살펴볼 자료”라는 선택 가능한 묶음으로 제공한다. 선별 묶음이 새로 저장한 자료를 밀어내거나 개인화 추천으로 표시되지 않게 한다.

기본 보기로 간결한 목록을 권한다. 제목·내 메모 일부·출처·저장일·즐겨찾기를 보여 주고, 확보한 미리보기 이미지는 보조적으로 사용한다. 이미지가 없는 자료도 같은 밀도로 읽을 수 있어야 한다. 카드·그리드 전환은 첫 범위에서 제외한다.

## 3. 한 칸 입력 계약

| 입력 | 저장 동작 |
| --- | --- |
| 링크 하나 | 링크만으로 저장. 플랫폼·주소를 바탕으로 임시 표시 제목을 만들고 원문 제목이라고 단정하지 않음 |
| 생각이나 메모 | 그대로 저장. 첫 줄을 목록 표시 제목으로 사용하고 본문을 보존 |
| 링크와 내 메모 | 같은 자료에 원본 링크와 내 메모를 구분해 보관. 붙여넣은 전체 입력도 보존 |
| 인용문과 내 말이 섞인 글 | 입력 원문을 보존. 어느 부분이 원저자 발언인지 자동으로 확정하지 않음 |
| 여러 링크 | 추출한 링크 목록을 확인시켜 링크별 저장 또는 한 메모로 저장을 선택. 확인 전 여러 레코드를 자동 생성하지 않음 |

필수는 비어 있지 않은 입력 하나다. 제목·왜 저장했는지·태그·폴더는 선택 입력이며 초기 입력란에서 펼치지 않는다. 자료가 개인 범위에 저장됨을 작은 목적지 표시로 알린다. 회사 영역에서 시작했다면 현재 범위를 표시하고, 전체 보기에서 새로 입력할 때 기본은 개인으로 둔다. 조용히 회사 범위로 분류하지 않는다.

입력란은 여러 줄을 허용한다. Enter는 줄바꿈, Cmd/Ctrl+Enter는 저장으로 통일하고 한글 조합 중 키 입력으로 저장되지 않게 한다. 모바일은 명시적인 저장 버튼을 사용한다.

저장 후 화면을 이동하지 않고 입력 포커스를 유지한다. 새 자료가 목록에 나타나며 “저장됨 · 열기”를 제공한다. 초안 화면으로 자동 이동하지 않는다.

## 4. 저장을 기다리게 하지 않는 보완

링크 제목·미리보기 등 외부 정보 확인은 원본 입력의 저장과 분리한다. 외부 정보를 얻지 못해도 저장은 성공할 수 있다. 이때 URL과 내 메모를 바로 보여 주고, “링크만 저장됨”과 “내용 확인됨”을 구별한다. 제목 확보를 본문 요약이나 원문 분석 완료로 표시하지 않는다.

동일 플랫폼의 동일 게시물 ID 또는 보수적으로 정규화한 동일 URL이 있으면 기존 자료를 안내한다. 기존 자료 열기·메모 추가를 우선 제공하고 별도 저장도 선택할 수 있게 한다. 자동 병합으로 예전 메모를 덮어쓰지 않는다. 의미가 불분명한 URL 매개변수는 제거하지 않는다.

메타데이터가 늦게 도착해도 사용자가 직접 바꾼 제목·메모는 유지한다. 제목을 가져오는 공급 경로가 구현 시점에 검증되지 않으면 링크 저장부터 출시할 수 있다. 광범위한 자동 본문 수집은 첫 출시 조건이 아니다.

## 5. 읽기와 수정

목록을 누르면 데스크톱에서는 옆 상세 패널, 모바일에서는 읽기 공간을 충분히 확보한 상세 화면으로 연다. 뒤로 돌아오면 검색어·필터·스크롤 위치를 유지한다.

상세 순서는 **제목과 원본 열기 → 내 메모 → 확보된 요약·원문 발췌 → 확인 범위**다. 출처 주장과 내 메모는 분리한다. 긴 분석과 기술적인 확인 이력은 접어서 보여 주되 접근할 수 있어야 한다.

제목·내 메모·태그·즐겨찾기는 바로 고칠 수 있게 한다. 입력 임시는 로컬에 보존하고, 편집한 값은 자동 저장과 저장 중·저장됨·실패 표시로 상태를 알린다. 실패하면 쓴 내용을 유지하며 같은 변경을 재시도할 수 있어야 한다. 원문 요약을 사용자가 고친 경우에는 원래 수집한 내용과 사용자 편집을 구분한다.

삭제는 복구 가능한 휴지통으로 이동한다. 저장·수정·삭제를 실수했을 때 다시 입력하거나 원자료를 잃는 일이 없도록 한다.

## 6. 어디서나 편하게 입력

자료함의 입력을 먼저 완성하고 동일 입력 흐름을 기존 전역 빠른 입력에도 연결한다. 사용자는 다른 화면에서 자료를 넣고 하던 일로 돌아갈 수 있어야 한다. URL이 들어 있다는 이유만으로 기존 할 일·업무 메모를 자료함으로 자동 이동하지 않는다. 목적지가 자료함일 때 위 저장 계약을 적용한다.

첫 출시는 데스크톱·모바일 웹의 붙여넣기와 직접 입력을 지원한다. 이미지 첨부·OCR, 모바일 공유 메뉴, 브라우저 확장, 음성·메신저 수집은 반복 사용에서 실제 불편을 확인한 뒤 순서를 정한다. 이들 입력 경로를 동시에 만들지는 않는다.

## 7. 첫 출시 범위와 순서

| 순서 | 실제로 완성할 것 | 확인할 사용자 행동 |
| --- | --- | --- |
| 1. 입력·저장·목록 | 한 칸 입력, 저장 보존·재시도, 최근 목록, 원본 열기 | 링크만 또는 메모만 연속으로 저장하고 새로고침해 다시 찾기 |
| 2. 탐색·편집 | 전체 서버 검색, 상세 열기, 제목·메모 수정, 즐겨찾기, 목록 위치 복원, 휴지통 | 기억나는 단어로 찾아 내용을 고치고 목록으로 돌아오기 |
| 3. 기존 자료 이관·빠른 접근 | 기존 370건 및 별도 프로필 자료의 분모를 유지한 가져오기, 전역 입력 연결 | 옛 자료와 새 자료를 같은 검색에서 찾아보기 |

위 세 묶음까지를 **입력·모아보기 첫 출시**로 제안한다. 1번만 만든 상태를 요청 전체가 완료된 것으로 표시하지 않는다. 자료 가져오기는 미리보기·중복 판정·출처 보존·재실행 가능성을 확인하고 진행한다. 과거 자료를 가져온 실행 시각을 실제 최초 저장일로 위장하지 않는다.

원자료·내 생각을 저장할 때 콘텐츠 원고를 자동 생성하지 않는다. 자료 자체의 보관 기록을 유지하고, 후속으로 사용자가 “글감으로 사용”을 선택할 때 기존 소재함·Studio에 연결한다. 기존 업무 메모를 자동 복제하는 두 번째 메모함도 만들지 않는다. 가져온 자료는 DB의 실제 레코드로 보관하며 앱 코드에 370개 업무 데이터를 내장하지 않는다.

후속에는 글감 선택·여러 출처 연결·AI 초안·원고별 생성 근거 기록을 붙인다. 당시 사용한 자료 사본은 보존하고 현재 자료는 편집 가능하게 하는 방향으로 09-20의 고정 packet 제약을 재검토한다. 이번 출시에서 Studio 저장 계약을 먼저 확장하지 않는다.

## 8. 사용성 확인 기준

- 링크 하나를 넣는 데 제목·분류·글쓰기 기획 입력이 필요하지 않다.
- 입력 도중 다른 화면으로 이동하거나 새로고침해도 작성 중 내용이 복구된다. 로컬 임시 저장과 서버 저장 완료는 구별해 표시한다.
- 저장 실패·응답 불명 후 재시도로 같은 자료가 무작정 늘어나지 않는다.
- 외부 사이트 접근 실패가 내 입력 저장을 막지 않는다.
- 검색은 현재 화면에 불러온 일부가 아니라 저장된 전체 자료를 대상으로 한다.
- 자료를 읽고 돌아왔을 때 목록 위치·검색·필터가 유지된다.
- 잘못 저장하거나 수정한 자료를 삭제·수정·복구할 수 있다.
- 모바일의 키보드가 저장 버튼과 현재 입력을 가리지 않는다.
- 기존 자료의 요약·원문 확인 수준·선별 이력과 내 메모를 구분해 읽을 수 있다.

빠른 저장·다시 찾기의 단계 수와 실제 사용 중 막힌 지점을 확인한다. 구체적인 응답 시간 목표는 실측 뒤 정하며, 이번 기획에서 검증되지 않은 성능 수치를 약속하지 않는다.

## 9. 후속 설계 산출물

다음은 입력·목록·상세의 연결된 와이어프레임과 저장·실패·재시도·복귀 상태를 확정하는 것이다. 실제 수집 자료와 사용자가 입력한 메모로 사용 흐름을 확인한 뒤 저장 모델·API 구현 계획을 작성한다. 스타일과 인터랙션은 루트 DESIGN.md의 토큰·프리미티브·모바일·키보드 계약을 따른다. 이 문서는 화면 구현이나 운영 DB 이관 완료 기록이 아니다.
