# CRM·프로젝트: 간결한 보기, 빠른 입력, 고객 연결

> 상태: 사용자 요구 3개 확정 / 아래 화면·동작은 권장안 / 구현 전
> 사용자 요구: 한 화면에 너무 많은 것을 담지 않기, 편리한 정보 보기·입력, 프로젝트에서 고객 태그 가능.
> 관계: 같은 날 작성한 `2026-09-21-crm-optimization-usability-ux-plan.md`의 §3·4를 화면 역할과 프로젝트 연결 관점에서 보완한다. 앞선 생성 이미지 6개는 탐색 자료이며 채택된 화면이 아니다. 기존 확정 PMS 분류·입력 계약은 유지한다.
> 상위 정본: `docs/README.md`, 운영자 프로필, 개인 운영 OS 심화 설계, `DESIGN.md`, 09-20 실사용 입력 개선.

## 1. 기획 원칙

**한 화면은 한 업무에 집중하고, 고객·프로젝트·기록은 연결을 통해 오간다.**

- 목록은 찾기, 상세는 이해하기, 입력은 남기기를 맡는다.
- 고객 목록·프로젝트 실행·긴 기록 입력창을 동시에 펼치지 않는다.
- 읽을 때 편집 필드를 숨기고, 입력할 때 주변 정보는 현재 고객·프로젝트만 남긴다.
- 단순히 모든 내용을 접어 탐색 횟수를 늘리지 않는다. 다음 행동과 최근 대화는 기본 노출한다.
- 고객 태그는 검색해서 고른 실제 고객으로 연결되는 칩이다. 자유 분류 태그 `#교육`과 별개다.

## 2. 화면별 정보 예산

| 화면 | 기본으로 보는 정보 | 필요할 때 여는 것 | 주 행동 |
| --- | --- | --- | --- |
| 고객 목록 | 이름·소속, 최근 대화 한 줄, 다음 행동·날짜 | 선택 고객의 요약 | 고객 찾기·선택 |
| 고객 요약 | 이름·소속, 다음 약속, 최근 대화, 중요 니즈 한 줄, 연결 프로젝트 | 전체 기록·거래·연락처 | 기록 남기기 |
| 프로젝트 | 제목·상태·기한, 관련 고객 칩, 다음 행동, 할 일 | 기록·자료, 목표·설정 | 할 일 추가 |
| 기록 입력 | 본문, 현재 고객·프로젝트, 저장 | 연락 결과·날짜, 추가 연결, 선택 분석 | 기록 저장 |

고객 목록을 선택하면 데스크톱에서 상세 영역 하나가 열린다. 상세가 이미 열렸으면 내용을 교체한다. 읽기와 입력은 같은 패널의 모드 전환 또는 기존 compact Drawer를 사용하며 드로어를 겹치지 않는다. 모바일은 상세를 한 화면으로 열고 돌아갈 때 목록 위치를 복구한다.

프로젝트 본문은 `할 일 / 기록·자료`를 전환하는 구성을 제안한다. 두 내용을 긴 세로 대시보드에 동시에 펼치지 않는다. 목표·결정·전체 이력의 진입점은 남긴다. 확정 탭 구조를 이 문서만으로 변경하지 않는다.

## 3. 프로젝트에서 고객 태그

예시 배치(가상 이름):

```text
강사 교육 도입 프로젝트                    진행 중 · 9/30
관련 고객  [김지안 · 이음교육] [+ 고객 연결]

다음 행동  교육 사례를 정리해 전달
할 일 | 기록·자료

□ 사례 자료 정리                         9/23
□ 자료 전달                             9/24
+ 할 일 추가
```

- 프로젝트 제목 바로 아래에 `관련 고객`을 둔다. 생성의 세부 설정 안에서만 찾게 하지 않는다.
- `+ 고객 연결`은 검색 가능한 선택창을 연다. 이름·소속을 함께 보여 동명이인을 구분하고, 검색어만 입력한 상태에서 새 고객을 만들지 않는다.
- 고객 칩을 누르면 최근 대화·다음 약속·짧은 니즈를 확인한다. 더 긴 내역은 `고객 전체 보기`로 연다.
- 고객에서 돌아오면 프로젝트의 탭·스크롤·입력 초안을 복원한다.
- 고객 상세에는 같은 관계를 역조회한 `연결 프로젝트`를 표시한다. 양쪽에서 별도 사본을 관리하지 않는다.
- 여러 고객 연결은 확장 권장안이다. 채택하면 처음 두 칩과 `+N`만 노출하고 전체 목록에서 수정한다. 역할·대표 고객 지정은 필수 입력으로 만들지 않는다.
- 연결 해제는 관계만 해제한다. 고객·프로젝트·과거 기록을 삭제하거나 거래를 종료하지 않는다.
- 기본 고객 단위는 사람이다. 기존 리드·계정이 사람과 연결되지 않았다면 검증된 실제 레코드 이름·소속으로 표시하고 임의의 담당자를 만들지 않는다.

## 4. 입력은 현재 위치를 이어받는다

### 기본 메모

`본문 입력 → 연결 확인 → 저장`을 기본으로 한다. 제목·반응·기한을 필수로 강제하지 않는다. 프로젝트에서 열면 프로젝트를 채우고, 특정 고객 칩에서 열면 고객과 프로젝트를 함께 표시한다. 연결은 저장 전에 바꿀 수 있다.

프로젝트에 고객이 연결됐다는 이유로 모든 내부 메모를 해당 고객의 연락 이력으로 처리하지 않는다. 프로젝트 본문에서 작성한 일반 메모는 프로젝트만 기본 연결하고, 고객을 직접 선택한 입력에서만 고객을 함께 연결한다. 고객이 여러 명이어도 메모를 모두에게 복제하지 않는다.

### 실제 연락 결과

`연락 결과`를 선택한 때에만 반응과 후속 입력을 드러낸다. 다음 행동은 `날짜 있음 / 기약 없음 / 후속 없음`을 구분한다. 메모 저장을 연락 완료로 계산하지 않는다.

### 기록과 할 일 연결

가상 사례: 프로젝트에서 김지안 태그를 누르고 “목요일에 교육 사례 전달하기로 함”을 기록한다. `할 일로 추가`를 선택하면 제목·9/24·프로젝트·고객을 확인해 추가한다. 날짜만 적힌 메모를 자동으로 확정 약속이나 발송으로 해석하지 않는다.

목표 경험은 기록 한 건을 고객과 프로젝트 양쪽에서 다시 찾는 것이다. 기존 활동 원장에 프로젝트 연결이 이미 있다고 가정하지 않는다. 구현 시 기록 식별자와 문맥 연결을 명시하고 중복 활동·중복 연락 집계가 생기지 않도록 한다. 이미 만들어진 후속 할 일은 같은 ID로 연결하며 약속 사본을 별도로 만들지 않는다.

저장 성공 후에만 입력을 비운다. 실패·대상 변경·화면 이동 시 초안 보존과 복귀 계약을 유지한다.

## 5. 앞선 새 기능의 자리

| 탐색한 기능 | 이번 방향에서 배치 | 우선순위 제안 |
| --- | --- | --- |
| 대화에서 업무로 | 기록창의 `내용 정리`를 눌렀을 때 원문과 추출 후보를 비교하는 별도 모드 | 연결·저장 경험 다음 |
| 약속 지도 | 날짜를 조정하려고 선택하는 일정 보기 | 후속 |
| 변화 인박스 | 요청한 분석에 변경 후보가 생겼을 때 확인하는 표면 | 후속 |

세 기능을 기본 고객·프로젝트 화면의 고정 패널로 추가하지 않는다. AI 없이도 보기·입력·연결을 완료할 수 있어야 한다. AI는 원문 근거와 후보를 제시하고 운영자가 선택한 내용만 반영한다.

## 6. 현재 코드에서 재사용할 것과 확장할 것

2026-09-21 코드 확인 기준이며 운영 배포 확인을 뜻하지 않는다.

- `project-create-drawer.jsx`는 세부 설정의 `관련 리드/고객` select와 `entityKey`를 이미 제공한다.
- `project-ledger-context.js`는 프로젝트의 `lead_id` 또는 `customer_account_id`를 `entityRef`로 읽는다.
- `20260719_0022_project_context_links.sql`은 두 필드 중 최대 하나만 허용한다. 현재는 프로젝트당 연결 고객 1개다.
- `project-detail-panel.jsx`는 진척·다음 행동·속성·목표·체크리스트·업데이트·결정·메모를 이어서 보여준다. 고객 칩과 핵심 정보 위계를 먼저 적용하고 나머지는 목적별 진입점으로 옮길 후보로 본다.
- `RelatedMemos`는 프로젝트·리드·계정별로 직접 연결한 최근 메모와 전체 보기를 제공한다. 이 패턴을 재사용하되 고객 연결만으로 모든 메모의 귀속을 확장하지 않는다.
- 다중 고객은 칩 UI 변경만으로 끝나지 않는다. 별도 관계 저장·검색·역조회와 기존 단일 연결 이관 계약을 설계해야 한다. 동일 workspace 검증, 실제 고객 참조, 중복 관계 방지를 함께 유지한다. 자유 텍스트 태그 배열로 우회하지 않는다.

## 7. 적용 순서와 검증

1. 기존 고객 1개 연결을 프로젝트 상단 칩으로 노출하고 고객 요약·프로젝트 복귀·역조회 흐름을 만든다.
2. 읽기와 입력을 나누고, 문맥을 이어받는 공통 기록창과 고객·프로젝트 기록 연결을 완성한다.
3. 다중 고객 연결을 확장한다. 이름·소속 검색, `+N`, 해제, 중복·동명이인·읽기 실패를 검증한다.
4. 실제 입력이 충분히 쌓인 뒤 선택 분석·약속 지도·변화 인박스 중 필요한 기능을 추가한다.

완료 판단은 위젯 수가 아니라 실제 흐름으로 한다: 프로젝트에서 고객의 최근 대화를 확인하고 돌아오기, 같은 자리에서 메모 저장, 해당 기록을 고객에서 다시 찾기, 후속 할 일을 중복 없이 연결하기. 같은 탭 새로고침·저장 실패·조회 실패·연결 해제·모바일에서도 문맥과 원문이 보존되어야 한다.

이번 작업은 기획 문서화만 수행했다. 앱 코드·DB는 변경하지 않았고 동작 테스트는 실행하지 않았다.
