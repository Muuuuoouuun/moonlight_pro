# 고정비 이용 상태·재개 일정

> 운영자 요청: 멈췄는지 이용 중인지와 재개 여부, 통신비를 함께 관리한다.
> 관계: 2026-10-05 현금 흐름 목록 스펙의 계약 표시·검토 항목을 확장한다. 결제일 기준 월별 표와 개인 범위는 유지한다.

- 계약 이름 옆에 이용 중·일시중지·해지를 LifecycleBadge로, 확인 필요를 CertaintyBadge로 표시한다. 기존 계약의 기본은 확인 필요이고, 운영자가 현재 이용 중이라고 명시한 계약은 자술 근거로 이용 중을 기록한다. 서비스 계정에서 확인한 사실과 구분하며 거래만으로 현재 이용 상태나 해지를 추정하지 않는다.
- 상세의 `serviceStatus`는 unknown/active/paused/cancelled다. 일시중지·해지에는 nullable `resumeDate`를 입력한다. 다른 상태로 바꾸면 재개 예정일을 비운다. 예정일이 지나도 자동 재개하지 않는다.
- 중단·해지 계약은 과거 결제와 환불을 그대로 유지한다. 다음 일정은 직접 입력한 재개 예정만 표시하며 과거 약정이나 자술 기간으로 미래 청구를 생성하지 않는다.
- 통신비는 운영자가 언급한 고정비 계약으로 등록한다. 수집 근거가 없으면 통신사·금액·납부일·현재 상태를 미확인으로 둔다. 등록용 가짜 결제나 0원 거래를 만들지 않는다.
- 계약만 등록하는 import는 빈 entries와 한 개 이상의 subscriptions, `coverage.contractsOnly:true`가 필요하다. 빈 전체 bundle과 결제 관측이 섞인 계약 전용 bundle은 거절한다. 계약 등록일로 실제 결제 수집 범위를 늘리거나 덮어쓰지 않는다.
- review 검증은 Hub와 DB가 같은 상태 enum·달력 날짜·재개 조건을 지킨다. 합친 최신 검토값도 검증하고 revision 충돌은 기존 409·초안 보존 흐름을 유지한다. 원본 관측과 금융 권한은 그대로다.
- CFO 더보기에는 이용 상태별 계약 수를 함께 제공한다. 외부 구독 서비스의 실제 해지·재개나 Office 자동 실행은 이 관리 기록의 동작이 아니다.

검증: 상태 저장·잘못된 날짜/상태 거절·재개 조건·stale revision·계약 전용 등록 재시도·관측 범위 보존·기존 소비 합계 보존, 실제 브라우저 저장·재조회·모바일·중간 너비·라이트/다크를 확인한다. 개인 자료와 화면 증거는 저장소 밖에만 둔다.
