# 운영 배포의 아이디·비밀번호 로그인

> 상태: 운영자 요청으로 구현 승인 (2026-09-23)
> 관계: 기존 Hub의 운영자 비밀키 입력 화면과 운영 배포의 브라우저 쓰기 금지 계약을 이 범위에서 대체한다. `docs/README.md`의 배포 상태 기록은 실제 운영 적용 뒤 갱신한다.

## 결정

Moonlight는 단일 운영자 도구다. 배포된 Hub의 로그인 화면은 아이디와 비밀번호를 받는다. 가입, 비밀번호 찾기, 여러 계정, 권한 등급은 만들지 않는다.

서버는 `COM_MOON_OPERATOR_USERNAME`, `COM_MOON_OPERATOR_PASSWORD_HASH`, `COM_MOON_OPERATOR_SESSION_SECRET` 세 값을 요구한다. 비밀번호는 무작위 salt가 포함된 scrypt 해시로 보관한다. 로그인 실패는 아이디와 비밀번호 중 무엇이 틀렸는지 드러내지 않는다. 운영자 세션은 현재의 HttpOnly·Secure 쿠키와 12시간 만료를 유지한다. 서버 간 `COM_MOON_HUB_WRITE_SECRET`는 브라우저 로그인 비밀번호와 별개의 값이다.

운영자 세션을 가진 브라우저의 같은 출처 쓰기 요청만 운영 배포에서 허용한다. 출처가 다르거나 세션이 없으면 거부한다. MCP·cron의 서버 자격 검사는 기존대로 유지한다. 로그인과 세션 설정이 불완전하면 미들웨어는 닫힌 상태를 유지한다.

설정 화면 프로필 카드에서 로그아웃할 수 있다. 로그인과 로그아웃 요청도 같은 출처에서만 받는다. 운영 런타임의 localhost 요청에는 별도의 브라우저 쓰기 우회가 없다.

로그인 API의 입력 크기를 제한하고 로그인 시도 경로 `/api/operator/session`에 Vercel Firewall 속도 제한을 적용한다. 앱 인증·DB 연결·쓰기 검증이 끝날 때까지 Vercel Deployment Protection을 유지한다. 보호를 해제하면 URL을 아는 누구나 로그인 화면에 도달하므로 마지막 적용 시점에 운영자가 이를 검토한다.

## 비교한 접근

| 접근 | 이점 | 비용 |
| --- | --- | --- |
| 환경 변수의 단일 계정 + scrypt 해시 (선택) | 현재 세션 구조를 재사용하고 별도 인증 서비스가 필요 없다 | 계정 생성·교체는 배포 환경 변수 작업이다 |
| Supabase Auth | 사용자 관리와 로그인 제한 기능이 있다 | Auth 계정·JWT·쿠키 체계를 새로 연결해야 한다 |
| 기존 Hub 쓰기 키를 비밀번호로 입력 | 코드 변경이 작다 | 사람용 비밀번호와 서버 간 권한이 같은 값이 된다 |

## 완료 기준

- 아이디·비밀번호로 로그인하고 새로고침 뒤에도 세션이 유지된다.
- 틀린 자격, 누락된 설정, 다른 출처 쓰기는 거부된다.
- 인증된 같은 출처 브라우저 쓰기와 유효한 서버 자격 호출은 통과한다.
- 세션 비밀키와 비밀번호 또는 서버 쓰기 키는 서로 대체되지 않는다.
- Vercel 환경 변수·Firewall·Deployment Protection 변경과 실제 DB 연결은 운영 배포에서 별도로 검증한다.
