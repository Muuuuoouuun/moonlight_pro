# Guru 카드의 내부 읽기 글

> 상태: **운영자 확정(2026-09-25)** — 원자료를 외부 링크로 여는 대신 Moonlight가 만든 Markdown과 참고자료를 재구성한 블로그형 글을 읽는다. 카드별 글 26편을 둔다. 글마다 한 장의 **내용 요약 인포그래픽**을 붙인다는 후속 결정을 반영한다. 기존에 만든 개념 일러스트 26장은 인포그래픽으로 인정하지 않고 로컬에만 보관한다. 새 인포그래픽의 제작·연결·검증 상태는 [제작 계획](../plans/2026-09-25-guru-infographics.md)을 따른다.
> 관계: `2026-09-25-guru-focus-atlas-floating-chat-design.md`의 Focus·Atlas·대화·팁은 유지하고, 카드 상세의 `원자료·원문 확인` 및 모든 Guru 출처 링크 표면만 이 문서가 대체한다.

## 콘텐츠 계약

- 23 Guru와 3 Legend의 카드 ID 하나당 `apps/hub/content/guru/<id>.md` 글 하나를 둔다. 글은 H1 제목, 서술형 도입, 관점 설명, 사용할 장면, 적용 경계를 포함한다. 원자료의 정확한 문장을 복제한 글이 아니라 **Moonlight의 편집·재구성 글**이다.
- 바탕은 카드의 검수된 한 주장과 해당 내부 참고 문서의 관련 절이다. 기존 대형 MD의 미검증 인용, 효과 수치, 고객 사례, 보편적 성공 약속은 옮기지 않는다. 원저작의 개념과 Moonlight의 현재 업무 응용을 글에서 구분한다.
- 각 글은 인물 고유의 개념이 왜 필요한지, 어떤 정보를 확인하며 판단하는지, Moonlight에서 어떻게 질문으로 바꿀지, 적용하지 않을 조건을 충분한 문단으로 풀어낸다. 예시는 가정임을 드러내고 실제 고객·성과 사실처럼 쓰지 않는다. 동일한 문단 틀을 26편에 반복하거나 분량을 위해 근거 없는 주장을 덧붙이지 않는다.
- `source.path/section/url`은 내부 감사와 AI 출처 추적용 메타데이터로 남긴다. 화면은 내부 글을 주 내용으로 보여주고 외부 원전 링크나 저장소 파일 경로를 주 행동으로 표시하지 않는다. Keenan·Seth의 확인된 짧은 직접 인용만 별도 `원문 발췌`로 표시한다.

## 카드별 요약 인포그래픽

- 26편 각각에 **글의 핵심 주장·판단 단계 또는 비교·적용 경계가 실제 한국어 문구로 읽히는** 고유한 2D 인포그래픽 한 장을 제작한다. 삽화나 분위기 연출은 요약 자료를 대신할 수 없다. 인물 초상·로고·3D 표현·가짜 고객 기록·근거 없는 수치·성과 표현은 제외하고, Hub의 차콜·실버·차가운 청색 계열을 따른다.
- `apps/hub/content/guru/infographics-sales.json`과 `infographics-other.json`에 카드 ID별 제목·핵심 주장·도식 유형·단계/비교 항목·적용 경계의 **확정 한국어 문구**를 둔다. 이 요약 문구는 해당 Markdown 글의 주장과 경계를 압축하며 새 사실을 추가하지 않는다. 글이 내용의 정본이고 JSON은 이미지 생성과 읽을 수 있는 대체 표현의 공통 입력이다.
- 이미지 모델은 카드별 문구와 구조를 사용해 인포그래픽을 생성한다. 완성된 이미지의 글자·순서·연결선·경계가 JSON과 일치하는지 원본 크기에서 시각적으로 판독한다. 글자가 깨지거나 의미가 달라진 이미지는 게시하지 않고 다시 생성한다. 생성 이미지 자체를 근거·원문 인용처럼 표시하지 않는다.
- 데스크톱은 검수된 WebP를 글 안에서 보여 주며, 작은 화면은 같은 JSON을 의미 구조가 있는 HTML로 읽는다. 화면 읽기 도구에도 동등한 텍스트를 제공한다. 이미지 누락·요청 실패·검수 보류 시 HTML 요약으로 전환하고 Markdown 글과 질문 흐름은 계속 읽을 수 있다.
- 앞서 만든 글 없는 개념 일러스트 26장은 Git·앱에서 제거하고 **로컬 전용 보관함**에 둔다. 나중에 별도 콘텐츠의 참고로 쓸 수 있지만, 쓰는 시점에 콘텐츠에 맞춰 다시 생성한다. 이 보관본을 현재 글의 인포그래픽으로 재사용하지 않는다.

## 화면과 연결

- Focus·Atlas 카드 클릭 및 `?card=<id>`는 동일한 상세 Drawer를 연다. Drawer 본문은 글 제목, 인물·분야, 편집 성격 안내, 카드별 요약 인포그래픽, 블로그형 본문, 바탕 자료 이름, 적용 질문 순서다. Guru의 명시적 질문 버튼은 유지하고 Legend는 읽기 전용이다.
- 글이 로드되는 동안에는 Skeleton, 읽기 실패에는 명시적 오류와 재시도를 표시한다. HTTP 200의 `{status:'error'}`를 빈 글로 오해하지 않는다. 글 열기 자체는 AI 요청·알림·업무를 만들지 않는다.
- 서가·맥락 레일·챗의 공용 자료 표시는 외부 `원전 열기` 링크를 제거하고 Moonlight 재구성 글의 바탕 자료임을 짧게 표시한다. 맥락 레일의 읽기 행동은 해당 카드의 `?card=<id>`로 연결한다.
- 데스크톱 읽기 폭은 긴 줄을 피하고, 모바일은 기존 compact Drawer 안에서 단일 열로 읽힌다. Hub 디자인 토큰과 프리미티브를 유지한다.

## 전달과 검증

- 인증된 Hub GET 경로는 등록된 26개 카드 ID만 파일명으로 허용한다. Markdown과 검수된 인포그래픽 WebP는 `public/`에 두지 않고 서버에서 읽는다. 이미지는 `/api/hub/guidance-articles/[id]/infographic` 경로로 제공한다. 글과 이미지 응답은 private/no-store이며 Next 파일 추적에 해당 MD·WebP를 포함한다.
- Markdown은 제목·문단·소제목·목록·인용의 제한된 집합만 텍스트로 렌더한다. HTML, 이미지, 외부 링크는 실행하거나 링크로 만들지 않는다.
- 카드 26장과 MD 26편·JSON 요약 26건·**검수 통과 WebP 26장**의 일치, 이미지 안 한국어 문구의 정확성·읽기 크기·도식의 의미, 출처·인용 표시, 실패 봉투와 이미지 누락 시 HTML·글 읽기, 딥링크, 밝고 어두운 화면, 390px 읽기, 배포 파일 추적을 확인한다. 검수가 끝나지 않은 이미지는 26장에 포함해 완료로 계산하지 않는다. 운영 배포는 개발 서버에서 읽기 경험을 확인한 뒤 별도로 다룬다.
