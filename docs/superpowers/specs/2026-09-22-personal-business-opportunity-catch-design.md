# 개인 사업 기회 캐치 — AI 자문·리뷰의 공통 기준

> 상태: 운영자 요청 반영 · 코드 구현, 검증 결과는 아래 기록. 배포·실제 모델 품질 검증은 별도.
> 요청: 개인 브랜드 수익화를 우선하며 수익 모델은 미정, 유력 후보는 SaaS 또는 컨설팅. 이 방향을 AI와 리뷰 보고서 작성의 기회 포착 요소로 포함한다.
> 관계: [기회 탐색 2차](2026-09-13-opportunity-discovery-v2-design.md)의 요청형 AI 후보 방향을 분석 기준으로 보강한다. 기회 레코드의 상태·저장 계약이나 [하루 리뷰](2026-09-12-daily-review-and-council-design.md)의 직접 기록 계약을 대체하지 않는다. 기존 [브랜드 리서치](2026-09-21-brand-research-editorial-system-design.md)의 초안 수량·주기와도 별개다.

## 1. 승인된 목적과 이번 범위

개인 사업의 플라이휠은 문제 발견 → 콘텐츠 → 문의·상담 → 작은 유료 제안 → 해결·사용 → 결과·사례 → 다음 개선이다. AI는 이미 전달된 기록에서 이 연결의 단서를 찾는다. 판매할 SaaS를 Moonlight 자체의 판매·다중 사용자 전환으로 해석하지 않는다.

이번 변경은 기존 요청형 AI 호출에 공통 판단 기준을 추가한다. 정기 실행·외부 발송·DB 마이그레이션·새 화면·기회/프로젝트 자동 생성은 포함하지 않는다. 기존 경로의 자문 저장·승인 큐 제안 동작은 그대로이며, 이 기준이 별도의 실행기를 만들지 않는다.

## 2. 포착 신호

| 신호 | 해석할 수 있는 것 | 아직 확인할 것 |
| --- | --- | --- |
| 같은 고객군의 반복 문제·수작업·우회 방법 | 공통 문제 또는 표준화 후보 | 사건의 독립성, 반복 빈도, 현재 대안 |
| 해결·구축·대행 요청 | 컨설팅 또는 도입 지원 가설 | 제공 범위, 구매 주체, 실제 지불 의사 |
| 예산·가격 질문·지불 의사·결제 | 각각 다른 강도의 상업 신호 | 문의와 결제의 차이, 약속과 실제 결과 |
| 콘텐츠를 보고 자기 문제를 설명한 문의 | 콘텐츠와 고객 문제의 연결 | 구체 출처, 유료 해결 필요 |
| 여러 고객에게 재사용한 해결 절차 | SaaS/표준 서비스 가설 | 도움 없는 사용, 유지 비용, 반복 사용 |
| 납품 결과·재구매·추천 | 재사용 가능한 해결 근거 | 실제 결과, 공개 가능 범위, 반대 사례 |

개인 불편 한 건은 문제 가설이다. 조회·좋아요·저장·게시량만으로 구매 수요를 확정하지 않는다. 같은 사건의 재기록 및 AI 요약을 독립 고객 수로 세지 않는다. 유료 컨설팅의 성공을 SaaS 수요 검증으로 바로 바꾸지 않는다.

## 3. 결과 형식

후보 0~3개를 제안하며 다음 항목을 함께 남기도록 지시한다.

1. 고객군과 문제.
2. 관찰 근거: 입력에 있는 원문 ID·날짜·발췌. 없는 값은 미제공.
3. SaaS / 컨설팅 / 혼합형 / 판단 보류와 그 이유.
4. 근거 단계: 문제 가설 / 해결 요청 / 지불 의사 / 유료 검증 / 반복 사용.
5. 미확인 사항과 반대 근거.
6. 최소 검증 행동 하나와 확인할 결과.

관찰·가설·미확인을 분리하고 근거가 없으면 `근거 부족 / 확인된 후보 없음`으로 남긴다. 주간 보고서는 후보별 검증 행동을 비교하되 기존의 최종 `다음 주 단 1가지 실험`을 유지한다. 선택한 후보를 기존 기회 탐색에 옮기는 것은 운영자의 후속 행동이다.

## 4. 적용 경로

- Engine `persona-chat`: Council의 advice/chat/critique/sparring 및 weekly-review. 다른 페르소나의 weekly-review에도 적용하되 회사 영업 persona인 guru/sales는 제외한다.
- Engine `brand-mentor`: brand-strategy/audience-analysis/flow-review/sparring. 콘텐츠 문장 검수·회의 요약에는 사업 후보 절을 강제하지 않는다.
- Engine `pattern-analysis`: 기존 general 목적에 추가. JSON candidates 계약을 유지하며 observation/interpretation/actionableGuidance/evidenceQuotes에 기준을 반영한다. 다른 목적을 수익화 분석으로 바꾸지 않는다.
- 공통 기준: `apps/engine/lib/business-opportunity-catch.ts`, 버전 `personal-business-catch-v1`.

명시된 company/classin 문맥에는 이 개인 사업 기준을 주입하지 않는다. 문맥이 혼합되거나 소속이 미확인일 때는 개인 소속 또는 운영자가 개인 사업 검토용으로 명시한 자료만 근거로 사용하도록 지시한다. 이 프롬프트 규칙은 DB 수준 접근 제어 또는 자동 소속 판별 기능을 뜻하지 않는다.

기존 숫자 집계용 `/api/hub/weekly-report`에 새 AI 호출이나 결과 필드를 추가하지 않는다. 이번의 '보고서' 적용은 AI `weekly-review` 본문이며, 숫자 카드의 지표·집계 기간·조회 범위 변경은 별도다. 기존 요청에 포함되는 자료만 분석하므로 선택하지 않은 전체 메모·CRM을 검색했다고 표현하지 않는다.

## 5. 근거 검증 보강

RAG 발췌에는 원본 테이블·ID·날짜를 표시한다. Pattern parser는 입력에 없는 ID를 첫 기록으로 대체하지 않고, 유효한 인용이 하나도 없는 후보에는 첫 메모를 임의로 출처로 붙이지 않고 제외한다.

정확한 발췌 일치는 출처 검증이다. 모델 해석의 진위·고객 수요·사업성을 검증한 것으로 표현하지 않는다. 산문형 자문·보고서의 후보 개수와 근거 준수는 프롬프트 기준이며 별도 구조화 검증기로 강제한 것은 아니다.
