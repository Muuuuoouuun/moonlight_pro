# 콘텐츠 성과 하위 탭

상태: 구현·로컬 검증 완료(2026-09-22). 조회수 직접 입력을 우선하고 지정 채널·대시보드의 API/브라우저 수집은 후속으로 연결한다. 운영 DB 수치 저장·자동 수집·코드 배포 검증은 별도이며 [실행 기록](../plans/2026-09-22-content-performance.md)을 따른다.
관계: 09-12 콘텐츠 제작 스펙의 제작·발행 계약을 유지하고 성과 집계 표면만 추가. 운영자 프로필 §12의 후순위였던 단순 성과 조회를 이번 요청 범위에서 활성화한다. 브랜드 로그는 변경하지 않는다.

## 화면과 집계
- 콘텐츠 하위에 `성과`(/dashboard/content/performance)를 추가. 내부 `요약 / 이번 주 / 월별` 전환. 기본 요약, 브랜드·채널 필터, URL 보존, 새로고침.
- 요약은 이번 달 성과와 이번 주/올해 발행 건수. 이번 주는 한국 시간 월요일~현재, 일별 건수. 월별은 선택 연도 12개월의 발행량·조회수, 월 선택 시 발행 목록을 좁힌다.
- `content_variants.published_at`이 있는 채널별 원고를 1건으로 세며 동일 원고의 발행 로그 재시도는 더하지 않는다. 보관 상태라도 실제 발행 시각이 있으면 포함. 미래 시각은 제외. 발행 상태인데 시각이 없으면 별도 집계 제외 안내.
- 기존 최근80/160개 큐를 합산하지 않는다. 저장소를 workspace에 한정해 ID keyset 페이지로 끝까지 읽으며 실패·상한은 error로 처리한다.
- 조회·공유·답글은 `해당 기간에 발행한 원고의 최신 누적 수치`이다. 기간 중 발생한 증가량이나 고유 방문자 수가 아니다. 미입력은 null/미기록, 실제0은0, 부분 기록은 기록된 원고 수/대상 수와 함께 표시. 최신 기록 시각 노출.
- 세그먼트와 입력은 기존 primitives, dark tokens, mobile44px/16px, Skeleton/EmptyState/TruthBadge. 목록에서 원고 열기와 수치 기록을 바로 실행.

## 직접 기록
- variant.meta.performance={views,shares,replies,capturedAt,source:'manual'}. 세 값은 nullable 비음수 안전 정수이며 최소 한 값 필요. 기록 시각은 서버가 부여한다. 기존 임의 metric 키를 추정하지 않는다.
- read는 원고별 값/업데이트 시각을 제공. PATCH는 variantId,expectedUpdatedAt,views,shares,replies만 수용한다. 서버 workspace·실제 발행 여부 검증, 기존 meta 보존, updated_at 조건의 비교 후 쓰기로 충돌 방지. 다른 창 변경 시 내 입력을 보존하고 다시 읽기/명시적 재시도. 네트워크 결과 미확인은 자동 재전송하지 않는다.
- read API HTTP200 status:error/preview 계약. write guard+기존 middleware 유지. 실제값만 사용하며 미연동에 dummy를 넣지 않는다. 새 DB table·외부 발행·수집 스케줄은 이번 범위에 없다.
- 원고 버전 복원은 최신 `meta.performance`를 유지한다. 성과 수치는 원고 본문 버전과 별개이므로 이전 스냅샷 값으로 되돌리지 않는다. 이를 보장하는 전진 마이그레이션을 코드 적용 전에 반영해야 한다. 기존 발행 시각 복원 계약은 유지한다.

## 완료 기준
연초 주 경계·KST 월말·다중원고·보관발행·미기록/0/부분기록·중복로그 배제·160개 이상·페이지 실패·다른 workspace·write 충돌·metadata 보존을 테스트한다. 실제 화면에서 세그먼트/필터/직접 기록/모바일/오류를 확인한다. 문서·내비 동시 갱신, 격리 작업 공간에서 검증 후 통합·정리.
