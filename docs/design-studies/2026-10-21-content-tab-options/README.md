## 지킨 규칙
- 단계는 색이 아니라 글리프 + 글자: 아이디어 ○ · 계획 ◇ · 제작 ◐ · 다듬기 ◑ · 발행 대기 ●(§5.3 lifecycle). 아이디어 카드는 점선, 이후는 솟은 면.
- 빨강은 **놓침**(밤 정리 때 안 올린 예약, 09-29 확정 3번) 한 곳 — 1px 레일 + 글자. 시각 지남 · 막힘 없는 계획 미완은 빨강이 아니다.
- 게이트·권장은 막지 않고 알려 준다: 점선 마름모 + `권장`/`제안` 직접 라벨(§5.3). 13a 제작 칸의 "동시에 2개까지"도 권장이다.
- 이번 주 7칸: 발행 = 잉크 ✓, 오늘 = Moonstone 1px, 예약 = 파선, 앞날 = 점선(하루 1개 목표, 운영자 프로필 §12).
- 계획 칸 이름은 지금 `BRIEF_FIELDS` 6칸 그대로, 형식 이름은 스레드 · 카드뉴스 · 쇼츠(09-28 발행 흐름 목업과 같음).
- 주제 · 문장 · 숫자는 모두 **예시 값**이다(코드에 넣지 않는다).

## 운영자가 고를 것
1. 세 안 중 어느 첫 화면으로 갈지 — 섞는다면 어느 조각을 가져올지(예: 13b를 기본 `만들기` 보기로 + 13a를 `보드` 보기로).
2. **계획 단계를 상태로 둘지.** 지금 상태값은 `idea · draft · review · scheduled · published`로 계획이 없다. 13a는 `계획` 칸이 필요하다 — 기획 칸이 채워지면 파생(마이그레이션 없음)할지, 상태를 새로 둘지(마이그레이션).
3. **기획 6칸을 본문으로 꺼낼지.** 2026-09-23 Studio 단순화가 기획 6칸을 `더보기`로 옮겼다. 13b·13c는 계획을 원고 작성 앞(13b) 또는 위 한 줄(13c)로 꺼내므로 그 스펙 §3 표면 예산과 `content-studio-surface.test.mjs`를 함께 고쳐야 한다. 13a는 원고 작성 화면을 건드리지 않는다.
4. 13c를 고르면 원고 작성(`dashboard/content/studio`)과 소재·제작(`dashboard/content/queue`)을 한 경로로 합칠지, 둘 다 남기고 작업대를 새로 둘지.
5. 페이지 제목: 세 안 모두 11a·11b · 12a~c와 맞춰 44px/200 디스플레이로 그렸다. 콘텐츠 탭은 지금 20px/500이라 §11 예외가 새로 필요하다.
6. `바로 가능` 표시의 기준: 시안은 "원문 메모나 참고 링크가 있음"으로 그렸다(점수 없음 — 프로필 §12 "직감 + 지금 바로 만들 수 있는가"). 운영자가 직접 켜는 표시로 둘지.
