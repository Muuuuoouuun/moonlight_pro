## 요청과 시안
| 요청 | 시안 | 핵심 |
| --- | --- | --- |
| ① 편하게 쓰기 | **16a 원고 책상** | 가운데 원고지 한 장에 브랜드 · 제목 · 연결 글만. 글 폭 최대 600px(≈ 한글 35자), 본문 17/1.85. 목차·결과물은 왼쪽 여백, 말투·AI 후보·올릴 곳은 오른쪽 여백 |

| ③ 예약하거나 바로 올리기 | **16b · 16c · 16d** | 채널마다 연결 상태를 보고 `지금 올리기` · `예약`(그 시각에 자동 / 알림만) · `직접 올리기`(복사 → 링크 붙이기). 올린 뒤 상태 8가지, 브랜드 쪽 한 주 일정 |
| (공통) 휴대폰 | **16e** | 같은 원고지 한 단, 입력 16px · 누르는 곳 44px, 올리기는 전체 높이 시트 |

### 16a 원고 책상
- **위계 다섯 층**: ① 본문 `17px / 1.85 --fg`(가장 넓다) → ② 제목 `30px / 300`(칸 테두리 없는 문서 제목) → ③ 어디에(브랜드 pill · 형식 탭 13px) → ④ 도구(AI · 목차 · 말투, 12px `--fg-dim`) → ⑤ 저장 상태(11.5px `--fg-faint` 한 줄).
- **여백**: 원고지 안쪽 위 30 · 좌우 56(왼쪽 56 안에 연결 글 번호와 이음선), 글 폭 최대 600px — 넓은 화면에서도 더 늘지 않는다. 연결 글 사이 22 + 1px 선 + 26. 여백 칸은 판 없이 바탕 위(오른쪽 카드만 낮게 솟음).
- **연결 글 블록**: Threads 글을 번호 블록으로 나눠 쓰고 블록마다 `n / 500`. 지금 쓰는 블록 번호만 잉크(현재 위치). 500자를 넘으면 그 블록에 1px 빨강 레일 + 하단 바 이유 한 줄 + `올리기` 비활성 — 실제로 올라가지 않는 막힘이라 빨강을 쓴다. 줄 끝에서 빈 줄 + Enter = 다음 연결 글(지금 엔진의 빈 줄 분할 규칙과 같다).
- **원문 메모**: 제목 아래 접힌 한 줄, "AI 초안의 재료 · 복사·올리기에 안 들어가요".
- **편하게 저장**: 자동 저장 1.2초(지금과 같음) → `✓ 저장됨 08:42`. AI 적용 · 예약 · 올리기 때 버전을 자동으로 남긴다.
- **하단 바**: 왼쪽 AI(초안 · 다듬기 · 첫 줄 3안, ghost) — 가운데 `연결 글 3 · 209자` — 오른쪽 `복사` · `예약` · **`올리기`**(유일한 primary). 지금의 `발행했음`은 올리기 창의 `직접 올리기`로 들어간다.
- **오른쪽 여백**: 브랜드 말투(브랜드 기준에서 세 줄) · AI 후보(요청했을 때만, 적용하면 버전 남김) · 올릴 곳(브랜드의 채널별 연결 상태와 남은 권한 일수).

### 16b 올리기 — 브랜드 → 채널 → 언제
- 가운데 창 1040×800, 테두리 없이 `--shadow-window`, 배경 흐림 6px. 왼쪽 세 단계, 오른쪽 미리보기 + 올리기 전 확인.
- ① **브랜드**: 타일 5개(아이콘 · 이름 · 핸들 · 채널 칩). 한 번에 브랜드 하나 — 브랜드가 곧 계정이고 말투가 다르기 때문(같은 글을 여러 브랜드에 동시에 올리는 길은 두지 않았다).
- ② **채널**: 연결됨(솟은 줄, 체크) / 결과물 없음(`카드뉴스 만들기`) / 지정 전(`이 브랜드에 지정`) / 연결 전(`설정에서 연결`) / 연결 만료(빨강 1px 레일 + `다시 연결`). 줄마다 무엇이 올라가는지(스레드 연결 글 3개 · 카드뉴스 6장 + 캡션).
- ③ **언제**: `지금 올리기` · `예약` · `직접 올리기`. 예약은 빠른 시각 3개 + 직접, 그리고 **그 시각에 자동으로 올리기**(연결된 채널만, "지금 이 내용 그대로 · 예약 뒤 고치면 다시 승인") / **그 시각에 알림만**(지금 방식).
- **주 버튼이 대상을 말한다**: `Class.Moon Threads에 지금 올리기` · `오늘 19:00 자동 업로드 예약` · `오늘 19:00 알림으로 예약` · `복사하고 Threads 열기`. 못 할 때는 비활성 + 이유 한 줄(`올릴 채널을 골라 주세요`, `500자 넘는 연결 글을 나눠 주세요`).
- **올리기 전 확인**: 브랜드 · 글자 수 · AI `확인 필요` 0건 · 계정 연결(남은 일수) · 권장(◇ 점선, 발행 기록 기준 자주 올린 시각).
- **지금 올리기 진행**: `계정 확인 → 올리는 중 → 링크 확인` 3단계(창을 닫아도 계속, 결과는 원고 하단 바에) → `✓ 올라감 · 링크`.

### 16c 올린 뒤 — 글 상태 8가지
`올리는 중 ◐` · `올라감 ✓`(공급자 글 번호와 링크를 다시 읽어 본문과 맞을 때만) · `예약됨 · 자동 ↑`(실선) · `예약됨 · 알림 ◷`(파선, 지금 방식) · `고쳐서 다시 승인 ◇`(대기라서 빨강 아님) · `확인 필요 ?`(응답이 끊겨 올라갔는지 모름 — 다시 올리지 않고 멈춤) · `실패 ✕`(빨강) · `놓침 !`(빨강, 09-29 확정 그대로). 원고 하단 바 · 발행 로그 · 홈 "지금 올릴 글"이 같은 말을 쓴다.

### 16d 브랜드 › 채널과 발행
브랜드 상세 맨 위에 둔다. 머리(아이콘 · 이름 · 핸들 · 이번 주 4/5 · 예약 · 올릴 준비 + `이 브랜드로 새 글`) → **채널 카드 3장**(연결 상태 · 권한 만료일 · 이번 주 올림 · 예약 · 자주 올린 시각 · `예약하면 기본은 자동 | 알림`) → **이번 주 7칸**(올라감 ✓ 테두리 · 자동 ↑ 솟음 · 알림 ◷ 파선 · 놓침 ! 빨강 레일, 오늘 Moonstone 1px) + **올릴 준비된 글**(예약 · 올리기) + 말투 요약. 기존 `방향과 표현 기준` 패널은 그 아래로 내려간다.

### 16e 휴대폰 390
원고지 한 단 — 여백 칸은 없어지고 목차는 연결 글 머리 `1 / 3 · 38 / 500`으로. 본문 16px / 1.8, 하단 바 `복사(아이콘 44) · 예약 · 올리기`. 올리기는 전체 높이 시트(2026-09-30 기록창의 `sheet="full"`과 같은 그릇) — 브랜드 44px 칩, 채널 56px 줄, 주 버튼 52px.

## 지킨 규칙
- 색은 의미에만: 현재 위치 · 고른 것은 Moonstone 1px 또는 잉크, 빨강은 **올라가지 않는 실패**(500자 초과 · 연결 만료 · 못 올림)와 **놓침**뿐. 이미지 없음 · 브랜드 미지정 · 다시 승인 대기는 글자와 모양으로(§5.2 · §5.3).
- 채널 연결 상태는 모양: 연결됨 ● 채움 · 연결 전 ○ 점선 · 지정 전 ○ 파선 · 만료 `!` 빨강. 예약 방식도 모양: 자동 = 실선/솟음 + ↑, 알림 = 파선 + ◷.
- 권장은 점선 마름모 + `권장` 직접 라벨, 막지 않는다.
- 탭 묶음은 눌린 pill 트랙 + 잉크 현재 칸, 판은 테두리 없이 그림자, 입력은 눌린 홈(2026-10-22).
- 버튼 하나가 primary — 원고는 `올리기`, 창은 대상 이름을 말하는 주 버튼.
- 숫자·주제·문장·시각·만료일은 모두 **예시 값**이다(코드에 넣지 않는다). 브랜드 이름·핸들은 `social-brand-registry.js`의 것을 썼고 채널 상태는 화면 설명용으로 섞어 그렸다.

## 운영자가 고를 것
1. **직접 발행 보류를 풀지.** `docs/README.md` §3의 "콘텐츠 직접 발행 · 보류"(별도 하드 게이트)와 운영자 프로필 Q126("Moonlight가 직접 발행할 것인가, 플랫폼 발행 화면으로 넘길 것인가")에 대한 답이 필요하다. 시안은 둘 다 둔다 — 연결된 채널은 `지금 올리기`, 아니면 `직접 올리기`.
2. **채널 순서.** 권장: Threads 글(저장소 불필요, 고래 시험 계약 재사용) → Instagram 카드뉴스(이미지 저장소) → YouTube Shorts(영상 저장소 · 브랜드 지정).
3. **원고 책상의 여백 칸.** 16a는 오른쪽에 말투 · AI 후보 · 올릴 곳, 왼쪽에 목차 · 결과물을 둔다. 2026-09-23 Studio 단순화 §3의 "사이드 패널(`<aside>`) 없음" 예산과 `content-studio-surface.test.mjs`를 함께 고쳐야 한다. 여백 칸 없이 가려면 말투 · 올릴 곳은 올리기 창(16b)에만 두고 AI 후보는 지금처럼 본문 아래에.
4. **자동 예약의 경계.** 시안 규칙: 운영자가 누른 예약만 자동으로 올라간다(예약 버튼 = 그 내용에 대한 승인), 예약 뒤 본문이 바뀌면 자동은 멈추고 다시 승인, 실패하면 알림으로 돌아온다. AI · 에이전트는 예약을 만들지 않는다(agent-layer-direction "어느 계층도 자동으로 일을 만들거나 밖으로 보내지 않는다"). 채널별 기본값(자동 / 알림)을 브랜드 카드에 둘지도.
5. **브랜드 상세 제목 크기.** 16d는 40px/200(제품·기회 탐색·오늘과 같은 스케일)으로 그렸다. 지금 브랜드는 §11 기본 20px/500이라 예외가 새로 필요하다.
6. **영상 파일 보관.** YouTube Shorts를 Moonlight에서 올리려면 영상 파일을 어디에 둘지(Supabase Storage · 외부 드라이브 링크 · 로컬 앱에서 직접 업로드) 정해야 한다.
7. **확인 필요 흐름.** 응답이 끊기면 다시 올리지 않고 멈춘 뒤 운영자가 `올라갔어요 / 안 올라갔어요`로 정리하는 방식이 괜찮은지(중복 게시 방지 우선).
8. **브랜드 미지정 원고.** 권장: 원고는 브랜드 없이 써도 되지만(AI는 `담백하게`, 09-29 확정), API로 올릴 때는 브랜드(= 계정)를 반드시 고르게 한다. 직접 올리기는 브랜드 없이도 된다.
