# 호감과 결정 기준은 다르다: MEDDIC로 검토 과정을 읽기

제안에 긍정적인 반응이 있어도 결정이 어떻게 이뤄지는지 모르면 다음 대화가 막막해진다. 이때 필요한 것은 상대의 마음을 추측하는 일이 아니라, 조직이 실제로 무엇을 확인해야 하는지 듣는 일이다.

## 관점 읽기

Dick Dunkel이 정리한 MEDDIC는 복잡한 영업 기회의 자격을 여러 요소로 살피는 틀이다. 이 카드에서는 그중 선택 기준, 의사결정에 참여하는 사람, 결정 과정을 구분하는 관점만 가져온다. 담당자가 제안을 마음에 들어 하는 이유와 조직이 비교하는 기준은 같을 수도, 다를 수도 있다. 누가 어떤 자료를 보고 어떤 순서로 판단하는지를 알아야 제안의 빈칸도 보인다.

## 대화에서 써보기

Moonlight에서는 검토가 길어진 제안의 기록을 먼저 읽고, 아직 확인하지 못한 부분 하나를 질문으로 바꾼다. 예를 들어 기준을 모른다면 내부에서 제안을 비교할 때 무엇을 가장 중요하게 보는지 묻는다. 과정이 불분명하다면 최종 확인까지 어떤 단계가 남았는지 묻는다. 답변을 들은 뒤에는 실제로 요청받은 자료만 준비한다.

## 적용 경계

MEDDIC의 항목을 고객에게 순서대로 캐묻는 면담표로 쓰지 않는다. 지연을 예산 부족이나 특정인의 반대로 단정하지 않으며, 내부 구조를 알려주지 않는 고객에게 공개를 압박하지 않는다. 확인된 말과 아직 모르는 부분을 나누어 적는 데서 시작한다.
