## P2 - Idempotency Key For Nil Provider Event IDs

**What:** Require or derive idempotency keys for public provider routes when `provider_event_id` is missing.

**Why:** The unique index only protects events with stable provider IDs. Retries without IDs can create duplicate project updates.

**Pros:** Protects ledger integrity at provider scale.

**Cons:** Deriving a safe hash requires careful field selection to avoid false duplicates.

**Context:** Start with `apps/engine/lib/project-webhook.ts` and shared webhook payload builders. Prefer provider-native IDs; otherwise support an `Idempotency-Key` header or a provider/source/entity/timestamp hash.
